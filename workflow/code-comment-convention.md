# C / C++ 函数与文件分区注释规范

适用范围：所有 C 和 C++ 工程，不限定芯片、操作系统、框架、平台或业务领域。

## 1. 文件内职责分区（分类注释）

为方便后期维护与管理，**一个源文件内功能明显不同的代码块应当用分类注释分隔管理**。
当文件中存在两个及以上职责区域，或函数按用途可归为不同组时，使用以下格式作为一级分类标题：

```c
/******************** 网络事件处理 ********************/
```

适用场景（出现任一即应加分类注释）：

- 初始化、资源释放、事件处理、线程或任务、协议收发等逻辑分区；
- 状态机的“状态迁移 / 定时处理 / 数据上报”等区域；
- 驱动、库或应用文件的“私有数据 / 初始化 / 读写接口 / 回调处理”等区域；
- **功能明显不同的函数群**：例如 `BLE 上报门控 / JSON 发送 / 签到·权限 / 下行解析 / 各业务上报`，彼此职责独立，应各自成区，不要混在一块。

规则：

- 标题应描述职责，不能只写“功能 1”“其他”。
- 分类注释放在该类第一个函数之前；区与区之间靠标题自然分隔，不必额外加空行墙。
- 不需要为了凑分区而过度添加；单一职责的小文件（只做一件事）可以不使用分类注释。
- 同一文件的分区标题格式与星号数量保持一致。
- 分类注释与函数注释（见第 2 节）配合使用：**分类管“块”、函数注释管“点”**，二者互补而非重复——分类标题说清这块是干什么的，块内每个函数再用单行注释说清自身作用/参数/返回值。

## 2. 函数注释：默认单行，超长才换行

> **默认规则：一律先写成单行。** 单行是默认形态，双行 / 三行只是“超长时的兜底”，绝不可当作默认写法，更不能无脑拆成三行。

每个新增或修改的函数定义前，统一写中文 `//` 行注释，内容顺序固定为
`函数作用：` → `参数：` → `返回值：`，段与段之间用单个空格连接。

单行长度阈值 **70 字符**（按字符数统计，含 `// ` 前缀，中文按 1 个字符计，不按显示列宽）。
该阈值是“不允许再长的硬上限”，不是“建议长度”；**应优先用精炼措辞把注释压到一行内**，而非默认拆行。

换行规则（仅在超出 70 字符时才递进使用）：

- **默认（首选）：合并为一行。** 绝大多数函数都应落在此类，能一行写完就绝不拆。
- **仅当单行 > 70 字符**：第一行只写「函数作用」，第二行写「参数 + 返回值」。
- **仅当第二行仍 > 70 字符**：三段各占一行（最后兜底，极少见；出现时应先精简文字避免三行）。

```c
// 函数作用：初始化激光/显示相关 GPIO、PWM 默认参数和通信帧序号。 参数：无。 返回值：无。
```

```c
// 函数作用：配置 PWM 占空比，用于调节输出功率。
// 参数：ratioValue：千分比占空比，超过 1000 时按 1000 限幅。 返回值：无。
```

```c
// 函数作用：解析来自串口控制器的协议帧，校验帧头帧尾后按命令字更新设备状态。
// 参数：data：接收到的完整协议帧。
// 返回值：无。
```

即使函数只有一行实现也照此书写；不要把注释写成 `/** ... */` 块。

适用于：

- 对外公开函数；
- `static`、匿名命名空间或私有辅助函数；
- 线程、任务、事件和回调处理函数；
- C++ 成员函数、静态成员函数与模板实现函数。

## 3. 组合示例

```c
/******************** 网络事件处理 ********************/

// 函数作用：处理网络地址获取事件并通知上层。 参数：event：事件数据。 返回值：无。
static void on_address_ready(const event_t *event)
{
    // ...
}

/******************** 配置加载 ********************/

// 函数作用：加载远端配置并更新运行时信息。 参数：无。 返回值：0 表示成功；其他值表示加载或解析失败。
int load_remote_config(void)
{
    // ...
}
```

若项目使用 Doxygen、Javadoc 风格或其他 API 文档工具，头文件/公开接口仍保留完整契约；源文件中的分区标题和函数注释用于帮助快速阅读实现。
