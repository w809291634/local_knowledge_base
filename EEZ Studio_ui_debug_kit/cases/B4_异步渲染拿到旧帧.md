# B4 批量抓图内容重复（异步渲染拿到旧帧）

## 现象

连续抓取多个视图的原生渲染图，其中几张**文件大小完全相同**：

```
viewA.png     23327 B
viewB.png     23327 B
viewC.png     23327 B
```

`md5sum` 校验后确认它们**逐字节相同** —— 即后两张拿到的根本不是自己的画面。

## 证据

```bash
md5sum <抓图目录>/*.png | awk '{print $1}' | sort | uniq -d
# → 同一个哈希出现多次
```

再对比文件体积：正常视图的 PNG 在十几 KB 到三十几 KB 之间波动，
而"重复组"体积一模一样 → 内容逐字节相同。

## 曾经的误判

**误判为**："应用没响应点击，视图没切过去。"

**实际**：视图**切过去了**（点击事件的返回值显示点中了正确的节点，坐标也合理），
只是**画布还没重绘**，而脚本"一发现画布存在就取"→ 取到了**上一视图留下的旧帧**。

## 真因

渲染是**异步**的：

- 切换视图只触发了"重绘请求"，`<canvas>` 元素**一直都存在**（只是内容还没更新）
- 脚本的判定条件是"**存在 canvas**"，不是"**canvas 内容属于当前视图**"
- 于是第一次轮询就命中旧帧并退出循环

同类问题的另一面：一次会话里连续切换，引擎可能**只在第一次真正重绘**，
后续视图的画布保持上一次的内容（表现为"永远抓不到第 2 个视图以后的新画面"）。

## 修法

三条一起上：

```js
// ① 只在"像素与上一帧不同"时才落盘
const data = c.toDataURL('image/png');
if (prev !== null && data === prev) continue;      // 还是旧帧，继续等
prev = data;                                       // 记下本帧，供下一个目标比对

// ② 过滤空白帧（单色图压缩后极小，正常画面不会这么小）
if (buf.length < 2500) continue;

// ③ 点选时优先"目标列表"里的候选，避免点到同名的标签/标题
```

外加一条**工程实践**：**一个目标一次启动**。虽然理论上一次会话能连抓多张，
但实测"第二次起不再重绘"的概率很高 —— 与其猜，不如重启（可接受的时间成本）。

## 验证

```bash
# 张数 == 目标数
ls <抓图目录>/*.png | wc -l

# 唯一 md5 数 == 目标数（关键断言，防重复）
md5sum <抓图目录>/*.png | awk '{print $1}' | sort -u | wc -l
```

## 通用化

**"截图/抓图必须等画面稳定"** 是所有异步渲染 UI 的通病：

| 场景 | 典型表现 | 对策 |
|---|---|---|
| 组件树引擎切页/切视图 | 抓到上一个视图的画面 | 等像素变化（本案） |
| Web SPA 路由切换 | 截图抓到白屏/旧页 | `waitForSelector` + `waitForLoadState('networkidle')` |
| Canvas / WebGL 渲染 | `toDataURL()` 返回空白 | 在 `requestAnimationFrame` 内取；或开 `preserveDrawingBuffer` |
| 列表虚拟滚动 | 只截到可视区 | 先 `scrollTo` + 等一帧 |
| 字体晚加载 | 文本先方框后正常 | 等 `document.fonts.ready` |

**通用判别法**：只要出现"**多张图 md5 相同**"或"**图像内容与操作的视图不符**"，
一律先怀疑"**没等画面变化**"，而不是"操作没生效"。

**通用自检**：任何批量抓图任务，结束前都跑一次
`唯一哈希数 == 目标数`，不等就说明有重复，必须报告而不是静默交付。
