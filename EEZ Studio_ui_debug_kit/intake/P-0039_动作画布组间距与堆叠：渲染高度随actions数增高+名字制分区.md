# P-0039 动作画布组间距/堆叠：渲染高度随 actions 数增高 + 名字制分区

- **状态**：fixed
- **发现日期**：2026-10-01
- **提示词**：PR-0065
- **标签**：EEZ-flow, 画布布局, 渲染高度, 堆叠, 组间距, 名字制分区, 分区键

---

## 一、现象（用户原话：「组之间不用隔太远，同时组里面的 actions 不要堆叠了」）

P-0037/38 的分区布局遗留两问题：
1. 组之间距离过远——音乐/通知两个**无动作链的空分区列**也各占 420px；
2. 组内 actions 视觉堆叠——**EEZ 组件渲染高度随 actions 数自动增高**
   （JSON 里声明的 height=54 只是最小值），行距按固定 90/70 排，
   getter（9 个 action）实际渲染 ~340px、Add（2 个）~110px，把下方组件盖住。

## 二、修复（json2eez.py::build_page）

1. **行距动态化**：`_row_h(n) = max(90, 60 + n*32)`；分区列 `_slot(path, n_actions)`
   按「下一个组件的 action 数」累计 y；tabsync 的 Compare/Add 行距按
   `max(80, 50 + len(group)*32)` 累计（yy）；getter 的声明 height 同步
   `max(54, 40 + len(acts)*30)`。
2. **列距收紧**：620 → 420。
3. **名字制分区（根治空列与组名错位）**：`_bucket` 返回**分区名**（字符串），
   `col_of[名] = 列号` 按首次出现顺序分配——无动作的分区永不占位，
   组名与列天然一一对应。首版「数字桶 + 空列压缩重映射」会产生
   **组名错位**（主导航组被标成音乐）：重映射改写 x 后组名仍按旧列号查表。

## 三、证据

- 分区列实测：AI x=820（9 组件）、设置·Wi-Fi x=1240（10）、主导航/全局 x=1660（5）、
  换页同步链 x∈[2080,3820]（18）——组间距 420 紧凑、无空列、
  组内垂直 0 重叠（按渲染高度估算校验）。
- `all.py --shots` EXIT=0：11 屏对照 8.61%、6 条 swipe 断言全过。

## 四、沉淀

- **布局键用语义名，不用数字序号** —— 数字桶 + 重映射是错位温床；
- **EEZ 组件渲染高度 = max(声明值, actions 行数推导值)**，画布布局必须按
  渲染高度排，不能按声明 height 排。
- 诊断手法：`_bucket` 加环境变量门控的 path 打印，一次定位误判来源。
