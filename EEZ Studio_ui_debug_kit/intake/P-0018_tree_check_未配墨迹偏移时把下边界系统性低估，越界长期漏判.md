# P-0018 · tree_check 未配墨迹偏移时把下边界系统性低估，越界长期漏判

- **工程**：小艺 · 智能屏 8
- **日期**：2026-09-27
- **工具**：WorkBuddy
- **状态**：fixed
- **标签**：tree_check,越界,假通过,墨迹,精度
- **关联提示词**：PR-0032

## 现象（看到什么）

G4 报告「几何越界 0」看似通过，但判定基准本身是错的：未配 fonts.ink_offset_from_box_top 时，tree_check 用 y+1..y+px+1 当墨迹框，比真实墨迹低好几个像素

## 复现（怎么稳定重现）

python -c "import kit;tm=kit.TextMeasurer(cfg);print(tm.glyph_metrics('状态栏Ag01:24',size=px))"

## 根因（真正的原因）

13px 真实墨迹 bot=17 而保守估计只有 14（低估 3px）；54px 真实 70 vs 保守 55（低估 15px）。字号越大低估越狠，而屏幕底部正是状态栏/导航栏区域 —— 垂直越界几乎必然被漏判。属于「检查通过了但检查本身不成立」的假通过，与 P-0012 同类

## 修复（做了什么）

tree_check.py 在无该配置时不再用保守常量，改为调 `TextMeasurer.glyph_metrics()` 对该串字形做 PIL 实测 `(top, bot)` —— 比手工维护一张易错的偏移表更可靠，任何工程零配置就能拿到真实度量。

## 证据（数字 / 命令输出）

修复前后对比：13px bot 14->17、42px 43->54、54px 55->70；从严后 tree_check 复跑仍为「几何越界 0 / 折行 0 / 字体 0 / 死链 0 / 入口页 0 / 无墨迹 0」，全门禁 G1/G4/G5 依旧 PASS，说明结论不是靠漏判撑住的

## 沉淀（新增断言 / 案例 / 文档）

新增工具 tools/config_check.py（配置适配体检）；修正 tree_check 越界判定
