## 现象（看到什么）

用户诉求（PR-0111 逐字，与本条相关两句）：
> 「m_cats_wifi 这个触发的 flow，不应该直接弹出 wifi 连接界面，而是像其他两个按钮一样，切换到指定的 tabpager 页即可」
> 「你的修改错误了，先还原上次修改，我的意思是，点击 网络 与 链接 弹出 【配图】 这个界面，简单修改即可」

用户配图 = **通用页**那一屏（设备卡 + 无线网络 / 语音唤醒 / 主音量 / 屏幕亮度 / 勿扰模式）。

我第一遍把「切到指定 tabpager 页」理解成「**新增一页 Wi-Fi 面板**」：做了 `tab_net` 子页、
`pane_network` 建两份（子页 prefix `netp_` / 浮层 `net_`）、页序改成 4 页并同步了 6 处索引
（那一份过程记录在 **P-0089**）——被用户当场打回还原。

## 复现（怎么稳定重现）

点左栏第一项「网络与连接」：
- 误解版 → 切到一个**新建的**「网络」子页（4 页页序：0 通用 / 1 网络 / 2 显示 / 3 唤醒）；
- 正确版 → 切到**已存在的**通用页（tab 0），左栏高亮，浮层不弹。

## 根因（真正的原因）

**语义误解，不是技术缺陷**：用户说的"指定页"往往就是某个**已有**页 —— 左栏 wifi 归通用页，
因为通用页里第一行就是「无线网络」。把"切到指定 tabpager 页"读成"新增一页"，
凭空造出 `tab_net` + `netp_` 一整份重复结构，还要牵动 6 处页序索引（P-0089 那份清单正是这么来的）。
为什么容易踩：`rail_cats` 里旧形态是 `"pop"`（弹浮层），改成"切页"时最直觉的做法就是
"给它一页可切"，而没先问"目标页是否已经存在"。

## 修复（做了什么）

**最终净改动只有 3 行 + 删 pop 分支**：

1. `CATS`：wifi 由 `"pop"` 改成 **`0`**（通用页），sun/mic 保持 1/2 ⇒ **页序仍是 3 页**
   （0 通用 / 1 显示 / 2 唤醒），不新增任何页。
2. `rail_cats`：删掉 pop 分支（旧链是 `switchTab(tab=None)` 只同步高亮 + `onShow` 开浮层
   两条动作组件）与 `pop_refs` 参数；wifi 行改成与 sun/mic **完全同款**的
   `switchTab{tv_ref, tab:0}` + clear/add 高亮链。
3. 高亮分组 `cats_add` **3 组**：0=wifi / 1=sun / 2=mic（沿用 P-0034「每页都要有归属高亮」）。
4. 通用页 `pane_settings` **不动** ——「无线网络」那一行仍 `onShow` 弹浮层做连接设置。
5. 页序没变 ⇒ `sim.py` 只在 `nav_btn_for` 加 `case 0 → m_cats_wifi`，**其余索引一律不动**。

## 沉淀（新增断言 / 案例 / 文档）

- ★★ **「切到指定 tab 页」≠「新增一页」**：改导航前先确认**目标页是否已存在**；
  需求有歧义就问清目标页，别自己发明新页（本轮第 105 轮的整套 netp_ 结构就是白造的成本）。
- ★ 极简改动的判据：**净 3 行 + 删一个分支**，且不牵动页序索引（对比误解版的 6 处同步）。
- **P-0089 的走路器对象表上限修复（700→1600 + 自证行）予以保留** —— 那是独立真 bug
  （`wmap_add` 静默丢尾部），与本次理解错误无关，不随误解版一起回退。
- 与 P-0079/P-0080 同族的方法论教训：别把字面读成意图；改前确认用户已有设定，
  改后真点/真切一遍取证（cattab 目检就是这一步）。
