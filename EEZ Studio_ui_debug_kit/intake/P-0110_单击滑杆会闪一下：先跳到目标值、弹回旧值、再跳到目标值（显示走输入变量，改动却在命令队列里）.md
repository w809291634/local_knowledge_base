# P-0110 · 单击滑杆会闪一下：先跳到目标值、弹回旧值、再跳到目标值（显示走输入变量，改动却在命令队列里）

- **工程**：eez-test
- **日期**：2026-10-03
- **工具**：Qoder
- **状态**：fixed
- **标签**：滑杆,闪烁,回弹,输入变量,命令队列,统一表,乐观回显
- **关联提示词**：PR-0168

## 现象（看到什么）

用户实测：点一下音量滑杆，UI 先到指定音量，又回到之前的音量，随后再跳到指定音量 —— 一次可见闪烁。拖动时看不出来（后面连续事件盖住了），单击才暴露

## 复现（怎么稳定重现）

PC 侧同理：单击滑杆（一次 VALUE_CHANGED）⇒ 该拍若先跑 io_sample_inputs 再排空命令，就会看到 旧值→新值 的二次发布。真机单击音量/亮度滑杆目视即现

## 根因（真正的原因）

显示值与改动值不是同一个即时性：滑杆 value 绑的是**输入变量** APP_IN_VOLUME_PCT（io 侧每拍从 g_set 发布），而 set_var_volume_pct 只往命令队列投一条 APP_OUT_VOLUME_SET，要等 user_io_tick 排空才生效。于是单击后有一拍 io_sample_inputs 仍按**旧表值**发布 ⇒ 把用户刚点到的位置打回旧值，命令落地后再跳回来。P-0108 之后这个窗口更容易撞上：tick 里 app_settings_tick() 排在 io_sample_inputs 之前，而命令排空排在最后

## 修复（做了什么）

native_vars.cpp 里 5 条滑杆型 set_var_*（volume_pct / brightness / wake_sens / music_vol / alert_vol）**先写统一表 g_set**，再投命令。表 = 唯一内存，落硬件/存 NVS 仍由 app_settings_tick 的变更比对负责；旧值从此不可能再被发布，回弹窗口消失。命令保留（io 侧日志与平台差异处理不动，重复赋同值无害）。顺带补 native_vars.cpp 的 #include "app_settings.h"

## 证据（数字 / 命令输出）

`_device_syntax_check.py` 4 文件（io_esp / native_actions / app_model / native_vars）= 0 错 0 警；
`all.py --sim` rc=0、9 屏平均明显差异 **9.89%**（阈值 25%）无缺屏；
`--walk=volpull` 断言轨迹：`gettext m_np_np_vol_pct = " 42 %"` → 拖到 30 → `" 30 %"` → 拖到 55 → `" 55 %"`
（每步之间等 700ms = 几十拍，中间不再出现旧值）。
⚠ 但要如实说：PC 走路器**抓不到这个闪烁本身** —— 旧值窗口是亚帧级的，gettext 的采样点跨不过去；
这条自证只保证"值不会停在旧值上"，最终判定以**真机单击目视**为准。

## 沉淀（新增断言 / 案例 / 文档）

通用规则：**UI 写、io 读的循环里，显示值必须与用户动作同拍更新**（乐观回显），否则任何"投队列再排空"的往返都会开出可见的旧值窗口；拖动被连续事件掩盖、单击才暴露 ⇒ 交互回归要专门测"单击"而不只是"拖动"；走路器新命令 gettext 可打 label 当前文本当断言载体

## 追加（同日）：只写表**没治好** ⇒ 还有第二条路径，且 PC 根本复现不出来

用户回真机：还是闪。说明"写表"只补了 io 侧那条发布路径，**漏了 UI 侧的绑定回写**：

- EEZ 对绑变量的滑杆，每次刷新都会执行 `lv_slider_set_value(obj, get_var_volume_pct(), ...)`；
- 而 `get_var_*` 读的是**模型槽 `APP_IN_VOLUME_PCT`**，那个槽要等
  `user_io_tick → io_sample_inputs` 才更新；
- ⇒ 单击后有一帧：绑定按**旧槽值**把滑杆打回去，命令落地再跳回来 = 闪烁。
  写表改的是"发布什么值"，改不了"绑定读什么"。

**断根改法**：5 条滑杆的 `get_var_*` 改成**直接读统一表 `g_set`**
（`volume_pct / brightness / wake_sens / music_vol / alert_vol`）。表在 `set_var` 里同拍写过
⇒ 绑定不可能再读到旧值。`APP_IN_*` 照旧发布（待机页等别的消费者还在用），
只是不再当滑杆的真值源。

★ **PC 复现不出来**（重要，别再拿 PC 绿当修好）：新加走路命令 `getval <obj>`
（读滑杆真实值；`lv_obj_get_value` 在本工程 LVGL 9.x **不存在**，链接期 undefined reference，
真名是 `lv_slider_get_value` —— 又应验 P-0090"写之前先 grep 确认符号真身"）
+ 走路脚本 `--walk=volflash`（setslider 后每 20ms 采样）。修复前后在 PC 都是
`42 → 25 → 一路 25`，**一帧回弹都抓不到** ⇒ 这类"绑定 vs 事件"的亚帧竞态只有真机看得见。
教训：**UI 绑定回写型控件的时序 bug，PC 仿真没有对应的那条刷新顺序，就不能用 PC 绿来判定修好**；
要么真机验，要么把仿真做成同一条路径（这里没做到）。

验证（PC 能验的部分）：`native_vars.cpp` 等 4 文件真编译 0 错 0 警；`--walk=volpull`
`42→30→55` 稳定；`all.py --sim` = 9 屏 9.92%（逐屏比对：只有 01 待机主屏 10.66%→10.85%，
是待机页时钟/最近对话随时间变的抖动，其余 8 屏小数点后两位完全一致 ⇒ 非布局回归）。
