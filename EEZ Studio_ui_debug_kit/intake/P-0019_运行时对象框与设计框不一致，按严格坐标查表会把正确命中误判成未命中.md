# P-0019 · 运行时对象框与设计框不一致，按严格坐标查表会把正确命中误判成未命中

- **工程**：小艺 · 智能屏 8
- **日期**：2026-09-27
- **工具**：WorkBuddy
- **状态**：fixed
- **标签**：LVGL,坐标,命中,查表,框偏差
- **关联提示词**：PR-0033

## 现象（看到什么）

G3 首跑报 20 个未命中，全部集中在 bar/switch/row；看起来像大面积遮挡问题

## 复现（怎么稳定重现）

python design/sim.py --ui-only --probe，严格按 (x,y,w,h) 相等查表

## 根因（真正的原因）

运行时对象框与设计框存在两类系统偏差：带边框对象外扩 1px（300,164->301,165，宽高不变）；bar 的对象框被撑高（设计 5px 实际 12px、6px 实际 14px），中心不变。点击其实都正确命中了自己，是查表方式太苛刻造成的假阳性

## 修复（做了什么）

查表从严格相等改为按命中对象中心点反查登记条目（同页多个包含该点时取面积最小的）；框不一致时额外打印偏差量，便于发现真正的位置问题

## 证据（数字 / 命令输出）

改前 11 屏合计未命中 20 个；改后 81 个控件 11 屏 0 未命中。--click-all 端到端派发 81 次单击，0 落空，[CLICK] 打印行全部正确

## 沉淀（新增断言 / 案例 / 文档）

click_trace.cpp 的 map_lookup_point；README §4.④ 记录了偏差成因
