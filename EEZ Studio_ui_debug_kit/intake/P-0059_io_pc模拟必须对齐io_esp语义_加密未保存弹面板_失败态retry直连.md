# P-0059 · PC 模拟的 Wi-Fi 语义必须对齐真机 `io_esp`（否则静态截图全绿、走路才露馅）

- **日期**：2026-10-02（PR-0107）
- **工具**：WorkBuddy + PC 仿真器交互走路器
- **症状**：`io_pc.cpp` 的 `io_wifi_pick` 一律直连（加密网络也不弹密码面板），
  `io_wifi_join` 是个只打桩没有状态的空函数 —— 静态钉态截图根本看不出来
  （钉态是手工置位的），一上走路器「点 AP → 输密码 → 连接 → 结果」立刻暴露。
- **根因**：PC 假后端与真机后端各写一份语义，长期不同步；真机 `io_esp::io_wifi_pick`
  的口径是「开放网络 / 已保存过的加密网络 → 直连；加密且没保存过 → 弹密码面板」，
  PC 没对齐。同理，真机「重试」= 清 user-disconnect + `StartStation` 恢复自动连接
  （清错误、直接进连接态），不是把密码面板再弹一遍 —— PC 若走普通 pick 分支就会
  又弹面板，导致「失败 → 重试 → 成功」这条链走不通。
- **规则**：
  1. `io_pc.cpp` 的 pick / join / retry 三处，改之前先读 `io_esp.cpp` 同名函数当真值；
  2. PC 侧失败态（`s_wifi_state == 4` 且同槽位）特判成 retry：清 `wifi_err` + 进连接态；
  3. **验收靠走路脚本而不是钉态**：钉态是手工置位，只能证明"画面画得对"，
     证明不了"这套交互真的跑得通"。
- **状态**：fixed（pick 加密分支 / join 真实现 / retry 特判三处已对齐；
  `--walk=wifi`（失败）、`--walk=wifi_ok`（已保存直连成功）、
  `--walk=wifi_retry`（失败→重试→成功）三条链路均跑通）
