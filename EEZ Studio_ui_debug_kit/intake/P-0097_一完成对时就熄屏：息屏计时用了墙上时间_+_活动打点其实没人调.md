# P-0097 · 一完成对时就熄屏：息屏计时用了墙上时间 + 活动打点其实没人调

- **工程**：eez-test
- **日期**：2026-10-03
- **工具**：Qoder
- **状态**：fixed
- **标签**：息屏,背光,timeNULL,esp_timer,单调时钟,跨任务,io_note_ui_activity
- **关联提示词**：PR-0129

## 现象（看到什么）

用户报：有时候一完成 WiFi 连接后就出现熄屏休眠，跟有没有人操作无关。

## 复现（怎么稳定重现）

设置里把「息屏时间」调到 1 分钟，开机自动连网等到对时/OTA 完成那一刻 —— 原实现会在对时瞬间黑屏（旧版 time(NULL) 计时）；改后同条件不再出现 screen OFF，只有满 1 分钟无交互才熄。

## 根因（真正的原因）

两处叠加：1 io_sample_inputs 里用 time(NULL) 与上次活动相减，而对时是 settimeofday 阶跃（1970 跳 2026）—— 差值瞬间超过 timeout，必然熄屏；2 io_note_ui_activity 虽在 io_iface.h 声明且注释写着每条 UI 命令打点，实际全工程没有调用者，只有 io_set_screen_timeout 自己调，续期只剩 indev 采样。

## 修复（做了什么）

计时基准换 esp_timer_get_time 的单调毫秒；app_model 的 user_io_tick 排空命令后按 acted 调 io_note_ui_activity，io_pc 补实现（否则 PC 链接 undefined reference）；CMakeLists REQUIRES 显式加 esp_timer。再因工作任务也要写这个时间戳，把 int64 微秒改成 volatile uint32 毫秒 + 无符号回绕比较 —— RV32 上 64 位读写非原子，会撕裂成巨大 idle。s_screen_off 也加 volatile。

## 证据（数字 / 命令输出）

真机判据：对时/OTA 后不再出现 screen OFF；息屏中点 UI 出 wake by UI command，触摸出 wake by touch。设备侧真编译 4 文件 0 错 0 警，PC 走路 keep 与 wifi_ok 回归通过。

## 沉淀（新增断言 / 案例 / 文档）

MEMORY.md：跨任务共享时间戳一律 32 位单调毫秒；time(NULL) 只做显示
