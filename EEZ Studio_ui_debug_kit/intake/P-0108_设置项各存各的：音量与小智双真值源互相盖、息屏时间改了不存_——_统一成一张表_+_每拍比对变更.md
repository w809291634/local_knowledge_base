## 根因（真正的原因）

15 个设置散在 io_esp.cpp / io_pc.cpp 两份 static + 各自 NVS。音量是**双真值源**：AudioCodec 自己就存 NVS（audio/audio_codec.cc:29-45，namespace audio / output_volume），云端 MCP self.audio_speaker.set_volume（mcp_server.cc:55-62）直接调 codec->SetOutputVolume；我们又存一份 ui_settings/vol 且 UI 读自己那份 ⇒ 必然不同步。to_min 更直接：开机 load 读它，但 io_set_screen_timeout() 不写、settings_save() 里也没这个键 ⇒ 天生不持久化

## 修复（做了什么）

用户点单的模型：一张结构体 + 软件定时器周期比对变更再输出。新增 src/native/app_settings.{h,cpp}：g_set 唯一实例（15 项，默认值逐字照抄迁移前）+ app_settings_hw_t 钩子（read/write_volume、write_brightness、save）+ app_settings_tick()：先读回硬件真值→表变了才落硬件→整表 memcmp 变了才存 NVS（最快 1 秒一次）。tick 挂在 user_io_tick() 且放在 io_sample_inputs 之前 ⇒ 同一帧就发布。io_esp：15 个 static 全删（改名 92 处），settings_save/load 换成 esp_settings_save(const app_settings_t*)/esp_settings_load()，键名与 namespace 全部沿用（老固件升级不丢），新增 to_min 写入、**删掉 vol 的读写**（音量以 codec 为准，旧键留着不碰）；20 余处 settings_save() 调用点清除，setter 只写表；io_init 里 bind 钩子 + reset_shadows()（首拍必落一次硬件，等价原 apply_backlight+apply_codec_volume）。板级加 app_audio_get_output_volume()（codec 判空返回 -1=读不到）。io_pc 同表 + 假 codec 寄存器（EEZ_SIM_AI_VOLUME 模拟云端改音量）⇒ 读回/输出两步在仿真里真跑
