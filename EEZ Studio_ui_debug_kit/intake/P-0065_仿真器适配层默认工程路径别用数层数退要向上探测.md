# P-0065 · 仿真器适配层默认工程路径别用 `../` 数层数退，要向上探测

- **工程**：小艺·智能屏 8（eez-test）/ PC 仿真器 lv_port_pc_vscode_v9.5
- **日期**：2026-10-02
- **工具**：WorkBuddy
- **状态**：fixed
- **标签**：CMake,适配层,TARGET_PROJ_DIR,路径,报错可读性,仿真
- **关联提示词**：无

## 现象（看到什么）

不带 `-DTARGET_PROJ_DIR=` 直接 `cmake ..` 时：

```
CMake Error at CMakeLists.txt:198 (add_executable):
  Cannot find source file:
    D:/esp32_8266_files/esp-idf-v5.5.5_ol/examples/p4_touch_lcd4_3_exp/lvgl_demo_ai/eez-test/design/sim_cmake/main.c
  Tried extensions .c .C .c++ ...
CMake Error at CMakeLists.txt:198 (add_executable):
  No SOURCES given to target: main
CMake Generate step failed.  Build files cannot be regenerated correctly.
```

注意路径里的 `examples/**p4_touch_lcd4_3_exp**` —— 少了 `idf_v555_my_exps` 这一级。

`sim.py` 流程不受影响（它每次都显式传 `-DTARGET_PROJ_DIR=<工程根>`），所以只在**手动裸跑 cmake** 时暴露。

## 复现（怎么稳定重现）

```bash
cmake -S <PC_SIM>/lv_port_pc_vscode_v9.5 -B <某空目录> -G "MinGW Makefiles"
```

（不传 `-DTARGET_PROJ_DIR`，且 `design/sim_cmake/main.c` 存在。）

## 根因（真正的原因）

适配层原写法是硬数层数：

```cmake
get_filename_component(TARGET_PROJ_DIR
    "${PROJECT_SOURCE_DIR}/../../../../p4_touch_lcd4_3_exp/lvgl_demo_ai/eez-test" ABSOLUTE)
```

从 `${PROJECT_SOURCE_DIR}`（`.../examples/idf_v555_my_exps/common/PC_SIM/lv_port_pc_vscode_v9.5`）退 4 层 = `examples` 那一层，
而目标工程在退 5 层的位置（`examples/idf_v555_my_exps/p4_touch_lcd4_3_exp/...`）。**少退一级**，
于是拼出一个不存在的路径。`add_executable` 才报 "Cannot find source file"，错误信息只给路径、不给原因，
不看上下文很难想到是"数错了层数"。

## 修复（做了什么）

文件：仿真器根 `CMakeLists.txt`（适配层，唯一被改的文件）

1. 默认定位改成**向上探测**（不再数层数，目录嵌套再深也不受影响）：
   从 `${PROJECT_SOURCE_DIR}` 一路 `get_filename_component(... DIRECTORY)` 往上找，
   直到 `${_sim_probe}/p4_touch_lcd4_3_exp/lvgl_demo_ai/eez-test/src/ui` 这个哨兵文件存在为止；
   找不到就 `FATAL_ERROR` 并提示用 `-DTARGET_PROJ_DIR=` 显式指定。
2. 在 `SIM_MAIN_DIR` 之后加存在性断言：
   `main.c` / `lv_conf.h` 任一缺失就 `FATAL_ERROR` 说清"多半是 TARGET_PROJ_DIR 指错，或目标工程还没跑过 sim.py"，
   不再拖到 `add_executable` 抛看不出原因的错。
3. 关键路径打 `message(STATUS "[sim] TARGET_PROJ_DIR = ...")` / `"[sim] SIM_MAIN_DIR = ..."`，
   配置日志里一眼能核对"到底指向了哪个工程"。

## 证据（数字 / 命令输出）

修复后裸 configure（不带 `-D`）：

```
-- [sim] TARGET_PROJ_DIR = D:/.../examples/idf_v555_my_exps/p4_touch_lcd4_3_exp/lvgl_demo_ai/eez-test
-- [sim] SIM_MAIN_DIR    = D:/.../examples/idf_v555_my_exps/p4_touch_lcd4_3_exp/lvgl_demo_ai/eez-test/design/sim_cmake
-- Configuring done (1.1s)
-- Generating done (0.3s)
```

（修复前：`Cannot find source file: .../examples/p4_touch_lcd4_3_exp/...` + `Generate step failed`。）

## 沉淀（新增断言 / 案例 / 文档）

- 经验：任何"默认路径靠相对层数推导"的适配层，都改成**哨兵文件探测** + 缺失即 FATAL 报因。
- 已加可自证的配置期 message（`[sim] TARGET_PROJ_DIR` / `[sim] SIM_MAIN_DIR`），一眼核对指向。
- 未加断言（属 CMake configure 期，不在 `tools/audit_ui.py` 的 UI 断言范围内）。
