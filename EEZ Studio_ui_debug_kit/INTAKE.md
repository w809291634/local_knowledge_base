# INTAKE.md —— 「新问题」与「提示词」的记录规约

> **本文件是给任何 AI 工具（和人）看的写入说明。**
> 你在用本技能开发时，只要发生下面两件事，就必须往工具箱里记一笔 —— 不要只在对话里说说就完事。

| 发生什么 | 记到哪 | 编号 |
|---|---|---|
| 遇到一个**新问题**（报错 / 表现异常 / 踩坑） | `intake/P-####_*.md` + `intake/index.md` 一行 | `P-0001`, `P-0002`… |
| 用户给出一条**提示词**（每次输入） | `prompts/PROMPT_LOG.md` 追加一段 | `PR-0001`, `PR-0002`… |

两者的关系：**提示词是"因"，问题是"果"**。一条提示词可能引出 0~N 个问题；一个问题也可能由多条提示词迭代而来。互相用编号引用（`P-0001` / `PR-0007`），日后就能顺着追《当时用户说了什么 → AI 怎么定位 → 改了什么》。

---

## 0. 两条硬性纪律

1. **只往后追加，绝不改历史。** 判断被推翻时，不要删旧条目 —— 新写一条说明"为什么当初误判"。这比只留正确答案有价值。
2. **提示词逐字抄。** 用户的原始输入不要改写、不要润色、不要翻译。要的是可追溯的"原话"。

---

## 1. 怎么记（两种方式，任选）

### 方式 A：跑脚本（推荐，任何能执行命令的 AI 都行）

```bash
# 记一条提示词（通常在每一轮对话结束时做）
python tools/log_entry.py prompt "用户的原始提示词" \
    --tool WorkBuddy --ask "用户想达成什么" --out "这轮做了什么/结论" --link P-0001

# 记一个新问题
python tools/log_entry.py problem --title "按钮点了没反应" \
    --project "<你的工程名>" --tool WorkBuddy --tags "点击,遮挡" --status open \
    --symptom "点按钮中央无反应，只有边缘有效" \
    --repro "固定坐标 (160,136) 点击，命中对象是装饰容器" \
    --root "装饰 container 默认可点，盖在按钮上吃掉了点击" \
    --fix "给该容器 clickable=False" \
    --evidence "命中仿真：修复前命中 ContainerA，修复后命中 Button" \
    --sink "新增断言 A5" --link PR-0007

# 看看已经记了什么 / 下一个编号是多少
python tools/log_entry.py list
python tools/log_entry.py next-id problem
```

脚本只用 Python 标准库，路径固定为 `<工具箱>/intake` 与 `<工具箱>/prompts`，无需配置、无需联网。

### 方式 B：手写（脚本跑不了时的兜底）

1. 新建 `intake/P-<下一个四位号>_<短标题>.md`，照抄 `intake/TEMPLATE.md` 的段式；
2. 在 `intake/index.md` 末尾加一行 `| P-0003 | 日期 | 标题 | 标签 | 状态 |`；
3. 提示词则往 `prompts/PROMPT_LOG.md` 末尾追一段，格式照抄已有条目。

> 编号取"当前最大值 +1"，不要复用、不要留空号。

## 2. 一个问题要写到什么程度

只写"报错了、修好了"没有价值。**必须有可复现的证据**。段式要求见 `intake/TEMPLATE.md`，核心是这 6 段：

| 段 | 要求 |
|---|---|
| 现象 | 用户/你**看到**什么（不是猜测）。带上可观察的坐标、屏名、报错原文 |
| 复现 | 怎样**稳定重现**（一条命令 / 一个坐标 / 一段输入） |
| 根因 | 真正的原因（不是表面症状）。说清"为什么以前没发现" |
| 修复 | 具体改了什么（文件 + 关键改动），不要写"优化了一下" |
| 证据 | **数字或命令输出**：命中对象前后对比、断言条数、编译结果 |
| 沉淀 | 有没有把它固化成**断言/案例/文档**（这是本技能的自我进化动作） |

---

## 3. 和 `cases/` 的分工

- `intake/` = **原始流水**：开发中随遇随记，允许粗糙、允许未定论。
- `cases/` = **提炼后的案例**：一个坑彻底搞懂、且能推广到别的项目后，按 `cases/README.md`
  的七段式模板**提炼**一条（可引用 `intake/P-####`）。

> 判据：能被下个项目直接复用的，进 `cases/`；只对当前工程有意义的，留在 `intake/`。

---

## 4. 给 AI 的常驻指令（请遵守）

> 1. **每轮对话结束前**，用 `log_entry.py prompt` 把用户本轮的提示词逐字追加进 `prompts/PROMPT_LOG.md`
>    （工具名填你自己；补录历史时 `--time` 写 `"YYYY-MM-DD（补录）"`）。
> 2. **一旦定位到一个非平凡问题**，立即用 `log_entry.py problem` 登记；修好后把 `--status` 更新为
>    `fixed` 并补齐 `--root / --fix / --evidence`。
> 3. 若该问题能推广，**顺手**在 `cases/` 加一条并互相引用。
> 4. 若该问题本可被某条断言提前拦住，就把它加成断言（`tools/audit_ui.py` 的 `CHECKS` 字典）——
>    这是本技能"越用越强"的唯一途径。
> 5. 记录区（`intake/` `prompts/` `skills.md`）**随项目累积**，换新工程时保留，靠每条里的 `工程` 字段区分。
