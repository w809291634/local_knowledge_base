## 2a. 第②步：确认门、标注、跳转与批注回路

第一步设计确认后，第二步在同一 H5 中完成控件标注、分层查看、跳转演练和用户批注；不另拆一步。交互和版式以 w78 示例及 `reference/14` 为准。

- 第一阶段的设计由用户在 H5「高清设计图」页签确认，确认后才开展第二步控件与跳转评审；不得继承示例的确认状态。
- `export_ui.py` 中的旧原型有状态读取逻辑，但当前 `overview_pro.py` 未据此自动隐藏控件或热区；确认顺序由工作流程执行，不能声称 H5 已自动强制。
- 改标注＝改设计源（控件语义表 + `nav_map.py`）→ 重跑生成器刷新 H5；**永远不手改 HTML**。
- 出口判据：用户在高清设计图页签点一遍认可；分层总览无红框（状态页除外）；门禁全绿。
- H5 通过**不替代** ④⑤：EEZ 画布与仿真照做。

## 3. H5 结构（2026-11-04 现状）

- 顶栏：三视图切换（分层总览 / 跳转演练 / 高清设计图）+ 面包屑（`当前页 ← 返回目标`）。
- 分层总览：按 BFS 层级分组列页卡，点卡 → **右侧停靠栏**放大该页 + 控件表；点空白处收起（不设关闭键）。
- 跳转演练：帧上真控件可点真跳页，**直接换页、不做过渡动画**；`‹` 按统一 `trail` 栈返回上一屏；
  卡片点击 => 进详情/切页，与真实 UI 一致。
- 高清设计图：同一帧的 1:1 大图，默认显示全部控件的序号与分类标注，可一键关闭；设计确认在这一页完成。跳转热区的交互规则见下。
- 热区规则：**只给换页类控件叠热区**；开关、滑条、场景只做视觉反馈，不跳页。

## 4. 门禁（缺一不可）

1. `target` 必须存在于页面清单（`nav_audit` A）。
2. 非根页至少 1 条权威入边、每页有回边、BFS 全可达（B/C/D）。
3. 没有入边的页必须显式登记为状态页（E）。
4. 设计源 / H5 / 控件清单三处跳转数逐页一致（F）。
5. 跳转表 ↔ 控件表 target 双向对账；**卡片残留 target 必须为 0**（G/H）。

## 5. 实测证据（w78 智能家居，2026-11-04）

- 23 屏；权威边与逐页入口数由 `nav_audit.py` 打印；D5 逐页相似度见 `d5_相似度.txt`。
- 浏览器真点：主控→客厅→灯详情→`‹`→客厅→主控；通知→查看①→灯详情→返回；

## 6. 坑（都踩过）

| 现象 | 根因 | 处理 |
|---|---|---|
| 热区"点了没反应" | `element.dispatchEvent` 绕过命中测试 | 用 CDP `Input.dispatchMouseEvent`，并用 `elementFromPoint` 自证命中 |
| 返回跑到主页 | 两套返回栈（地图历史 vs 跳转栈）并存 | 只留一个 `trail` 栈，`pushTrail()` 统一入栈 |
| 叠了 28 层页面 | `querySelector('.pg')` 取到第一层而非最后一层 | 换层用整块 `innerHTML` 替换；已取消横滑动效后不再叠层 |
| 放大镜跟着鼠标、干扰视线 | 悬停放大被绑在返回键等热区上 | 改为右侧停靠栏；点空白收起 |
| 高清设计图里点不到返回 | `marks:false` 时没渲染热区 | 单独渲染 `hotBack` 命中框 |
| 房间页只有"返回"一个热区 | 房间设备格的目标表没合并进主表 | 建完 `ROOM_TARGETS` 立即 `NAV_TARGETS.update(...)`，门禁兜底 |
| 某详情页永远进不去 | 场景格没有「详情」，目标表也没登记「执行」 | 场景格单独登记「执行」→ 场景详情；门禁按权威入边查 |
| 卡片挂了跳转却不跳 | 行为层不是"换页"，H5 判类把 target 丢掉 | 卡片只做底板；跳转一律单独控件 + 行为层"换页" |
| 表格底部溢出/行挤成一团 | 行高固定 30 | 行高 = min(30, 可用高度 / 行数) |
| 内联 SVG 不显示 | 设计源产出的是 `<svg>` **片段**，没有外层尺寸 | 包一层 `<svg viewBox="0 0 800 480" width height>` |
