## 2. 单一真值怎么拆

```
design/simple_control.py   基元 + 主控 + 房间模板 + 几何常量（ROOM_GRID/TILE_GRID/BACK_BOX/CAT_COLORS）
design/pages.py            其余页面帧 + 每页控件语义表 (名称, 分类, 点击后, 行为层, 控件框)
design/nav_map.py          跳转目标表 {(页面, 控件名): 目标页面}
design/preview_pages.py    出 01_preview_pages.svg（逐屏长图）
design/export_ui.py        出 00_page_map.svg + prototype/index.html
```

**控件框坐标只写一次**：页面上画控件和热区用的是同一个 `box`，标注图与 H5 因此不会漂。

## 2a. 两种形态与标注回路

- **全览态（默认）**：随第①步的 SVG 设计图**一起生成**，打开 `index.html` 直接落在全览树（`#work` 才进单页）；看设计图默认看这张树，SVG 仍留档供逐屏像素核对。
- **可点态（过确认门）**：`design/flow_state.json` 的 `overview_confirmed=true` 才生成，一次出两样——热区跳转（页面连接）+ **AI 预估控件图**（帧 + 控件表，标题带「AI 预估，待你改口径」）。
  未确认时前端 `D.confirmed=false`：不建热区、控件表换成"全览尚未确认"提示，顶栏提示语同步变。
  命令行：默认读状态文件；`--confirmed` 强制出可点态；`--tree-only` 强制退回核对态。
- **热区数量 = 跳转表里的换页控件数**；用户改标注即改设计源（控件表 + `nav_map.py`）后重生成。
- **标注回路**：用户在 SVG 截图上标（序号/类型/跳向/控制哪个硬件）→ AI 改设计源（控件语义表 + `nav_map.py`）→ 重跑生成器刷新 H5。**永远不手改 `index.html`**。
- 出口判据：用户点一遍认可跳转；全览树无红框（状态页除外）；门禁全绿。
- H5 通过**不替代** ④⑤：EEZ 画布与仿真照做。

## 2b. 全览树（H5 顶栏「全览」；在 SVG 设计图确认之后才做）

- **每个节点内嵌该页真实设计图**：帧与 H5 单页用同一段 SVG 字符串等比缩略，不另画、不用截图。
- **小图看位置**：节点宽 240（0.3 倍）够用；每个会跳转的控件在缩略图上打**橙色序号点**（= 控件框左上角，编号 = 右侧控件表行号），一眼看出「这页哪几个按钮会跳页」。
- **大图看箭头**：悬停弹 `#peek` 全尺寸 800×480，同一批控件画**橙框 + 序号 + 箭头指向「→ 目标页」标签**；缩放 `min(1, max(0.35, 视口适配))`，越界自动翻到左侧。帧与序号都来自同一份 rows，不另画。
- 布局：按跳转边做 BFS 分层，`L0=主控`，`L1..Ln` 逐层；同层子节点**按主父节点 x 排序**，让箭头尽量竖直。
- 画布固定 1560 宽，节点宽 = `min(168, 按最挤一行算出的可用宽)`，否则右侧节点会被裁掉。
- 线：实线橙=换页（标签写控件名，贴在子节点上方；一个子节点入口 >3 个时合并成「入口 ×N」，全名放 `<title>` 悬浮）；
  青色虚线=返回（每页只画一条，来自 `cat=="back"` 的行）。
- 框：节点卡内 `硬件 N` / `只读 N` 用方框标签，**不画线**（用户口径：下发硬件的只标注）。
- 红框=无入口的页（状态页，如离线态），当场暴露"进不去的页面"。
- 点节点直接跳到该页并回到工作视图；`index.html#tree` 可直开全览。

## 3. H5 结构

- 左栏：按层分组列页（一级 / 房间 / 设备详情 / 工具页），点即切页。
- 中间：800×480 舞台，内联 `<svg viewBox="0 0 800 480">` + 绝对定位热区 `div.hot`。
- 右栏：当前页控件表（序 / 控件 / 分类 / 点击后 / 行为层），点行也能跳。
- 顶部：面包屑 + `‹ 返回`（历史栈）+ `回主控`；Esc = 返回。

热区规则：**只给"换页"类控件叠热区**（分类 `nav` / `back`）；开关、滑条、场景只做视觉反馈，不跳页。
热区悬停显示 `控件名 → 目标页`，用户不需要猜哪里能点。

## 4. 门禁（缺一不可）

1. 每个 `target` 必须能在页面清单里找到（防指向不存在的页）。
2. 非根页恰有 1 个 `back` 行，且行为层为"换页"（导航闭环）。
3. 每页控件行数 ≤ 表格高度能容纳的行数（当前 14），否则表格溢出。
4. 同一页序号唯一；每个控件框宽高 > 0。
5. 屏数下限（本工程 20）与跳转控件数打印出来，作为交付证据。

## 5. 实测证据（w78 智能家居，2026-11-03）

- `[GATE] 屏 22 跳转控件 63`。
- 浏览器真点：主控→客厅→灯详情→`‹ 返回`→客厅→`回主控`；
  通知→查看①→灯详情→返回；全部设备→＋添加→选类型→配网中→上一步。
- 灯详情只有 1 个热区（返回），其余 7 个是开关/滑条 —— 说明热区只叠在换页控件上。

## 6. 坑（都踩过）

| 现象 | 根因 | 处理 |
|---|---|---|
| 房间页只有"返回"一个热区 | 房间设备格的目标表建了但忘记合并进主表 | 建完 `ROOM_TARGETS` 立即 `NAV_TARGETS.update(...)`，并靠门禁 1 兜底 |
| 界面上的圆形徽标盖住按钮文字 | 徽标半径固定 10px，控件缩到 0.5 后只有十几像素宽 | 框高/宽 < 22px 时用半径 7.5、字号 7.5 |
| 表格底部溢出/行挤成一团 | 行高固定 30 | 行高 = min(30, 可用高度 / 行数) |
| 内联 SVG 不显示 | 设计源产出的是 `<svg>` **片段**，没有外层尺寸 | 包一层 `<svg viewBox="0 0 800 480" width height>` 再插 |
| 返回被画成实线、根节点显示「入口 ×11」 | 跳转边表把 `back` 行也算成出边 | 抽边时过滤 `cat=="back"`，返回只走虚线通道 |
| 某详情页永远进不去 | 场景类设备格没画「详情」按钮，目标表也没登记 | 门禁按"每个非根页至少 1 条入边"查，全览树用红框直显 |
| 全览缩略看不清页面 | 节点宽按画布自适应缩到 ~150px（0.19 倍） | 节点 240（0.3 倍）+ 跳转控件打序号点 + 悬停全尺寸带箭头；画布放宽靠滚动 |
| 悬停预览算出负缩放 | 小视口下 `(innerWidth-40)/800` 为负，且用正则回读 transform 解析丢符号 | 缩放存变量并夹在 `0.35–1`，别回读样式串 |
| 4 个入口按钮挤在一起 | 主控顶部固定 64px 宽 | 入口数变化时重算起始 x 与宽（本工程 4×56，x=540 起） |

## 7. 边界（写进交付说明）

H5 只证明**跳转逻辑与页面内容**。像素、字号、圆角、动效节奏仍以 **EEZ 生成 + 仿真截图**为准；
H5 是核对工具，不是像素验收依据。
