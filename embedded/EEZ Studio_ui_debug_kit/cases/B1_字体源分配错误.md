# B1 图标全空白 / 正文变方框（字体源分配错误）

## 现象

- 预览与设备上：**图标全部空白**，正文（中文）显示成方框，英文正常
- 构建后字体资源文件**消失且不被重新生成**，产物缺字体符号

## 证据

- 应用界面上弹出红字提示（可用 `tools/cdp/grab.js --text` 抓到原文）：

  ```
  Font "<字体名>" extraction failed:
  Font "<...>.ttf" doesn't have any characters included in "…"
  ```
  引号里那串字符是**图标私有区码位**（U+E000..U+F8FF）。

- 抓到原生渲染图后对比：修复前画布 PNG 体积很小（只有底色与少量文本），
  修复后明显变大 —— **体积变化本身就说明"终于画出了东西"**。

## 曾经的误判

**误判为**："无头环境不支持字体烘焙，只能手动在 GUI 里构建。"

**为什么那样想**：CLI 构建确实删掉了字体资源文件且不重建，现象与"环境不支持"吻合。

**什么推翻了它**：用文本抓取脚本读到了**界面上的报错原文** —— 不是"没烘焙"，
而是"提取失败"。删除字体资源只是提取失败的**后果**（工具清理了它认为非法的产物）。

## 真因

字形的**来源**被分配错了：

| 声明位置 | 工具会去哪里取字形 | 结果 |
|---|---|---|
| 正文字体自身的 `symbols`（图标码位） | **正文 TTF** | **找不到 → 整份字体提取失败** |
| 语言字符的 `ranges` | 正文 TTF | 正常 |
| **附加字体源**的 `symbols` | 该附加源文件（图标字体） | 正常 ✔ |

一旦"图标码位写在正文字体自己身上"，工具会拿正文字体去提取图标 → 失败 →
**整份字体被判为提取失败**（于是正文也一起坏）。

## 修法

把图标码位从正文字体身上**移走**，放进独立的附加字体源：

```json
"symbols": "",
"additionalSources": [{
    "filePath": "<绝对路径>/<图标字体>.woff",
    "ranges": "",
    "symbols": "<图标码位>"
}]
```

配套四条：

1. 正文/语言字符 → 正文 TTF 的 `ranges`
2. 这个分配要**对每一份字号都做**（多档字号时最容易漏掉大字号那份）
3. 字体源路径用**绝对路径**（相对路径常常解析不到）
4. 转换脚本里的顺序：**先补建字体条目 → 再填字形**（反了新字体拿不到字形）

## 验证

- 应用界面**不再出现**提取失败提示
- 原生渲染图的 PNG 体积显著变大（从"只有底色"变成"内容齐全"）
- 断言：UI 用到的每个码位都能在"某个已声明源"里找到（`tools/tree_check.py` 的字体检查项）

## 通用化

这个坑的本质是**"多字体源的字符集分配"**，每种栈都有对应形式：

| 栈 | 正文/语言字符 | 图标字符 | 容易搞错的点 |
|---|---|---|---|
| 组件树框架 | 字体 `ranges` → 正文 TTF | 附加源的 `symbols` → 图标字体 | 三处（ranges/symbols/附加源）语义混淆；图标塞进正文会整份失败 |
| Web | `@font-face` 主字体 | `unicode-range` 单独声明 | 忘了 `unicode-range` → 回退成方框 |
| Android | `fontFamily` 主字体 | 单独字体 + `fontFeatureSettings` | 用了 `.ttf` 而非 `.ttc` 导致找不到码位 |
| Qt | `QFont` 主字体 | `QFontDatabase::addApplicationFont` 兜底 | fallback 链没配 |

**通用判别法**：只看"英文正常但中文/图标不正常"这件事，就该往"字体源分配"上想；
再用界面文本抓取拿报错原文，往往能直接得到"哪个字体缺哪些码位"。
