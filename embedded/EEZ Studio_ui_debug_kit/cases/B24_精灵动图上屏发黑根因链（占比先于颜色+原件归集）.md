# B24 精灵动图"上屏发黑"根因链（黑胶唱片五轮返工 + 动图原件归集）

> **检索别名**：动图看不见 / 唱片是黑的 / 素材上屏发黑 / 盘身颜色 / 精灵太小 /
> 画布占比 / 并集裁框 / 表圈安全半径 / 抠黑抠掉了主体 / GIF 预览和上屏不一样 /
> 动图原件放哪 / MANIFEST / 停用帧表删除 / collect_originals。

**一句话**：素材"上屏发黑"先量**主体占画布的比例**，再谈颜色；判色必须在**页面真实底色**上判，
GIF 查看器的白/透明底会骗人；改色改尺寸一律走"原件→帧表"的参数化生成器，不手改 PNG。

## 1. 现象与时间线（watch2 音乐页黑胶，2026-11-03）

| 轮 | 用户反馈 | 当时做法 | 真实问题 |
| --- | --- | --- | --- |
| ① | "黑色的唱片显示不出来" | 把纯黑抠成透明 | 抠掉的正是盘身本身 |
| ② | "圆形盘子看不见" | 改染绿/灰、泛洪填充 | 泛洪留下方形角残留，仍否 |
| ③ | "使用灰色的吗" | **不抠黑**：自绘深灰盘 + 只叠原片白线，出 GIF 后用户点头 | 盘径错取 r=39.5（见 §2-2） |
| ④ | 编译后"还是黑色的" | 盘身 56→92→120 提亮 + 精灵 56→68 | **提亮是治症状** |
| ⑤ | 用户拿 `tmp/vinyl/vinyl_gray_160.gif` 问"为什么不是这张" | 盘径改 **r=80/160（铺满画布）**，盘身回原色 (56,56,72) | 根因坐实 |

## 2. 三条根因（按排查顺序）

1. **主体被抠掉**：源片是"黑盘+白线"，深底 UI 上黑盘≈不可见 ⇒ 正确做法是**不抠黑**，自绘盘身再叠白线。
2. **主体占画布比例**：帧表按"全帧并集 bbox"裁框，飘散的声波弧线也计入 bbox ⇒ 唱片本体只剩 r=39/160（49%），
   56px 精灵上屏唱片仅 **27px**。**自绘底盘要按原片暗盘的实际覆盖半径取，不是按可见亮线的外圈。**
3. **判色底色**：(56,56,72) 在 GIF 查看器白底像深灰，落到页面真实底色 `#0A0A0F` 上亮度差仅 46 ⇒ 读作黑；
   但本例把盘身提到 120 只是压住症状，**盘径改对后原色就成立**（用户最终选回 56,56,72）。

## 3. 量法（可复制）

- **主体半径**：沿画布中心做径向亮度剖面，`for r in range(0, R, 3)` 采样，找 alpha>200 的亮环/暗盘边界。
- **上屏直径** = `2 × 主体半径/画布边长 × size`（本例 2×39/160×56 ≈ 27px ⇒ 一眼看出"小"）。
- **放大上限**（圆表，屏心 (233,233)、安全半径 R−8）：精灵中心距屏心 d、半边长 u，解 `u² + (d+u)² ≤ (R−8)²`
  ⇒ 中心 (233,46) 处 d=187、上限 size≈70，取 68。
- **底色**：直接采样设计页 PNG 的精灵区外像素（`designer/app_music.png` → (10,10,15)），别凭样式表猜。

## 4. 落地口径

- **参数化生成器**：`design/build_music_vinyl.py`（原件 GIF → 帧表，`BODY`/`DISC_R`/`CROP`/阈值都在文件头），
  改外观只动参数并重跑；**手改 PNG 会在下一轮重烘时丢**。
- **重烘链**：`build_music_vinyl → design_view → build_watch_ui → cli_build → eez_font_engine → bake_sprite_i4 → run_sim.bat build`。
- **自检**：`WATCH_AUTOTEST=1`（自动 `SDL_VIDEODRIVER=dummy`、跑完 `exit(0)`，不弹前台窗口）。
  ★ 截图落在 **exe 的工作目录**（`design/sim_cmake/build_rel/bin/tmp/sim_shots/`），不是工程根 `tmp/`——
  量上屏像素前先按 mtime 确认是本轮新图，旧图会把结论量反（本例差点误判"改了没生效"）。
- **上屏取证**：解 I4 位图（`0x..` 表 → palette+4bit 索引）或裁仿真截图，直接报盘身 RGB 三元组。

## 5. 动图原件归集（同轮用户定）

- 一个工程**一个原件目录**：`design/assets/_originals/` 收当前 `SPRITES` 引用的每张**站内原始 GIF**（未裁框/未染色/未压缩）。
- 同目录 `MANIFEST.md` + `manifest.json`：页面→帧表→原件→名称/作者/许可→直链→字节+SHA256；
  收集脚本 `design/collect_originals.py`，**已存在不重下**（站内会重渲染同一 GIF，重下会把入库凭证换掉）。
- 校验三层：SHA 一致→同源；不符→目检首帧 + 对"去重帧数/整轮时长"；出厂时序一律以帧表 `meta.json` 为准。
- 换过件的停用帧表与候选帧表**直接删**（watch2 删 8 个目录约 3.3MB），台账里指向旧目录的行同步改写，不留"已删除"式修订注。

## 7. 边界

- 本例只解决"素材上屏观感"，像素真值仍以 EEZ 工程 + 仿真为准；设计图交付口径见 NO_FLOW §2.0/§2.0b。
- 若还要更大的唱片：只能裁掉盘面飘散件，或把精灵挪到页面里更宽的位置（watch2 中部绿色 `mu_disc` 位可容 ~250px），属版面改动，先问用户。
