# B6 样式值写错语法被静默吞掉（GUI 报错、CLI 构建却说"零错误"）

## 现象

目标 IDE 打开工程时，在组件树上报 **invalid color**；同一份工程用**命令行构建**
却输出 `No error and no warning detected / Build successfully finished`。

报错路径形如 `Pages / AiChat / Components / Screen / Children / Container`，
且**只有个别容器**中招 —— 同一页其它几十个容器都没事，很容易被当成偶发。

## 证据

对工程 JSON 做一次样式值扫描，得到**恰好 3 处**同值错误：

```
AiChat  .../LVGLContainerWidget  MAIN.DEFAULT.bg_color = "2764868"
History .../LVGLContainerWidget  MAIN.DEFAULT.bg_color = "2764868"
History .../LVGLContainerWidget  MAIN.DEFAULT.bg_color = "2764868"
```

`2764868 = 0x2A3044`。设计源里那句话是：

```python
av_bg = 0x2a3044 if who == "me" else PRIMARY     # ← 少了引号，是 int 不是 str
```

三处的分布也对得上：这三个容器是「我」的气泡头像 —— 该页有 1 条 / 2 条"我"的消息。

## 曾经的误判

无（用户直接给了报错路径，按路径反查样式表即定位）。但**差点**误判成
「工程文件损坏」——因为 CLI 构建一直说没问题，第一反应是 GUI 读到了缓存。

## 真因

两层机制叠在一起，导致错误被"吞掉"：

1. **序列化把类型信息抹平**：设计源里的颜色 token 是 Python 的 `int`，
   写工程时统一 `str()`，于是 `0x2a3044` 变成十进制字符串 `"2764868"`。
2. **消费端认不出就静默忽略**：目标工具的 `ColorFormat.parse()` 只接受
   `0xRRGGBB` / `#RRGGBB` / 颜色名，认不出置 `UNKNOWN`，`isValid()` 返回 false。
   这个校验**只在 GUI 的工程检查里跑**，CLI build 那条路径不跑 → "零错误"。

同类还有：样式里引用的**字体名 / 图片名 / 样式名写错**——工具链大多不报错，
只是静默回退（"大标题突然变小"就是字体名对不上，见 D4）。

## 修法

1. **修数据**：颜色统一走常量（`SW_OFF = "0x2a3044"`），不要在表达式里裸写 `0x…`。
2. **修流程（关键）**：在生成阶段加白名单校验，不合格直接抛错并打印出错对象路径。

```python
COLOR_PROPS = {"bg_color", "bg_grad_color", "border_color", "text_color", ...}
PAT = [r"^#?[0-9a-fA-F]{3,6}$", r"^0[xX][0-9a-fA-F]{6}$"]

for part, state, k, v in iter_style_props(node):
    if k in COLOR_PROPS and not any(re.match(p, str(v).strip()) for p in PAT):
        raise ValueError("%s %s.%s.%s = %r 不是合法颜色" % (path, part, state, k, v))
```

3. 把它固化成断言 **A10 样式值语法**（见 `tools/audit_ui.py`），并在提示里直接点破：
   `值为 int（2764868），序列化后会变成十进制 ← 少写了引号`。

为什么是根治：把"消费端才暴露、且只有 GUI 暴露"的校验**前移到生成端**，
并给出可操作的提示，而不是让下一个人对着 `invalid color` 猜是哪个值。

## 验证

```bash
# 单元级：往设计源里注入一个 int 颜色，断言必须拦住
python - <<'PY'
  d["pages"][0]["screen"]["bg"] = 0x0a0c11      # 故意不加引号
  → A10 输出：Main screen[None] bg = 658449：值为 int，序列化后会变成十进制 ← 少写了引号
PY
# 全量：修复后
python ui_debug_kit/tools/audit_ui.py A10        # → OK，0 处不合法
```

## 通用化

**「写错的样式值被静默忽略」是通用失败模式**，任何"设计源 → 目标工程"的转换都会有：

| 值类型 | 写错的后果 | 校验方式 |
|---|---|---|
| 颜色 | GUI 报 invalid color / 变成黑色 | `0xRRGGBB` 白名单 |
| 字体名 | 静默回退默认字号 | 必须在"已声明字体"集合内 |
| 图片/资源名 | 空白 / 占位图 | 必须在"已声明资源"集合内 |
| 枚举值 | 静默取默认值 | 枚举白名单 |
| 单位后缀 | 数值被当像素 | 校验键名 + 取值形态 |

判据：**只要一个值"错了也不会报错"，就必须在生成端加白名单断言。**
