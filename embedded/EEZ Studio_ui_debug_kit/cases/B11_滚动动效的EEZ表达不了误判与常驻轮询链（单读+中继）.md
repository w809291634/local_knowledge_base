# B11 滚动动效被误判"EEZ 表达不了"（真因=只查了事件面）+ 常驻轮询链的"单读+中继"瘦身

## 现象

手表 AppList 的滚轮动效（滑动时中心行放大、上下按距离连续递减）：
1. 第一轮被判定「EEZ flow 读不到滚动位置 → 铁律例外 → 走 native（C 模块）」；
2. 用户两次追问（"不是要求从 eez 里面来改吗"、"严格读英文资料看能否在 eez 中实现"）后复查——
   **纯 EEZ flow 完全可实现**，native 退役；
3. 实现后 LVGL actions 面板出现"公式墙"：一个动作组 66 行、每行 ~100 字符长公式刷屏，
   用户截图反馈"内容很多"。

## 证据

- **可行性**：手册 A43 动作组含 `Set Obj Style Prop`（写任意样式属性）+ 实装 `Obj Get Display X/Y`
  （读**屏幕坐标**、含滚动位移）；A42 `Loop(start/next→seqout/done)` + P6.2（无入线组件在 flow
  启动时立即执行；Delay 跨帧重排队不忙等）；运行时 `executeLVGLApiComponent` 动作列表同步顺序执行。
- **数值**（受控、可复现）：静止态盘径反推 scale 192/212/243/219/195 = 公式逐位；滚动态
  57/74/65 = 理论 57.6/73.6/64.4；EEZ 构建 `No error and no warning detected`。
- **减负**：编辑器最长行 102→**38** 字符（`verify/eez_editor_slim.png`）；帧执行 110→66→**67**
  （与 66 持平）；公式全文出现 44 份→0 份。
- **受控实验（推翻旧库断言）**：表达式加恒等项 `% 2147483647` 全链重建，盘径与基线逐位一致
  ⇒ int×int 的 `%` 保整数（旧经验"`%` 也永远产 double"不成立）。

## 曾经的误判（三次，都值得后来者避开）

1. **只查"事件面"就下结论**：可绑定事件只有 12 种、无 SCROLL ⇒ "动效必须 native"。
   错在把"事件驱动"当成唯一可能——**轮询链同样成立**（漏查了动作面/调度语义/运行时源码）。
2. **"CHECKED 双态必须同写"**：为对抗"CHECKED 样式表（权重 1）压过 local DEFAULT（权重 0）"，
   每行动作里写了 4 份。更优解=**在源头删掉静态缩放样式**，冲突消失、单写 DEFAULT（帧动作 −40%）。
3. **"公式该做成公用函数"**：查档后确认 EEZ 的"公用函数"=User Action+Call Action 组件，
   但**表达式不能内联调用用户函数**（只能当流程节点）；单点复用场景内联/中继更省（22 次调用/帧
   反而更重）。真函数版留作"第二处复用"时的升级路径。

## 真因

三个机制叠加决定了正解形状：
1. **触发方式**：flow 不一定要事件驱动——`Start`（无入线即执行）+`Loop(To 给大数)`+`Delay(ms)`
   就是内置的"常驻帧循环"，`objGetDisplayY` 读的坐标含滚动位移，等价于"每帧读滚动位置"；
2. **表达式约束**：动作参数是**自包含表达式**——没有中间变量、禁用除法（`/` 恒产 double，
   经 `getUInt32()` 直读 union 会位型毒化），所以公式必须定点化（`>>`）且会天然重复；
3. **可读性约束**：重复把面板刷成"公式墙"；破法有二——**刚性子项单读**（同容器间距固定的
   子项，读一个基准项就能推全表）与 **SetVariable 组件中继**（A43 动作组内没有赋值动作，
   组件层是唯一中继手段）。

## 修法

生成器直出以下链条（`design/build_watch_ui.py: wheel_flow_applist()`）：

```
Start → Loop(wlc, 0..2147483646, 1, version:1) → Delay(30ms)
  → A1[objGetDisplayY(row_0) → wy]                      # 单读（22 次读 → 1 次）
  → SetVariable[k0..k21 = Math.max(352 − |wy ± Ci|, 0)] # 短中继（Ci=88i−207 折叠进表达式）
  → A2[44 × objStyleSetProperty，值 = 176 + ((ki*ki*1236) >> 21)]  # 只引用短变量
  → 回连 Loop@next
```

三条硬约束（缺一就踩坑）：① 帧表达式整数型（禁 `/`，比例用 `>>` 定点化）；② 动作 `object`
参数写**规范化源码标识符**（`row_SportMode`→`row_sport_mode`，否则构建报
`Widget index not found`）；③ 控件若有静态 CHECKED 样式则必须双态同写，否则先把静态样式从
生成端删除、单写 DEFAULT（源头消冲突 > 绕着写）。

## 验证

四层全过（可复现）：EEZ headless 构建零错误；仿真静止态/滚动态盘径反推 = 公式逐位
（dragtest 夹具注入真实鼠标：点击导航 ✓ 滚动 ✓）；门禁（A8 需配 `links_event_outputs:["CLICKED"]`）
全 PASS；**EEZ Run（F5）肉眼可见可交互**（纯 flow 的最大红利：native 时代 Studio 里看不到）。

## 通用化

- **任何"随滚动位置逐帧改样式"的动效**（视差、淡出、缩放、位移）都可用此骨架：
  `Start→Loop→Delay→[单读基准项]→[中继中间量]→[批量写样式]`；
- **"工具/框架做不到 X"的判断纪律**：事件面 / 动作API面 / 调度语义面 / 运行时源码面——四面对查，
  再搜官方样例工程；只查一面必误判（P-0131）；
- 跨栈对照：浏览器里等价于 `requestAnimationFrame` 轮询 + `getBoundingClientRect`（含滚动）
  + 写 CSS 变量；嵌入式里的对应物同样是"常驻定时器读几何→写样式"，事件驱动只是优化项。
