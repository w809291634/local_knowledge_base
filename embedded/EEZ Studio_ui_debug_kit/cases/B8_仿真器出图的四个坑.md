# B8 把生成代码接进 PC 仿真器出图（快照字节序 / 大缓冲 / 进程不退 / 配置生效路径）

## 现象

为了拿到"真运行时"的验收图，把生成的 UI 代码编译进 PC 仿真器（真 LVGL + 真 SDL），
再逐屏 dump 像素。一路上四个**互不相关**的坑，表现分别是：

1. 导出的 PNG **颜色全错**：深蓝底变成 `#110C0A`（棕），蓝色控件渲染成橙色；
2. 快照失败：`lv_draw_buf_create_ex: No memory: 800x480, cf: 16, stride: 3200, 1536000Byte`；
3. 脚本挂死：exe 出完图**不退出**，前台跑满超时；
4. 改了配置**不生效**：`LV_USE_SNAPSHOT` 明明改成 1，编译仍报 snapshot 不可用。

## 证据

1. 颜色：raw 帧头部 `800 480 3200 16`，取 (5,5) 四字节 = `11 0C 0A FF`；
   按 `B,G,R` 解释 → `#0A0C11`（与设计稿一致），按 `R,G,B` 解释 → `#110C0A`（偏棕）。
   再用同一点与设计稿像素对比：`bg png=#110c0a` vs `design=#0a0c11`，锁定是解释方式错了。
2. 内存：报错里直接给了 `1536000Byte` = 800×480×4，而运行时配置里
   `LV_MEM_SIZE (1024 * 1024)`。
3. 进程：构建本身 1.3 秒完成，但进程 3 分钟不退出。
4. 配置：`cmake` 的配置文件参数是 `LV_CONF_PATH`，但框架自带的 `os_desktop.cmake`
   实际用的是 `${CMAKE_SOURCE_DIR}/lv_conf.h`。

## 曾经的误判

- 颜色问题第一反应是"渲染管线错了 / 颜色格式设成了 BGR"，
  在工程配置里翻 `colorFormat`。**实际工程配置没问题**，
  错在读取 raw 帧的 Python 侧：`Pillow.frombytes("RGBA")` 把字节当 `R,G,B,A`，
  而小端 `lv_color32_t` 的内存序是 `B,G,R,A`。
  一次"重排一下试试"就翻盘 —— 但要注意**重排方向**：正确写法是把
  `split()` 出来的第 0/2 通道对调，写成 `merge("RGB", (c2, c1, c0))`。
  我第一次写成 `merge("RGB", (b, g, r))`，变量名误导，等价于没换，白折腾一轮。

## 真因

| # | 真因 |
|---|---|
| 1 | 目标缓冲格式 ARGB8888 在**小端**下内存序是 `B,G,R,A`；读取端按 `R,G,B,A` 解释 |
| 2 | 快照要一整块连续缓冲（w×h×4），而运行时用的是**内置静态堆**，容量固定 1MB |
| 3 | 该程序的退出依赖 UI 线程收到"构建完成"消息，headless 下没人发 |
| 4 | 构建系统读的配置路径 ≠ 命令行传的配置变量，**两份配置文件，改错了那份** |

## 修法

1. **字节序**：明确写死并注释依据，别靠试。

```python
im = Image.frombytes("RGBA", (stride // 4, h), data)   # 只是把字节装进来
c0, c1, c2, _a = im.split()                            # 第 0 通道其实是 B
img = Image.merge("RGB", (c2, c1, c0))                 # → 真正的 R,G,B
```

2. **大缓冲**：仿真器把分配器换成 CRT 堆（`LV_USE_STDLIB_MALLOC = LV_STDLIB_CLIB`）；
   真机则要评估是否真的需要整屏快照，或改用分块/降位深（RGB565 只要一半）。
3. **进程不退**：出图模式结尾直接 `_exit(0)`；调用端用"产物文件是否齐全"判定成功，
   而不是等退出码 —— 并给超时。
4. **配置路径**：`grep` 一下构建脚本里配置变量的**实际使用点**，两份都写，或直接
   用命令行覆盖成绝对路径；改完**看一眼编译日志里是否出现你的改动**。

## 验证

```bash
# 输出：[ok] 01_standby … [ok] 11_notifications / 截图 11/11

# 输出：平均明显差异 8.30%

```

## 通用化

**"从运行中的渲染器 dump 像素"是本工具链最有价值的一层**（真运行时 + 真生成代码），
但它必然踩这四个通用点：

| 通用坑 | 通用对策 |
|---|---|
| 像素字节序（ARGB/BGRA/RGB565） | 用**已知颜色的标定点**反推，别靠文档猜；把结论写成常量+注释 |
| 整屏快照内存 | 先算 `w×h×bpp`，和运行时堆容量对账；不够就换分配器或降位深 |
| headless 下进程不退出 | 产物落盘即视为成功；补齐超时与强制回收 |
| 配置有多份 | 改配置后**在编译日志里验证它被读到**；同名配置只保留一份 |

配套习惯：仿真器工程**拷到临时目录**再改，不污染用户仓库；
UI 源码与渲染引擎**分开增量编译**（引擎几十分钟，UI 几十秒）。
