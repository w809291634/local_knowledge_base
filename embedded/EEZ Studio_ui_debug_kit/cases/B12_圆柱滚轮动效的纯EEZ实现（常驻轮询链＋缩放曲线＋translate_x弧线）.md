# B12 圆柱滚轮动效的纯 EEZ 实现（常驻轮询链 + 缩放曲线 + translate_x 弧线）——观感词三轮歧义与"要标注图"教训

> **检索别名**：腕表滚动特效 / 滚轮动效 / 圆柱滚轮 / 列表滚轮 / AppList 滚动 / CoverFlow 纵置 /
> 中心放大 / 弧线 / 弧度。下次说"腕表滚动特效"即指本案例这套效果。

> 前置：B11（轮询链骨架本身怎么搭、三条硬约束）。本篇讲**曲线形状**（缩放+弧线）怎么做对，
> 以及一次典型的**需求沟通事故**：用户嘴里的"弧度/倾斜/反了"，三轮理解三轮偏。

## 现象

手表 AppList 列表滚轮（410×502，行距 88，图标基径 76）。B11 的轮询链已实现"中心行放大"，
但用户对照参考视频反馈：**"滚动效果和视频是反的"**。追问澄清得到三个描述：

1. "弧度/倾斜的朝向……可以是正中心放大，现在是弧度方向反了" —— 中心放大 OK，弧度不对；
2. （两轮照片测量+两种解读都猜偏后）"我要的是左侧高、右侧低，并且差别幅度可以大一些"；
3. 最终用户**手绘红线标注图**："不是图标左高右低，而是像图片中，这个旋转的弧度要大一些"——
   红线沿图标列画出一条**竖直弧线**：中心行最凸左、上下偏心行右收。

参考视频本身不可裁决：实拍帧受手指遮挡 + 相机旋转污染，同一帧内"盘 vs 文字"高差符号在
±10px 间摇摆（照片透视主导），据此反推设计参数必然出错。

## 证据

- **错误方案（整行旋转）的量化**：`transform_rotation` 5°→8°→12° 三轮，8° 实测盘文高差
  10.6/9.2/7.5/5.7px（=124·sin5° 理论吻合）；12° 时放大行行心被推离屏心 **43px**
  （pivot 陷阱，见"真因"），破坏"放大行=屏心行"这一视频锚定的不变量。
- **正确方案（列弧线）的数值**：flow 每行盘+文字写 `translate_x = ((352−k)²·181)>>18`；
  剖面 中心 0 → |u|=88 5px → 176 21px → 220 34px → 可见边缘 295 **60px**（界外封顶 85px；
  视频实测仅 ~25px，按用户"要大一些"刻意放大一档）。
- **L4 断言**（旋转感知检测器）：静止态盘横心实测 [96, 89, 94]，与弧线模型
  `90+((352−k)²·181)>>18` 偏差 ≤8px；中心行最凸 ✓；scale 剖面、放大行=屏心行、
  文案不随行缩放等 12/12 PASS。
- **交互零回归**：dragtest 5/5（行点击命中、空白拖拽 Δ417、图标上拖拽 Δ451、单选导航）。

## 曾经的误判（按时间序，四条）

1. **拿实拍照片硬拟合设计参数**：三轮脚本测视频帧（行距剖面/盘高宽比/盘文高差），全部被
   手指遮挡与相机透视淹没，测出来的"方向"自相矛盾。正解：观感争议回到**用户要的行为定义**，
   照片只用作参考氛围；裁决不了就请用户标注（他后来真画了红线图，一次终结歧义）。
2. **把"弧度"理解成整行旋转**："左侧高右侧低"字面执行成 `transform_rotation`，还连调三档
   角度（5→8→12）"加大弧度"——方向整个错了，调参只是在错误假设上精修。
   教训：**观感词（弧度/倾斜/反了/弹性）先要一张标注图或一个参照物再动手**。
3. **LVGL 9 的 `transform_pivot` 样式默认 = (0,0)（左上角），不是中心**：整行旋转绕左上角，
   旋转角越大、内容离枢轴越远，整体位移越夸张（12° 把表推离屏心 43px）。
   8° 时同缺陷已存在（下移 ~12px）但被容差掩盖——**角度/位移类改动后必须复测既有不变量**
   （本案是"放大行=屏心行"）。
4. **检测器给圆盘加了 (cosθ+sinθ) 包围盒修正**：假设"旋转使 bbox 膨胀"——对矩形（文字块）
   成立，对**圆不成立**（圆转了还是同径圆）。首版把 scale 压低 17%，用 blob 实测
   65×66=直径证伪后删除。几何修正要按形状分类，不能一把梭。

## 真因

目标效果是**圆柱面列表**（CoverFlow 纵置）：行贴在绕竖直轴旋转的圆柱面上滚动，投影后
① 尺寸 ∝ cos(θ)（中心大、边缘小）——B11 的缩放曲线已覆盖；② **横向位置 ∝ sin(θ)**——
中心行最靠近观察者（最凸左），偏心行沿弧线右收。此前实现只有 ① 没有 ②，行距又恒定，
间隙向边缘张开，整体读感就是"弧度反了"。② 才是"弧度"的本体。

## 修法

在 B11 轮询链的 A2 动作组里，每行追加两条 `objStyleSetProperty`（盘 + 文字，共 88 条动作）：

> **§30 后记**：此段是当时形态；现已优化为——弧线合并到**行容器一条**（A2 共 66 条），
> 且链上加了 SwitchCase 静止门控。以文末"参数调节手册"表为准。

```
translate_x = ((352 − k_i) * (352 − k_i) * 181) >> 18      # 全整数，无除法
```

三条安全约束（本案验证过的选型理由）：

1. **反馈安全**：链的 A1 只读 `objGetDisplayY`（Y 向），translate_**X** 不改 Y →
   单读链零反馈闭环。（若做纵向位移效果，必须另加"从不被赋样式的锚点控件"供读取。）
2. **命中/滚动范围不变**：translate 只写盘与文字子控件，**不写行容器**——行的布局坐标
   （点击区、容器 content 范围、横向滚动条）全部不变。
3. **文字控件要可被动作寻址，必须显式给 `ident`**（自动生成名不可依赖）。

配套：L4 检测器升级为旋转/弧线感知（`measure(tilt_deg=)`、横心断言=弧线模型、盘 blob
窗口放宽防右移裁瓣）；flow 组件加 `description` 描述名（EEZ 的组件展示名走 GENERAL →
Description，`name` 键会被静默忽略——编辑器实证）。

## 验证

主链全绿（可复现）：EEZ headless 构建 0/0 → 16 屏出图 → L4 12/12（含新断言
"sim 图标横心=弧线模型"）→ dragtest 5/5 → 门禁全 PASS → PC_SIM 重建 →
EEZ Run 静止/滚动双截图（弧峰跟随屏心行）。

## 通用化

- **"弧度"类滚轮效果的分解式**：圆柱列表 = 缩放曲线(∝cos) + 横移曲线(∝sin/抛物近似) +
  （可选）行距挤压。先和用户确认要哪几个分量、拿标注图定方向，再各配一条定点表达式；
- **效果写在哪一层决定副作用面**：写容器（改命中/滚动范围/枢轴语义）vs 写子控件
  （只改视觉）——EEZ/LVGL 里默认选后者；
- **整数定点化模板**：`shift = (m*m*C) >> S`，C/S 由"目标像素值 @ 最大 m"反推
  （本案 60px @ m=295 → C=181, S=18），永不碰 `/`；
- **需求沟通**：观感词歧义率极高，两轮问答内没对齐就**主动要图**（用户画一条红线 = 三轮
  测量+两次返工）。
