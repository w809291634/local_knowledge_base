# B22 仿真器按键没反应（远程键盘 / 焦点 / 事件形态）——单一按键做全局导航的落地口径

> **检索别名**：按 A 没反应 / 键盘没反应 / 远程键盘 / RDP 按键 / 远程输入工具 / 按键收不到 /
> SDL 键盘 / SDL_AddEventWatch / TEXTINPUT / 键盘焦点 / 返回箭头全删 / 单键返回 /
> 一键切换页面 / 硬件按键导航。
>
> 场景：EEZ no-flow + LVGL 9.4 PC 仿真器（SDL2）。用户要求**删掉所有页面的返回箭头**，
> 统一用**一个按键**完成"表盘↔列表切换 + 各页返回"，列表里点图标进功能页。
> 回归全绿（自灌事件能切页），但**真人在仿真窗口里按 A 毫无反应**。

## 现象

1. 无头回归里 `真灌 SDL KEYDOWN(A) → applist` 一直 PASS；真人在窗口里按 A 什么都不发生。
2. 换成远程桌面/远程键盘（RDP、手机远程输入工具）后同样无效，控制台没有任何输出。
3. 偶发 `collect2.exe: error: ld returned 1 exit status`，`ninja: no work to do` 又照常出现——
   实际是**上一次启动的 main.exe 还在跑**，占用 exe 导致不能重链接，bat 于是启动的还是旧二进制。

## 证据

1. 用 `SDL_AddEventWatch` 监听，回归里 `SDL_PushEvent(SDL_KEYDOWN/A)` 能触发 → **事件总线本身没问题**。
2. 向窗口投递 `WM_KEYDOWN`（`wParam=0x41`）第一次**完全无效**；把 lParam 里的扫描码
   从 `SDL_SCANCODE_A=4` 换成**硬件扫描码 `0x1E`**（`lParam = (0x1E<<16)|1`）后立刻触发。
   说明真机链路正常，缺的是"按键有没有以正确形态进到进程里"。
3. `SetForegroundWindow` + `SendKeys("a")` 反复试都收不到任何 SDL 键盘事件——
   Windows 前台锁让"从外部抢焦点"经常静默失败。
4. 远程键盘类工具常见三种下发形态，实测必须都认：
   - `SDL_KEYDOWN` 且 `keysym.sym == SDLK_a`；
   - `SDL_KEYDOWN` 但只有 `keysym.scancode == SDL_SCANCODE_A`（keycode 映射丢失）；
   - **只有 `SDL_TEXTINPUT("a")`**，根本没有 KEYDOWN。
5. `SDL_GetKeyboardState()` 只反映"已经带焦点收进来的键"；窗口没焦点时它恒为 0。

## 曾经的误判

1. **以为是导航/事件总线写错了**——回归一直绿就说明不是；真正缺的是输入没进进程。
2. **以为 `SDL_AddEventWatch` 一定会收到所有按键**——它只在事件入队路径被调用，
   且行为随平台/焦点/远程通道变化；不能把"唯一入口"压在它身上。
3. **以为 `PostMessage` 里该填 SDL 的 scancode 值（A=4）**——lParam 要的是**硬件扫描码**（A=0x1E），
   填错就静默丢弃，看起来像"程序不响应"。
4. **以为 `SendKeys` 能替代真人按键**——前台锁/焦点不在目标窗口时，它只是把键发给当前前台程序。
5. **忽略"旧进程占用 exe"**——`ninja: no work to do` + 启动成功，实际跑的是旧二进制，
   改了也看不到效果。

## 真因

键盘输入能到达程序，需要三层同时成立：

```
① OS 把按键送到本窗口（窗口要有键盘焦点；远程会话/终端抢走焦点就断在这里）
② SDL 把它转成事件（远程键盘/输入法可能只给 TEXTINPUT，或 scancode≠keycode）
③ 程序收到事件并派发（事件监听 + 每帧轮询两条都要有，任一条断都表现为"按了没反应"）
```

"回归绿 + 真人无效"= ③ 正常，断在 ① 或 ②。这两层都不能靠单一机制兜住。

## 修法

### 1) 输入源只发布事件，跳转由订阅者执行（导航侧）

```c
/* 一个按键 = 一条自定义事件；按键层不碰页面 */
static lv_event_code_t s_evt_a_key;

static void a_key_event_cb(lv_event_t *e)
{
    lv_obj_t *act = lv_screen_active();
    if (act == objects.watchface) { go_applist(); return; }          /* 表盘 → 列表 */
    if (act == objects.quick_picker) { strip_open(n + 1, MOVE_RIGHT); return; }
    go_screen(page_parent_of(act));                                   /* 按层级返回 */
}

void watch_nav_a_key(void)                 /* 键盘 / 物理键 / 手机都只调这一个 */
{
    if (!s_evt_a_key) return;              /* 注册前调用=空操作 */
    lv_obj_send_event(objects.watchface, s_evt_a_key, NULL);
}
```

`page_parent_of()` 用"当前屏 → 父屏"一张表统一返回：列表→表盘、APP 页→列表、
设置子页→设置、编辑器→闹钟、选择页→条带「+」槽。
**页面里不出现任何返回控件**，设计源的 `back` 控件全删（声明条目 354→308，审计同步归零）。

### 2) 焦点：启动后重试抢，抢不到就明说

```c
/* Windows 前台锁会让首次 SetWindowInputFocus 静默失败 → 前 3 秒每帧重试 */
static void ensure_keyboard_focus(void)
{
    if (!s_win) return;
    if (SDL_GetKeyboardFocus() == s_win) { s_focus_noticed = 1; return; }
    if (lv_tick_get() < 3000) { SDL_RaiseWindow(s_win); SDL_SetWindowInputFocus(s_win); return; }
    if (!s_focus_noticed) {
        s_focus_noticed = 1;
        printf("[SIM] 提示：仿真窗口没有键盘焦点 → 先点一下窗口，再按 A\n");
        fflush(stdout);
    }
}
```

窗口句柄：`lv_sdl_window_get_window(disp)`（LVGL SDL 驱动有公开取法）。

### 3) 识别全部按键形态 + 每帧轮询兜底

```c
static int key_is_a(const SDL_Keysym *k)
{
    return k->sym == SDLK_a || k->scancode == SDL_SCANCODE_A ||
           k->sym == SDLK_RETURN || k->sym == SDLK_KP_ENTER ||
           k->scancode == SDL_SCANCODE_RETURN || k->scancode == SDL_SCANCODE_KP_ENTER;
}

static int key_event_watch(void *ud, SDL_Event *e)
{
    if (e->type == SDL_KEYDOWN && !e->key.repeat && key_is_a(&e->key.keysym)) s_key_pending = 1;
    else if (e->type == SDL_TEXTINPUT &&
             (e->text.text[0] == 'a' || e->text.text[0] == 'A')) s_key_pending = 1;
    return 0;                              /* 0=不吞事件，框架自己的键盘 indev 照常收 */
}

/* 每帧再读一次键盘状态做边沿检测（与监听共用同一待办位，不会重复触发） */
static void key_poll_edge(void)
{
    const Uint8 *ks = SDL_GetKeyboardState(NULL);
    int down = (ks && (ks[SDL_SCANCODE_A] || ks[SDL_SCANCODE_RETURN])) ? 1 : 0;
    if (down && !s_a_was_down) s_key_pending = 1;
    s_a_was_down = down;
}
```

要点：
- **Enter 作为等价键**——远程输入工具常把回车映射过去，多一个入口不增加交互复杂度；
- 监听与轮询**共用 `s_key_pending`**，同一帧重复置位只发布一次；
- 事件回调里只置位，切屏放主循环（SDL 事件泵跑在 LVGL timer 里，回调里直接加载屏幕会绕过刷新时序）。

### 4) 诊断：前几次按键打印原始键值

```c
printf("[SIM] 收到按键：name=%s sym=0x%x scancode=%d\n",
       SDL_GetKeyName(e->key.keysym.sym), (unsigned)e->key.keysym.sym,
       (int)e->key.keysym.scancode);
printf("[SIM] 收到文本输入：\"%s\"\n", e->text.text);
```

只打前 5 次，够判断"键有没有进来 / 进来的是什么形态"，又不会刷屏。

### 5) 回归必须覆盖"事件形态"分支

```c
/* 链路一：KEYDOWN(A) */
SDL_PushEvent(KEYDOWN_A);  pump(若干帧);
expect_scr(objects.applist, "键盘 A → applist（SDL 事件链）");
/* 链路二：只有 TEXTINPUT("a")，模拟远程键盘 */
SDL_PushEvent(TEXTINPUT_a); pump(若干帧);
expect_scr(objects.applist, "TEXTINPUT a → applist（远程键盘兜底）");
```

### 6) 环境纪律（和按键无关但一定会踩）

- 链接报 `ld returned 1 exit status` 先查**残留进程占用 exe**（`Get-Process main | Stop-Process`）；
- `ninja: no work to do` 不等于"跑的是新代码"，要看 exe 时间戳；
- bat 里错误分支 `pause`（长期规矩），并在 bat 自身 echo 按键提示（子进程 stdout 可能不被终端转发，见 B20）。

## 验证

```text
投递 WM_KEYDOWN（lParam 硬件扫描码 0x1E）→ 日志：[SIM] A 键已触发（第 1 次）   ← 真机链路通
回归：[NAV] 键盘 A → applist（SDL 事件链）                       PASS
      [NAV] TEXTINPUT a → applist（远程键盘兜底）                PASS
      [NAV] 附录 14 页 A 键 → applist / 设置子页 A 键 → app_settings  PASS
      RESULT: PASS 167 / FAIL 0
④-A 声明层对账：308/308，差异 0（删返回箭头后同步下降）
用户真机（远程键盘）实测：按 A 可完成 表盘↔列表 与各页返回
```

## 通用化

| 问题 | 跨栈对照 |
|---|---|
| "回归绿但真人按键无效" | 输入链路有三层（OS 送达 → 框架翻译 → 程序派发）。先在入口打印原始键值定位断在哪层，别改业务代码 |
| 只认一种按键事件 | 桌面框架普遍存在 KEYDOWN / TEXTINPUT / scancode-only 三种形态；远程桌面、输入法、自动化工具各发一种 → **全部接受** |
| 窗口没焦点 | 任何桌面程序都收不到键盘；要么启动后重试抢焦点（前台锁会失败），要么明确提示用户点一下窗口 |
| 一个按键做全局返回 | 用"当前屏 → 父屏"映射 + 一条事件；页面里不要放返回控件，避免两套入口漂移 |
| 自动化测试按键 | 测试要分别覆盖"KEYDOWN"和"只有 TEXTINPUT"两条链路，否则远程场景一上线就废 |
| 旧进程占用 exe | 链接失败或改动看不到效果时，先查残留进程与 exe 时间戳，再怀疑代码 |
