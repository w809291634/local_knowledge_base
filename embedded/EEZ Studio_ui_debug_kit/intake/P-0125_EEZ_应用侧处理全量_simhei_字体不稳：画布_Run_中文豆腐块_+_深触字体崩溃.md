# P-0125 · EEZ 应用侧处理全量 simhei 字体不稳：画布/Run 中文豆腐块 + 深触字体崩溃

- **工程**：Design Watch（watch UI 工程）
- **日期**：2026-10-16
- **工具**：Qoder
- **状态**：fixed
- **标签**：EEZ,字体,豆腐块,Run模式,崩溃,simhei,字体提取
- **关联提示词**：PR-0210

## 现象（看到什么）

EEZ 编辑器画布与 Run 模式中文全为豆腐块（图标位图与拉丁/数字正常）；更深触字体时应用不稳：加载工程副本挂起、首页双击条目整进程崩溃、点右侧 Fonts 资产面板退回首页。对照工程 eez-test 初始打开也豆腐，但其字体提取成功一次后自愈（抓到了通知原文）。

## 复现（怎么稳定重现）

打开 watch.eez-project（cn22..cn60 七档，字体源 fonts/simhei.ttf 9.7MB）即豆腐；应用侧全程无任何提取成功/失败通知（MutationObserver 监听 100s + DOM 残留翻查）。

## 根因（真正的原因）

候选：应用侧（渲染进程字体引擎）处理全量 simhei（近 3 万字形）时资源不足/崩溃，导致提取永远完不成；对照工程用小体量 TTF（YaHei_Consolas_Hybrid）则正常。非 C 端问题——kit 内核/CLI 构建产物逐字节正确、真机与仿真渲染中文完好。

## 修复（做了什么）

候选修法（未实施，待用户确认）：字体源换为只含所需字形的小体量子集 TTF（数十 KB 级），C 端字形与渲染不变、应用侧提取变轻。

## 证据（数字 / 命令输出）

verify/校验报告.md §14.2；对照：通知『Font "YaHei_Consolas_Hybrid_13" extracted successfully.』残留可查；本工程零提取通知。

## 更新（2026-10-16 晚 · 闭环，open→fixed）

**决定性变量是「字体条目形态」，不是字体文件大小**（A/B 对照实测）：

- A：simhei + 旧条目形态（无 renderingEngine / `lvglRanges` 空 / 无 lvglGlyphs）→ 豆腐 + 点 Fonts 面板必崩；
- B：hybrid 字体 + **同一旧形态** → **仍然**豆腐 + Fonts 面板照崩（只换字体无效！原"TFF 太大"候选被推翻）；
- C：hybrid + EEZ 原生形态条目 → 画布中文恢复 ✓ + Fonts 面板正常列出 cn22~cn60 ✓ + 应用稳定。

**正解**（对齐 kit 已有方法：skills §3.3/D5「中文进 `lvglRanges`」+ §11.12 的 `renderingEngine='LVGL'`）——
`design/build_watch_ui.py` 的 font 条目改为 EEZ 原生形态：
`renderingEngine:"LVGL"` + `lvglRanges`=数字码位表（中文与 ASCII 全进）+ `lvglSymbols:""` +
`lvglGlyphs:{encodings:[{from,to}…], symbols:""}` + `glyphs:[]`。

**字体源**：按用户要求（PR-0211）换为示例工程验证过的 `YaHei_Consolas_Hybrid.ttf`（140/140 码位逐字核验；
观感更接近参考视频：Consolas 数字 + 雅黑中文）。烘焙仍走官方引擎（kit 内核方案 C）。

**验证证据**：EEZ 画布 AppList/Dial「01 周三」正常（截图 native2.png / dial_eez.png）；Fonts 面板零崩溃；
7 档烘出字体各含 140/140 个 U+；渲染回归 16/16 逐张 MD5 一致（条目修正零渲染影响）；
dragtest Δ+418/+417；PC_SIM 16:13 重建。

**方法论教训（比结论值钱）**：先把锅扣在"全量 TTF 太大"上，B 组对照直接推翻——定位于"**与原生工程逐字段对照**"
（eez-test font 条目 vs 我们的），并且**先查经验库已有方法再动手**（用户 PR-0212 原话提醒）。

## 更新 2（2026-10-16 深夜 · 受控复核，PR-0213 触发）

用户要求通读经验库复核上述结论。用**唯一变量法**做了两个受控工程（干净会话、同样等待）：

| 受控 | 字体 | 条目形态 | 画布中文结果 |
|---|---|---|---|
| T1 `_revA` | hybrid | 旧形态 | ❌ 豆腐（等 6+ 分钟仍豆腐；首次打开还崩过一次） |
| T2 `_revB` | **simhei（全量 9.7MB）** | **新形态** | ✅ **正常渲染（约 2 分钟出字）** |
| 当前工程（对照） | hybrid | 新形态 | ✅ 正常 |

**复核结论**：

1. ✅ **核心结论坐实**：决定性变量 = 条目形态（双向对照，与此前 A/B/C 一致）；
2. ⚠️ **修正一：字体文件完全不是因素**——simhei 配新形态同样正常渲染。"换示例字体"不是修复的必要条件，
   仅为按用户要求做的观感选择（数字→Consolas、中文→雅黑）；
3. ⚠️ **修正二：不存在"等待提取完成"的过程**——原表述"提取完成前必是豆腐块"易被误读成"等等就好"；
   实测为准：**形态对 ≈2 分钟内即正常、形态不对永远豆腐**（T1 6 分钟+仍豆腐）。
