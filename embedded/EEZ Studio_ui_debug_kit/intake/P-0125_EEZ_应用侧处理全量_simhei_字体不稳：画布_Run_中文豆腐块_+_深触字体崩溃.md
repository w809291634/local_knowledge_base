## 现象（看到什么）

EEZ 编辑器画布与 Run 模式中文全为豆腐块（图标位图与拉丁/数字正常）；更深触字体时应用不稳：加载工程副本挂起、首页双击条目整进程崩溃、点右侧 Fonts 资产面板退回首页。对照工程 eez-test 初始打开也豆腐，但其字体提取成功一次后自愈（抓到了通知原文）。

## 复现（怎么稳定重现）

打开 watch.eez-project（cn22..cn60 七档，字体源 fonts/simhei.ttf 9.7MB）即豆腐；应用侧全程无任何提取成功/失败通知（MutationObserver 监听 100s + DOM 残留翻查）。

## 根因（真正的原因）

候选：应用侧（渲染进程字体引擎）处理全量 simhei（近 3 万字形）时资源不足/崩溃，导致提取永远完不成；对照工程用小体量 TTF（YaHei_Consolas_Hybrid）则正常。非 C 端问题——kit 内核/CLI 构建产物逐字节正确、真机与仿真渲染中文完好。

## 修复（做了什么）

候选修法（未实施，待用户确认）：字体源换为只含所需字形的小体量子集 TTF（数十 KB 级），C 端字形与渲染不变、应用侧提取变轻。

verify/校验报告.md §14.2；对照：通知『Font "YaHei_Consolas_Hybrid_13" extracted successfully.』残留可查；本工程零提取通知。
