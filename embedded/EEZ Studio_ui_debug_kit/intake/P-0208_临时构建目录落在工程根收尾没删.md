# P-0208 · 临时构建目录落在工程根，收尾没删

- **工程**：app-wifi-scan-conn-no-flow
- **日期**：2026-10-25
- **工具**：Qoder
- **状态**：fixed
- **标签**：过程文件,构建目录,清理,流程
- **关联提示词**：PR-0382

## 现象（看到什么）

为绕开"仿真器占用 bin\main.exe 导致链接失败"，临时建了一个备用构建目录；第一次脚本路径算错，
把 `build_alt/` 落在了**工程根**（775K，只有 CMakeCache 与空目录），`git status` 里以未跟踪目录出现。

## 复现（怎么稳定重现）

用脚本按 `%~dp0..\design\sim_cmake` 推路径、又粘错变量顺序时，`BUILD_DIR` 会退化成相对盘根；
目录就落在工程根。收尾不检查 `git status`，它就一直在。

## 根因（真正的原因）

临时产物没有"归属 + 收尾动作"：既没限定只许放 `tmp/`，也没在收尾时核对工作区里多了什么。

## 修复（做了什么）

删除该目录与临时脚本；`.gitignore` 补 `build_alt/`；流程层新增条款：
NO_FLOW §2.4 / FLOW §2「收尾纪律」——过程文件收尾即删，暂存只放工程 `tmp/`，交付件只放正位。

## 证据（数字 / 命令输出）

删除后 `git status` 只剩本轮正式改动；`ls build_alt` → 不存在；`git check-ignore build_alt` 命中新规则。

## 沉淀（新增断言 / 案例 / 文档）

收尾清单加一条：**看 `git status` 有无意外目录**；临时件只放 `tmp/`，当轮结束清掉。
