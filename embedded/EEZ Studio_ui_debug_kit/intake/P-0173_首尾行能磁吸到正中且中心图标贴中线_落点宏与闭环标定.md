# P-0173 · 列表首尾行能停在正中、中心图标贴水平中线，观感不对

- **工程**：watch-app-list-rxroller
- **日期**：2026-10-22
- **工具**：Qoder
- **状态**：fixed
- **标签**：样式,磁吸,落点,宏配置,闭环标定,拖动行程,判据设计
- **关联提示词**：PR-0288、PR-0290

## 现象（看到什么）

① 中心图标贴在屏宽中点，参考图要在横向 1/3；② 第一行 / 最后一行都能磁吸到正中，
上下没有「还有更多」的暗示。后续口径又反转为：**允许一路拖到最上 / 最下，只在松手时弹回第 n 个**。

## 复现（怎么稳定重现）

起仿真往下拖到顶：中心停在行 0 不动；量中心图标绝对 x：182（屏宽 410）。

## 根因（真正的原因）

1/3 那条：`pad_left → 行位置` 的映射还叠着边框固定偏差（锚点 140 实量行左缘 117，差 8px），
写死一个 `pad_left` 一改 `ROW_W` 就会飘。

磁吸那条：上游 `rx_clamp_distance` 的范围就是 `[0, count-1]`，首尾项天生可以居中。
中途我先做成「改上游钳位」，实测能挡住 —— 但那**把拖动行程一起锁死了**，
与「允许拖到顶」直接冲突，属于修过头；判据也差点设计成「我的兜底生效了」，
而不是「绕过我的兜底还能过」。

## 修复（做了什么）

1. 1/3 定位：`watch_list_align_center_x()` 一次性闭环标定（割线法**实测**斜率，不假设 1/2，
   最多 12 次 `lv_obj_update_layout`），只在建轮时跑，不是逐拍轮询。
2. 磁吸落点：宏 `EDGE_SNAP_TOP_ORDINAL` / `EDGE_SNAP_BOTTOM_ORDINAL`（1-based 序号）
   + `watch_list_snap_edge()`，由行 / 根 RELEASED 经 `lv_async_call` 延一拍做一次纠正。
   上游钳位补丁整条撤销，账单回到 14 hunks。
3. 加 `watch_list_center_no_clamp()` 探针：断言先证明**行程真的放开**（能停在行 0 / 行 21），
   再断言弹回第 n 个。

## 证据（数字 / 命令输出）

```
[WHEEL] center-x: target=136(=410/3) got=136 pad_left 140->48 步数=3
[ASSERT] 首行可以拖到正中（行程不限）   PASS  13 -> 0
[ASSERT] 松手弹回顶部第 n 个            PASS  0 -> 1
[ASSERT] 末行可以拖到正中（行程不限）   PASS  1 -> 21
[ASSERT] 松手弹回底部倒数第 n 个        PASS  21 -> 20
```
单变量把宏改 3 ⇒ 落点变「第 3 个」、区间变 `[2,20]`，证明是宏驱动不是写死。

## 沉淀（新增断言 / 案例 / 文档）

断言从 5 条扩到 11 条；preflight 第 6 组按名字逐条核对断言在位。
经验库 [[feedback-one-change-at-a-time]] 补「事件驱动兜底也常常只是比较体面的兜底，
判据要选绕过自己那层还能过的那种」。
