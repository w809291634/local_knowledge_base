# P-0135 · 常驻动效链瘦身：静态缩放样式在源头删除 + flow 单写 DEFAULT（双态双写只在有静态 CHECKED 样式时才必要）

- **工程**：watch (Design Watch)
- **日期**：2026-10-16
- **工具**：Qoder
- **状态**：fixed
- **标签**：eez-flow,objStyleSetProperty,双态双写,样式权重,源头消冲突,帧动作瘦身
- **关联提示词**：PR-0220,P-0131

## 现象（看到什么）

用户问『为什么公式那么长，可以优化吗』：滚轮动作组 110 条/表达式 88 份副本（x/y × DEFAULT/CHECKED × 22 行），每帧写样式 88 次

## 复现（怎么稳定重现）

读生成器 wheel_flow_applist：每行 1 get + 4 set；page_applist 里行带静态 DEFAULT 216/CHECKED 249

## 根因（真正的原因）

『长』= 三约束叠加：动作参数自包含(无中间变量, k 必写两遍)+禁除法(定点化 ×1236>>21)+每行 4 份副本。其中 CHECKED 双写只为对抗『CHECKED 样式表(权重1)压过 local DEFAULT(权重0)』——而那个静态样式是旧设计（顶部行放大口径）遗留，滚轮时代已属冗余

## 修复（做了什么）

① page_applist：删行静态 transform_scale（localStyles 仅剩 NO_PAD）→ 冲突源头消失；② wheel_flow_applist：只写 DEFAULT（1 get + 2 set/行）；③ 公式换严格等价的 Math.max(…,0) 形（115→102 字符，保留防橡胶筋回弹夹取）

## 证据（数字 / 命令输出）

动作 110→66(−40%)、副本 88→44(−50%)；静止态盘径 57/48/72/65/58 与优化前逐位一致；滚动后(scroll_y=771)行10/12/13=65/63/57 vs 理论 65.3/63.5/57.0；EEZ 构建零错误；门禁全绿；EEZ Run 静止+滚动复测同前
