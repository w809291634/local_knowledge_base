# P-0042 画布组件重叠：渲染高度公式低估（40+n*30）+ 链区起点相撞

- **状态**：fixed
- **发现日期**：2026-10-01
- **提示词**：PR-0079「记得新建的组，不要重叠了」
- **标签**：EEZ-flow, 画布布局, 渲染高度, 堆叠, 行距, 律动链, tabsync

---

## 一、现象

用户在 EEZ GUI 里看到新加的「唱片律动链」组件组与换页同步链重叠。
渲染高度感知 2D 扫描（rect = left/top/w/ max(声明高, 40+actions*30)）抓到 **18 对重叠**：

1. 律动链 X 起点 = 分区列右缘 + 420，落在 tabsync 链区内部（两条链各占 950）；
2. 分区列与 tabsync 区内部互压 7~42px：9 动作的 LVGLActionComponent 渲染高
   ≈ 310px，而行距公式只给 268（34+9*26）。

## 二、根因

**行距公式的分母用错了**：EEZ 组件渲染高度 ≈ `40 + n_actions*30`（声明 height
只是最小值，P-0039 已发现但公式仍低估——34+n*26 的系数 26 与基线 34 都偏小）。
凡按声明高度排行的画布公式都会随动作数线性恶化。另有历史遗留：tabsync 的
点亮组件在 X0+510，而 Compare 止于 X0+517（7px 相压）。

## 三、修复（json2eez.py）

- 律动链起点 = 分区列右缘 + `len(tabsync)*950 + 80`；链内**单行排布**
  （FRAME 组件渲染长高，多行必纵向互压）+ 组名 Comment 标题条；
- tabsync 点亮组件 X0+510 → **X0+530**；
- `_row_h` / tabsync 行距改 **`max(86, 40 + n*30 + 16)`**（渲染高 + 间距）。

## 四、证据

修复后同款扫描：55 组件**重叠对 0**；律动链 X 3940..6760，tabsync 右缘 3345；
all.py --shots EXIT=0、[np] 断言全绿、11 屏对照 8.65% 无回归。

## 五、沉淀

- 画布布局节写入 `reference/07_project_json_schema.md`；
- 行距公式二修教训：**公式分母是渲染高度（40+n*30），不是声明高度**——
  改画布公式前先对一个多动作组件实测渲染高度。
