# P-0212 · 嵌套列表保留滚动链，会把根页面标题拖出屏幕

- **工程**：watch2
- **日期**：2026-10-25
- **工具**：Codex
- **状态**：fixed
- **标签**：LVGL,scroll-chain,嵌套滚动,页面固定,仿真截图
- **关联提示词**：PR-0385

## 现象（看到什么）

快捷功能选择列表滑到末尾时，列表本身出现了最后 6 项，但 `选择快捷功能` 标题也被一起向上拖动，
只剩半行；首屏正常，所以普通静态截图抓不到。

## 复现（怎么稳定复现）

父对象是 EEZ 默认 `SCROLLABLE` 的 screen，子对象是 14 行纵向列表，子对象保留
`LV_OBJ_FLAG_SCROLL_CHAIN_VER`。调用 `lv_obj_scroll_to_y(host, lv_obj_get_scroll_bottom(host), LV_ANIM_OFF)`
或真手势划到列表底部。

## 根因（真正的原因）

列表到达边界后把剩余纵向滚动传播给可滚动的根 screen；根页面并无可滚内容，却仍改变了自身
scroll offset，于是固定标题和返回按钮整体离开圆屏安全区。

## 修复（做了什么）

列表宿主移除 `LV_OBJ_FLAG_SCROLL_CHAIN`，只允许它自己纵向滚动；同时移除
`quick_picker` screen 的 `LV_OBJ_FLAG_SCROLLABLE`。其他页面的横滑手势页也应先移除
root `SCROLLABLE`，再开启 `GESTURE_BUBBLE`，避免滚动抢走左右手势。

## 证据（数字 / 命令输出）

无头回归新增 `lv_obj_get_scroll_bottom(host) > 0` 断言并抓取末尾截图；修复后标题保持完整、
末尾 `秒表/计时/计算器/指南针/找手机/设置` 六行完整可见，整体回归 `80 PASS / 0 FAIL`。

## 沉淀（新增断言 / 案例 / 文档）

**每个可滚动子列表都要测到底部截图，检查父页面的固定头部是否仍在原位。**
不要只验证“列表能滚”，还要验证滚动不会越权移动父页面。
