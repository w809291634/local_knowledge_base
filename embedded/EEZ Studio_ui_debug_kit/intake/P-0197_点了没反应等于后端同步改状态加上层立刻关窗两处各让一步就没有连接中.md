# P-0197 · 「点了没反应」＝后端同步改状态 + 上层立刻关窗，两处各让一步就没有连接中

- **工程**：app-wifi-scan-conn-no-flow
- **日期**：2026-10-24
- **工具**：Qoder
- **状态**：fixed
- **标签**：异步,状态契约,连接中,反馈,真接口副作用
- **关联提示词**：PR-0366

## 现象（看到什么）

用户报：「当点击连接另外一个 wifi 时候，比如两个已经保存的，就应该连接另一个 wifi，
但是当前硬件没有切换，也没有看到提示连接中提示」。
两条症状同时出现：① 点已保存行后界面无任何过程反馈；② 真接口下网卡确实没换过去（后来查明是
目标网络密码已失效，`WlanConnect` 关联失败，界面停在原网上看不出来）。

## 复现（怎么稳定重现）

反向测试两条，各自 rc=1：
1. 在 `wifi_logic` 的 `APP_OUT_WIFI_CONNECT` 分支里补回 `wifi_nav_close_sheet()`
   （"一点就关窗"）→ `[NAV] FAIL 连接中半页仍在前台（不是一点就关）`；
2. 把假后端的 `s_try_t0 = clock()` 改成"已经到期"（同步完成）→
   `[NAV] FAIL 点开放网络 → 标题先写「正在连接 X…」` 等 3 条。

## 根因（真正的原因）

不是单点问题，是两处各自"合理"叠加后把过程吃掉了：
1. **假后端同步改内存**——`io_wifi_connect()` 里当场置 connected、当场写「已连接 X」，
   中间态根本不存在；真后端虽然是异步的，但只在 5s 后看一眼，也没有可观察的中间态；
2. **上层立刻关窗**——`wifi_logic` 发完命令就 `wifi_nav_close_sheet()`，
   于是"半页消失"成了唯一反馈，用户无法区分"在连"和"没反应"；
3. 结果文案也不分成功/失败（旧口径连上才写文案，失败时标题还停在"已发现 N 个网络"）。
另外记一条真接口副作用：`WlanConnect` 是**先断后连**，目标连不上就两头空
（本机实测：从 `1号楼6层WiFi` 换 `yjt_dev_2.4G` 失败后，`netsh` 显示"已断开连接"）。

## 修复（做了什么）

1. 新增状态契约 `APP_IN_CONN_STATE`（0 空闲 / 1 连接中 / 2 成功 / 3 失败），
   口径写进 `platform/wifi_platform.h`：**后端负责写，`wifi_logic` 负责消费**；
2. 两份后端同口径：真接口下发即置 1 +「正在连接 X…」，每秒回查、15s 判失败；
   假后端用 `CONNECT_SEC=1.2` 演出同一段中间态（这样三态在**无头门禁里可验**，不必真连网）；
3. `wifi_logic` 不再在发命令时关半页，收到 2 才关；收到 3 保持前台让用户改密码
   （本轮定的最小方案：失败提示只走标题栏文案，不补半页内红字控件）；
4. 双击 `run_sim.bat` 的默认后端翻向真接口，门禁改成**主动设** `WIFI_PC_FAKE=1`（见 P-0196）。

## 证据（数字 / 命令输出）

`[NAV] RESULT: PASS 40 / FAIL 0`（比上轮多 10 条，含"点下先看到正在连接""连接中半页仍在前台"
"成功才自动关""结果已被 logic 消费"）；`preflight --skip-cli --with-sim` 全绿 rc=0。
真机（不设任何变量）：`[IO] io_init (pc REAL wlanapi)` →
`[REACH] 点下之后标题=正在连接 yjt_dev_2.4G…` → 15s 后 `文案=连接失败 yjt_dev_2.4G`，
`netsh` 独立回读 `状态: 关联 → 已断开连接`，随后用 `netsh wlan connect name="1号楼6层WiFi"` 恢复。

## 沉淀（新增断言 / 案例 / 文档）

**任何"用户点了要等外部世界"的动作，中间态必须是契约字段而不是文案巧合**：
后端写状态、上层消费状态，假实现必须演出同一段中间态，否则门禁绿了但真机永远"没反应"。
落档：工程 `EEZ_WORKFLOW.md` §5.9。
