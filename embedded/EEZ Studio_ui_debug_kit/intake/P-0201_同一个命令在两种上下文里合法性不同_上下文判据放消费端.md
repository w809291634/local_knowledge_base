# P-0201 · 同一个命令在两种上下文里合法性不同：上下文判据放在消费端，别让后端猜

- **工程**：app-wifi-scan-conn-no-flow
- **日期**：2026-10-24
- **工具**：Qoder
- **状态**：fixed
- **标签**：命令契约,上下文,校验位置,UI口径
- **关联提示词**：PR-0371

## 现象（看到什么）

用户报「连接时候密码不能空」。原来的路径里，半页空着密码点「连接」会照常下发连接命令：
假后端把它当成功（还顺手转一圈圈），真后端拿空密码去连一个需要密码的网络，注定失败。

## 复现（怎么稳定重现）

无头用例里点开半页、不输密码直接点「连接」：`APP_OUT_WIFI_CONNECT` 照发，
`wifi_busy_show()` 照弹——把守卫那行 `if (0 && ...)` 掉就能稳定复现。

## 根因（真正的原因）

`APP_OUT_WIFI_CONNECT` 这一个命令有两种来源：**半页的「连接」（必须有密码）** 和
**列表上的直连（已保存/开放网络，密码本来就该是空）**。把"密码不能空"塞进后端，
后端只能靠"这个网络有没有锁/有没有 profile"去猜场景，猜错就把直连也堵了。

## 修复（做了什么）

`app/wifi_logic.cpp` 消费命令处：`if (wifi_nav_sheet_open() && !has_visible_char(pw))` →
不调 `io_wifi_connect`、不关半页、不弹转圈，标题栏写「请输入密码」。
"半页开着"就是"必须输密码"的充要条件，判据来自 navigation 层的模态状态，不需要后端参与。
纯空格也算空（`has_visible_char`）。

## 证据（数字 / 命令输出）

`[NAV] RESULT: PASS 47 / FAIL 0`（新增 3 条：半页不收 / 不转圈不发起 / 标题有提示）；
反向测试（去掉守卫）→ 这 3 条全红、rc=1；`preflight` 全绿。

## 沉淀（新增断言 / 案例 / 文档）

**一条命令的合法性依赖上下文时，把上下文判据放在"知道上下文"的那一层（这里是 logic + navigation 状态），
不要让底层后端反推场景**；否则同一个命令的两条来源会被一条规则误伤。
工程口径表：`EEZ_WORKFLOW.md` §5.7（加了「半页「连接」/ 密码为空」一行）。
