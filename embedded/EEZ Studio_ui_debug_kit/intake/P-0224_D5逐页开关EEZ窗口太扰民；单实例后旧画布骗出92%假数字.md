# P-0224 · D5 逐页开关 EEZ 窗口太扰民；改单实例后被"旧画布"骗出 92% 假数字

- **工程**：w78-tabview-smart-home
- **日期**：2026-11-05
- **工具**：Qoder
- **状态**：fixed
- **标签**：D5,EEZ,画布,多标签,CDP,抓图,相似度,窗口
- **关联提示词**：PR-0504

## 现象（看到什么）

D5 逐页比对时，26 页会连续启动/关闭 26 次 EEZ Studio 窗口，用户明确要求"处理 eez 时候不要不断地打开和关闭窗口"。
改成整轮只起一次 EEZ、逐页切页签后，相似度反而从 97–99% 普遍掉到 92–94%（主控 92.12%），
并偶发"疑似抓错页"。

## 复现（怎么稳定重现）

1. 启动一次 EEZ，依次打开「Wi-Fi 密码」「场景详情」「主控」三个页签；
2. 双击树节点切到「主控」，抓画布；
3. 抓到的仍是「Wi-Fi 密码」；侧栏并排图前半是主控设计、后半是密码页。

## 根因（真正的原因）

1. **页签存在 ≠ 已激活**：编辑器整页有多个 tabset（Pages / 属性 / 页签栏），每个 tabset 都有一个
   `flexlayout__tab_button--selected`。旧逻辑只检查"页签文本存在"或"任意 selected"，没有校验
   **目标页签自身**是否 selected。
2. **抓错画布**：`grab.js --canvas` 按"最大画布"取；多标签下每个页签各挂一个 800×480 画布，
   隐藏页签的画布同样大，于是取到的常是旧页。
3. 早期为了规避画布残留才改成"每页重启"，代价是窗口反复开关。

## 修复（做了什么）

- `design/d5_pages.py` 的 `CLICK_JS`：双击树节点后，点一次目标页签，再校验**该页签自身**带
  `selected` 才返回 OK；否则返回 NOSEL 进入重试。
- `tools/cdp/grab.js`：新增 `--visible`，只选 `getBoundingClientRect()` 非零的画布；
  `d5_pages.grab()` 固定传 `--canvas --visible`。
- 主流程：**整轮只 `launch()` 一次**，逐页切页签；某页连续抓不到才单页重启兜底
  （26 页里通常 0 次），结束时统一 `kill_eez()`。
- 新增 `--pages a,b,c` 便于小样本复测切换链路。

## 证据（数字 / 命令输出）

- 4 页复测（密码/场景/主控/客厅）：97.57 / 98.57 / 97.52 / 97.91%，与旧"每页重启"基线一致。
- 26 页全量单实例：**平均 98.46%，最低 97.52%（主控）**；Wi-Fi 三屏 97.89 / 97.57 / 99.10%。
- 全程 EEZ 只启动 1 次；导航仿真 `[NAV] 82/82 PASS`。

## 沉淀（新增断言 / 案例 / 文档）

- `reference/14` §7 新增 17–19：页签自身 selected、`--visible` 取视口画布、D5 整轮只起一次 EEZ。
- NO_FLOW §2.2 D5 行补"整轮只起一次 EEZ、逐页切页签"。
- 判据不变：抓图后差异 >20% 仍判"抓错页"重试，不把错页数字写进相似度表。
