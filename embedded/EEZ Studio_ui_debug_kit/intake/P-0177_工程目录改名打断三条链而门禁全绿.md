# P-0177 · 工程目录改名打断三条链，而门禁全绿

- **工程**：EEz_stidio_examples\watch-app-list-rxroller_no_flow
- **日期**：2026-10-22
- **工具**：Qoder
- **状态**：fixed
- **标签**：改名,gitignore,CMakeCache,路径活性,假门禁,空壳目录,索引漂移
- **关联提示词**：PR-0313

## 现象（看到什么）

目录从 `watch-app-list-rxroller` 改名为 `watch-app-list-rxroller_no_flow` 之后：
`git status` 冒出 `?? upstream_Rxroller/`（上游整仓克隆裸露）；`run_sim.bat build` 在配置阶段报
`The current CMakeCache.txt directory … is different than the directory … where it was created`。
而这两件事发生的同时，`preflight` rc=0、行为断言 19/19 PASS。

## 复现（怎么稳定重现）

把工程目录改名，然后依次跑 `git status --short`、`python design/preflight.py`、`run_sim.bat build`。

## 根因（真正的原因）

三处**按目录名硬编码**的东西不跟着改名走：① 仓库 `.gitignore` 的两条路径规则——改名后
**静默失效**，不报错，只是不再匹配；② `build_rel/CMakeCache.txt` 里 6 处绝对路径，CMake 缓存
本就不可搬迁；③ 根 README / CODE_WIKI 索引行与工程内文档的路径文字。
脚本自身反而一直没事（路径全从 `__file__` 推）——这正是"能跑"不等于"索引对"。
门禁没抓到是因为它压根没有"路径活性"这一维。

## 修复（做了什么）

`.gitignore` 两条按新名重写并补上同级变体目录；工程文件用 `git mv` 跟着改名；
删掉两个失效的 `build_rel/`（gitignore 内的可再生物）重新配置，全量重建 562 目标通过；
根 README/CODE_WIKI 与工程内 7 个文件的路径引用全部同步。

## 证据（数字 / 命令输出）

`preflight` rc=0（含新第 7 组）；`git status --porcelain` 无裸露文件；
`run_sim.bat build` → `build succeeded`；断言 19/19 PASS。

## 沉淀（新增断言 / 案例 / 文档）

新增门禁第 7 组「路径活性」：扫文档与脚本里所有"工程目录名形状"的 token，凡既不等于当前
实际目录名、同级又不是真实 EEZ 工程 ⇒ FAIL；并核对 `.gitignore` 两条确实按当前目录名在位。
★ 反向测试的教训：第一版豁免条件写成"同级有这个目录就放过"，投毒后**照样绿**——
改名在磁盘上留下了一串 0 文件的空壳目录（`旧名/design/sim_cmake/build_rel/…`），
`isdir` 为真就放过去了。⇒ 判"同级引用合法"要用**工程标记文件**（`*.eez-project` 存在），
不能用 `isdir`。空壳目录本身也是"目录删不掉/搬不走"的元凶，要一并清。
