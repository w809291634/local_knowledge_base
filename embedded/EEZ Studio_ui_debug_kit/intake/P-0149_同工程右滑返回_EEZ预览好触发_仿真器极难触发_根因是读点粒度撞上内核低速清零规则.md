# P-0149 · 同一工程右滑返回：EEZ Run 预览好触发、PC 仿真器极难触发——根因是"读点粒度"撞上内核低速清零规则

- **工程**：watch (Design Watch)
- **日期**：2026-10-19
- **工具**：Trae
- **状态**：fixed
- **标签**：gesture,lv_indev,低速清零,读点粒度,sdl,emscripten,wasm,asar取证,仿真器
- **关联提示词**：无（本轮口头链：applist 返回滑动难触发 → 是不是鼠标驱动问题 → 不建议改内核 → 读手册查明原因）

## 现象（看到什么）

AppList 右滑回表盘（§35 手势导航，工程内 GESTURE 事件 + flow，构建 0 错 0 警）：
EEZ Run 预览里正常手速就能触发；PC_SIM / 沙箱仿真器同一手势"很难触发"——
要又快又稳的猛甩才行（用户两次实测确认；修好后用户实测可用）。

## 复现（怎么稳定重现）

`bin/main.exe --gt`（本轮加的手势自测模式：SDL_PushEvent 注入合成滑动）：
- 用例1 纯水平慢滑 120px（120 个 1px motion）
- 用例2 带 1:4 纵向漂移的右滑 120px
修复前两用例均"未触发"；修复后（30ms 轮询 indev）均触发（用户实测人手滑动亦可用）。

## 根因（真正的原因）

**内核规则**（真 LVGL 9.4，`src/indev/lv_indev.c:1731-1741`）：每次读点若 |vx|<3 且 |vy|<3
→ gesture_sum **清零**；攒满 gesture_limit=50px 才发 GESTURE。min_velocity=3 / limit=50
是 .c 里裸 `#define`（:46-49），lv_conf.h 不可覆盖、无公开 setter、结构体不透明。

**三环境的差异只在"读点粒度"**（每次 lv_indev_read 携带的位移量）：

| 环境 | 输入路径 | 读点频率 | 150px/s 慢滑每读点 | 结果 |
|---|---|---|---|---|
| PC 仿真器（旧） | lv_sdl_mouse 逐事件直通（`lv_sdl_mouse.c:201` 无条件 lv_indev_read） | 鼠标硬件级 125~1000Hz | 0.2~1.2px → 每次都清零 | 需 >900px/s 猛甩 |
| EEZ Run 预览 | **真 LVGL 9.4.0 编译成 WASM**（Emscripten）+ SDL2 port，SDL 事件来自 **DOM mousemove（浏览器按帧合并 ~60Hz）** | ~60Hz | ~2.5px → 逃过清零 | 正常 |
| 真机 | 触摸驱动 30ms 轮询（LV_INDEV_DEF_READ_PERIOD） | 33Hz | 4.5px | 正常 |

**asar 取证**（纠正本轮早前的误判"EEZ 是 JS 模拟器没实现清零规则"——撤回）：
从 `app.asar` 解出 `project-editor/flow/runtime/lvgl_runtime_v9.4.0.js`（886KB），
它是 **Emscripten 加载器**：`wasmExports['lv_indev_get_gesture_dir']` 等真导出 +
注释 "this is used by the SDL2 port"（libsdl-org/SDL#6304）。EEZ 预览跑的是真内核，
它能触发纯粹因为浏览器把鼠标事件合并到帧率，读点粒度天然接近真机。
文件清单：`lvgl_runtime_v8.4.0/9.2.2/9.3.0/9.4.0/9.5.0.js` 按工程 lvglVersion 分档。

**两个次生结论**：
1. 9.4 新手势框架 `LV_USE_GESTURE_RECOGNITION`（lv_indev_gesture.c）只有
   PINCH/ROTATE/TWO_FINGERS_SWIPE，**无单指 swipe**（`LV_INDEV_GESTURE_SWIPE.recog_fn=NULL`），开它没用。
2. 事件模式下内核还会恢复 30ms read_timer（`lv_indev.c:1361-1364`）注入 0px 读点——
   这就是第一版修复（SDL 过滤器合并 <3px motion 事件）失败的原因：治了事件粒度治不了定时读。

**与 P-0141 的关系**（不改历史）：P-0141（2026-10-17，Qoder）实测 Run 预览不产生 GESTURE；
本轮用户实测预览**可以**触发。两轮环境可能有差（预览运行时版本/窗口形态），
但"手势验证以 PC_SIM/真机为准"的分工结论不变，且本轮补齐了为什么 PC_SIM 自己也会偏难的机制。

**手册边界**：784 页参考手册无预览运行时内部文档——Run mode 仅 §P3.2 一句
"在编辑器内执行"；手势相关只有 W1.2.38 Gesture bubble（冒泡开关）等控件属性。
阈值/粒度属于 EEZ 未文档化实现细节，只能 asar 取证。

## 修复（做了什么）

**内核零改动**（用户裁定不动共享内核树）。改 `watch/design/sim_cmake/main.c`（仿真器入口，
真机不编译此文件）：
- 弃用 `lv_sdl_mouse_create()`（逐事件读点），自建指针设备：
  `SDL_AddEventWatch(sdl_state_watch)` 只跟踪 mx/my/mdown 状态，
  `lv_indev_create()+set_read_cb(sim_mouse_read)` 走默认 **MODE_TIMER + 30ms** 轮询
  （与真机触摸节奏一致，每次读点=30ms 位移量，正常速度滑动远超 3px 不触发清零）；
- 加 `--gt` 手势自测模式（合成滑动注入，无需人手，可回归）；
- 遗留待清理：main() 开头有一段描述已废弃"过滤器方案"的过时注释。

**不做的事**：不改内核两个常量（用户裁定）；不开 LV_USE_GESTURE_RECOGNITION（无单指 swipe）。

## 证据（数字 / 命令输出）

- 修复前自测：`[gt] 用例1 纯水平慢滑120px: 未触发`、`[gt] 用例2 带漂移右滑120px: 未触发`
  （当时换用 windowID 修正后的合成事件，排除"事件没进驱动"假象：`lv_sdl_get_disp_from_win_id`
  按 windowID 分发，合成事件必须填真 windowID）。
- 修复后：用户实测慢滑可触发（PC_SIM bin\main.exe 重编于 2026-10-19）。
- asar 解包：`lvgl_runtime_v9.4.0.js` 886307 字节，含 `createExportWrapper('lv_indev_get_gesture_dir', 1)`。
- 触发速度量化：旧路径需每次读点 ≥3px×250Hz ≈ 750~900px/s 持续位移；新路径 ≥100px/s
  （3px/30ms）即可，与真机同阈值。
