# P-0194 · 投影层只按扫描态变化回显文案，连接/忘记之后标题永远停在旧句子

- **工程**：app-wifi-scan-conn-no-flow
- **日期**：2026-10-24
- **工具**：Qoder
- **状态**：fixed
- **标签**：投影,回显,渲染断言,状态更新
- **关联提示词**：PR-0363

## 现象（看到什么）

用户报「点击忘记时候，状态没有更新」。后端状态确实变了（`saved` 清掉、列表重排、行号变化），
但顶部标题一直写着「已发现 12 个网络」，连接成功后也不会变成「已连接 X」。

## 复现（怎么稳定重现）

把 `wifi_view_sync()` 的文案回显条件退回 `if (state != s_last_state)`，重编重跑 `WIFI_NAVTEST=1`：
`[NAV] FAIL 标题 label 上真的写着这句（渲染层）`、rc=1。

## 根因（真正的原因）

`APP_IN_SCAN_STATE` 只在 0/1/2（空闲/扫描中/完成）之间变；连接、忘记这类操作把
`APP_IN_SCAN_STATUS` 换了新句子，但 state 恒为 2。原来那段代码把"文案"和"刷新按钮态"绑在
同一个 `state != s_last_state` 判据里，于是文案只在扫描态切换时上屏一次。
为什么容易踩：model 槽里读得到新文案（`app_get_input_s` 一切正常），只有渲染层没跟上——
断言量的是 model 就会全绿。

## 修复（做了什么）

`app/wifi_view.cpp`：新增 `s_last_status[APP_IN_STR_MAX]`，回显条件改成
`state != s_last_state || strcmp(st, s_last_status) != 0`；刷新按钮的文案/CLICKABLE 仍只在
state 变化时动。

## 证据（数字 / 命令输出）

`[NAV] RESULT: PASS 30 / FAIL 0`（连跑 3 次一致），其中新增渲染层断言一条；
反向测试（退回只比 state）rc=1 且点名该条 FAIL。

## 沉淀（新增断言 / 案例 / 文档）

凡是"界面上应该看得到"的状态变化，断言要量 `lv_label_get_text(控件)`，不能只量 model 槽——
model 改了 ≠ 界面改了（与「观感断言要量渲染值不是布局值」同源）。
