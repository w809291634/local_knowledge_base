# P-0213 · 仿真截图必须落 `tmp/`，不得污染工程根

- **工程**：watch2
- **日期**：2026-10-25
- **工具**：Codex
- **状态**：fixed
- **标签**：仿真,截图,过程文件,tmp,工程卫生
- **关联提示词**：PR-0386

## 现象（看到什么）

无头仿真每跑一次就在工程根生成 `shot_alarm_editor.bmp`、`shot_applist.bmp` 等 27 张 BMP。
它们是回归过程证据，不是设计交付图；根目录被过程件淹没，用户容易误当成应提交资源。

## 根因（真正的原因）

`take_shot()` 直接把调用方传入的 `shot_*.bmp` 当相对路径打开。仿真器的工作目录是工程根，
所以所有过程截图都落在根目录。

## 修复（做了什么）

截图入口统一创建并写入 `tmp/sim_shots/<文件名>`；调用侧只传文件名，不再自行拼根目录路径。
`designer/` 保留给用户确认的设计交付图，`tmp/` 才是可随时清理的过程件目录。

## 证据（数字 / 命令输出）

清理根目录历史 27 张截图后重跑仿真：输出逐条打印
`[SHOT] saved tmp/sim_shots/...`，统计为 `root=0 tmp=27`，导航回归 `80 PASS / 0 FAIL`。

## 沉淀（新增断言 / 案例 / 文档）

**仿真、探针、对照中间图一律写 `tmp/`；只有用户确认的设计图或交付图才进入 `designer/` 等正式目录。**
