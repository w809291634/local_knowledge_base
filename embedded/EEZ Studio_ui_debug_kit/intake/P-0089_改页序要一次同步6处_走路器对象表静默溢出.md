## 现象（看到什么）

用户诉求（PR-0110 逐字）：「m_cats_wifi 这个触发的 flow，不应该直接弹出 wifi 连接界面，
而是像其他两个按钮一样，切换到指定的 tabpager 页即可」；澄清后范围 = **左栏切页 + 通用页那行仍走浮层**。

本轮实现把页序从 3 页改成 4 页（0 通用 / 1 网络 / 2 显示 / 3 唤醒），跑走路器时出现一条
极像"对象改名了"的报错：

```
!! longpress: 没有对象 m_net_net_slot0_hit
```

而 `m_net_net_slot0_hit` 在 `src/ui/screens.h` 里**明明存在**。

## 复现（怎么稳定重现）

- 页序类改动：只改 `build_ui.py` 的 CATS 而不改 sim.py 的 `nav_btn_for` / `VIEWS`，
  仿真就会点到旧页（表现为"切页切错"）。
- 对象表溢出：`screens.h` 对象数涨过 `WALK_MAX_MAP 700`（本轮恢复网络子页后涨到 **~846**），
  再跑任何按名字找对象的走路命令（如 `--walk=forget`）必现 `!! ...: 没有对象 <名>`。

## 根因（真正的原因）

1. **页序是全局约定，不是一个表**。它至少牵动 6 处，漏一处仿真就点错页：
   ① `build_ui.py` 的 **CATS** 表（rail 行 → tab 索引）；② **rail_cats 的 switchTab**；
   ③ **pane_settings 每行的 tab_i**；④ **onTabChange 的高亮分组**（改成 4 组，且
   `cats_add[0]` 也归 wifi —— 左栏没有「通用」项，通用页与网络页共用第一项，
   沿用 P-0034「每页都要有归属高亮」）；⑤ **sim.py 的 `nav_btn_for` / `VIEWS` 表**；
   ⑥ **sim.py 的冒烟段 / 滑动断言期望值**。
2. 同源内容两份共存：`pane_network` 在子页（prefix **`netp_`**）与浮层（**`net_`**）各建一份，
   共享同一批 native 变量与命令 ⇒ 状态天然一致；但 `json2eez` 画布分区 `_bucket` 要补 `/netp_`。
3. ★★ **走路器对象表上限会静默溢出**：`wmap_add` 写的是 `if (o && s_nwmap < MAX)` ——
   超过上限就**丢尾部**，不报错、不自证；症状极像「对象改名了」，会把排查带到完全不同的方向。

## 修复（做了什么）

- **build_ui.py**：CATS 的 wifi 由 `"pop"` 改成 tab 1（sun/mic 顺延 2/3）；`rail_cats` 删掉 pop 分支
  （旧链是 `switchTab(tab=None)` 只同步高亮 + `onShow` 开浮层两条动作组件）与 `pop_refs` 参数；
  新增 `set_net = tab("网络", …, id="tab_net")` 排在通用之后，`set_nav` children 加它并在
  `SET_X` 挂 `place(pane_network(SW, CONTENT_H), …, "netp_")`；`onTabChange` 高亮分组改 4 组；
  `pane_settings` 行目标页：语音唤醒 2→3、主音量/屏幕亮度 1→2（「无线网络」仍 `"pop"`）。
- **sim.py**：`nav_btn_for` 加 `case 1 → m_cats_wifi`；`VIEWS` 表 `08_wake_word` 的 set_nav 2→3、
  `10_display` 1→2；冒烟段 **3 处** `set_tv_layer(3, …)` 同步；滑动断言语义与期望值更新
  （tab0 通用→tab1 网络，cats 期望 100）；**新增走路脚本 `cattab`**（点左栏四项各切一页 + `state`）。
- **json2eez.py**：画布分区 `_bucket` 补 `/netp_`。
- **走路器（独立真 bug）**：`WALK_MAX_MAP` **700 → 1600**，并在 `wmap_build` 结尾打印
  「对象表 N 条（上限 M）★已满」的**自证行** —— 以后再出现"没有对象"先看这一行。
