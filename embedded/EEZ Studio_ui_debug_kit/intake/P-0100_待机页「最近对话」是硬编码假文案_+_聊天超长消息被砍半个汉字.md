# P-0100 · 待机页「最近对话」是硬编码假文案 + 聊天超长消息被砍半个汉字

- **工程**：eez-test
- **日期**：2026-10-03
- **工具**：Qoder
- **状态**：fixed
- **标签**：聊天,待机页,UTF8截断,chat_copy_clip,假反馈,输入框装饰
- **关联提示词**：PR-0136

## 现象（看到什么）

待机页那两行（音乐推荐 · 今天 19:12 / 已为你播放《Deep Focus》歌单，共 32 首）永远不变；云端长回复超 256B 时尾部乱码。

（待补）

## 根因（真正的原因）

两行 label 是设计稿写死的静态文案，native 有 chat_store 环形队列却没人读它；chat_append 用裸 strncpy(...,255) 拷 256B 缓冲，三字节汉字会被切成半个 => 非法 UTF-8 序列。另外输入框只是 box+静态 label，没有真 textarea，APP_OUT_CHAT_SEND 也不带文本 => 真机发送是装饰（用户 2026-10-03 明确：文本输入不做，作为已知边界保留）。

## 修复（做了什么）

chat_item_t 加 time_t ts；新增 chat_copy_clip（按 UTF-8 字符边界找最大可放前缀，留 4B 给 … +NUL）；新增 chat_publish_last() 发 APP_IN_CHAT_LAST/_TIME 两个串输入；气泡与待机页都用**截断后的快照**（原来 chat_make_row 吃原始 text，会与快照不一致）；发布前还要再过一次 clip —— app_set_input_s 的串缓冲只有 64B，不截照样砍半字。DSL 侧两个 label 改 var= 绑定并声明变量。

## 证据（数字 / 命令输出）

新增走路 --walk=chataudit 实测：待机页 m_txt_6=19:39、m_txt_7=「好的，已经为你找到相关的歌单并开始播放了…」，无乱码；文字体检「该有文字却没文字且可见」=0；时间未对时（<2020）显示空串不显示 1970 假时间。

## 沉淀（新增断言 / 案例 / 文档）

MEMORY.md：运行期文本一律过 UTF-8 边界截断；绑变量 label 的串缓冲上限也要算
