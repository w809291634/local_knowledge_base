# P-0203 · 入场动画用 translate 不动布局，但会动命中测试——夹具必须等动画结束

- **工程**：app-wifi-scan-conn-no-flow
- **日期**：2026-10-24
- **工具**：Qoder
- **状态**：fixed
- **标签**：LVGL,动画,translate,命中测试,无头夹具
- **关联提示词**：PR-0375

## 现象（看到什么）

给连接半页加入场动画（遮罩淡入 + 半页自底部上滑 200ms）后，肉眼正常；
但无头用例里"点 × / 点「连接」"这类操作开始偶发点空——断言报"没关窗/没发起"，
重跑有时又能过。

## 复现（怎么稳定重现）

动画时长改大到 600ms 后必现：`[NAV]` 里"点 × → 半页隐藏"那一拍，点击坐标算的是布局位置，
而半页此刻还停在屏幕下方（translate_y 未归零）。

## 根因（真正的原因）

`lv_obj_set_style_translate_y()` 只改**绘制/命中**用的变换，不改布局值（`get_coords` 返回的是
含变换后的区域，但父容器布局、我们算坐标用的对象中心并不跟着动）。
用例在"对象已显示"就点，可对象还在半路上 → 点到的是它原来的位置（此刻那里是列表）。

## 修复（做了什么）

1. 导航层暴露 `wifi_nav_animating()`（动画 ready 回调里清零）；
2. 夹具把 `pred_sheet_visible` 改成 `!hidden && !animating`——所有"等半页显示"的地方
   自动变成"等半页落位"；
3. 关闭/互斥切走时 `lv_anim_delete` + 复位 translate 与遮罩透明度。

## 证据（数字 / 命令输出）

`[NAV] RESULT: PASS 48 / FAIL 0`（新增断言「点开后半页正在上滑（入场动画在跑）」，
它同时保证"动画真的在跑"而不是被静默跳过）；反向测试（注释掉动画启动）→ 该条 rc=1；
600ms 长动画下连跑 3 次仍 48/0。

## 沉淀（新增断言 / 案例 / 文档）

**"可见"不等于"可点"**：任何位移/缩放/透明度动画期间，坐标与命中都可能偏离布局值。
门禁里表示"界面就绪"的谓词必须把"动画结束"算进去，并且单独留一条"动画真的在跑"的断言，
否则动画被删掉也不会有人发现。
