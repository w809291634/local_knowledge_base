# P-0275 · EEZ 生成逻辑按工程各写一份导致规则漂移，收敛为单入口通用生成器

- **工程**：多参数监护仪 UI（multipara_monitor_ui）
- **日期**：2026-11-08
- **工具**：Trae
- **状态**：fixed
- **标签**：生成器,单入口,复用,模板,schema
- **关联提示词**：PR-0626

## 现象（看到什么）

同一条规则修好一处、另一处还是错的：按钮子标签 content、Slider 独立轨道、读数 Label 实测盒这三条
在 w78 与多参数监护仪两边各修一遍；新工程还要再复制一份生成器，规则继续分叉。

## 复现（怎么稳定重现）

任意两个工程各自维护 `design/build_ui.py`（或等价生成器）；在其中一处修 BTN_CHILD / Slider /
Label 规则后，另一工程重新生成，同样的缺陷原样复现。

## 根因（真正的原因）

生成规则与工程数据耦合在同一个脚本里。规则（模板克隆、字段集、各控件类型写法、跳转落地）是通用的，
工程差异只有页面/节点/主题/字体映射与 EEZ 骨架，但这部分没有独立成数据。

## 修复（做了什么）

- 新增 `tools/eez_gen_template.py`：单入口生成器，按控件类型分函数
  （container / label / button / switch / slider / line），CLI 与 `generate()` 两种调用方式。
- 工程只提供两份数据：
  - `design/design_source.json`：页面、节点、主题、`font_tokens`、`ttf_by_token`；
  - `design/eez_base.json`：EEZ 工程骨架（settings、字体条目、页面壳）。
- 工程侧 `design/build_ui.py` 退化为薄封装，只做路径拼装后调用 `gen.generate(...)`。
- 三条硬规则内置在生成器里，不再由工程重复实现：
  BTN_CHILD（子标签 content）、Slider（独立 6px 轨道 + MAIN 透明）、读数 Label（原文实测盒）。

## 证据（数字 / 命令输出）

- 通用生成器输出与多参数监护仪原专用生成器**逐页字节一致**：14 业务页 / 540 节点 / 630 控件 / 44 跳转。
- A14 字段集 630/630；BTN_CHILD 76/76；A 声明层差异 0；D4 C 语法 7/7；B1 14/14 平均相似度 97.26%。
- `python tools/eez_gen_template.py --src ... --base ... --out ...` 可直接在任意工程复用。
