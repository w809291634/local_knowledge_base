# P-0229 ESP32 最终链接测量：模板换 UI 的两处假失败 + 资源账口径

> **检索别名**：ESP32 占用 / P4 占用 / esp32_size / idf.py size / ui_size_report /
> 模板换 UI / 备份被当组件 / ninja 不重编 / 资源树。

- **时间**：2026-11-05
- **工程**：`w78-tabview-smart-home`（800×480，24 屏）
- **环境**：ESP-IDF 5.5.5 + P4 模板
  `D:\esp32_8266_files\esp-idf-v5.5.5_ol\examples\idf_v555_my_exps\p4_touch_lcd4_3_exp\lvgl_demo_template_no_flow`
- **脚本**：`design/esp32_size.py`（换 UI → 构建 → 读 map → 还原模板）

## 现象

1. 第一次构建：CMake 报
   `Requirement native.__w78_backup__ and requirement ui.__w78_backup__ are both added as "project_extra_components"`。
2. 第二次构建：链接报 `ui_font_cn76` / `img_sp_app_sport_f09` 等未定义 —— 实际链接的是模板旧 UI。

## 根因

- 备份目录原本放在 `eez-test/src/` 下，而 `eez-test/src` 是 `EXTRA_COMPONENT_DIRS`，
  IDF 会把它的每个子目录当组件扫描，`*.backup__` 于是变成两个候选组件。
- `copytree` 保留源文件 mtime；源比模板上次构建的 `.obj` 旧，ninja 判定无需重编，
  只重新链接，结果新旧对象混在一起。

## 修复

- 备份移到 `eez-test/__w78_measure_backup__/`（在 `src` 之外，组件扫描不到）。
- 拷入 UI 后对 `*.c/*.h/*.cpp` 逐个 `os.utime(p, None)` 强制刷新 mtime。
- 还原时同样 touch，再 `idf.py reconfigure build`（GLOB 在 configure 期求值，必须重跑）。
- 还原构建可能遇到 components 服务偶发
  `Server returned invalid or empty JSON`，重跑即可，与工程无关。

- PC 同源编译（gcc -O1，未链接/未 gc）为 525KB + 7KB，只能当上限参考。
- 口径：**只报编译后占用**；有 IDF 环境时以目标最终链接为预算基准，PC 并列保留。
- `mem_report.py` 读 `design/esp32_size.json` 的 `ui_hash`，UI 一变即标记过期并回退 PC 上限。

## 工具链只编译够不够（2026-11-05 实测）

| 口径 | UI Flash | RAM | 相对最终链接 |
|---|---|---|---|
| PC gcc -O1，未链接 | 525KB | 7KB | +30% |
| 目标 riscv 工具链同参数只编译、不链接 | 487,379 B（475.9KB） | 3,892 B | **+17.5%** |
| IDF 最终链接（`--gc-sections`） | 414,649 B（404.9KB） | 3,798 B | 基准 |

- 工具链只编译能拿到**目标架构**的逐文件字节，RAM 误差仅 +2.5%，适合快速看趋势；
  但 Flash 会多算未引用的函数/字体/图片（本工程 cn32 7.5KB、EEZ 未绑定回调等），
  不能作为 D9/交付判据。
- **优化等级对比**（riscv 工具链只编译；IDF 当前为 `-O2`，字库 241,845B 不随等级变）：

  | 等级 | UI Flash | RAM |
  |---|---|---|
  | `-O0` | 528.0KB | 3.8KB |
  | `-O1` | 474.5KB | 3.8KB |
  | `-O2`（IDF 当前） | 476.0KB | 3.8KB |
  | `-O3` | 476.0KB | 3.8KB |
  | `-Os` | 475.2KB | 3.8KB |

  本级 UI 上 `-O1/-Os` 反而略小于 `-O2`，但 RAM 不变；报告必须写明等级并给这张对比。
- 精确值必须走一次最终链接；**不需要把 UI 并进 IDF 工程**：`esp32_size.py` 只是在测量模板里
  临时换 `src/ui`、链接、读 map 后立刻还原。PC 与目标本来就不同，不能互相替代。
- **默认口径（2026-11-05 用户定）**：日常资源树用 `design/esp32_estimate.py` 只编译估算
  （目标架构、同参数、每次实时算，Flash 偏高约17%），**默认优化 `-O2`（IDF 当前），并给各等级对比**；
  PC 编译上限并列；**只有用户点名“用 IDF 工程编译”时**才跑 `esp32_size.py` 做最终链接复核。
