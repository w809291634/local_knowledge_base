# P-0015 · 只放一个图标的胶囊按钮，图标左边窄右边宽（布局助手给最后一项也加了间隔）

- **工程**：test.eez-project（EEZ Studio → LVGL 9.4 / 800×480）
- **日期**：2026-09-24
- **工具**：WorkBuddy
- **状态**：fixed
- **标签**：布局,gap,间隔语义,pill
- **关联提示词**：PR-0030（"检查一下其他位置，也哟这个问题"）

## 现象（看到什么）

一类**只放了一个图标、没有文字**的小胶囊按钮，图标不在正中：
左空隙 10~11px，右空隙 16~17px —— **恒定右边多 6px**。
带文字的胶囊按钮全部正常。

命中 6 处：`ac_ic_more`(32×30) / `vc_ic_close`(36×30) / `hi_ic_plus`(37×26) /
`np_ic_more`(32×28) / `ml_ic_search`(43×30) / `nf_ic_tune`(43×30)。

## 复现（怎么稳定重现）

```bash
python design/build_ui.py
python build/verify_center.py     # 看这 6 行的左/右间隙列
```

## 根因（真正的原因）

布局助手 `pill_btn()` 在拼「点 + 图标 + 文字」时，**给每一项后面都无条件追加一个 `gap`**：

```python
cur += iw + gap      # ← 纯图标时这条尾巴也被算进总宽
```

于是总宽 = `图标宽 + gap + pad_l + pad_r`，而图标仍从 `pad_l` 起画 ——
右边多了一份尾随间隔，图标偏左 `gap/2 = 3px`。

`gap` 的正确语义应是「**项与项之间的分隔符**」（首尾都不该有），
就像 CSS flexbox 的 `gap` 天然不含首尾。

**为什么容易踩**：带文字时最后一项后面正好跟着内容，尾巴被"吃掉"，看不出来；
只有纯图标这种退化形态才暴露。

**曾经误判**：第一反应去查左右内边距是否不对称 —— 查完发现 6 处全部对称（10/10、11/11）。
定向线索是「**只有一个方向偏**、且偏移量恰好等于间隔常量」→ 指向排布逻辑而非坐标换算。

## 修复（做了什么）

`design/build_ui.py` 的 `pill_btn()`：把间隔改成**只在前面已有内容时才补**：

```python
if icon:
    if inner:
        cur += gap        # 只在项与项之间补
    inner.append(sym(cur, …, icon, icon_px, fg))
    cur += iw             # 不再无条件 +gap
if text:
    if inner:
        cur += gap
    …
```

`icon + text` 的既有间距**完全不变**（前项推进 `iw`，下一项前 `+= gap`，结果仍是 `iw+gap`）；
只有纯图标胶囊变窄 `gap`，且它通常按返回值做右对齐，会自行跟随。
