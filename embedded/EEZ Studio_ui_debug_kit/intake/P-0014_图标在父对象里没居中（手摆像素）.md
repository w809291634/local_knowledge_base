# P-0014 · 圆形按钮里的图标没落在父对象正中（居中是被"算"出来的，不是被"声明"的）

- **工程**：test.eez-project（EEZ Studio → LVGL 9.4 / 800×480）
- **日期**：2026-09-24
- **工具**：WorkBuddy
- **状态**：fixed
- **标签**：居中,布局,dsl,像素偏差
- **关联提示词**：PR-0030（"检查一下其他位置，也哟这个问题"）

## 现象（看到什么）

1. AiChat 歌单卡片的圆形播放钮，播放图标不居中（用户先发现这一处，见 PR-0026 系列修复）。
2. 用户追问"其他地方是不是也有"后全量扫描，发现**同一类写法共 65 处**，其中：
   - Voice 页聆听光球（112×112）里的 42px 星形、NowPlaying 暂停圆钮（52×52）里的暂停图标
     ——**严重偏左**，因为代码是 `sym(0,0,…)` 再用 `x=int(round(ox-56))` 事后覆盖坐标，
     覆盖进去的其实是**圆的左上角**。
   - `rail()` 侧栏 logo（38×38，**11 个页面共享**）、AiChat 发送按钮（46×46）
     ——用 `sym(与父框完全相同的盒)` 手摆中心。
   - `badge()` 徽标方块 —— 用 `sym(x,y,sz,sz)`，**约 20 处调用点**。
   - 还有一处与编辑器差 1px：Python `round()` 是 **half-even**，编辑器（JS `Math.round`）
     是 **half-up**，`(32-11)/2=10.5` 前者得 10、后者得 11。

## 复现（怎么稳定重现）

```bash
python design/build_ui.py
python build/verify_center.py          # 列出全部「父容器唯一子对象」的四边间隙
```

修复前输出 6 处左右间隙差 6px（另 2 处是上述 `sym(0,0,…)` 覆盖型，不进间隙判据）。

## 根因（真正的原因）

**「居中」这件事在组件树里不存在** —— EEZ 编辑器那两个「相对父对象居中」按钮（源码语义）
也只是**当场算一次 `(父−子)/2` 写死**，生成的仍是 `lv_obj_set_pos`。
于是没人维持这个关系：一旦辅助函数手写恒坐标（还和被算好的 position 打架）就漂；
再加上生成脚本与编辑器的**舍入模式不一致**（half-even vs half-up），出现稳定 1px 差。
另有一条次因：content 尺寸的 label **没写回真实字形宽高**，编译器兜底成 100×40 ——
编辑器 rect 显示错、它的居中按钮按错尺寸算，核验脚本也因而算不出四边间隙。

## 修复（做了什么）

`design/build_ui.py`：
- `center_in(child, parent)` 用**声明式**表达居中，内部改用 `int(x+0.5)`（= half-up，对标 JS）；
- `sym()` 也写回真实字形尺寸 `tw/lh`，让编译器/编辑器/核验三边一致；
- 把 `badge()` / `rail()` logo / AiChat 发送钮 / Voice 光球 / NowPlaying 暂停钮
  五种形态的手动写法全部换成 `center_in(icon(...), parent)`。
