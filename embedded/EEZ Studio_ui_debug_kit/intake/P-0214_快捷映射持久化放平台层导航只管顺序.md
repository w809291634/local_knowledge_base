# P-0214 · 快捷映射持久化放平台层，导航只管顺序

- **工程**：watch2
- **日期**：2026-10-25
- **工具**：Codex
- **状态**：fixed
- **标签**：navigation,platform,NVS,PC模拟,用户偏好,持久化
- **关联提示词**：PR-0387

## 现象（看到什么）

用户从 `+` 页添加运动、心率后，左滑能按映射直达；但原实现只存在 navigation 的静态内存中，
重启后又回到空映射，不符合“下次仍可直接切换”的预期。

## 根因（真正的原因）

导航层保存了运行时顺序，却没有通过 PC/真机替换边界读写用户偏好；直接在 navigation 写文件或 NVS
会让页面路由依赖具体平台，破坏分层。

## 修复（做了什么）

在 `watch_platform.h` 增加 `watch_platform_quick_map_load/save`。navigation 仅校验应用索引、
去重和维护顺序；PC 实现写 `tmp/quick_map.txt` 模拟 NVS，真机实现预留相同接口接板级 NVS。
无头回归启动前删除这份模拟数据，添加两项后再从平台重载，验证冷启动读取语义。

## 证据（数字 / 命令输出）

日志依次输出 `quick-map save=1`、`save=2`、`load=2`、`restored=2`；断言“重载映射第 1 项是运动、
第 2 项是心率”均通过，完整导航回归 `83 PASS / 0 FAIL`。

## 沉淀（新增断言 / 案例 / 文档）

**页面去向属于 navigation，跨重启保存属于 platform。** 先定义小而稳定的 load/save 接口，
PC 用 `tmp/` 模拟，板级项目再把同一接口绑定 NVS，禁止 navigation 直接碰文件系统或 SDK。
