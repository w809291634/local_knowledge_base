# P-0068 · 真机「点加密网络不弹密码面板」：先取固件字符串证伪「固件太旧」，再补「已保存」标识与三分支日志

- **日期**：2026-10-02（PR-0111）
- **症状**：真机设置/浮层里点「可用网络」里的一个加密网络，不弹密码面板（用户预期弹）。
- **取证手法（可复用，先做这步再猜代码）**：
  1. `git show <最近提交>:./src/native/platform/io_esp.cpp | sed -n '/void io_wifi_pick/,/^}/p'`
     —— 看**已提交**版本长什么样（工作区改动不一定进了你烧的那份固件）；
  2. `ls -la build/*.bin` 看真机构建时刻（本次 10-02 09:55，晚于 io_esp.cpp 07:59，排除旧固件）；
  3. **在固件二进制里直接 grep 日志串**（最硬的一条证据）：
     `grep -q "password entry not supported yet" build/lvgl_demo_v9.bin` → 不在；
     `grep -q "show password panel" build/lvgl_demo_v9.bin` → **在**。
     ⇒ 弹面板分支确实进了固件，问题不在"代码没写"，只能落在运行期三条分支之一。
- **三条分支（真机 `io_wifi_pick`）**：①`!ap.ssid[0]` 空槽 → 什么都不做；
  ②`!ap.lock`（判成开放网络）→ 直连；③`have_password`（SsidManager 里有该 SSID）→ 直连；
  ④加密且未保存 → `APP_IN_WIFI_PWD_SHOWN=1` 弹面板。
- **根因（本次）**：用户在真机上点的是**早已连过、存进 SsidManager/NVS 的网络** → 走分支③
  直连，按设计不弹面板；但真机扫描时 `sub` 一律写死 `"WPA2 PSK"`（PC 侧 `io_pc` 对已保存的
  写 `"WPA2 PSK · 已保存"`），**界面上没有任何"已保存"提示**，用户看到的就是"点了不给输密码"。
- **规则 / 修法**：
  1. **PC 与真机的槽位文案必须逐字一致**（含 `" · "`：空格 + U+00B7 中点 + 空格）。
     两边判据都是 `sub` 里的"已保存"字样，文案一歪两边就对不上，仿真说能弹真机说不弹。
  2. 真机扫描期就查一次 SsidManager 给 AP 打「已保存」标识（工作任务里查，微秒级）；
     `io_wifi_pick` 里再判定是否直连时**复用同一个 helper**，别在函数里抄第二份判等。
  3. `scan_ap_t::sub` 容量要按 UTF-8 字节数算：`"WPA2 PSK · 已保存"` = **21 字节**，
     原 `sub[16]` 会被 safe_copy 截成"…已保"（像错别字，还毁判据）→ 放宽到 24。
     改完必须过 `python design/_device_syntax_check.py`（保留 -O2 真编译，抓得到截断）。
  4. **三个分支各打一行日志**（原来只有弹面板/空槽有）——真机没有仿真器，
     "点了没反应"这类问题的定位成本几乎全在日志上；一条 entry 自证
     （slot / ssid / lock / sub）+ 每条分支一行，翻串口一次就能定性。
- **状态**：fixed（三处改完；`_device_syntax_check` 四文件 0 错 0 警；
  `--walk=wifi_ok` 3 张图、`--walk=pwd` 2 张图全通；`io_pc.cpp` 语义未动）
