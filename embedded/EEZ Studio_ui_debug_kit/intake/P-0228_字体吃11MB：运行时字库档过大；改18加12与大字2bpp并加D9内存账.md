# P-0228 · 字体吃 11MB：运行时字库档过大；改为 18/12 + 大字 2bpp 并加 D9 内存账

- **工程**：w78-tabview-smart-home
- **日期**：2026-11-05
- **工具**：Qoder
- **状态**：fixed
- **标签**：内存,字体,GB2312,bpp,Flash,预算,D9
- **关联提示词**：PR-0510

## 现象（看到什么）

用户要求"工作流始终注意内存占用，以减少内存占用优先"。统计 `src/ui`：
字体 .c 合计 **11.06MB**，其中运行时字库 `cn24f` 3.64MB、`cn12f` 1.42MB；总生成物 12.29MB。

## 根因（真正的原因）

1. 动态中文（SSID/状态）需要 GB2312 全字库档，最初用了 **24px** 一档（sheet 标题），24px 字形坐标大，C 数组最贵。
2. 设计字体统一 bpp4；大字（30/38/40px）用 4bpp 收益很低（人眼分不出 16 级灰度）。
3. 没有内存预算门禁，字体涨了没人拦。

## 修复（做了什么）

- 运行时字库档：`cn24f` → **`cn18f`**（设计里标题就是 18px），sheet 标题字号回到 18；
  运行时时档固定为 **12 / 18** 两号，不随设计字号扩散。
- 运行时档与大字号（≥30px）设计字体统一 **bpp 2**（4 级灰度）；小字号保持 4bpp。
- 新增 `design/mem_report.py` + `design/mem_budget.json`（字体 10MB / UI 合计 12MB），
  接入交付门禁 **D9**；超预算 FAIL。
- 工作流：AGENTS 规则 13「内存优先」；NO_FLOW D9 行；reference/07 字体节补做法。

## 证据（数字 / 命令输出）

- 字体 .c：**11.06MB → 9.80MB**；生成物合计 **12.29MB → 11.02MB**。
  - cn18f 2.37MB（原 cn24f 3.64MB）、cn12f 1.42MB；cn40 1.44→0.75MB、cn38 1.31→0.69MB、cn30 0.85→0.45MB。
- `python design/mem_report.py` → `[MEM] PASS`；门禁 `D9 内存账 PASS 字体 9.80MB / 合计 11.02MB（预算 10.0/12.0）`。
- 大字 2bpp 目检（主控 22°/23.5° 等）无可见断层；Wi-Fi 半页标题 18px 正常。

## 沉淀（新增断言 / 案例 / 文档）

- 预算门禁 D9 固化；后续加字号/字库先看 D9，超了先降 bpp/缩字符集/换小字号。
- 仿真 `LV_MEM_SIZE=4MB` 只为截图缓冲（snapshot 1.5MB），固件不要照抄。
