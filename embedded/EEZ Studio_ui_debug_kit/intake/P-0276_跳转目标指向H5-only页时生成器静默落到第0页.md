# P-0276 · 跳转目标指向 H5-only 页时生成器静默落到第 0 页

- **工程**：多参数监护仪 UI（multipara_monitor_ui）
- **日期**：2026-11-08
- **工具**：Trae
- **状态**：fixed
- **标签**：生成器,跳转,h5_only,静默失败,no-flow
- **关联提示词**：PR-0626

## 现象（看到什么）

仿真里点「确认关机」没有进入预期页面，而是停在主监护；工程里该按钮的
`eventHandlers.userData = 0`。设计源写的目标却是「开机自检」（H5-only 页）。

## 复现（怎么稳定重现）

设计源任一 goto 指向 `h5_only` 页（或任何不在 EEZ 业务页里的名字），
生成器执行 `page_index.get(goto, 0)`，静默写成页索引 0，无任何告警。

## 根因（真正的原因）

默认值兜底把「目标不存在」伪装成「去第一页」。H5-only 页不在 `biz` 列表里，
所以自检页永远拿不到索引；这类错误既不会在生成期暴露，A 对账也会因为
设计 44 == eventHandlers 44 而通过。

## 修复（做了什么）

- 生成器改为：`goto` 不在 `page_index` 时直接 `SystemExit` 报错，不再兜底 0。
- 设计源修正语义：「确认关机」不应跳页（真机由 native 关机/重启，自检是运行期
  覆盖层），从 `nav_map.py` 删除该条；控件保留为 native 按钮。
- 第⑤步 C 边表从设计源派生，自动跟随为 43 条。

## 证据（数字 / 命令输出）

- A 声明层对账：差异 0，跳转 43/43（设计 43 / eventHandlers 43 / 生成回调 43）。
- 第⑤步 C：43/43 PASS，含「系统设置 --关机--> 关机确认」。

## 沉淀（新增断言 / 案例 / 文档）

- `tools/eez_gen_template.py`：不可达 goto 直接报错（禁止默认页兜底）。
- 经验：**h5_only 页不能作为 goto 目标**；需要「重启/关机」时走 native 动作。
