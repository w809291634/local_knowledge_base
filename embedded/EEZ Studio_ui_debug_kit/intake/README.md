# intake/ —— 问题流水

> 开发中遇到的**新问题**都记在这里，每条一个文件。写入规约见 `../INTAKE.md`；
> 写入器：`../tools/log_entry.py problem`。

## 文件

| 文件 | 说明 |
|---|---|
| `TEMPLATE.md` | 空白模板（六段式：现象 / 复现 / 根因 / 修复 / 证据 / 沉淀）—— 手写时照抄它 |
| `index.md` | 总表：编号 / 日期 / 标题 / 标签 / 状态；新增一条问题就追加一行 |
| `P-####_*.md` | 每条问题一个文件（文件名 = 编号 + 短标题） |

## 规矩

1. 编号取"当前最大值 + 1"，**不复用、不留空号**。
2. **只追加**，不删历史条目；判断被推翻时补写"为什么当初误判"。
3. 必须带**可复现证据**（坐标 / 命令 / 前后对比数字），不要写"报错了、修好了"。
4. `intake/` 是**原始流水**（允许粗糙、允许未定论）；一个坑彻底搞懂且能推广后，
   按 `../cases/README.md` 提炼进 `cases/` —— 两者用编号互引。
5. 每条都记 `工程` 字段：换新工程时本目录**保留**，靠它区分历史记录。
