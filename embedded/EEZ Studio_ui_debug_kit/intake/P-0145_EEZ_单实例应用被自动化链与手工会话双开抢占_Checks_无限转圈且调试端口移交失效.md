# P-0145 · EEZ Studio 单实例被"自动化链 + 手工会话"双开抢占 → 用户侧 Checks 无限转圈、脚本侧 9222 端口"移交"失效

- **工程**：watch (Design Watch)
- **日期**：2026-10-18
- **工具**：Qoder
- **状态**：fixed
- **标签**：eez-studio,单实例,cdp,checks,转圈,自动化冲突,字体提取超时
- **关联提示词**：PR-0243

## 现象（看到什么）

用户手工打开工程看新改动，EEZ 底部 **Checks 页签转圈永不结束**；同时我侧 eez_build.py
连续两轮报 FONT-EXTRACT-INCOMPLETE/TIMEOUT（§42、§45 轮）。9222 端口始终不监听，
但 tasklist 里 EEZ Studio.exe 明明活着（用户实例）。

## 根因（真正的原因）

EEZ Studio 是 Electron **单实例**应用：
1. 我的链在 CLI 阶段（--build-project）会重写 watch/src/ui/*（含删字体 .c）；
   用户此刻开着的编辑器工程文件被"抽地基"，其 Build/Checks worker 卡死 → 转圈不停。
2. 我 GUI 阶段带 --remote-debugging-port=9222 的新启动，会被单实例机制
   **移交**给用户已开的实例（没有调试口）后自退 → 9222 永不监听；
   脚本退回盲点坐标 + 空等 300s → 超时误判"字体提取失败"。
（§34 的 CLI 删字体机制叠加本冲突，才让"重跑一次就好"看起来玄学。）

## 修复（做了什么）

eez_build.py GUI 阶段加早停诊断：等 9222 端口 80s 不起 → 直接报
"单实例抢占：请关闭手工打开的 EEZ 窗口后重跑"（rc=2），不再盲点空等。
协作纪律：链运行期间（3~5 分钟）双方只有一方碰 EEZ——AI 跑链时用户不开编辑器，
用户要开先让 AI 停链；产物由生成器兜底，杀实例零损失。

## 证据（数字 / 命令输出）

09:05 链启动、09:06 CLI 重写 src/ui+删字体（fonts.h mtime）、09:10 用户截图 Checks 转圈、
9222 无 LISTENING、5 个 EEZ 进程=用户单实例存活。加诊断后复跑：待回填。
