# P-0207 · 连接前先扫描会让四次握手超时，看起来像「点了没反应」

- **工程**：app-wifi-scan-conn-no-flow
- **日期**：2026-10-25
- **工具**：Qoder
- **状态**：fixed
- **标签**：wlanapi,扫描,WlanConnect,握手超时,时序
- **关联提示词**：PR-0381

## 现象（看到什么）

用户报「密码确认后有时候无连接反应」。标题停在「正在连接 X…」转圈，10 秒后报
「连接失败 X（特定的网络不可用）」；而同一份 profile 用 `netsh wlan connect` 立刻就能连上。

## 复现（怎么稳定重现）

在 `WlanConnect` 之前插一次 `WlanScan`，再隔 1.2 秒下发连接：通知里会出现
`reason=294917 动态密钥交换未能在配置的时间范围内成功`（四次握手超时），随后兜底成
「特定的网络不可用」。去掉这次预扫描 → 同一网络 3.1 秒连上。

## 根因（真正的原因）

扫频要占用射频，扫描没结束时发起的关联会在四次握手阶段被拖过 AP 的超时窗口；
上层只看到"连不上"，很容易误判成信号/密码/AP 问题。

## 修复（做了什么）

删掉 `WlanConnect` 前的 `WlanScan`，直接下发；并保证真接口里所有 early-return 都调
`try_fail`（否则转圈会一直挂着）。密码侧补长度判断（8~64），短口令在本地就拦住。

## 证据（数字 / 命令输出）

`netsh` 连同一网络：8001 成功；带预扫描 → `动态密钥交换…超时`；去掉后 app：
`[REACH] … 文案=已连接 yjt_dev_2.4G`（3.1s）、`[REACH] … 文案=已连接 YJT-1号楼办公`（3.5s）；
`[NAV] PASS 60 / FAIL 0`；短密码反向测试 rc=1、3 条红。

## 沉淀（新增断言 / 案例 / 文档）

**"扫描/探测"与"连接"是互斥的射频阶段**：任何在连之前顺手刷一次缓存的写法，都可能把握手拖超时；
失败文案会退化成"网络不可用"，掩盖真正原因（握手超时）。诊断时优先看 ACM 通知的 reason，
它比 event log 的兜底文案精确。
