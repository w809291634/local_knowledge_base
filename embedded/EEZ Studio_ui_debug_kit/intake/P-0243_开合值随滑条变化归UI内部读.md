# P-0243 开合值随滑条变化：归 UI 内部读（in_read），不是静态/外部读

> **检索别名**：开合 70% 分类 / in_read / UI 自己控制 / 滑条联动值 /
> 批注改错了 / 开合度。

- **时间**：2026-11-05
- **工程**：`w78-tabview-smart-home`
- **触发**：用户纠正：开合会随进度条变化，应属于 UI 自己控制，不能当静态文本。

## 分类修正

- `开合 70%`（客厅/主卧/窗帘详情/全部设备）与窗帘详情的 `70%`：
  - 恢复为控件行，类别 `uivalue` → `io_of` 映射 **`in_read`**（内部读，`r` 码）；
  - EEZ 里仍是真实 Label；滑条仍为 `out_write`。
- `1080P · 已加密`（客厅）保持静态文本，不恢复。
- 设计帧文字不变；静态标签改由 value Label 承载，避免重复。

## 实现

- `values.py`：`UI_READ`（窗帘详情 70%）+ `UI_READ_SUB`（含“开合 70%”）→ cat=`uivalue`。
- `overview_pro.io_of`：`uivalue → in_read`（先于 value/out_read）。
- `eez_gen.widget_kind`：value/uivalue → label。
- `control_table`：新增「UI 读数」类。
- H5 ANN_KEY 仍为 v2（旧批注不回显）。

## 结果

- 控件行 276 → **281**；H5 里 5 条 `开合 70%`/`70%` 均为 `in_read`；
  客厅 `1080P · 已加密` 仍是静态文本。
- A1–A12 PASS；PC 仿真构建通过；ESP32 `-O2` 只编译 442KB。
