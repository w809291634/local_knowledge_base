# P-0205 · 生成链把用户在 EEZ 里手改的工程覆盖了："出码≠设计源"要先分清是谁过期

- **工程**：app-wifi-scan-conn-no-flow
- **日期**：2026-10-25
- **工具**：Qoder
- **状态**：fixed
- **标签**：生成链,覆盖,EEZ手改,门禁判据,备份
- **关联提示词**：PR-0378

## 现象（看到什么）

④A 几何门禁报"出码≠设计源"（`pwd_ta` 高 35/36、`kb_main` y 86/92 等）。我按"生成物过期"处理，
跑了 `build_example.py → cli_build → gen_font`，把用户在 EEZ Studio 里手工调过的界面覆盖掉。
用户随后指出"我之前修改了一个版本，你又覆盖了"。

## 复现（怎么稳定重现）

在 EEZ Studio 里挪一个控件并保存（此时 `.eez-project` 与 `src/ui` 新、`build_example.py` 旧），
然后跑生成链——覆盖即发生。事后 `git log -- src/ui/screens.c` 能看到用户手改那次提交，
但我当时没查就下了"过期"的结论。

## 根因（真正的原因）

"出码≠设计源"只说明两边不一致，**不说明谁对**。本项目有两条写入路径（生成器 / EEZ 手工），
门禁只对比数值，没有"哪边更新"的信息；而我默认了"生成器是唯一真值"。

## 修复（做了什么）

1. 从用户手改那次提交恢复 `.eez-project` 与 `src/ui`（`git checkout <commit> -- …`）；
2. 把 EEZ 手改逐项回写到 `build_example.py`（几何常量 + 按钮描边 + 左内边距）与
   `mockup_gen.py` 共享常量；重生成后做**顺序无关的语义比对**：27 个对象的 pos/size/样式全等
   （只有 3 行描边属性书写顺序不同，值相同）；
3. `build_example.py` 覆盖前自动备份到 `tmp/eez_backup/<时间戳>-*.eez-project`；
4. 文档写死判据：先看 git 提交与常量差异，**只有一边有改动时以那边为准，回写另一边**。

## 证据（数字 / 命令输出）

恢复后 `pwd_ta` 364×35、`kb_main` (8,86) 回到用户值；
`diff tmp/screens_user.c src/ui/screens.c` 只剩属性顺序；
语义比对输出 `对象数：user=27 now=27；样式/几何不一致的对象：0`；
生成时打印 `backup : …	mp\eez_backup61025-022302-*.eez-project`。

## 沉淀（新增断言 / 案例 / 文档）

- 覆盖式生成前必须有备份（哪怕用户没要）；
- 门禁只报"不一致"时，**判据要包含"哪边带有人工改动"**（git 提交/文件新旧），别默认生成器正确；
- 用户手改 EEZ 后，正确的后续动作是"回写设计源"，不是"重跑覆盖"。
