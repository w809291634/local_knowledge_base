# P-0230 设计标注的控件在 EEZ 里只有透明容器：74 个交互件是假的

> **检索别名**：假控件 / 透明容器冒充 / 开关没有真控件 / 滑条是画上去的 /
> 按钮不是 Button / A12 / 标注控件必须真实建立 / EEZ 控件类型。

- **时间**：2026-11-05
- **工程**：`w78-tabview-smart-home`（24 屏，171 条控件标注）
- **触发**：用户检查 EEZ 工程发现设计图标注的很多控件在工程里不存在。

## 现象与量化

设计源 171 行控件，生成工程后按类型对账：

| 标注类别 | 实际生成 | 数量 |
|---|---|---|
| toggle | LVGLContainerWidget（透明容器） | 28 |
| slider | LVGLContainerWidget | 8 |
| scene（动作按钮） | LVGLContainerWidget | 38 |
| read（搜索框/设备名） | LVGLContainerWidget | 2（应为 Textarea） |

合计 **76 个标注控件没有真实物化**。`eez_check` 原有 A2 只核对“同框控件存在”，
容器也算存在，所以门禁一直 PASS——这是漏检根因。

生成器原逻辑：只有“窄的 nav/back”做真按钮，其余一律 `make_container()`；
开关/滑条/动作按钮的设计图形则作为装饰矩形画上去，看起来像控件、实际不可交互。

## 修复

1. `widget_kind()` 单一映射：toggle→Switch、slider→Slider、动作/跳转→Button、
   输入→Textarea、进度→Bar、图表→Chart、宽卡片→Container。
2. 整卡交互区（房间格）用“容器 + 卡内真控件”：子控件坐标**相对父对象**；
   开关/滑条几何从设计帧里的轨道矩形反推（找不到再用右下角兜底）。
3. 开关初值：读设计里旋钮位置，开→`states:"CHECKED"`（EEZ 会生成
   `LV_STATE_CHECKED`，不能写全名，否则生成 `LV_STATE_LV_STATE_CHECKED`）。
4. 已物化控件框内的设计图形（按钮底、开关轨道、滑条轨道、进度条）不再重复画装饰层。
5. 按钮内除“按钮文案”外的文字（角标、副标题）仍保留为标签，不能整框跳过（D2 会掉字）。
6. `eez_check` 新增 **A12**：逐行核对标注类别 ↔ 实际控件类型；整卡交互区核对
   “容器 + 卡内真 Switch/Slider”。Wi-Fi 页单独核对 list/textarea/keyboard/button 类型。

## 结果

- 工程控件 762 → **814**（新增真开关/滑条/输入/图表/进度及卡内子控件）。
- 实际类型：28 Switch、8 Slider、3 Chart、1 Bar、3 Textarea、其余 Button/Container。
- `eez_check` A1–A12 **PASS**；导航 AUTOTEST **72/72 PASS**。
- D5 当前 **平均 97.85%**（最低 92.42% 添加设备·配网中；旧确认 98.53% 已过期，需重新确认）。
- 资源估算：ESP32 `-O2` 只编译 **442KB（字体 236KB）**；PC 479KB。
- 证据图：`designer_annotated/sim_controls_{living,detail_light,settings,devices,energy}.png`。

## 坑

- 子控件坐标是**父对象相对坐标**；把设计绝对坐标直接塞进卡内子控件会跑到卡外（本轮实测整屏白块）。
- `states` 只写状态名（`CHECKED`），EEZ 自己加 `LV_STATE_` 前缀。
- A2 的“按框存在”不等于“类型对”；必须有 A12，否则容器可长期冒充。
