# P-0222 · 精灵动图底图没跳过精灵控件，第 1 帧起"两个人重叠"；坐标两套值致预览与动图不一致

- **工程**：watch2
- **日期**：2026-10-30
- **工具**：Qoder
- **状态**：fixed
- **标签**：精灵,动图,GIF,合成,幽灵像素,单一真值,门禁,圆屏表圈
- **关联提示词**：PR-0406

## 现象（看到什么）

运动页跑动 GIF 从第 1 帧起画面里有两个人叠着（用户："运动小人和背景图片中的人重叠了"）。
此前一轮用户报"预览图和动图效果不一致"：设计 PNG 的小人在 y=38/68px，动图口径在 y=52/68px。

## 复现（怎么稳定重现）

`design_sprite.page_with` 用 `compose_page(page)` 整页当每帧底图，而整页里含精灵控件（画第 0 帧）；
后续帧再 paste 动帧 → 静态第 0 帧永远留在背景。抽 GIF 第 6/12 帧放大即见双人。
坐标漂移：控件 x/y/size 写在 PAGES，anchor 写在 SPRITES，两处各改各的。

## 根因（真正的原因）

底图与动帧共用同一控件像素却没有互斥；坐标存在两套真值，没有渲染期断言把它们钉死。

## 修复（改了什么）

- `page_with`：`compose_page(page, skip_ids=(精灵控件 id,))` 后再逐帧 paste。
- `design_view._check_sprite_overlap` 加两道门禁：控件值 != SPRITES anchor_pick 值 → 漂移告警；
  bbox 四角越出内圈安全半径（屏心−8）→ "骑在表圈"告警。
- `page_with` 加幽灵像素门禁：数底图精灵区内染色像素（取染色列的不透明众数色，别取透明角像素——
  LANCZOS 缩放后透明角 RGB 归零，会和黑底假匹配）。

## 证据（数字）

- 反向测试：不 skip 时幽灵像素 460 检出；skip 后 0、渲染零告警。
- 表圈/标题间隙：52px @ (233,46)，上离表圈 16px、下离标题 15px；3× 放大逐帧目检单人。
- 52px 后 Flash 预算 RGB565 100 KB / 8bit 索引 69 KB（64px 时 152/95 KB）。
