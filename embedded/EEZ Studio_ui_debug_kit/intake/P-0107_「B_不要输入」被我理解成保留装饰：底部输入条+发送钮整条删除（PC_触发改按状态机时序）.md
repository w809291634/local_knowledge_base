# P-0107 · 「B 不要输入」被我理解成保留装饰：底部输入条+发送钮整条删除（PC 触发改按状态机时序）

- **工程**：eez-test
- **日期**：2026-10-03
- **工具**：Qoder
- **状态**：fixed
- **标签**：对话页,输入框,发送钮,装饰,需求理解,PC触发时序,走路器
- **关联提示词**：PR-0161

## 现象（看到什么）

对话页底部一条「说点什么，或按住说话…」输入条 + 一个发送圆钮：输入框只是 box+静态 label（不是 textarea），发送在真机什么都不做 —— 纯装饰，且 PC 有点而真机没有（两边行为不一致）

## 复现（怎么稳定重现）

真机点发送钮：APP_OUT_CHAT_SEND → io_chat_send 只打一行 TODO 日志。PC 点同一钮会追加假消息 + 2s 后假回复 —— 同一个控件两边行为不同，本身就是「仿真优先」被破坏

## 根因（真正的原因）

需求理解错：用户 2026-10-03 的四条裁决里 B 条原话是「不要输入」，我落成「不做输入功能、但把输入条和发送钮留成装饰」，还把这个错误口径写进了工程日志（2026-10-03.md:673「输入框/发送键在真机是装饰…这是用户接受的口径」）—— 用户从未接受，只是没逐条反驳。⇒ 教训：把「不做 X」听成「保留 X 的壳」是擅自扩范围，含糊裁决要回问一句

## 修复（做了什么）

DSL 侧（不手改 src/ui）：pane_chat 删 input_bar + send_fab 两段，返回 [hdr, cc]；chat_h 由 IN_H-hdr_h-inp_h-2*GAP 改成 IN_H-hdr_h-GAP（消息区吃掉腾出的高度）；PAGE_ROLES["AiChat"] 去掉两个角色；EXPLICIT_SHORT 去掉 input_bar/send_fab 两条死映射；native 变量表删 chat_send。native 侧连带删死链：APP_OUT_CHAT_SEND 枚举、app_model.cpp 的 case、action_chat_send、io_iface.h 声明、io_esp/io_pc 两份 io_chat_send 实现。PC 触发改法（删钮后消息从哪来）：io_pc 假状态机在 2->3（收音结束）投 stt 文本、隔 FAKE_CHAT_REPLY_SEC 投 tts 长回复，两条都走 chat_q_push；走路器 chataudit 去掉 mousef m_ic_send，改成 wait 8000 / wait 3000 两段
