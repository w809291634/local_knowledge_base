# P-0102 · app 分区余量被字库吃光：16MB 布局改 32MB（分区表一变必须整机重烧）

- **工程**：eez-test
- **日期**：2026-10-03
- **工具**：Qoder
- **状态**：fixed
- **标签**：partitions.csv,flash,ESPTOOLPY_FLASHSIZE,OTA,整机重烧,余量
- **关联提示词**：PR-0136

## 现象（看到什么）

13px 补完整字库后 bin 预计约 4.09MB，而 ota_0/1 = 0x3F0000 = 4,128,768 字节，余量只剩约 4 万字节，下一次加功能就会溢。

## 复现（怎么稳定重现）

（待补）

## 根因（真正的原因）

物理 flash 本来就是 32MB（开机日志：Detected size(32768k) larger than the size in the binary image header(16384k). Using the size in the binary image header.），但 sdkconfig/defaults 一直写 16MB，分区按 16MB 摆。

## 修复（做了什么）

partitions.csv 改 32MB 布局：ota_0/ota_1 各 0x800000（8MB）、assets 8MB 挪到 0x1020000（总用 24.1MB，剩 6.8MB）；sdkconfig 与 sdkconfig.defaults 同时改 CONFIG_ESPTOOLPY_FLASHSIZE_32MB=y 与 FLASHSIZE="32MB"。nvs/otadata/phy_init 偏移未动 => 已配网络与设置不被清。assets 落盘走 esptool_py_flash_to_partition(flash "assets" ...) 按标签，不写死偏移，所以挪地址安全。

## 证据（数字 / 命令输出）

实测 bin 3,686,768 字节 + 字库约 400KB；分区余量从 431KB 变 8MB 槽。

## 沉淀（新增断言 / 案例 / 文档）

MEMORY.md：改 app 体积前先量分区余量；改分区表要标注「整机重烧」
