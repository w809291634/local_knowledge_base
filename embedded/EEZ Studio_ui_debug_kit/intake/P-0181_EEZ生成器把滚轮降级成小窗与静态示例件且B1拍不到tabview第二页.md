# P-0181 · EEZ 生成器把"滚轮"降级成小窗+静态示例件；B1 画布核对结构性拍不到 tabview 第二页

- **工程**：D:\temp_d\AI_Temporary_Reply\watch
- **日期**：2026-10-23
- **工具**：Qoder
- **状态**：fixed
- **标签**：applist,Rxroller,滚轮,生成器,静态示例件,tabview,tab1漏拍,B1盲区,落点标定,负坐标哨兵,ANIM_OFF

## 现象（看到什么）

④⑤ 两站都"全绿"之后，用户一眼看出 `applist` 屏"完全不对"：仿真截图里整排图标贴左边界被切一半、
文字竖着叠、中间还浮着一个大图标。而 B1 对照图当时根本没出现这一屏，B2 拼图我肉眼扫过写了"逐屏一致"。

## 根因（三条独立成因，都要记）

1. **生成器降级**：设计源 `roller` 控件在 `build_watch_ui.py` 里被展开成
   `container(118,132,250,292)` 小窗 + 一个**静态示例图标/标签**（画焦点行用的），
   弧形剖面公式 `roller_rows()` 只喂给 `design_view.py` 画图，native 又往小窗里塞 14 行 flex 直列。
   LVGL 9 把子对象无条件裁到父边界 ⇒ 上下行全被切（=参考工程 FIXLOG FX-004 同款）。
2. **B1 结构性漏拍**：`eez_b1_shots.py` 把 applist 从待拍页里剔掉，还拿"tab_main 画布 ↔ applist 设计图"凑对；
   而 tab_main 打开停在 tab0 表盘 ⇒ applist 内容从没被渲染过，这一屏在 ④ 站等于没核。
3. **B2 肉眼放水**：B2 只机检"整屏墨量 <1% 算空屏"，被裁一半的屏照样有墨 ⇒ 判据太弱，我看拼图时又误判通过。

移植 Rxroller（上游 rxwind7/Rxroller）后又翻出三个坑，全部实证：
- 上游 `ANIM_OFF` 分支用 `(center+t)%count` 找步数 ⇒ 线性滚轮**只能往前走**，13→5 被算成 +6 再被 clamp 夹住，中心纹丝不动。
- 落点标定只在 create 跑一次，而那时宿主还在**隐藏的 tab 页**里 ⇒ `lv_obj_get_coords` 给的是未布局假坐标
  （行 x=980，显示后真值 0），算出的 pad 全错。
- 标定沿用"返回值 <0 即测量失败"的哨兵 ⇒ 图标中心没标定时本来就是负数（实测 -161），
  于是静默放弃校正，越修越看不见。

## 修复

- 生成器：`roller` 只出**全屏宿主**（0,0,466×466），删静态示例件；行全部由 native 建。
- 参数唯一出处改到 `src/native/watch_list_config.h`，`design_source.py` 经 `design/wconfig.py` 读它
  ⇒ 设计图剖面与 native 滚轮不可能分叉（中心档取 100%：位图原生 90px，中心行 1:1 不糊）。
- 移植件与差异账单：`PORTLOG.md`（上游 commit/SHA256、补丁 #15 带符号行差、D1~D5 口径差异）。
- 标定：读数前先 `lv_obj_update_layout`；失败判定改用 `center_icon_rect()` 的 bool 而不是"<0"；
  每拍（60ms）幂等校验 + 瞬时定位当场同步校验。
- 门禁：C 层新增 3 条滚轮断言（14 行逐行可居中 / 中心行落点=屏 38%·42% / 缩放剖面 256·221·186·151）；
  B2 加 6×6 分块墨量差判据（阈值 0.055，标定 max=0.0442，反向测试四类故障 0.0699~0.1693 全报警）。

## 防再犯

1. **设计源里"只用于画图"的公式，必须同时是生成代码的输入**；否则设计图与工程各说各话。
   判据：生成器里出现写死像素（`118,132,250,292`）就是分叉信号。
2. **tabview / 分页容器的每一页都要有独立截图路径**（改属性生成变体工程再截），
   拿"父页画布"对"子页设计图"＝没核。
3. **观感核对必须有量化判据 + 反向测试**：只检空屏的阈值等于没检；阈值要用当前全绿分布与故障态分布卡中间，
   并把两组数字写进代码注释。
4. 移植件里"负数当失败"的哨兵要当 bug 看：坐标类返回值可为负。
5. 没被证实的补丁不留（本轮试过一条 ANIM_OFF 前 `lv_anim_del`，实测与本例无关，已撤）。
