# P-0002 · tab_bar 模板默认值导致 A5 误报/静默失效

- **工程**：spilcd_spiopt_eez_lv_port_pc_tem_atks3 / main/test（ui_debug_kit 工具链）
- **日期**：2026-09-23
- **工具**：WorkBuddy
- **状态**：fixed
- **标签**：工具缺陷,配置陷阱,可移植性
- **关联提示词**：PR-0018

## 现象（看到什么）

`config.template.json` 里 `checks.tab_bar = { "y": 0, "h": 0, "w": 0 }`。
新工程照抄模板、忘了改这一项时，`audit_ui` 的 A5（底栏侵占）会去**找一个 y=0 的容器**
（通常是页根或顶栏）当底栏 —— 要么把页面下方元素全判成"压进底栏"（误报），
要么因把页根当底栏而整段跳过（静默失效）。

## 复现（怎么稳定重现）

配一份 `checks.tab_bar = {y:0,h:0,w:0}` 的配置（即模板默认值），跑：

```bash
python tools/audit_ui.py A5
```

`tabbar_rule()` 只要发现 dict 里有 `y` 键就认为"配了底栏"，于是按 y=0 去匹配。

## 根因（真正的原因）

用"键存在与否"判断"是否配置"，而模板必须给出字段**形状**（否则用户不知道该填什么），
于是把占位值 `0` 也当成了真配置。**"未配置"与"配了个 0"没有区分开。**

## 修复（做了什么）

- `tools/audit_ui.py` 的 `tabbar_rule()`：`y <= 0` 一律视为**未配置**（底栏不可能从 y=0 开始），返回 None
- `config.template.json`：`tab_bar` 默认改为 `null`
- `tools/gen_clicks.py`：改为复用 `audit_ui.tabbar_rule()`，不再各写一份判断（避免两处漂移）
- `CONFIG.md`：注明"须 `y>0` 才生效；不配 / null / y<=0 一律视为无底栏"

## 证据（数字 / 命令输出）

- 本工程 `tab_bar = {y:204,h:36,w:320}`（>0）→ 改后 A5 仍报 `1 处重叠`（Playlist），与改前一致，无回归
- `gen_clicks.py` 仍产出 `25 个按钮 + 13 屏不可达`，与改前一致
