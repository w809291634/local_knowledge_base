# P-0144 · LVGL image 对象框小于源图 = 静默切割（源图按原生尺寸绘制、被对象框裁掉，构建 0 错 0 警）

- **工程**：watch (Design Watch)
- **日期**：2026-10-18
- **工具**：Qoder
- **状态**：fixed
- **标签**：lvgl,image,裁剪,对象尺寸,静默,codegen,截图验收
- **关联提示词**：PR-0242

## 现象（看到什么）

心率功能页大红心下缘"明显被切割"（心尖切平，用户附截图）。工程模型里对象
`image(236,182,'g_hr_big',40)`——但 g_hr_big 源图 90×90（墨迹 y28..70）。
EEZ 构建 0 错 0 警，Run 预览与仿真一致地切。

## 根因（真正的原因）

LVGL 9 的 lv_image **不会把源图缩放进对象框**：源按原生像素绘制，对象框只当裁剪窗。
框 40×40 时可见区=源左上 40×40（EEZ 居中偏移后≈y 到 40 为止）→ 心尖（y 41..70）整段丢失。
"对象 size 参数"与"源图尺寸"不匹配 = 静默视觉 bug，编辑器/构建器全程无感。

## 修复（做了什么）

对象改原生 90×90、pivot 中心 (45,45)，位置按"墨迹中心保持原视觉锚点"换算
（x213,y157 → 墨迹中心 257.5,206 仍在 bpm 正下方）。生成器全表扫描 image() 的
size≠源图清单：仅 g_chev(34→30)/g_gear(52→46) 两处，按墨迹核算均在框内无可见
切割，保持不动（改动最小化）。

## 证据（数字 / 命令输出）

修复前仿真红墨带高 27px（平顶）；修复后 y186..225 高 40px（尖端回归，
tmp39/heart41.png）。hearttest 回归 ALL PASS。

## 沉淀（新增断言 / 案例 / 文档）

判据入 skills §11.42 附注：**给 image 控件定尺寸必须 ≥ 源图原生尺寸**（想缩小显示
要用 transform_scale，不是改对象框）；新页面接大位图时生成器可加
"size<源图" 断言扫描（本次已用同款脚本手查全表）。报告 §41。
