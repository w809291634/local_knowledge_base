# P-0196 · 后端能真动宿主系统后，门禁必须显式摘掉那个开关（并把摘除本身打印出来）

- **工程**：app-wifi-scan-conn-no-flow（PC 仿真接 wlanapi）
- **日期**：2026-10-24
- **工具**：Qoder
- **状态**：fixed
- **标签**：无头验证,门禁,真接口,可复现性,环境变量
- **关联提示词**：PR-0365

## 现象（看到什么）

`platform/pc` 加了真接口实现（WlanScan / WlanConnect / WlanDeleteProfile）之后，
`preflight --with-sim` 的 `[NAV]` 断言与六屏出图跑的还是同一个 exe——
一旦真接口成为默认路径，每跑一次门禁就会真的连一次网、真的删一次系统里存的 WiFi 密码，
而且断言依据（附近有哪些网、谁已连接）每次都不一样。

## 复现（怎么稳定重现）

把 `io_init()` 里 `if (getenv("WIFI_PC_REAL"))` 的判据改成恒真，再跑
`python design/preflight.py --skip-cli --with-sim`：`[NAV]` 立刻从 30 PASS 变成
"找哪条行、连上没连上"全看当时空口环境，同一份代码两次跑分结果不同。

## 根因（真正的原因）

分层把硬件调用关在 `platform/` 里，但**运行时选哪份实现**这件事原本没有守门人：
`platform/pc` 内部同时存在"假世界"和"真接口"，谁被调用只取决于一个环境变量。
不显式声明"门禁环境里这个变量必须不存在"，就等于把宿主系统的副作用挂在了回归链上。

## 修复（做了什么）

1. `io_init()` 决定走哪份实现，打不开无线接口（没网卡 / `wlansvc` 没起）就退回假表并打印原因；
2. 门禁与出图（`preflight.py:check_nav()`、`design/shot_states.py:run_exe()`）**把"走哪个后端"
   写死**，并打印 `OK 门禁已强制假世界（WIFI_PC_FAKE=1），真接口不会被触发`——
   关键是这件事**可见**，不是默默继承环境；
3. 真接口取证走独立入口：`WIFI_AUTOSCAN=1 WIFI_REACH=connect WIFI_AUTOEXIT=1`。

★ 本条写完当天方向就翻了一次：用户定了「双击 `run_sim.bat` 默认走真接口」，
于是假世界改成 `WIFI_PC_FAKE=1` 才走，门禁从「pop 掉开关」改成「主动设反向开关」。
**结论不变、手段要跟着换**：默认值越靠近"会动宿主"，门禁就越要显式钉死另一端，
而且钉死这件事必须打印出来——只靠"默认是安全的"迟早被一次默认值翻转破掉。

## 证据（数字 / 命令输出）

默认门禁：`[NAV] RESULT: PASS 30 / FAIL 0`、`PREFLIGHT PASS`（真接口开关不存在）；
真接口一次跑：`[WIN] query: 8 个网络` → `[WIN] WlanConnect 已下发：YJT-1号楼办公` →
`[REACH] connect 目标=YJT-1号楼办公 文案=已连接 YJT-1号楼办公`，
`netsh wlan show interfaces` 独立回读 `状态: 已连接`。

## 沉淀（新增断言 / 案例 / 文档）

与「无头 GUI 夹具要摘掉真实输入」同源：**任何会动宿主（网卡、串口、文件系统、注册表）的
后端开关，都要在门禁里显式摘除，并把摘除打印成一行可反查的输出**。
本工程另加一条静态门禁：`硬件符号不外溢`（`Wlan/esp_wifi/nvs_` 只许出现在 `platform/`），
已反向测试（在 widgets 里塞一个 `WlanConnect` 字样 → rc=1 并点名文件）。
