## 0. 总则：验证优先级金字塔（EEZ 为主，仿真为辅）

**一句话（2026-10-22 用户补充静动分界）：静态的图片和文字效果，以 EEZ 里看到的为准；动态的效果，以仿真器为主；真机负责终验。**

| 验证对象 | 第一现场（主） | 辅助（次） | 终验 |
| --- | --- | --- | --- |
| 视觉 / 布局（**静态**：图片、文字效果、排版） | EEZ 编辑器画布（工程模型原生渲染） | 仿真出图（像素对照、批量回归） | 真机 |
| **动态效果**（动画/滚动/帧序/跟手节奏） | **仿真器**（逐帧/量化对照；EEZ Run 的节奏与帧序不可信，且 Run 输入通道不产生 GESTURE，见 P-0141/P-0149） | EEZ Run 粗看通路 | 真机 |
| 交互（点击/跳转/状态） | **EEZ Run 模式（F5）** —— 真运行时、可点可滑 | 仿真器脚本化（数值化，如拖拽位移 Δ） | 真机 |
| 生成代码语义 | EEZ GUI Check/Build 或 headless CLI（二者语义一致，可互换） | 门禁断言 | 真机 |
| 数值回归 / CI | — | 仿真快照 MD5、断言集 | — |

零号铁律（用户 2026-10-17 明令，对所有 AI 生效，工程侧已钉进 `Design Watch/AGENTS.md`）：

0. **★ EEZ 优先——能在 EEZ 里实现的，必须在 EEZ 里实现。** 界面内容、控件联动、动效
   （缩放/弧线/旋转/搏动/透明度/图标内容动画……）一律走 EEZ 工程模型 + flow 动作组；
   **用户代码（src/native C）只允许用于控制外部硬件**。判"EEZ 做不到"前必须四面对查
   （事件面/A43 动作面/Loop+Delay 调度面/运行时源码面，见 §11.37 一），查完仍不行
   **必须通知用户**说明原因，得到同意才可出 EEZ。历史教训：native 滚轮"例外"曾被
   四面对查翻案（P-0131），提前下结论=返工。

其余纪律：

1. **改动只落设计源 / 生成器 / EEZ 工程**；`src/ui` 是覆盖式重写的只读产物（沿用 kit 最高优先级铁律）。
2. **编辑器画布没有输入**（skills §7.1）；要"在 EEZ 里点得动"，用 **Run 模式** —— 勿混淆这两个面。
3. **每层能证明什么要写清**：画布证明**静态**观感与工程模型；**动态效果以仿真的逐帧/量化判定为准**（§0 静动分界）；Run 证明交互通路与工程语义；真机证明物理/性能/手感。
4. **留痕**：提示词与问题按 `INTAKE.md` 规约记录（本文件即 PR-0210 的沉淀）。
5. **精灵动图交付前跑自检索引表**（NO_FLOW §2.0b）：逐条门禁全绿 + 三帧目检证据才交付；
   规则索引在 `ANIMATION_ASSETS.md` §6，本文件不复述。
6. **★ 默认只跑 EEZ 侧闭环，仿真器要等点名（用户 2026-10-17 明令，PR-0224）**：
   日常 UI 调整（布局参数、样式、动效曲线等）的缺省链路 =
   `生成器改 → build_watch_ui → eez_build → 烘字体 → 关闭工程重开 → EEZ 编辑器/Run 看一眼`，**到此为止**；
   **不**自动跑 sim_capture / L4 / dragtest / PC_SIM 重建。
   只有用户明说"要仿真/跑仿真/出图对照"时才进入仿真侧。
   代价与义务：跳过仿真时，与仿真断言耦合的东西（L4 期望值、dragtest 夹具坐标）可能失真——
   **必须在设计源注释里留下"下次跑仿真前需同步"清单**（例：AppList top0 120→0 时
   peak_row 期望与夹具行心），且交付说明里讲清"本次未经仿真量化验证"。
   **2026-10-22 澄清（用户定夺）**：「设计核对阶段仿真默认跑」属于 **no flow** 流程
   （其 §7 D⑤，见 `EEZ_FIRST_WORKFLOW_NO_FLOW.md`）；**本方式（flow）仍维持仿真器点名才跑**（2026-10-17 明令不变）。

## 1. 框架方案（从样板工程提炼，可整体移植）

### 1.1 目录分层

```
<固件工程>/                      ← IDF 工程根（build 目录在这）
├── main/                       板级胶水
├── components/                 板级组件（bsp / 显示 / 内存 …）
└── <ui工程>/  (eez-test/ 或 watch/)
    ├── xxx.eez-project         ★ EEZ 工程文件 —— UI 的真值
    ├── xxx.eez-project-ui-state   编辑器界面状态（不参与构建）
    ├── ui_debug_kit.config.json   工程侧配置（设计源路径 / 屏幕 / 字体 / 门禁挂载）
    ├── designer/               【给人看】效果图唯一真值（与实现不一致时改设计源）
    ├── design/                 【给机器】设计源 + 工具链
    │   ├── build_ui.py          唯一设计源（DSL 构建脚本；或等价生成器）
    │   ├── json2eez.py          DSL → EEZ 工程（与"生成器直出 EEZ JSON"二选一）
    │   ├── eez_build.py         EEZ headless CLI 构建
    │   ├── eez_font_engine.py / gen_fonts.py    字体烘焙与校验
    │   ├── sim.py               仿真器编译 + 逐屏截图（+ 对照）
    │   ├── compare.py           仿真图 vs 效果图对照（兼任门禁）
    │   └── architecture/        框架文档（回调 / 变量 / 仿真硬件分层）
    ├── src/
    │   ├── ui/                  EEZ 生成代码（只读产物）
    │   └── native/              用户代码隔离层（手写）
    └── build/                   本地产物（截图 / 报告；gitignore）
```

**三条铁律**（样板工程原话，照用）：

1. `designer/` 是给人看的效果图、`design/` 是给机器用的设计源；两者不一致时，改设计源。
   **交付形态＝一张 `designer/_overview.svg` 总蓝图**（两种框架方式通用，细则见
   `EEZ_FIRST_WORKFLOW_NO_FLOW.md` §2.0；有动效就内嵌 `anim/<页>.gif`，浏览器打开会循环播放），
   散页 PNG 只作过程件与核对物。
2. `src/ui` 由 EEZ 导出（覆盖式重写），**不要手改**；逻辑一律进 `src/native`。
3. **界面只在设计源里定义一次**（build_ui.py 或其等价物）；效果图、EEZ 工程、C 代码、仿真全部由它派生。

### 1.2 隔离层（UI 与用户程序只见契约）—— 四层

```
生成层  src/ui/*         EEZ 生成，永远不手改；接缝 = native_vars[]（get_var_ / set_var_）
适配层  native_vars.cpp  薄转发（get/set → app_get_input_* / app_set_output）
契约层  app_model.h      共享状态 + 输出命令队列（UI 与逻辑的合同）
平台层  platform/io_pc.cpp ← PC 仿真（假数据） / io_esp.cpp ← 真机（真硬件）
```

**PC 与真机唯一差别是平台层的一个文件** —— 上面三层（含 UI）完全相同。变量契约要点：
输入 `get_var_`（state / 电量 / 时钟…）、输出 `set_var_` 命令（`_cmd` 后缀、脉冲语义）、
派生输入在 native 侧现算；变量挂 `variables.globalVariables`、类型用 `"integer"`（踩坑见 src/native/README）。

### 1.3 双环境编译

- 固件：`<ui工程>/src` 挂成 IDF 组件（ui → native 链接顺序坑见 skills §7.6）。
- 仿真：独立 port（PC_SIM 或独立沙箱目录），**单向同步**工程源码进去编译，不污染工程；
  工具链路径在工程的 kit 配置 `sim` 段（**每机必须问用户，禁止猜**）。
- 快照流水线：仿真 exe 支持"逐屏快照"模式（skills §5.6），出图后可做 MD5 / 对照回归。
- **截图验证默认无窗口**：`SIM_SHOT` 走内存 display，不建 SDL 窗口；`SIM_SHOT=all` 一个进程批量出图；
  只有交互运行或显式 `SIM_WINDOW=1` 才开窗（P-0219）。

## 2. 开发流程（主链七步；EEZ 看效果是主验收）

| 步 | 动什么 | 入口 / 命令 | 判据 | 常见坑 |
| --- | --- | --- | --- | --- |
| ① 改设计源 | `design/`（DSL 或生成器） | 编辑 build_ui.py 等 | — | 别手改 src/ui |
| ② 生成 | 生成器 → EEZ 工程 | `python design/build_ui.py` → 生成器 / json2eez | 工程 JSON 合法、页面/字体条目齐全 | 字体条目字段形态（§3.2） |
| ③ EEZ 构建 | 工程 → src/ui | GUI Check/Build **或** headless（`eez_build.py`） | 构建完成、连接检查无报错 | GUI 会重写 src/ui；CLI 不烘字体需单独烘 |
| ④ **EEZ 里看效果（主验收）** | — | 打开工程：画布核视觉；**Run（F5）核交互** | 观感 → 画布；点击/滑动 → Run 实测 | 画布无输入；见 §3 |
| ⑤ 仿真辅助 | 编译 + 出图 / 交互 | `python design/sim.py`；脚本化拖拽 | 出图齐全、与基线/对照一致 | tick 源、输入设备等（§3.4） |
| ⑥ 门禁 | 断言集 | `python tools/run_gate.py` | 全绿才提交 | 缺屏/超阈值会非 0 退出 |
| ⑦ 真机 | 烧录终验 | `idf.py flash monitor`（R 段条例） | 物理 / 性能 / 手感 | ①②证通路不证真值；`#if ESP_PLATFORM` 代码仿真编不到 |

**顺序纪律：④ 在 ⑤ 之前** —— EEZ 里不对，先回工程改，别先跑仿真绕开。

**收尾纪律（2026-10-25 用户定）**：每步 / 每条功能收尾时删掉过程文件（探针脚本、临时构建目录、一次性补丁、日志、对照中间件）；暂存只放工程 `tmp/` 并收尾清空，交付件只放正位。

## 3. EEZ 应用侧实测注意（2026-10-16 补充，源自 watch 工程排障）

### 3.1 Run 模式（F5）是可交互的运行时

- 入口：工具栏 `Edit / Run / Debug` 的 **Run**（title "Enter run mode (F5)"）；渲染到真实分辨率画布。
- 可自动驱动：CDP（`--remote-debugging-port=9222`）+ 注入真实鼠标事件；实测点击导航 ✓、拖拽滚动 ✓（工具见 §5）。
- ★ **CDP 注入两纪律（2026-10-17 实测）**：别发 F5（页面当刷新用，整 renderer 重载）——进 Run 点工具栏 **Run 按钮**；
  截图/点击坐标**每轮自量 canvas rect**（画布位置随窗口操作漂移，写死 clip 会截到编辑器画布，见 P-0139）。
- Run 吃**工程模型**（widgetFlags 等）；生成器重写 `.eez-project` 后，必须在 Studio 里关闭工程再重开，否则 Run 仍用旧内存版本（P-0217）。

### 3.2 字体条目形态影响应用侧（P-0125）

- 画布 / Run 的中文依赖"会话内字体提取"完成；**提取完成前必是豆腐块**（对照工程实测：成功通知出现后即时自愈）。
- ★ **决定性变量是「字体条目形态」**（2026-10-16 A/B/C 对照实测，见 P-0125）：条目必须是 EEZ 原生形态——
  `renderingEngine:'LVGL'` + **中文码位进 `lvglRanges`（数字表）** + `lvglGlyphs:{encodings,symbols}` + `glyphs:[]`；
  缺字段 → 画布/Run 豆腐 + 点 Fonts 面板崩，**只换字体文件无效**。方法出处：skills §3.3/D5 + §11.12。
- 字体**文件**与豆腐无关（受控实测：全量 simhei + 正确形态同样正常；换 `YaHei_Consolas_Hybrid.ttf` 是观感选择，140/140 码位核验）。
- 不存在"等待提取完成"的过程：**形态对 ≈2 分钟内即正常渲染、形态不对永远豆腐**（T1 受控等 6+ 分钟仍豆腐）。

### 3.3 会话状态损坏的恢复（P-0126）

- 症状：工程打不开（首页按钮无效 / 双击条目崩溃 / 带参启动停在首页）；工程文件本身无恙。
- 处置：备份并删除 `%APPDATA%/eezstudio` 的 `Local Storage` + `Session Storage`，重启即恢复。

### 3.4 GUI 与 headless 等效性 + 回归守卫

- GUI Check/Build 与 headless CLI 产物**语义一致**（本栈实测：GUI 重写 src/ui 后，出图与基线逐张 MD5 一致、回归断言与拖拽复测全过）。
- GUI 构建**会重写 `src/ui`**（正常行为）；重写后重跑 ⑤⑥ 再交付。

## 6. 一次到位提示词公式（2026-10-18 复盘 watch 全程返工史总结）

**返工主因不是 AI 能力，是提示词缺了五要素之一**。对照真实返工记录：
① 滚轮做成 native 例外被推翻（缺"约束面"）；② "弧度"两轮对不齐（缺"观感基准"）；
③ 磁吸做完才补"贴顶贴底"（缺"边界行为"）；④ 图标动画做完才下"严格执行"令（缺"验收面"）；
⑤ 丢帧三轮才给到 33fps（缺"量化阈值"）；⑥ AppList 有钮被裁掉（缺"交互方式"）。

**五元组模板（每条新需求按此写，缺项写"沿用 AGENTS.md"即可）**：

```
【目标】哪个页面/控件、出什么效果（一句话说清"变成什么样"）。
【口径】唯一真值来源（变量/数据从哪来、谁能改）；交互方式（钮/手势/点击，谁有什么没有）；
        边界行为（到顶到底到什么状态、极端值怎么走）。
【验收】量化判据（帧率/误差/尺寸等数字）+ 行为判据（进得去回得来/点了必有所去），
        点名必须过的门禁（如 nav_audit PASS、构建 0 错 0 警、可复现证据）。
【约束】EEZ-first 是否适用（默认适用，不必重写）；例外须先四面对查并报备。
【验证与归档】跑不跑仿真/出图（点名才跑）；完成后登记报告 §N + kit P-/PR-。
```

**观感类需求附加款**：形容词（弧度/高级/遮挡/不流畅）两轮对不上就改喂
"标注截图/参考视频/数值目标"，并让 AI 单参数迭代出图对照，禁连续猜第三轮。

**存量约定不复述**：AGENTS.md 铁律、nav_audit、B12 手册参数、§38 时钟口径等
已固化的内容，提示词里只需引用编号（"按 §38 口径""遵铁律⑤"），AI 会读工程
AGENTS.md 自动生效；复述反而制造新旧打架。
