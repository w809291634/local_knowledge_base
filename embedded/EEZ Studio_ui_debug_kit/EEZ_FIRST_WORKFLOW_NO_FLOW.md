## 0. 总则：验证优先级金字塔（静看 EEZ，动看仿真）

**求解顺序**：先查本地经验库（`local_knowledge_base/AGENTS.md` 入口表 + **`intake/index.md` 问题索引**
（一行一个 P-####，按现象/标签检索）+ grep kit/intake/reference），命中就照做；未命中再联网或试验，
解决后回写经验库。**不凭记忆重造方法。**

**Wi-Fi 列表/连接页**：直接移植 `reference/15` 的成熟结构（单页 + lv_list 动态行 + 密码半页 + 忘记对话框 +
busy 遮罩），不要拆成三屏、不要自造交互。

**问题索引维护**：修完新问题跑 `python tools/log_entry.py problem`（落 `intake/P-####` 并自动在
`intake/index.md` 追一行）；流程正文只留一条指针，不复制全文。

**一句话（2026-10-22 用户补充静动分界）：静态的图片和文字效果，以 EEZ 里看到的为准；动态的效果，以仿真器为主；真机负责终验。**

**配套一条（2026-11-04 用户定，PR-0468）：设计载体不做过渡动效。** H5 评审页/可点原型的页面切换一律直接换页；动效节奏只在仿真与真机上判，放进设计载体既拖慢核对、又会引入"旧帧没退场"这类假故障。

| 验证对象 | 第一现场（主） | 辅助（次） | 终验 |
| --- | --- | --- | --- |
| 视觉 / 布局（**静态**：图片、文字效果、排版） | EEZ 编辑器画布（工程模型原生渲染） | 仿真出图（像素对照、批量回归） | 真机 |
| **动态效果**（动画/滚动/帧序/跟手节奏） | **仿真器**（逐帧/量化对照；EEZ Run 的节奏与帧序不可信，且 Run 输入通道不产生 GESTURE，见 P-0141/P-0149） | EEZ Run 粗看通路 | 真机 |
| 交互（点击/跳转/状态） | **EEZ Run（F5）**：只验证原生控件自身的按压/勾选/滑动 | 仿真器脚本化（跳转与硬件动作只能在仿真/固件核，no-flow Run 不执行 native 绑定） | 真机 |
| 生成代码语义 | EEZ GUI Check/Build 或 headless CLI（二者语义一致，可互换） | 门禁断言 | 真机 |
| 数值回归 / CI | — | 仿真快照 MD5、断言集 | — |

**PC 仿真读数与文件系统（2026-11-07 落地，流程步骤见 §2 ⑤b）**：内部读（滑条/开关派生）由 `value_bind` 按控件值刷新，
初始化即对齐一次；外部读（温度/湿度/功率/电量/码率/告警）由 `sim_reads` 每秒模拟抖动，
开关派生状态每 100ms 刷新；ESP32 上 `sim_reads` 编译为空实现。
**文件系统**：`sim_fs` 把 `A:` 映射到工程根，仿真可直接 `A:/assets/xxx` 读写宿主文件
（真机换 FATFS/LittleFS，路径写法保持一致）；初始化顺序 `lv_init → sim_fs_init → ui_init`。
自证：`run_sim.bat fstest`（文件读取）、`simtest`（外部读在变）、`behaviortest`（控件联动）、`test`（导航）。

零号铁律（对所有 AI 生效；2026-10-22 用户定稿 no flow 分阶段口径）：

0. **★ EEZ 优先——预生成阶段，设计图中指定的控件必须由 EEZ 生成**，方便坐标定位、控件布局；`src/ui` 不可手改。
   **全功能补全阶段（§2 第⑦步），动态的（不是固定的）界面内容不必须用 EEZ，可以使用原生代码实现。**

其余纪律：

1. **改动只落设计源 / 生成器 / EEZ 工程**；`src/ui` 是覆盖式重写的只读产物（沿用 kit 最高优先级铁律）。
2. **编辑器画布没有输入**（skills §7.1）；要"在 EEZ 里点得动"，用 **Run 模式** —— 勿混淆这两个面。
3. **每层能证明什么要写清**：画布证明**静态**观感与工程模型；**动态效果以仿真的逐帧/量化判定为准**（§0 静动分界）；Run 证明交互通路与工程语义；真机证明物理/性能/手感。
   **几何同理**：生成码里的 `set_pos/set_size` 不等于渲染几何，控件构造函数会改写它（cases B16）。
   判"位置对不对"要量运行时绝对坐标（`lv_obj_get_coords` 探针），静态对账只当第一道筛。
4. **留痕**：提示词与问题按 `INTAKE.md` 规约记录（本文件即 PR-0210 的沉淀）。
5. **★ 仿真时机（no flow）**：设计核对（§2 第⑤步）仿真出图核对**默认必跑**；
   日常微调仍等用户点名"跑仿真/出图对照"才跑。跳过仿真时，设计源注释留
   "下次跑仿真前需同步"清单（L4 期望值、夹具坐标等），交付说明注明"本次未经仿真量化验证"。
   **动态效果的验收不受本条限制**（§0 静动分界：动态以仿真器为主）。

## 1. 框架方案（从样板工程提炼，可整体移植）

### 1.1 目录分层

```
<固件工程>/                      ← IDF 工程根（build 目录在这）
├── main/                       板级胶水
├── components/                 板级组件（bsp / 显示 / 内存 …）
└── <ui工程>/  (eez-test/ 或 watch/)
    ├── xxx.eez-project         ★ EEZ 工程文件 —— UI 的真值
    ├── xxx.eez-project-ui-state   编辑器界面状态（不参与构建）
    ├── ui_debug_kit.config.json   工程侧配置（设计源路径 / 屏幕 / 字体 / 门禁挂载）
    ├── designer/               【给人看】设计效果图（由 design_view.py 渲染，第①步用户确认的就是它）
    ├── design/                 【给机器】设计源 + 工具链
    │   ├── build_ui.py          唯一设计源（DSL 构建脚本；或等价生成器）
    │   ├── design_view.py       独立设计图脚本（读同一设计源，渲染效果图落 designer/）
    │   ├── json2eez.py          DSL → EEZ 工程（与"生成器直出 EEZ JSON"二选一）
    │   ├── eez_build.py         EEZ headless CLI 构建
    │   ├── eez_font_engine.py / gen_fonts.py    字体烘焙与校验
    │   ├── sim.py               仿真器编译 + 逐屏截图（+ 对照）
    │   ├── compare.py           仿真图 vs 效果图对照（兼任门禁）
    │   └── architecture/        框架文档（回调 / 业务逻辑 / 仿真硬件分层）
    ├── src/
    │   ├── ui/                  EEZ 生成代码（只读产物）
    │   └── native/              用户代码隔离层（手写）
    ├── build/                   本地产物（核对报告 / 定稿截图 / declared_manifest；gitignore）
└── tmp/                     ★ 核对过程临时件（探针截图 / crop 目检图 / pid / 拼版草图；gitignore，随手可清）
                              —— 用户 2026-10-23 令：过程件一律进 tmp/，交付件才进 designer/、
                              designer_annotated/ 等正位；拿不准当临时件放 tmp/
                              —— 补：**一次性补丁/探针脚本也算过程件**（放 tmp/，跑完即删），
                              不许落在工程根或 design/ 正位；仓库 .gitignore 已有 `tmp/` 通配。
                              —— 例外：**`tmp/sim_build_<工程名>`、`tmp/compile_cache` 是构建/编译缓存，
                              保留不删**（用户 2026-11-05 令；build 按工程命名，防多工程冲突）。
```

**三条铁律**（样板工程原话，照用）：

1. `designer/` 是给人看的设计图、`design/` 是给机器用的设计源；两者不一致时，改设计源。
2. `src/ui` 由 EEZ 导出（覆盖式重写），**不要手改**；功能逻辑一律进 `src/native`。
3. **界面只在设计源里定义一次**（build_ui.py 或其等价物）；**设计图与 EEZ 工程同源派生**——
   设计图由独立脚本 `design_view.py` 渲染（与工程生成脚本分离），第①步用户确认的即渲染结果，
   不满意就改设计源重渲染；确认后 C 代码、仿真出图再全部由设计源派生。

### 1.2 隔离层 —— 分层按方式分

`native_vars / app_model / io_pc / io_esp` 四层与 `get_var_/set_var_` 变量契约是 **flow 方式的结构**（见 `EEZ_FIRST_WORKFLOW_FLOW.md` §1.2）。
本方式（no flow）不用变量桥：`src/ui`（EEZ 生成、不手改）直接对接 native 的事件回调与业务代码；
平台层 `io_pc.cpp / io_esp.cpp` 视是否保留 PC 仿真决定去留——要仿真时，PC 与真机仍只差这一个文件。
框图（颜色=代码归属分区，每一跳带函数代码）：[按键→外部硬件](diagrams/01_按键控制外部硬件.svg) ｜ [按键→切换页面](diagrams/02_按键切换页面.svg)

### 1.2b 父子层口径（2026-10-23 用户定，长期要求）

EEZ 生成的永远是**父层**（底图 / 容器 / tab 页 / 全屏宿主）；native 追加的一切都是它的**子对象**，不许另立平级父层。
父层要铺满它该有的区域，子对象不得越出父边界——LVGL 9 无条件把子对象裁到父边界，越界＝看不见（FX-004 家族）。
**有例外必须先跟用户交互说明并登记本库**：例如滚轮轮根要靠负 padding 把内容摆到父边界之外、
全屏子对象与父级 tabview 拖动切页的归属冲突，都属这类，不许默默实现完就算数。

### 1.3 双环境编译

- 固件：`<ui工程>/src` 挂成 IDF 组件（ui → native 链接顺序坑见 skills §7.6）。
- 仿真：独立 port（PC_SIM 或独立沙箱目录），**单向同步**工程源码进去编译，不污染工程；
  工具链路径在工程的 kit 配置 `sim` 段（**每机必须问用户，禁止猜**）。
- 快照流水线：仿真 exe 支持"逐屏快照"模式（skills §5.6），出图后可做 MD5 / 对照回归。
- **截图验证默认无窗口**：`SIM_SHOT` 走内存 display，不建 SDL 窗口；`SIM_SHOT=all` 一个进程批量出图；
  只有交互运行或显式 `SIM_WINDOW=1` 才开窗（P-0219）。

## 2. 开发流程（七步主线 + ⑤b 独立步骤；② 包含控件标注与 H5 交互评审）

| 步 | 做什么 | 判据 / 规约 |
| --- | --- | --- |
| ① 设计图 | 用户提供；没有则由 AI 生成——先写设计源，**设计图由独立的设计图脚本从同一设计源渲染**（与 EEZ 工程生成脚本分离），**必须经用户确认核对后才算数**；**同时询问 UI 内存预算档位（200K/500K/1M/2M/4M 或实际值）并落 `design/mem_budget.json`**；**字号先定一套令牌（≤3 档，全工程共用）**，作为字号/动图规模的输入 | 效果图落 `designer/`；**交付形态＝评审页「高清设计图」页签（§2.0，H5 为主）**；可选另导 SVG（辅助/留档，不强制）；**先经用户确认**，确认通过后才进 ② 的控件标注与 H5 交互评审；**预算未确认不进入 ④ 预生成** |
| ② 控件标注与 H5 交互评审 | **第一步设计确认后**，基于同一设计源和 H5 评审页，AI 根据设计图推导并标注控件（含类型、数据流向、硬件动作、跳转目标和动态读数），由用户核对修正；**严格复用** `tools/h5_overview_template.py` 评审框架（完整参考 `reference/w78_h5_template/`）及三视图，按本节模板门禁验证。**分层总览**：点跳转标签定位目标、点页面卡片在右侧查看标注图与清单；**跳转演练**：直接点击设计帧上的真实跳转控件切页并可返回；**高清设计图**：默认显示全部控件序号和分类，可一键关闭。用户在 H5 中右键控件清单/标签或画面添加批注，导出 JSON；AI 根据批注改设计源并重新生成 H5。 | **统一交付工程内 `designer_simple/overview_pro.html`**，含分层总览、跳转演练、高清设计图、控件清单与批注导出；独立 SVG/PNG 标注图仅为可选留档。控件清单包括序号、名称、类型、作用、跳转目标和控件框；设备动态读数也要标注。目标页存在、非根页有权威入边且可返回（明确登记的状态页按状态页规则处理），导航门禁通过，并以真实浏览器点击验证；用户核对标注、跳转及批注结果后确认。未明确行为的对象须核实；确认无行为者按纯展示处理。详细要求见 §2.0c、§2.1、`reference/14`。 |
| ③ 框架确认 | 确认本工程走 **no flow**（本文件即此方式的流程）；若改选 **flow**，弃用本文件、转 `EEZ_FIRST_WORKFLOW_FLOW.md` 执行，结论写进工程文档 | 两种方式框架有区别，选型只在此一步定 |

**生成方式（2026-11-04 用户定，PR-0473~0475）：所有控件都按 EEZ 原生默认结构改，不是只按钮。**
**后续所有项目（no flow / flow）新建控件一律严格按模板库语法执行：先克隆模板 → 只改值 → 过 A14 字段集门禁；

新建控件一律从 `eez-widget-templates/templates/` 克隆；模板是 **EEZ UI 拖拽后保存的原始对象**，
`defaults.json` 由同一工程派生，**不是按 `classInfo` 复位**；`validate_templates.py` 逐字段/占位符/
defaults/manifest 校验。`tools/eez_defaults.py` 只用于从**已有工程**采自定义样板/做对照，
不再作为新建控件来源；冷门类型先在模板工程新增画布、拖入该控件、保存后重跑 `extract_templates.py`。
生成器只能"克隆默认 → 改几何/identifier/文本"，不许自己拼字段；字段对照见 `reference/07`。
**属性字段白名单（2026-11-06 用户定）**：可改字段一律以 **`reference/16_widget_properties.md`**
（36 类控件 + Screen 的全字段表，来自 EEZ 前端属性面板 classInfo × 官方手册 W 章节 × 模板落盘值三方核对）
为准；表里没有的字段不许写，Style 只写表内列出的 LVGL 样式属性。需要新字段时先在 EEZ UI 里把该属性改出来、
保存工程，再回填该表并重提模板，之后才允许出现在生成器里（详细步骤见 `reference/16_widget_properties.md` §6）。
**滑块/开关尺寸（LVGL 9.4 源码口径）**：旋钮直径＝控件高度＋KNOB 的 `pad_*`（`width/height` 不参与，EEZ 也不生成）；
轨道高＝控件高度－MAIN 上下 pad（上下相等才居中）。w78 配方：滑条高 20 + MAIN pad 7/7 → 6px 轨道居中、
KNOB pad=-2 → 16px 旋钮；开关 44×24 + pad=-2 → 20px 旋钮，触摸区用透明容器承载。键都在 `reference/16` 表内。
必配门禁：按钮恰一子标签、子标签文本非空、按钮自身无 `text`、字体覆盖所有字符。
**克隆后仍要检查"表达式型"属性**：新模板的表达式型字段都已复位为 literal；若从旧工程/别的工程取样，
需清掉表达式型字段绑定（如 `text/hiddenFlag` 的 expression），避免生成未声明的
`get_var_xxx()`（w78 实测）。
**生成器十二条**（w78 23 页实测，每条都对应一次真缺陷）：
① 页名用 ASCII（中文被消成 `SCREEN_ID___` 撞车）；② identifier 全工程唯一（加页前缀）；
③ 字号来自设计令牌（**≤3 档共用**）；镜像方案只有 1 档带汉字（尽量小），其余档 ASCII/数字；生成时校验；④ 替换后的字符必须进字体子集；
⑤ **宽卡片/格子只做底板**（按钮自带居中文字会压住名字/数值/详情）；但设计明确标注为
   **动作/跳转按钮的窄控件必须做真实按钮**，不能一律退化成透明容器；
⑥ **行式控件做按钮时要 `align=LEFT_MID` + 左偏移 + 用设计文案**（不是控件名），否则文字跑中间、与标签重复；
⑦ **颜色只接受 `#RRGGBB`**：`fill=none`/渐变/命名色一律跳过，写成 `0XNONE` 会让 EEZ Checks 报 `invalid color`；
⑧ **identifier 带类别码**：`{页ID}_{w/hw/r/hr/go/sw/st}{NN}`，与 H5 六类一一对应，
   类别码只在一处映射表定义；配门禁"码 ↔ `io_of()` 必须一致"（细则见 `reference/07`）；
⑨ **纯展示/装饰容器必须去掉 `CLICKABLE`**（只改 widgetFlags，不新增字段），
   否则透明底板会盖在按钮上吞掉点击——EEZ 画布看不出，仿真/真机才发现点不动；
⑩ **控件 JSON 禁止捏造**：新建控件**只从根目录 `eez-widget-templates/templates/`（kit `reference/eez_widget_syntax`）克隆**；
   不允许临时去其他工程抓样板。模板来自 **EEZ UI 拖拽创建并保存后的工程**，
   `validate_templates.py` 逐字段核对；不得按 classInfo/defaultValue 片段或拖动 payload 补字段，
   不要用脚本生成/修改 `.eez-project`；不得带源工程配色/字体/尺寸；
   生成器只改几何/identifier/文本/样式值；**字段集不得超出样板**，A10 门禁逐控件核对；
   Switch 必须带 `CHECKABLE`（A13）。
⑪ **标注控件必须物化为真实类型**：toggle→`LVGLSwitchWidget`、slider→`LVGLSliderWidget`、
   动作/跳转→`LVGLButtonWidget`、输入→`LVGLTextareaWidget`、进度→`LVGLBarWidget`、
   图表→`LVGLChartWidget`；整卡交互区用「容器 + 卡内真控件」（子控件坐标相对父对象）。
   **A12 硬门禁**逐行核对，透明容器冒充即 FAIL。**Switch 样板必须带 `CHECKABLE`（A13）**，
   否则点击不切换；验证发 `PRESSED → RELEASED`，只发 `CLICKED` 无效。
⑫ **设备读数单独成控件**：温度/湿度/百分比/功率/电量/在线状态等按 `value` 类追加控件行，
   生成真实 Label（`hr` 码）并进入控件表/H5 标注；标题、说明、按钮文案不误判为读数。
   w78 实测自动补 57 条读数，总控件 239。

### 2.2b EEZ 优先：不确定先查官方手册，参数在 EEZ 里改（2026-11-06 用户定）

| 可以做 | 禁止 |
|---|---|
| 在 EEZ 属性面板 / 工程设置 / 位图设置里改参数，构建后看 `.c` 产物取证 | 用脚本改 `.eez-project` 或 `src/ui` 来"绕过 EEZ 的选项" |

### 2.5 UI 内存预算：按档位控制效果，不压呈现质量（2026-11-05 用户定）

`src/native` 下全部 UI 代码（自动发现 `.c/.cpp`，新增 UI 模块不用改脚本）；
只排除 `platform/**`（硬件平台与 PC 仿真）和硬件业务（如 `wifi_logic/model/events`）。
报告分「EEZ UI / Native UI / 合计」，预算与 `[MEM-BIN] ui=` 用**合计值**；
开机页 `boot_selftest`、背景图 `ui_bg`、导航/绑定、UI 控件都计入。
`assets/` 下的 MP4/PNG 走文件系统，不算固件 Flash/RAM（真机只占存储）。
标准模板 `minimal-lvgl-project-no-flow` 与 w78 使用同一套脚本。

**设计阶段就确认预算（第①步询问用户，别默认）**：常见档位 200K / 500K / 1M / 2M / 4M，或项目实际值；
确认结果写进 `design/mem_budget.json`，未确认不进入 ④ 预生成；再由 AI 按档位决定字号档数、bpp、图片与动图规模。**不做固定上限**，
也不为省内存牺牲清晰度和主视觉。

**分配顺序**：可读性优先——字体（必要字号/字符集）→ 静态图 → 动图；先裁未用字符/字号，
再降 bpp/色深，最后才减动效。任何压缩后必须逐屏目检 + D5。

| 档位（示例） | 字体 | 图片 | 动图 |
|---|---|---|---|
| 200K | 2–3 档字号，1–2bpp | 小图标、索引色 | 只做属性动画（translate/opa/zoom） |
| 500K | 4–6 档，2–4bpp | 按显示尺寸、低 bpp | 1–2 套小序列帧（约 ≤64×64/≤12 帧/2bpp） |
| 1M | 6–8 档，4bpp | 常规切图 | 2–4 套（约 ≤96×96/≤16 帧/4bpp） |
| 2M | 8–12 档，4bpp | 多图/大图 | 4–6 套（约 ≤128×128/≤24 帧） |
| 4M+ | 全字号、高 bpp | 保真优先 | 较大/多套动图，优先还原设计 |

上表是**决策参考**，不是硬指标；项目预算不同就按比例调整。

- **字体（存储位置决定预算）**：**镜像**内字号 ≤3 档，且**只有 1 档允许常用/完整汉字**（尽量小，
  如 12px），其余档只放 ASCII/数字/符号；**SD 卡**字库从卡加载、不占镜像，可不限字号与字符集，
  但要保留镜像内 1 档兜底。设计阶段先确认字库放哪。
- **动图**：优先属性动画；序列帧按预算定尺寸/帧数/色深，够用即可，不常驻多套。
- **缓冲**：固件不跑 `lv_snapshot`；`LV_MEM_SIZE` 按峰值；仿真 4MB 只为截图。
- **展示（每次编译/测试都打，默认口径）**：
  **① 主口径＝IDF 工具链只编译估算**：`design/esp32_estimate.py` 用 IDF 同参数、目标架构编译
  UI，给逐文件字节 + UI/字体合计 + RAM；**默认优化等级固定 `-O2`（IDF 当前）**，
  并给 `-O0/-O1/-O2/-O3/-Os` 的 Flash/RAM 对比（按 `ui_hash` 缓存，UI 变了重算）。
  未链接（无 gc），Flash 偏高约 17%，预算按此值留余量。
  **② PC 编译上限并列**，仅作快速对比。
  **只有用户点名“用 IDF 工程编译”时**，才跑 `design/esp32_size.py` 做最终链接，
  数字与 `idf.py size` 一致。无 IDF/模板未构建时只给 PC 并标明“上限”，
  不得拿源码体积充数；估算每次按当前 UI 实时编译，不读过期缓存。
- **门禁**：D9 `design/mem_report.py` 按 `mem_budget.json` 的档位核账。**默认基准＝IDF 工具链
  只编译估算**（`design/esp32_estimate.py`，目标架构、同参数、每次实时算；Flash 偏高约17%，
  预算按此留余量）；**用户点名“用 IDF 工程编译”时**才以最终链接复核（`esp32_size.py`，
  `ui_hash` 对不上即过期）。PC 侧编译上限并列保留。超档先按上面顺序减，
  减到仍超再升级预算或降需求。

## 3. EEZ 应用侧实测注意（2026-10-16 补充，源自 watch 工程排障）

### 3.1 Run 模式（F5）是可交互的运行时

- 入口：工具栏 `Edit / Run / Debug` 的 **Run**（title "Enter run mode (F5)"）；渲染到真实分辨率画布。
- 可自动驱动：CDP（`--remote-debugging-port=9222`）+ 注入真实鼠标事件；实测点击导航 ✓、拖拽滚动 ✓（工具见 §5）。
- ★ **CDP 注入两纪律（2026-10-17 实测）**：别发 F5（页面当刷新用，整 renderer 重载）——进 Run 点工具栏 **Run 按钮**；
  截图/点击坐标**每轮自量 canvas rect**（画布位置随窗口操作漂移，写死 clip 会截到编辑器画布，见 P-0139）。
- Run 吃**工程模型**（widgetFlags 等）；生成器重写 `.eez-project` 后，必须在 Studio 里关闭工程再重开，否则 Run 仍用旧内存版本（P-0217）。

### 3.2 字体：F1–F7 索引（唯一清单，细节只写在 reference/07）

字体问题重复出现，所以固化成七个编号；**做 EEZ 工程/交付前逐条对照**，缺项即视为未完成。

| 编号 | 规则 | 不过会怎样 |
|---|---|---|
| **F1** | 三件套齐全：`fonts[]` 条目 + TTF 文件（相对工程目录）+ 控件的 `localStyles.*.text_font` | 缺一整屏无字，且不报错 |
| **F2** | 条目形态必须是 EEZ 原生：`renderingEngine:"LVGL"` + `lvglGlyphs:{encodings,symbols}` + `lvglRanges` + `glyphs:[]` | 只写 `lvglRanges` → 官方引擎 `-Infinity`；画布豆腐/点 Fonts 崩 |
| **F3** | 字形覆盖先核源字库 `cmap`；`‹ › − ▶ ◀` 这类黑体没有的先替换，再把替换后的字符集写进 `encodings` | 界面豆腐块 |
| **F4** | 多字号 = 多个条目共用同一个 TTF；**全工程 ≤3 档**；**镜像内只有 1 档带汉字（尽量小）**，其余档只放 ASCII/数字；SD 卡字库不受限 | 版式乱；字体内存翻倍；镜像塞多个中文档会爆 |
| **F5** | headless build **不烘字体**，且构建会**清空 `src/ui/fonts`**：必须"先构建、后烘字体"，每字号一个 `ui_font_*.c` | 构建"成功"但字体文件为 0 |
| **F6** | 验收三连：单烘成功 + 文本覆盖对账（设计帧每条字都能在工程里找到）+ 每个字体条目都有 `ui_font_*.c` | 靠目测猜"应该好了" |
| **F7** | **运行时中文**（SSID/状态文案）设计子集覆盖不到：单独烘 GB2312 一级字库档（如 `cn12f`/`cn24f`），新建控件显式设该字体，并开 `LV_FONT_FMT_TXT_LARGE`；运行时时档优先 18/12 两档、大字用 2bpp，交付跑 D9 内存账 | 真机/仿真里中文 SSID 全是豆腐块；大字库还过不了编译 |

补充事实（P-0125 实测）：字体**文件**与豆腐无关（全量 simhei 与子集一样正常）；形态对 ≈2 分钟内正常渲染，形态不对永远豆腐。

### 3.3 会话状态损坏的恢复（P-0126）

- 症状：工程打不开（首页按钮无效 / 双击条目崩溃 / 带参启动停在首页）；工程文件本身无恙。
- 处置：备份并删除 `%APPDATA%/eezstudio` 的 `Local Storage` + `Session Storage`，重启即恢复。

### 3.4 GUI 与 headless 等效性 + 回归守卫

- GUI Check/Build 与 headless CLI 产物**语义一致**（本栈实测：GUI 重写 src/ui 后，出图与基线逐张 MD5 一致、回归断言与拖拽复测全过）。
- GUI 构建**会重写 `src/ui`**（正常行为）；重写后重跑 ⑦ 内环的仿真与门禁两步再交付。

## 4. 误区速查

| 误区 | 实际 |
| --- | --- |
| "EEZ 里点不了" | 外部重写后先关闭工程再重开（P-0217）；画布无输入，Run 只验原生控件反馈 |
| "仿真过了就行" | 静态观感主验收在 EEZ、动态效果主验收在仿真，但都非终验——真机才定手感与性能 |
| "重叠 0、相似度够就没问题" | 间距漂移（按钮低 8px、列表近 10px）D5 与重叠都查不出；必须跑 `layout_check --divider` 的 L5 页骨架间距 |
| "行卡逐行写死 y" | 同一页的整行卡必须由统一行距常量推导（高+间隙），手写 y 迟早出现某行贴住上一行（w78 设置页 Wi-Fi 行贴住自动锁屏卡） |
| "把 MP4 转成帧序列就是播放视频" | 仿真要求**真实 MP4 解码**（ffmpeg → LVGL canvas）；帧序列/动图只允许作为真机资源包，不能冒充"播放视频"（2026-11-07 用户定） |
| "开机只做自检页，或只做动画" | 成品固定为 **自检 0→100% → 真实 MP4 → 主界面** 两段衔接；`boottest` 必须打印 `selftest=100 video=N active=0`（N>0） |
| "大字号写中文更好看" | 本栈只有 `ui_font_cn12` 带汉字；`cn24/cn32` 仅 Latin/数字，写中文全是豆腐块；中文一律用 cn12 + `letter_space` 撑开 |
| "资源账只统计 src/ui 就够了" | UI 还包括 `src/native` 的导航/绑定/开机页/背景/控件；漏算会让固件预算偏低。脚本自动发现 native UI，只排除 `platform/**` 与硬件业务 |
| "仿真替身放进 app" | `sim_fs` / `sim_reads` / `sim_video` 等 PC 专用替身必须放 `src/native/platform/pc/`；`app/` 只留跨平台业务（2026-11-07 用户定） |
| "手改一下 src/ui" | 覆盖式重写；永远回上游改设计源 |
| "字体全量 TTF 最省事" | 字体大小不是要害；**条目形态（D5/renderingEngine/lvglGlyphs）才是**——缺了就崩（P-0125） |
| "D5 相似度高就没问题" | D5 只证明"画布像设计图"；设计源自己叠了，两边一致照样高分。**重叠必须用几何门禁查**：`tools/layout_check.py` L2 / A15（P-0262） |

## 6. 一次到位提示词公式（2026-10-18 复盘 watch 全程返工史总结）

**返工主因不是 AI 能力，是提示词缺了五要素之一**。对照真实返工记录：
① 滚轮做成 native 例外被推翻（缺"约束面"）；② "弧度"两轮对不齐（缺"观感基准"）；
③ 磁吸做完才补"贴顶贴底"（缺"边界行为"）；④ 图标动画做完才下"严格执行"令（缺"验收面"）；
⑤ 丢帧三轮才给到 33fps（缺"量化阈值"）；⑥ AppList 有钮被裁掉（缺"交互方式"）。

**五元组模板（每条新需求按此写，缺项写"沿用 AGENTS.md"即可）**：

```
【目标】哪个页面/控件、出什么效果（一句话说清"变成什么样"）。
【口径】唯一真值来源（变量/数据从哪来、谁能改）；交互方式（钮/手势/点击，谁有什么没有）；
        边界行为（到顶到底到什么状态、极端值怎么走）。
【验收】量化判据（帧率/误差/尺寸等数字）+ 行为判据（进得去回得来/点了必有所去），
        点名必须过的门禁（如 nav_audit PASS、构建 0 错 0 警、可复现证据）。
【约束】预生成阶段控件必须 EEZ 出（铁律0）；全功能阶段的动态内容可用原生代码。
【验证与归档】设计核对阶段仿真默认跑，日常微调点名才跑；完成后登记报告 §N + kit P-/PR-。
```

**观感类需求附加款**：形容词（弧度/高级/遮挡/不流畅）两轮对不上就改喂
"标注截图/参考视频/数值目标"，并让 AI 单参数迭代出图对照，禁连续猜第三轮。

**存量约定不复述**：AGENTS.md 铁律、nav_audit、B12 手册参数、§38 时钟口径等
已固化的内容，提示词里只需引用编号（"按 §38 口径""遵铁律⑤"），AI 会读工程
AGENTS.md 自动生效；复述反而制造新旧打架。
