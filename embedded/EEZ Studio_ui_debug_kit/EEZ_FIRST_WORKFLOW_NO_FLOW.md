## 0. 总则：验证优先级金字塔（静看 EEZ，动看仿真）

**一句话（2026-10-22 用户补充静动分界）：静态的图片和文字效果，以 EEZ 里看到的为准；动态的效果，以仿真器为主；真机负责终验。**

| 验证对象 | 第一现场（主） | 辅助（次） | 终验 |
| --- | --- | --- | --- |
| 视觉 / 布局（**静态**：图片、文字效果、排版） | EEZ 编辑器画布（工程模型原生渲染） | 仿真出图（像素对照、批量回归） | 真机 |
| **动态效果**（动画/滚动/帧序/跟手节奏） | **仿真器**（逐帧/量化对照；EEZ Run 的节奏与帧序不可信，且 Run 输入通道不产生 GESTURE，见 P-0141/P-0149） | EEZ Run 粗看通路 | 真机 |
| 交互（点击/跳转/状态） | **EEZ Run 模式（F5）** —— 真运行时、可点可滑 | 仿真器脚本化（数值化，如拖拽位移 Δ） | 真机 |
| 生成代码语义 | EEZ GUI Check/Build 或 headless CLI（二者语义一致，可互换） | 门禁断言 | 真机 |
| 数值回归 / CI | — | 仿真快照 MD5、断言集 | — |

零号铁律（对所有 AI 生效；2026-10-22 用户定稿 no flow 分阶段口径）：

0. **★ EEZ 优先——预生成阶段，设计图中指定的控件必须由 EEZ 生成**，方便坐标定位、控件布局；`src/ui` 不可手改。
   **全功能补全阶段（§2 第⑦步），动态的（不是固定的）界面内容不必须用 EEZ，可以使用原生代码实现。**

其余纪律：

1. **改动只落设计源 / 生成器 / EEZ 工程**；`src/ui` 是覆盖式重写的只读产物（沿用 kit 最高优先级铁律）。
2. **编辑器画布没有输入**（skills §7.1）；要"在 EEZ 里点得动"，用 **Run 模式** —— 勿混淆这两个面。
3. **每层能证明什么要写清**：画布证明**静态**观感与工程模型；**动态效果以仿真的逐帧/量化判定为准**（§0 静动分界）；Run 证明交互通路与工程语义；真机证明物理/性能/手感。
4. **留痕**：提示词与问题按 `INTAKE.md` 规约记录（本文件即 PR-0210 的沉淀）。
5. **★ 仿真时机（no flow）**：设计核对（§2 第⑤步）仿真出图核对**默认必跑**；
   日常微调仍等用户点名"跑仿真/出图对照"才跑。跳过仿真时，设计源注释留
   "下次跑仿真前需同步"清单（L4 期望值、夹具坐标等），交付说明注明"本次未经仿真量化验证"。
   **动态效果的验收不受本条限制**（§0 静动分界：动态以仿真器为主）。

## 1. 框架方案（从样板工程提炼，可整体移植）

### 1.1 目录分层

```
<固件工程>/                      ← IDF 工程根（build 目录在这）
├── main/                       板级胶水
├── components/                 板级组件（bsp / 显示 / 内存 …）
└── <ui工程>/  (eez-test/ 或 watch/)
    ├── xxx.eez-project         ★ EEZ 工程文件 —— UI 的真值
    ├── xxx.eez-project-ui-state   编辑器界面状态（不参与构建）
    ├── ui_debug_kit.config.json   工程侧配置（设计源路径 / 屏幕 / 字体 / 门禁挂载）
    ├── designer/               【给人看】设计效果图（由 design_view.py 渲染，第①步用户确认的就是它）
    ├── design/                 【给机器】设计源 + 工具链
    │   ├── build_ui.py          唯一设计源（DSL 构建脚本；或等价生成器）
    │   ├── design_view.py       独立设计图脚本（读同一设计源，渲染效果图落 designer/）
    │   ├── json2eez.py          DSL → EEZ 工程（与"生成器直出 EEZ JSON"二选一）
    │   ├── eez_build.py         EEZ headless CLI 构建
    │   ├── eez_font_engine.py / gen_fonts.py    字体烘焙与校验
    │   ├── sim.py               仿真器编译 + 逐屏截图（+ 对照）
    │   ├── compare.py           仿真图 vs 效果图对照（兼任门禁）
    │   └── architecture/        框架文档（回调 / 业务逻辑 / 仿真硬件分层）
    ├── src/
    │   ├── ui/                  EEZ 生成代码（只读产物）
    │   └── native/              用户代码隔离层（手写）
    ├── build/                   本地产物（核对报告 / 定稿截图 / declared_manifest；gitignore）
└── tmp/                     ★ 核对过程临时件（探针截图 / crop 目检图 / pid / 拼版草图；gitignore，随手可清）
                              —— 用户 2026-10-23 令：过程件一律进 tmp/，交付件才进 designer/、
                              designer_annotated/ 等正位；拿不准当临时件放 tmp/
```

**三条铁律**（样板工程原话，照用）：

1. `designer/` 是给人看的设计图、`design/` 是给机器用的设计源；两者不一致时，改设计源。
2. `src/ui` 由 EEZ 导出（覆盖式重写），**不要手改**；功能逻辑一律进 `src/native`。
3. **界面只在设计源里定义一次**（build_ui.py 或其等价物）；**设计图与 EEZ 工程同源派生**——
   设计图由独立脚本 `design_view.py` 渲染（与工程生成脚本分离），第①步用户确认的即渲染结果，
   不满意就改设计源重渲染；确认后 C 代码、仿真出图再全部由设计源派生。

### 1.2 隔离层 —— 分层按方式分

`native_vars / app_model / io_pc / io_esp` 四层与 `get_var_/set_var_` 变量契约是 **flow 方式的结构**（见 `EEZ_FIRST_WORKFLOW_FLOW.md` §1.2）。
本方式（no flow）不用变量桥：`src/ui`（EEZ 生成、不手改）直接对接 native 的事件回调与业务代码；
平台层 `io_pc.cpp / io_esp.cpp` 视是否保留 PC 仿真决定去留——要仿真时，PC 与真机仍只差这一个文件。
框图（颜色=代码归属分区，每一跳带函数代码）：[按键→外部硬件](diagrams/01_按键控制外部硬件.svg) ｜ [按键→切换页面](diagrams/02_按键切换页面.svg)

### 1.2b 父子层口径（2026-10-23 用户定，长期要求）

EEZ 生成的永远是**父层**（底图 / 容器 / tab 页 / 全屏宿主）；native 追加的一切都是它的**子对象**，不许另立平级父层。
父层要铺满它该有的区域，子对象不得越出父边界——LVGL 9 无条件把子对象裁到父边界，越界＝看不见（FX-004 家族）。
**有例外必须先跟用户交互说明并登记本库**：例如滚轮轮根要靠负 padding 把内容摆到父边界之外、
全屏子对象与父级 tabview 拖动切页的归属冲突，都属这类，不许默默实现完就算数。

### 1.3 双环境编译

- 固件：`<ui工程>/src` 挂成 IDF 组件（ui → native 链接顺序坑见 skills §7.6）。
- 仿真：独立 port（PC_SIM 或独立沙箱目录），**单向同步**工程源码进去编译，不污染工程；
  工具链路径在工程的 kit 配置 `sim` 段（**每机必须问用户，禁止猜**）。
- 快照流水线：仿真 exe 支持"逐屏快照"模式（skills §5.6），出图后可做 MD5 / 对照回归。

## 2. 开发流程（七步主线；用户 2026-10-22 定义）

| 步 | 做什么 | 判据 / 规约 |
| --- | --- | --- |
| ① 设计图 | 用户提供；没有则由 AI 生成——先写设计源，**设计图由独立的设计图脚本（design_view.py）从同一设计源渲染**（与 EEZ 工程生成脚本分离），**必须经用户确认核对后才算数**；不满意改设计源重渲染 | 效果图落 `designer/`；确认通过才进 ② |
| ② 控件标注 | 用户在图上用**序号**标注：哪些是控件、控件类型、哪些用于跳转界面、哪些用于控制硬件；同时说明页面关系（是否归 tabview、有无 top bar / bottom bar）。AI 已能推导控件时，先按 §2.1 出标注图交用户改口径 | 产出**控件清单表**（序号/名称/控件类型/作用/跳转目标）＋ **§2.1 标注图**；**未标注作用的控件＝纯展示、不接任何行为** |
| ③ 框架确认 | 确认本工程走 **no flow**（本文件即此方式的流程）；若改选 **flow**，弃用本文件、转 `EEZ_FIRST_WORKFLOW_FLOW.md` 执行，结论写进工程文档 | 两种方式框架有区别，选型只在此一步定 |
| ④ 预生成全部界面（含**静态确认核对**，§2.2 的 A+B1 层在本步完成） | 用 EEZ 预生成所有界面，含字体条目（原生形态，见 §3.2/P-0125）与图标；**大图需用户确认是否走 TF 卡**；生成后逐屏做静态核对：A 声明层对账（工程 JSON↔设计源字段逐项，差异=0）→ B1 EEZ 画布逐屏截图对照 `designer/`（CDP canvas-shot，画布=真实 wasm 渲染）。**自主修复条款（2026-10-23 用户授权）：④站内 AI 发现不对可自己修复重跑（改生成器/设计源→重建→重核）直到达标，无需逐次请示；仅"改设计本体"或"新增豁免项"两类事升级用户裁决**。A+B1 全绿后**交用户确认 EEZ 的界面效果**（贴 B1 对照拼图或用户自开编辑器看），点头才进 ⑤ | 构建 0 错、中文渲染正常、页面/控件与 ② 清单一一对应；**A 差异=0 且 B1 逐屏一致或经豁免，再经用户确认 EEZ 界面效果，才算 ④ 完成** |
| ⑤ 导航闭环核对（本阶段仿真默认跑） | **本步重心＝把各界面连接起来**（native 导航接线：跳转/切换/每屏可达可回），页面细节功能留⑦：C 行为层——仿真 AUTOTEST 按清单表逐跳转边发事件断言落点（EEZ 画布无输入、no-flow Run 不执行 native 绑定，跳转只能在仿真器核）；B2 仿真逐屏截图与 ④ 的 B1 互证 | 导航判据：清单表每条跳转可走通、每屏进得去回得来，`[NAV]` 全 PASS；B2 差异逐处归零或经用户豁免 |
| ⑥ 用户核对＋真机 | 用户亲自核对预生成界面；烧录到硬件，确认界面可显示、可调整、测试正常 | 用户点头＝设计冻结；此后改设计须回 ① 走确认 |
| ⑦ 逐个补全功能 | **本步核心＝补齐每个界面的核心功能**（④⑤站"细节后补"的全部在此兑现：测量/计时/播控/开关状态/数据灌入…）；按用户需求逐屏逐控件过一遍，确保没有"看得见但没功能"的空壳屏；每条按 §6 五元组提示词立项，各走一轮下面的内环 | 门禁全绿才提交；留痕 PR-/P-；对照清单表 44 项逐条勾销，全勾才算工程功能齐 |

**⑦ 的内环（每条功能一轮，不得绕开）**：
① 改设计源 → ② 生成器出 EEZ 工程 → ③ EEZ 构建 →
④ EEZ 画布/Run 核对（静态主验收；点击/跳转通路）→
⑤ 仿真（**动态效果主验收**）→ ⑥ 门禁 `run_gate` 全绿 → ⑦ 真机（点名才做）。
内环保持 ④ 在 ⑤ 之前：EEZ 里不对，先回工程改，别先跑仿真绕开。
常见坑（字体条目 §3.2、GUI 重写 src/ui、tick 源 §3.4、`#if ESP_PLATFORM` 仿真编不到）见 §3。

### 2.1 第②步 AI 侧交付物：控件标注图 + 树状总览（2026-10-22 用户定稿，PR-0313~0316）

参考图（watch 工程实产出，照此形制做）：[diagrams/03_控件标注树状总览_参考图.svg](diagrams/03_控件标注树状总览_参考图.svg)

用户只看总预览图 ⇒ **总图必须自足**，不逼用户翻单页或对照表。落 `designer_annotated/`：

1. **单页图**（每页一张，无行为控件的页不出）：原设计图 + 控件框 + 圆形徽标。
   徽标=**分类序号** `1按钮 2开关 3滑条 4滚轮 5步进 6chips 7按键网格…`（每类独立连续编号）。
2. **树状总览 `_tree.svg`**（交付真值；cairosvg 光栅化到工程外自证后另存 `_tree.png`）：
   节点=**已标注缩略图**（框+徽标可见，边长 ≥260px）；每条连线挂**发起控件圆徽**——
   **绿底=UI 内部切换，红底=输出硬件/手机**；根=tab_main（tab 间虚线标"滑动切换"）；
   右侧画"外部·板级硬件 / 外部·手机 App(BLE)"红框节点，硬件控件全部接红连线。
3. **同源纪律**：控件的序号/类型/输出去向/跳转全部落设计源注册表（如 design_source.py `CONTROLS`），
   由独立脚本（design_annotate.py）生成图；改设计源后与 design_view.py 一起重跑，**禁止手 P 图**。
4. 光栅与 SVG 共用同一判据函数（徽标避让、连线取点），保证两版一致。

### 2.2 第④⑤步核对方法：四层两站（2026-10-23 用户定稿；静态核对归④，导航归⑤）

**A/B1 属第④步（预生成的静态验收），C/B2 属第⑤步（连接界面的动态验收）**。
第⑤步本体＝**把各界面连接起来**（native 导航接线：跳转/切换/每屏可达可回），
页面细节功能留第⑦步。EEZ 画布无输入、no-flow Run 不执行 native 绑定 ⇒ **跳转只能在仿真器核对**。
核对分四层，按 A→B1（④站内）→C→B2（⑤站内）做：

| 层 | 核什么 | 手段 | 判据 |
| --- | --- | --- | --- |
| A 声明层（硬，先跑） | 生成器没走样：EEZ 工程 JSON 与设计源逐项一致（坐标/尺寸/颜色/字体档/identifier↔清单表 44 项一一对应） | 审计脚本读 watch.eez-project + design_source 对账，出差异表 | 差异=0 才继续；有差异回生成器修，不进渲染层 |
| B1 EEZ 画布静态（样式主核①） | 每屏样式与设计图一致（单屏、无交互） | 画布=真实 LVGL wasm 渲染（P-0164 勘误）；CDP `--remote-debugging-port=9222`+canvas-shot 逐页截图（纪律见 §3.1：勿发 F5、canvas rect 每轮自量），vs `designer/*.png` 拼图目检 | 逐屏一致或入豁免清单；**跳转类不在本层核**（画布无输入、no-flow Run 不执行 native 绑定） |
| C 行为层（本步主判据） | 导航闭环：每条跳转边可走通、每屏可达可回 | 仿真 AUTOTEST：按清单表逐边 send CLICKED + 断言落点屏/落点 tab，输出 `[NAV] PASS/FAIL` 计数 | 全 PASS；FAIL 逐条修 native 绑定重跑 |
| B2 仿真截图（样式主核②） | 与 B1 互证 + 供真机前基线 | 仿真逐屏截图（snapshot BMP→PNG）vs `designer/*.png`：平均差异率阈值 + 拼图目检 | 差异逐处归零或列入豁免清单经用户点头 |

**豁免清单基线**（预生成阶段声明，非缺陷）：纯装饰件未生成（时刻刻度/表盘外环）；
符号按钮 ASCII 占位（`< > >>`，simhei 无 U+25C0/25B6）；字体渲染引擎差异（PIL 设计图 vs LVGL 烘焙字形，
允许笔画级差异，量到"字号/颜色/位置对"即可）。

**顺序纪律**：A → B1 → C → B2，前者不过不进后者（样式先由 EEZ 画布核住，跳转由仿真断言，
最后仿真截图与画布互证；样式再对，页面进不去也是白核）。
B1/B2 截图目录与报告落 `build/sim_shots/`，随步⑤交付贴给用户。

### 2.3 目检物规定：逐屏全分辨率对照长图（2026-10-23 用户定）

目检必须看**一屏一条**的全分辨率左右对照图（仿真截图 | 设计图 + 量化差值），工程侧由
`design/proof_sheet.py` 出 `tmp/proof/proof_<页>.png`；同源的 SVG 版可再光栅化回 PNG 自证通路。
多屏缩略网格图（`_b1/_b2_compare.png`）只用来查"有没有漏屏"，**不得当作目检依据**——
watch 的 applist 行名称比设计图小一号，就是在 233px 网格上被判成"逐屏一致"放行的。
量化判据（如 6×6 分块墨量差 ≤阈值）是**下限门禁**，不替代读图；阈值要用"当前全绿分布的最大值"
与"故障态分布的最小值"卡中间，两组数字连同反向测试写进代码注释。
AI 自己核对时必须在报告里逐屏写结论（看了哪几屏、差异是什么、哪条判断被推翻或已修）；
只报"门禁全绿"不算核对过。

## 3. EEZ 应用侧实测注意（2026-10-16 补充，源自 watch 工程排障）

### 3.1 Run 模式（F5）是可交互的运行时

- 入口：工具栏 `Edit / Run / Debug` 的 **Run**（title "Enter run mode (F5)"）；渲染到真实分辨率画布。
- 可自动驱动：CDP（`--remote-debugging-port=9222`）+ 注入真实鼠标事件；实测点击导航 ✓、拖拽滚动 ✓（工具见 §5）。
- ★ **CDP 注入两纪律（2026-10-17 实测）**：别发 F5（页面当刷新用，整 renderer 重载）——进 Run 点工具栏 **Run 按钮**；
  截图/点击坐标**每轮自量 canvas rect**（画布位置随窗口操作漂移，写死 clip 会截到编辑器画布，见 P-0139）。
- Run 吃**工程模型**（widgetFlags 等）：生成器一改、重生成即生效。

### 3.2 字体条目形态影响应用侧（P-0125）

- 画布 / Run 的中文依赖"会话内字体提取"完成；**提取完成前必是豆腐块**（对照工程实测：成功通知出现后即时自愈）。
- ★ **决定性变量是「字体条目形态」**（2026-10-16 A/B/C 对照实测，见 P-0125）：条目必须是 EEZ 原生形态——
  `renderingEngine:'LVGL'` + **中文码位进 `lvglRanges`（数字表）** + `lvglGlyphs:{encodings,symbols}` + `glyphs:[]`；
  缺字段 → 画布/Run 豆腐 + 点 Fonts 面板崩，**只换字体文件无效**。方法出处：skills §3.3/D5 + §11.12。
- 字体**文件**与豆腐无关（受控实测：全量 simhei + 正确形态同样正常；换 `YaHei_Consolas_Hybrid.ttf` 是观感选择，140/140 码位核验）。
- 不存在"等待提取完成"的过程：**形态对 ≈2 分钟内即正常渲染、形态不对永远豆腐**（T1 受控等 6+ 分钟仍豆腐）。

### 3.3 会话状态损坏的恢复（P-0126）

- 症状：工程打不开（首页按钮无效 / 双击条目崩溃 / 带参启动停在首页）；工程文件本身无恙。
- 处置：备份并删除 `%APPDATA%/eezstudio` 的 `Local Storage` + `Session Storage`，重启即恢复。

### 3.4 GUI 与 headless 等效性 + 回归守卫

- GUI Check/Build 与 headless CLI 产物**语义一致**（本栈实测：GUI 重写 src/ui 后，出图与基线逐张 MD5 一致、回归断言与拖拽复测全过）。
- GUI 构建**会重写 `src/ui`**（正常行为）；重写后重跑 ⑦ 内环的仿真与门禁两步再交付。

## 6. 一次到位提示词公式（2026-10-18 复盘 watch 全程返工史总结）

**返工主因不是 AI 能力，是提示词缺了五要素之一**。对照真实返工记录：
① 滚轮做成 native 例外被推翻（缺"约束面"）；② "弧度"两轮对不齐（缺"观感基准"）；
③ 磁吸做完才补"贴顶贴底"（缺"边界行为"）；④ 图标动画做完才下"严格执行"令（缺"验收面"）；
⑤ 丢帧三轮才给到 33fps（缺"量化阈值"）；⑥ AppList 有钮被裁掉（缺"交互方式"）。

**五元组模板（每条新需求按此写，缺项写"沿用 AGENTS.md"即可）**：

```
【目标】哪个页面/控件、出什么效果（一句话说清"变成什么样"）。
【口径】唯一真值来源（变量/数据从哪来、谁能改）；交互方式（钮/手势/点击，谁有什么没有）；
        边界行为（到顶到底到什么状态、极端值怎么走）。
【验收】量化判据（帧率/误差/尺寸等数字）+ 行为判据（进得去回得来/点了必有所去），
        点名必须过的门禁（如 nav_audit PASS、构建 0 错 0 警、可复现证据）。
【约束】预生成阶段控件必须 EEZ 出（铁律0）；全功能阶段的动态内容可用原生代码。
【验证与归档】设计核对阶段仿真默认跑，日常微调点名才跑；完成后登记报告 §N + kit P-/PR-。
```

**观感类需求附加款**：形容词（弧度/高级/遮挡/不流畅）两轮对不上就改喂
"标注截图/参考视频/数值目标"，并让 AI 单参数迭代出图对照，禁连续猜第三轮。

**存量约定不复述**：AGENTS.md 铁律、nav_audit、B12 手册参数、§38 时钟口径等
已固化的内容，提示词里只需引用编号（"按 §38 口径""遵铁律⑤"），AI 会读工程
AGENTS.md 自动生效；复述反而制造新旧打架。
