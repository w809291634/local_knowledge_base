# TI CC2530 / CC2538 / CC2640（8051+RF 与 RISC 双核）

> 协议栈与 OSAL 机制单独成篇 → `zigbee-zstack-osal.md`。`⚠校核` 见 `embedded/mcu-peripherals/ERRATA-*.md`。

## 1. CC2530（8051 内核 + ZigBee RF）

### 时钟切换（本篇第一坑，网上常见写法是错的）
```c
SLEEPCMD &= ~0x04;                       // 退出 PM2/PM3 睡眠请求
while (!(CLKCONSTA & 0x40));             // 等时钟切换稳定
CLKCONCMD &= ~0x7F;                      // ★ 必须连 TICKSPD[5:3] 一起清零
SLEEPCMD |= 0x04;
```
- **只清 `~0x47`（保留 TICKSPD）会导致 T1/T3/T4 的时基错误** —— 作者明确说这是纠错后的写法。
  症状：定时周期莫名是设定值的 2/4/8 倍，而 `delay_us` 之类软件延时正常。
- **TICKSPD 高于主频时会被钳制为主频**（所以不能只按名义值算时基）。

### 定时器 / PWM
| 项 | 内容 |
|---|---|
| T1 模模式定时 | `T1CTL \|= (1<<1)`；1MHz 分频 `T1CTL \|= (1<<3)`；`T1CC0 = 50000` ⇒ 50ms；中断 `#pragma vector = T1_VECTOR` + `IEN1 \|= 0x02; EA = 1` |
| PWM 引脚选择 | `PERCFG &= ~0x40` 选 **Alt1（P0_2~P0_6）** |
| **与 USART0 抢引脚** | 冲突时用 `P2DIR \|= 0xC0` 提高外设优先级通道 2-3 的优先级 |
| 通道配置 | `T1CCTL2/3/4 = 0x24`；**通道 0 没有比较模式 6/7** |
| 舵机映射 | 20ms 周期、0.5~2.5ms ⇒ 0~180°；`pwm1 = 2000*angle/180 + 500` |
| ⚠ 写法风险 | `T1CC0L = LO_UINT16(arr) - 1` 在 arr 低字节为 0 时会借位出错（本例 arr=20000 未触发） |

### printf 与内部 Flash
| 项 | 内容 |
|---|---|
| 重定向 | `__near_func int putchar(int c){ UTX0IF=0; U0DBUF=c; while(UTX0IF==0); return c; }`；协议栈版本是 `__ATTRIBUTES int putchar` 走 `at_uart_write`（两种并存，别混用） |
| 必须 | `#include <stdint.h>`；IAR 里 printf 选项要选 **Full formatting** |
| 内部 flash 读 | `FlashRead(addr, buf, n)`：页号 = `addr >> 11`、页内偏移 = `addr & 0x7FF`、按 4 字节读，**跨页要逐页调 `HalFlashRead`** |

### 单总线 DS18B20（CC2530 上实测）
| 项 | 内容 |
|---|---|
| 引脚 | P0_1 |
| 时序 | 复位：**750µs 低 + 15µs 高**；存在脉冲检测 **240µs 超时** |
| 命令 | `0xCC` 跳过 ROM、`0x33` 读 ROM、`0x55` 匹配 ROM、`0x44` 转换温度、`0xBE` 读温度 |
| 数据 | **LSB 先**；温度 = `raw >> 4`（整数）+ `raw & 0xF`（小数） |
| ⚠风险 | 该章的 `delay_us` 是空 for 循环计数 ⇒ **µs 精度不可保证**，DS18B20 的 480µs/时序窗口属于临界，作者未验证 |

### 5.1 CLKCONCMD 位域表（照抄截图，`ch02/004~006`）

| 位 | 名 | 复位 | 读写 | 含义（照抄） |
|---|---|---|---|---|
| 7 | `OSC32K` | 1 | R/W | 32 kHz 时钟振荡器选择。设置该位只发起改变，`CLKCONSTA.OSC32K` 才反映当前设置。**要改该位必须先选 16 MHz RCOSC 作为系统时钟**。0：32 kHz XOSC　1：32 kHz RCOSC |
| 6 | `OSC` | 1 | R/W | 系统时钟源选择。0：32 MHz XOSC　1：16 MHz RCOSC |
| 5:3 | `TICKSPD[2:0]` | 001 | R/W | 定时器标记频率：000 32MHz / 001 16MHz / 010 8MHz / 011 4MHz / 100 2MHz / 101 1MHz / 110 500kHz / 111 250kHz |
| 2:0 | `CLKSPD` | 001 | R/W | 时钟速度，**不能高于 OSC 位设置的系统时钟** |

> ⚠校核：本表把 `OSC32K` 记在 **bit7**、`CLKSPD` 占 **3 位（2:0）**。这与常见的 CC2530 手册口径
> （`OSC32K`=bit6、`OSC`=bit5、`TICKSPD`=bit4:3、`CLKSPD`=bit2:1、bit0=STATH）不一致，**上机前必须对官方手册核一遍**。
> 这个差别会改变 §1 那句 `CLKCONCMD &= ~0x7F;` 的语义：按本表它保留 bit7（OSC32K）、清掉 OSC/TICKSPD/CLKSPD；
> 按手册口径 `~0x7F` 会**连 OSC32K(bit6) 一起清掉** ⇒ 两种口径下"清零"的效果不同，属高风险点。

**截图里的实测数值**（`ch02/002`、`003`）：

| 图 | 内容 |
|---|---|
| IAR `Power Mgmt and Clocks` 窗口 | `SLEEPSTA=0x68`、`SLEEPCMD=0x00`、**`CLKCONSTA=0x80`（红）**、**`CLKCONCMD=0x80`（红）**、`PCON=0x00`、`CLD=0x00`；展开位：`OSC32K=1`、`OSC=0`、`TICKSPD=0x0`、`CLKSPD=0x0` ⇒ 面板位定义与上表一致（OSC32K 取 bit7） |
| IAR 数值换算小窗 | `HEX 47 / DEC 71 / OCT 107 / BIN 0100 0111` ⇒ 即 `0x47`。配文（文字层原话）："这张图为 `CLKCONCMD &= ~0x7F;` 时，**一定要清零，否则定时器时钟错误**" |
| 官方协议栈配置后的最终结果（`ch02/007`） | `SLEEPSTA=0x4D`、`SLEEPCMD=0x04`、`CLKCONSTA=0x00`、**`CLKCONCMD=0x00`（高亮）** ⇒ 官方栈是**全清**，不是只清低 7 位 |

### 5.2 T1CTL / T1CCTL0 / PERCFG 位域表（照抄，`ch02/010`、`011`、`016`）

**`T1CTL`**：位 7:4 保留；位 3:2 `DIV[1:0]`（复位 00）分频：**00 标记频率/1、01 /8、10 /32、11 /128**；
位 1:0 `MODE[1:0]`：**00 暂停、01 自由运行 0x0000→0xFFFF、10 模模式 0x0000→T1CC0、11 正/倒计数（0→T1CC0→0）**。

**`T1CCTL0`（通道 0 捕获/比较控制）**：

| 位 | 名 | 复位 | 含义（照抄） |
|---|---|---|---|
| 7 | `RFIRQ` | 0 | 置位时用 **RF 中断捕获**，而非常规捕获输入 |
| 6 | `IM` | 1 | 通道 0 中断屏蔽，置位使能中断请求 |
| 5:3 | `CMP[2:0]` | 000 | 比较模式：000 比较时**置**输出 / 001 **清**输出 / 010 **翻转** / 011 向上比较置、到 0 清 / 100 向上比较清、到 0 置 / **101、110 没有使用** / 111 初始化输出引脚（CMP 不变） |
| 2 | `MODE` | 0 | 0：捕获模式　1：比较模式 |
| 1:0 | `CAP[1:0]` | 00 | 00 未捕获 / 01 上升沿 / 10 下降沿 / 11 所有沿 |

⇒ 这张表**印证了 §1 表里"通道 0 没有比较模式 6/7"**：`CMP=101/110` 官方标注就是"没有使用"。
⇒ `RFIRQ` 位是"用 RF 中断做捕获"的入口，做 TOF/同步采样时才用得到，普通 PWM 不要误置。

**`PERCFG(0x61)`**：位 7 未使用；**位 6 `T1CFG`：0 = 备用位置 1（Alt1）、1 = 备用位置 2（Alt2）** ⇒ 与 §1 的 `PERCFG &= ~0x40` 选 Alt1 一致。

**T1 计数波形图**（`ch02/008`、`009`）：自由运行模式纵轴 `0000h→FFFFh`、模模式纵轴 `0000h→T1CC0`，
两者都在回零点标 `OVFL` ⇒ "模模式的溢出点是 T1CC0 而不是 0xFFFF"，这是 `T1CC0` 同时当周期寄存器的直观依据。

## 4. 跨代提醒

- CC2530 是 **8051**（IAR 8051 工具链、`__near_func`、SFR 直接读写），
  CC2640 是 **ARM + TI-RTOS/ICall**（BIOS、任务、`ICall_*` API），
  CC2538 是 **ARM Cortex-M3**；三者**代码与调试方式完全不通用**，只有 ZigBee/BLE 概念层可共享。
- 从 8051 系迁到 ARM 系时，最大的思维差别：**不再有 SFR 直写，改为 GPIO/UART 驱动层 + 配置文件**；
  时钟/延时也不再靠指令周期数估算。
