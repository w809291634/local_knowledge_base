## 1. STC8H（以 STC8H1K28 / 1K16 为主）

| 资源 | 内容 | 范围 |
|---|---|---|
| 存储 | **128B data + 128B idata + 1024B xdata**；最大 33K Flash；**EEPROM 512 字节、单页擦除、擦写 10 万次以上** | STC8H1K28 |
| 时钟 | **IRC ≤ 36MHz，常温精度 ±0.3%**；**ISP 区固定用 24MHz IRC**；上电复位先跑 ISP 程序，下载后按 ISP 设定的 IRC 运行；切外部晶振顺序 = 先使能 → 轮询稳定 → 写 `CLKSEL(FE00)`/`CLKDIV(FE01)`；**代码里 `FOSC` 必须等于 ISP 里选的频率** | STC8H★ |
| **XFR 访问** | 访问 `0xFA00~0xFFFF` 的扩展 SFR 必须 `P_SW2 |= 0x80`（EAXFR）+ 用 `MOVX`；宏 `EAXSFR()` / `EAXRAM()` | STC8G/8H★ |
| 定时器 | **T0~T4 共 5 个**；T0 模式 3 会占用成 NMI；T1 模式 0 = 16 位自动重装；**1T 模式周期 = (65536 − 重装值)/SYSclk，12T 模式再 ×12** | STC8H★ |
| 串口波特率 | UART1 波特率发生器可选 **T1 或 T2**（`AUXR.B0 = S1ST2`）；**UART2 固定用 T2**；1T 模式重载值 = `65536 − SYSclk/(4×波特率)`；24MHz@115200 误差 +0.16%、@9600 零误差 | STC8H1K28 |
| 串口引脚切换 | `S1_S(P_SW1 B7:6)`：00=P3.0/P3.1、01=P3.6/P3.7、10=P1.6/P1.7、11=P4.3/P4.4；`S2_S(P_SW2 B0)`：0=P1.0/P1.1、1=P4.6/P4.7 | STC8H1K28 |
| GPIO 四态 | `PxM1:PxM0` = **00 准双向 / 01 推挽 / 10 高阻 / 11 开漏**；**除 P3.0/P3.1 外上电默认都是高阻**；P5.4 复用为复位脚时内部 4K 上拉开约 **6.5ms** | STC8H★ |
| ADC | **10 位、12 通道，最快 500K/s**；通道 15 = 内部 1.19V BGV ⇒ 可用 `Vx = BGV/res_bg × res_x` 做比例测量（抗电源漂移） | STC8H1K28 |
| PWM | **PWMA = 4 对互补输出带死区**，PWMB = 4 路单端，其余功能完全相同；**与 T0~T4 完全独立、不占用它们**；1K28 **不支持 HSPWM** | STC8H1K16 |
| ISP 硬件选项 | "上电复位使用较长延时"写的是**配置字节而非 SFR**，需**重新上电**才生效；文档给 366.6 / 138.56 / 7.141ms（**作者自注：数值不在 PDF 原文，来自 CSDN 实测**） | STC8H |
| 4 线自动下载 | 芯片内 Bootloader **上电即监听 P3.0/P3.1 握手并自动测波特率**（扫描 2400~最高 115200）；用 **DTR/RTS 驱动三极管模拟"拔电再上电"**实现免按键 | STC8★ |
| 浮点代价 | 8 位 STC 无 FPU：`float` 链接软件库导致 ROM 暴涨（**一个 float 乘法约 +1.5K、`%f` 约 +5K**）⇒ 建议改定点数；STC32G 有 TFPU 但要用 C251 | STC8/15★ |

### STC 侧的坑（本篇最值钱的三条）

1. **轮询 + 中断混用会死锁**：一旦开了 `ES2`（UART2 中断），**ISR 里必须清 `S2TI/S2RI`**；
   否则 ISR 抢先把标志清掉，主循环里 `while(TI==0)` 的轮询**永远等不到 ⇒ 死锁**；
   反过来**不清标志就是中断风暴**。⇒ 同一串口不要混用轮询发送与中断接收，或统一由中断驱动。
2. **上电时序**：除 P3.0/P3.1 外所有 IO 上电为高阻 ⇒ 外部有下拉的负载（如 MOS 栅极）在上电瞬间状态不确定，需要外部确定态。
3. **USB 下载判据**：上电时 `P3.0/P3.1/P3.2` **不能同时为低**，否则会进 USB 下载模式
   （文档另一处写判据是 P3.2 经 4K 上拉读取，`⚠校核B` —— 两处不一致，以手册为准）。

### ⚠ 文档里不可用的两条"编译选项"
`#pragma OPTIMIZE(9)` = Favor Speed、`#pragma __declspec(noinline)/always_inline` ——
**Keil C51 优化级只有 0~8（语法 `OPTIMIZE(8,S/T)`），且不支持 `__declspec`**。这两条疑为 AI 生成内容，直接删。

### (a) STC8H1K28-36I-LQFP32/QFN32 最小系统图（ch07/008）—— 本章最值钱的一张

**引脚复用组（图里成表给出，可辨认部分）**：

| 功能组 | 通道/脚 |
|---|---|
| ADC | `ADC0~ADC7` = **P1.0~P1.7**；另有内部 **1.19V** 通道 |
| 比较器 CMP | `CMP+` = P3.7、`CMP-` = P3.4、`CMPO` = P3.6；`ADCIN` = P3.6；内部基准 **1.18V** |
| UART1 | `RXD`=P3.0、`TXD`=P3.1（第二组候选含 P1.6/P1.7） |
| UART2 | `RXD2`=P1.0、`TXD2`=P1.1（另有候选脚，图上小字不清） |
| SPI | `SS/MOSI/MISO/SCLK` 有 **三组候选脚**（P1.x / P2.x / P3.x），由 `P_SW1` 的 `SPI_S[1:0]` 选 |
| I2C | `SCL/SDA` 多组候选（P3.3/P3.2 等），由 `P_SW2` 的 `I2C_S[1:0]` 选 |
| PWMA | `1N~4N` + `ETR/BRK/CMPO`，候选脚集中在 **P1.0~P1.7 / P2.0~P2.7**，由 `PWMA_PS(FEB2H)` 的 `C1PS~C4PS[1:0]` 选 |
| PWMB | `5P~8P` + `ETR/BRK/CMPO`，由 `PWMB_PS(FEB6H)` 的 `C5PS~C8PS[1:0]` 选 |
| 复位/时钟输出 | **`P5.4/nRST/MCLKO/PWME_2`**（同一脚三用） |

**图上的三条硬件注意（照抄要点）**：

1. **`ADC_Vref+` 必须有 2.4V ~ MCU Vcc 的外部参考**，或直接接 Vcc；**不能接有源驱动**。
2. **不需要软件模拟 I2C 时：上电/复位瞬间 `P3.2/P3.3` 不可同时为低**，
   否则芯片进入"软件模拟 I2C 等待下载"模式（表现为"上电不进用户程序"）。
   可在 **ISP 软件 F8 项**里取消"下次上电时使能软件模拟 I2C 模式"。
3. **`P5.4/nRST` 出厂默认是 P5.4 普通 I/O**，要当复位脚必须**烧录时取消"复位脚用作 I/O"**；
   且**改完要断电再上电才生效**；而"程序里改复位脚/I/O"是**立即生效** —— 两种生效时机不同，别混。
4. **GND 电流纪律**：为保证 ADC 与模拟电路精度，**不要让 I/O 驱动大电流（如 LED 推挽输出）走同一地线**，
   否则地线压降污染测量 ⇒ **ADC 采样期间 I/O 不驱动大电流**。

⇒ 第 2、3 条是 STC8H 特有的"上电行为坑"，与 PY32 的 `PC0=NRST`、GD32 的 `PB3/PB4=JTAG` 同族：
**症状都是"引脚不听 GPIO 配置"，根因在选项/复用而不是代码**。

## 2. 沁恒 CH 系列

### CH583（RISC-V + BLE5.3）规格
青稞 **V4A RV32IMAC**、32KB SRAM、**512KB Flash**、BLE5.3（2M/1M/500K/**125K** PHY）、RX **−98dBm**、TX **+6dBm**、
2×USB、4×UART、2×SPI、12 路 PWM、1×IIC、14 通道 12 位 ADC、14 路触摸、40 GPIO（**4 个 5V 容忍**）、最低 1.7V、AES-128、QFN48/28。
CH582 vs CH583：文档写"583 多一个 SPI、支持宽电压、48 脚固定"（`⚠校核C`：官方通常以引脚数/GPIO 数量区分，此说法无原文佐证）。

### Flash 映射与分区规划（**做 OTA/IAP 前必看**）
| 区 | 地址/容量（CH573/CH571） |
|---|---|
| CodeFlash | CH573 **448KB**(0~0x6FFFF)；CH573Q/CH571 **192KB**(0~0x2FFFF) |
| DataFlash | **32KB @ 0x70000** |
| BootLoader | 24KB @ 0x78000 |
| InfoFlash | 8KB @ 0x7E000 |
| SRAM | 18K（16K + 2K） |
| BLE SNV 默认 | **0x77E00（保留 512B）** |
| 示例冲突 | OTA 示例偏移 `0x7000`、IAP 示例偏移 `0x0000` ⇒ **合入同一工程必须互相避让** |
| 越界风险 | `BOOT_LOAD_CFG(0x7E000)`、`ROM_CFG_ADDR(0x7F000)` 在 DataFlash 32K **之外** |

### 时钟 / 中断 / ISR（RISC-V 特有，最容易翻车）
| 项 | 内容 |
|---|---|
| 时钟 | PLL = 32MHz × 15 = **480MHz** 再分频；`SYS_CLKTypeDef`：`0x40\|分频`，`0x48` = 60MHz；`GetSysClock()` 读 `R16_CLK_SYS_CFG(0x40001008)`；**20MHz 是 Flash 基本零等待点** |
| 定时器 | 4 × **26 位** TMR0~3（TMR1/2 带 DMA），计数时钟 = Fsys；另有 8 路 8 位 PWM4~11（周期固定 8 档） |
| 复用冲突 | 按优先级顺序仲裁：**PB23 RST# 优先、PWM11 最低** |
| **PFIC** | 256 中断、8 位优先级但**只有 [7:4] 有效**、数值小者优先、bit7 分两个抢占组、**只有 2 级嵌套**；**复位值 0 = 未配置 = 最高可编程优先级**；Reset/NMI/EXC 固定最高 |

### (a) **RST 脚被外设占用 → 板子一直复位**（ch08/015、016，本章最值钱的实战案例）

- 015：CH571F 引脚图局部 —— 第 **16 脚 = `PB2/RST#/TMR3`**，图里被红框标成 **`BUZ`**（蜂鸣器驱动）。

## 2.2 截图层补充 · 第 8 章 019–035（CH571/CH573 手册页，2026-10-16）

### (a) **上电默认主频只有 6.4 MHz**（ch08/026、027，本章最值钱的一条）

`R16 CLK_SYS_CFG`，地址 **`0x40001008`**，**复位值 `0x0005`**：

| 位 | 名 | 读写 | 含义（照抄） | 复位 |
|---|---|---|---|---|
| 15:8 | Reserved | RO | 保留 | 00h |
| 7:6 | `RB_CLK_SYS_MOD` | RWA | HCLK 系统时钟源模式：**`00`/`10` = `CK32M`（默认 32MHz）分频**；**`01` = PLL（默认 480MHz）分频**；**`11` = `CK32K`（默认 32KHz）作为 HCLK** | `00b` |
| 5 | Reserved | RO | 保留 | 0 |
| 4:0 | `RB_CLK_PLL_DIV` | RWA | HCLK 输出分频系数：**最小值 2，`0` 代表最大值 32，写 `1` 关闭 HCLK** | `00101b` |

计算公式（照抄）：
```
Fck32m = XT_32MHz
Fck32k = RB_CLK_OSC32K_XT ? XT_32KHz : RC_32KHz
Fpll   = Fck32m * 15 = 480MHz
Fsys   = (RB_CLK_SYS_MOD == 3) ? Fck32k
       : (RB_CLK_SYS_MOD[0] ? Fpll : Fck32m) / RB_CLK_PLL_DIV
上电默认：Fsys = Fck32m / RB_CLK_PLL_DIV = 32MHz / 5 = 6.4MHz
```
- 可配置范围（ch08/028）：**`Fsys` = 32KHz、2MHz~10MHz、15MHz~60MHz**。

⇒ **三条直接可用的结论**：
1. **不改时钟就是 6.4 MHz** ⇒ 所有"延时/波特率/定时器初值"按 6.4M 算才对；
   照抄例程里的 `SetSysClock(CLOCK_SYS_PLL_HCLK_48M)` 之类再沿用旧初值 = 快 7.5 倍。
2. **`RB_CLK_PLL_DIV` 写 `1` 会直接关 HCLK** ⇒ 这是"跑着跑着死掉、调试器也连不上"的一种自杀写法，
   分频值**只能写 0 或 ≥2**。
3. **`Fpll = 480MHz` 是内部固定 ×15**，对外只有 `Fpll/分频` ⇒ 想要 48M 就是 `/10`，
   想要 60M 上限就是 `/8` ⇒ **超出 2M~10M / 15~60M 两段的组合是不合法配置**。

### (b) 时钟树信号名（ch08/024，唯一副本；025 是同图加红笔标注）

| 环节 | 图里的信号名 |
|---|---|
| 32K 路 | `PA10/PA11 → X32K1/X32K0 →` 外部晶振 LSE → MUX → `CLK_0SC32K_XT` → RTC → `CK32K`；内部 32K / `LSI` 亦入 MUX；`PIN_XT32K_IE`、`CLK_XT32K_PON` |
| 高速路 | `X32MI/X32MO →` 外部晶振 HSE → **PLL 倍频器 ×15 = 480MHz（`Fpll`）** → 分频器 → MUX → `HCLK`；旁路 `Fpll/10 = 48MHz → CLK_SYS_MD0` |
| 外设门控 | USB→`SLP_CLK_USB`；ADC→`ADC_CLK_DIV`；BLE→`SLP_CLK_BLE`；Timer0~3→`SLP_CLK_TMRx`；SPI0→`SPI_CLOCK_DIV`→`SLP_CLK_SPI0`；PWM4~11→`PWM_CLOCK_DIV`→`SLP_CLK_PWMx`；UART0~3→`UARTx_DIV`→`SLP_CLK_UARTx`；RAM16K→`SLP_CLK_RAMX`；RAM2K→`SLP_CLK_RAM2K`；**PMU/CPU/GPIO/FlashROM/DMA ← `HCLK`**；右侧总线 `Fsys` |

⇒ **每个外设都有独立的 `SLP_CLK_*` 门控 + 自己的 `*_DIV`** ⇒ WCH 的低功耗不是"整体降频"而是**逐外设关时钟**；
   反过来，"外设没反应"要同时查 **门控位** 和 **分频位**，只开 GPIO 时钟不够。

### (d) PFIC 优先级寄存器（ch08/022，唯一副本）

| 寄存器 | 位域（高→低） |
|---|---|
| `IPRIOR0` | `[31:24]=PRI0_3`、`[23:16]=PRI0_2`、`[15:8]=PRI0_1`、`[7:0]=PRI0_0` |
| `IPRIORx`（通用） | `[31:24]=PRI0_(4x+3)`、`[23:16]=PRI0_(4x+2)`、`[15:8]=PRI0_(4x+1)`、`[7:0]=PRI0_(4x)` |
| `IPRIOR63` | `[31:24]=PRI0_255`、`[23:16]=PRI0_254`、`[15:8]=PRI0_253`、`[7:0]=PRI0_252` |

⇒ **`x = 0~63`、每寄存器装 4 个中断源** ⇒ 中断号 `n` 的优先级在 `IPRIOR[n/4]` 的第 `(n%4)*8` 位；
   这与 §2 里“CH32V 的 PFIC”是同一族机制（同为 `IPRIOR[n/4]` 的字节域排布）。
   **CH57x 实际定义到哪个中断号，本库暂无依据**（原文该处是空表，且我先前那版 §2.1 的"中断号 0~22"是编造的，已删）⇒
   用前查 `CH57x_common.h` 里的 `IRQn_Type`。

### (e) 选型表与"复用功能在前优先"（ch08/020、021、029、030）

- 选型表列头（020，照抄）：`Part NO. | Freq | Flash | SRAM | DataFlash | BLE | USB | TouchKey/ADC | Timer | PWM | UART/SPI/IIC | GPIO | RTC/WDG`
- **CH573 行（021，逐列照抄）**：`CH573 | 20MHz | 448K | 18K | 32K | 4.2 | 1*H/1*D | 10/10*12b | 4*26b | 12 | 4/1/- | 22 | √/√`
  > ⚠校核：该行 `Freq` 写 **20MHz**，而 (a) 的 `Fsys` 范围到 **60MHz**、(b) 默认 32M/480M PLL
  > ⇒ 选型表的 `Freq` 疑为"某典型/默认档"而非最大值，**不要拿它当主频上限**。
  > 另 `Flash 448K` 与 (c) 的 `CODE/ROM` 顶 `0x0008 0000`（512K 编址）也不等价 ⇒ 编址空间 ≠ 实配容量。
- **GPIO 复用的关键概念（029）**：引脚表有一列叫 **`复用功能在前优先`** ——
  示例 `PA8`（QFN32 第 9 脚 / QFN28 第 6 脚，类型 `I/O/A`）标注 **`RxD1 / A1IN12`**，
  含义：PA8 是通用双向 I/O，`RxD1` = UART1 数据输入，`A1IN12` = ADC 通道 12；
  **"在前优先"= 上电/复位后该脚默认承担列在前的复用功能**。
  > ⚠校核：小标题写"GPIO 的复用与重映射"，**图内容其实是"1.2 引脚描述"表** ⇒ 标题与图不符。
- 电源脚（029，照抄）：`GND`、`VDC1D`、`VSW`、`VDD33`(=VBAT)、`V1033`、`VIN5`（**5V 输入，内部稳压后输出到 V1033**）。
- 定时器引脚的 GPIO 模式（030/031，表 7-1）：**输入捕捉通道 → 浮空/上拉/下拉输入；输出 PWM 通道 → 推挽输出**。

⇒ **"复用在前优先"解释了 WCH 的一个常见现象：新板子上电 UART1 的 RX 脚（PA8/PA9 类）默认已是串口功能，
   不配 GPIO 也能收**；反过来说，**想当普通 IO 用时必须显式改复用**，否则输出会被外设抢走。
⇒ `VIN5 → V1033` 意味着 **5V 供电时内核电压由片内稳压器给出**，`V1033` 脚要接去耦电容，不能悬空。
