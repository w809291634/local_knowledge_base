# GD32（兆易创新）与 STM32 的差异

> 原文只覆盖 **GD32F4xx（F407）**；GD32F1/F3 系列未展开。`⚠校核` 见 `embedded/mcu-peripherals/ERRATA-*.md`。

## 1. 时钟树（对应 STM32F4 的位置）

| 项 | GD32 说法 | 与 STM32 的差异点 |
|---|---|---|
| 内部 RC | `IRC16M`、**`IRC48M`**、`IRC32K` | 名字不同；`IRC48M` 相当于 USB/SADI 用的 48M RC |
| 晶振 | `HXTAL` / `LXTAL` | ↔ HSE / LSE |
| PLL | **3 个 PLL** | STM32F4 是 PLLI2S/PLLSAI 等专用 PLL，用途划分不同 |
| 上限 | `CK_SYS` 最大 **240MHz**；AHB/APB2/APB1 = 240/120/60MHz | 比 STM32F407 的 168MHz 高一档，**同代码直接跑 240M 要先确认外设时序** |
| SysTick | = `HCLK/8`（与 STM32 同） | 一致 |
| ADC 时钟 | 由 **APB2 经 2/4/6/8 分** 或 **AHB 经 5/6/10/20 分**，由 `ADC_SYNCCTL.ADCCK` 选择 | STM32 是 ADCPRE(RCC_ADCCLK) 一套，**位域名不同且多一个 AHB 分频源** |
| 定时器时钟 | `RCU_CFG1.TIMERSEL` 选 `CK_APBx / 2x / 4x` | STM32 由"APB 分频≠1 则自动 ×2"隐式决定，**GD32 是显式可选** ⇒ 移植时算错倍频 |

## 2. 工程与库配置（照做即可跑）

| 项 | 内容 |
|---|---|
| 晶振宏 | `HXTAL_VALUE` **默认 25000000** ⇒ 用 8M 晶振必须在工程宏里改成 `HXTAL_VALUE=8000000` |
| 典型预处理宏 | `USE_STDPERIPH_DRIVER, GD32F407, __FPU_USED, HXTAL_VALUE=8000000` |
| 时钟档位宏 | `__SYSTEM_CLOCK_240M_PLL_8M_HXTAL` → 调 `system_clock_240m_8m_hxtal()` |
| 频率更新 | `SystemCoreClockUpdate()` 读 `RCU_CFG0` / `RCU_PLL` 计算 |
| Keil 支持包 | 装 `GigaDevice.GD32F4xx_AddOn.3.0.3.exe` + `DFP.3.0.4.pack` |
| 换库要替换的文件 | FWLIB → `standard_peripheral`、`system_gd32f4xx.c`、`startup_gd32f407_427.s`、`gd32f4xx_it.c/h`、新增 `gd32f4xx_libopt.h` |
| 宏改名 | `STM32F40XX` → `GD32F407` |
| 优先级分组 | `nvic_priority_group_set(NVIC_PRIGROUP_PRE2_SUB2)` |
| 版本门槛 | Keil4 ≥ 4.74、Keil5 ≥ 5.14、IAR ≥ 7.0 |
| 调试器 | J-Link / ST-Link（官方口径"仅完美支持 F1" `⚠校核C`）/ U-Link / **GD-Link** |

## 3. AF（复用功能）表与寄存器名差异 —— **最容易静默出错**

| 项 | GD32 | STM32 |
|---|---|---|
| 复用寄存器 | `GPIOx_AFSEL0 / AFSEL1` | `AFRL / AFRH` |
| AF 编号 | **完全另一套**：AF1=TIMER0/1、AF5=SPI0~5、AF7=USART0/1/2+SPI1/2、AF8=UART3/4+USART5/6/7、AF10=USB_FS/HS、AF13=DCI、AF14=TLI | STM32F4：AF1=I2C、AF7=USART1..6/SPI1..3 等 |
| 结论 | **STM32 的 `GPIO_AFx_y` 编号不能直接搬到 GD32**，引脚复用异常（无错误、只是不通）多半就是这里 | — |
| `⚠校核` | 文档抄的库注释里 AF5/AF6 的 SPI 范围重叠、AF9 混含 CAN/I2C/TLI ⇒ 属库注释原样转录，**必须回查手册 AF 表** | — |

## 4. 用 STM32 库/代码直接换到 GD32 的**四个具体不兼容点**（本篇最有用的一段）

| # | 症状 | 根因 | 对策 |
|---|---|---|---|
| 1 | **HSE 起振失败、PLL 锁不住**，系统跑在内部 RC 上 | GD32 沿用 STM32 的 `HSE_STARTUP_TIMEOUT` 太短 | 把 `HSE_STARTUP_TIMEOUT` 从 `0x0500` 提到 **`0xFFFF`**（文档写的 `0x05000` 与出处 `stm32f10x_rcc.c` 存疑 `⚠校核B`，按 0xFFFF 用即可） |
| 2 | **SPI 速率不对 / 改速无效** | 自写的 `SPI1_SetSpeed`（`CR1 &= 0XFFC7` 再写 BR）在 GD32 上行为异常 | **删掉该函数**，改回标准 `spi_i2s_deinit/spi_init`；重配前必须 `SPI_Cmd(SPIx, DISABLE)` → 改 → `ENABLE` |
| 3 | **刷屏特别慢（FSMC LCD）** | `FSMC_DataSetupTime = 0` 在 GD32 上不成立 | 改成 **≥ 1**（至少 1 个 HCLK 的建立时间） |
| 4 | 命名层 | `RCC↔RCU`、`TIM↔TIMER`；`USART` 同名但**寄存器位不同**；`HXTAL/IRC ↔ HSE/HSI` | 全局改名只解决编译，**行为差异要按 §1/§3 逐项核** |

### 5.1 时钟树全图（ch03/003）—— 移植算错倍频时看这张

| 节点 | 图里的取值/规则（照抄） |
|---|---|
| 系统切换 | `SCS[1:0]`：**00 = `CK_IRC16M`、01 = `CK_HXTAL`、10 = `CK_PLLP`**，旁边有独立 **Clock Monitor** 模块 |
| 上限 | `CK_SYS` **240 MHz max** → `AHB Prescaler /1,2…512` → `CK_AHB` **240 MHz max** |
| APB | `APB1 Prescaler /1,2,4,8,16` → **`CK_APB1` 60 MHz max**；`APB2 Prescaler /1,2,4,8,16` → **`CK_APB2` 120 MHz max** |
| **定时器分两组** | `TIMER1,2,3,4,5,6,11,12,13` 挂 **APB1**，`TIMER0,7,8,9,10` 挂 **APB2**；两组都再经 `x1 / x2 / x4` → `CK_TIMERx` **240 MHz max** |
| ADC 两条路 | `ADC Prescaler /2,4,6,8`（来自 APB 侧）与 `ADC Prescaler /5,6,10,20`（来自 `CK48M`/AHB 侧）→ `CK_ADCx` **40 MHz max**，送 ADC0/1/2 |
| 48M 域 | 独立 **`48 MHz IRC48M`** + **`CTC`** 模块 → `CK_CTC`；`PLL48SEL`、`ISSSEL` 选择后送 **USBFS / USHS / TRNG / SDIO / CK_I2Sx** |
| 时钟输出脚 | `CKOUT0DIV /1,2,3,4,5` + `CKOUT0SEL[1:0]`：**00 `CK_IRC16M`、01 `CK_LXTAL`、10 `CK_HXTAL`、11 `CK_PLLP`**；`CKOUT1SEL[1:0]`：**00 `CK_SYS`、01 `CK_PLL2R`、10 `CK_HXTAL`、11 `CK_PLLP`**（输出到 `CK_OUT0`/`CK_OUT1` 脚） |
| RTC/看门狗 | `RTCSRC[1:0]` 在 `32.768 kHz LXTAL OSC`（经 `/2 或 /1` 的 `CK_HXTAL` 支路）与 `32 kHz IRC32K` 之间选 → `CK_RTC`、`CK_FWDGT` |
| 以太网 | `ENET_TX_CLK` 有 **`/2 或 /0`** 两档 + **`ENET_PHY_SEL`** + `ENET_RX_CLK`；`ENETPHY` 缓冲 |
| USB HS | 图上标注 **`USB HS PHY clock 24MHz to 60MHz`** → 经 `ENUSB PHY` 缓冲 → `CK_USBHS_ULPI` |
| I2S 外部时钟 | `I2S_CKIN` 可经 `DIV`/PLL 支路进入 `ISSSEL` ⇒ **I2S 可用外部输入时钟**，STM32 侧对应 `I2S_CKIN` 但选路不同 |

**三条直接可用的结论**：
1. §1 表里"AHB/APB2/APB1 = 240/120/60"由本图证实，且**定时器倍频是显式 x1/x2/x4**（不是 STM32 的隐式 ×2）⇒
   移植时 `TIMER` 的 ARR 值必须按 `CK_TIMERx` 重算，**这是"定时周期差 2/4 倍"的第一嫌疑**。
2. **`TIMER0` 才是挂在 APB2 的高级定时器**（= STM32 的 TIM1）⇒ 换库时 `TIM1→TIMER0`、`TIM8→TIMER7`，
   写成 `TIMER1` 会静默落到 APB1 组，倍频与引脚全错。
3. **ADC 上限 40MHz、且有两个分频链**（§1 已记），本图给出分频档位：`/2,4,6,8` 与 `/5,6,10,20` ⇒
   改 ADC 采样率时**两条链都要看**，只改一条常常没效果。

### 5.2 晶振接法（ch03/001，文字层无）

原理图局部：`Y2` 标 **16M**，`1=IN`、`3=OUT`，网络名 **`PH0-OSC_IN` / `PH1-OSC_OUT`**。

- ⇒ GD32F4 的 `HXTAL` 在 **PH0/PH1**：**这两个脚被晶振占用，不能当普通 GPIO 用**（与 STM32F4 的 HSE 在 PH0/PH1 一致，
  但**移植时最容易忘**：STM32 工程里若把 PH0/PH1 当普通 IO 用过，换 GD32 后表现是"起振失败或该脚无输出"）。
- ⇒ 该板是 **16 MHz**，而 §2 写 `HXTAL_VALUE` 默认 25 MHz ⇒ **宏必须改成 16000000**，
  否则 `CK_SYS` 会按 25/16 的比例整体跑偏（240M 变 153.6M，或 PLL 直接锁不住）。

### 5.3 器件架构框图（ch03/002，可辨认部分）

可辨认：`ARM Cortex-M4`、**`Fmax 240MHz`**、`Flash Memory`、`SRAM0…SRAM5`、`PMU`、`BOR`、
`EXMC`、**`EDMA` 与 `MDMA` 两个 DMA**、`AHB2 Peripherals: TRNG / DCI / USBFS / USBHS`、
`ADC0~ADC2`（**3 个 ADC**，注明 `Powered by Vref`）、`DAC`、`CAN1/CAN2`、`I2C0~I2C2`、`QEI0`、
`SDIO`、`SPI1/SPI2/SPI3…`、`USART0~2 / UART3~4`、`TIMER0~TIMER13`、`LVD`、`HXTAL`、`LXTAL`、
`FWDGT`、`PKD?/WWDG?`、`RTC`、`IRC16M`、`IRC32K`、`PLL0/PLL1/PLL2`、`AHB Interconnect Matrix (Fmax=240MHz)`。
其余小标签分辨率不足（`截图不清，未提取`）。

**值得记住的两点**：① **`MDMA` + `EDMA` 双 DMA**（STM32F4 只有一组 DMA 流）⇒ 内存到内存的大块搬运可分流；
② **`QEI0` 独立列出** ⇒ GD32 把正交编码器接口作为可见资源，STM32 侧是 TIM 的从模式，**移植时不要漏配**。

## 6. 使用建议

- 从 STM32F4 迁到 GD32F4：**先跑默认时钟不改成 240MHz**，确认外设（尤其 SPI/ADC/LCD）都正常，再逐档提频。
- 凡是"配置了没反应、又不报错"的外设，第一个怀疑 **AF 编号**，第二个怀疑 **时钟源选择位（ADC/TIM 的 GD32 专有选择）**。
- GD32 的 ADC 时钟有两个来源，示波器量 ADC 触发与转换间隔能立刻确认实际生效的是哪个分频。
