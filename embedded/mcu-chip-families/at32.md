# AT32（雅特力 ArteryTek）要点与 STM32 差异

> 原文覆盖 **AT32F435/F437** 为主 + 少量 F403A。`⚠校核` 见 `embedded/mcu-peripherals/ERRATA-*.md`。

## 1. 选型表（照抄）

| 型号 | 内核/主频 | Flash | SRAM | 特色外设 | 电压/温度 |
|---|---|---|---|---|---|
| **F435 / F437** | M4F **288MHz** | 256 / 1024 / **4032KB** | 默认 384KB、最大 512KB | 3×5.33Msps ADC、2 CAN、2 QSPI、2 OTG、**XMC**、**DVP 8~14bit** | 2.6~3.6V、**IO 耐 5V**、−40~105°C |
| F402 | 216MHz | — | 102KB | — | — |
| F011 / L021 | **M0+ 80MHz** | — | 9KB | 低功率位 | — |

**板卡与工程不一致**：文中板卡是 `AT32F435CGT7`(LQFP48)，但工程路径/启动文件用的是 `AT32F435CGU7`(QFN48)
⇒ **封装不同引脚定义不同**，移植前先核对实物丝印。`⚠校核B`

## 2. 时钟与命名（与 STM32 的对齐表）

| AT32 | STM32 | 备注 |
|---|---|---|
| `HICK = 8MHz` | HSI | |
| `HEXT`（宏 `HEXT_VALUE`，默认 8M） | HSE / `HSE_VALUE` | **改晶振只改这个宏** |
| 内部 48M RC | HSI48/IRC48M | 精度：`ACC` 25°C 1%、全温 2.5% |
| `LXT = 32.768k`、`LIRC = 40k` | LSE / LSI | |
| **`CRM`** | `RCC` | `crm_periph_clock_enable(CRM_SPI1_PERIPH_CLOCK)` |
| **`TMR`** | `TIM` | |
| **`EXINT`** | `EXTI` | |
| **`IOMUX / MUXL / MUXH`** | `AFIO / AFRL / AFRH` | |
| `gpio_pin_mux_config(GPIOA, GPIO_PINS_SOURCE5, GPIO_MUX_5)` | `HAL_GPIO_Init` 里填 `GPIO_AFxx` | **复用是"引脚→MUX 编号"显式配置** |
| `spi_init / spi_enable(SPI1, TRUE)` | `HAL_SPI_Init/Enable` | |
| **`dmamux_init(DMA1MUX_CHANNEL1, DMAMUX_DMAREQ_ID_SPI1_TX)`** | `__HAL_LINKDMA` + Stream/Channel | **AT32 也是 DMAMUX 模型**（127 个请求源），与 STM32F4 的 Stream+CHSEL 思路不同 |
| `nvic_priority_group_config(NVIC_PRIORITY_GROUP_4)` | `HAL_NVIC_SetPriorityGrouping` | |
| `SystemInit()` | 同名 | **只把 CRM 复位到 HICK，不配 PLL** ⇒ PLL 配置在 `system_at32f435_437.c` 的档位函数里 |
| `system_core_clock_update()` | `SystemCoreClockUpdate` | 内部用 `pll_fr_table{1,2,4,8,16,32}`、`sys_ahb_div_table`；`hick_to_sclk && hickdiv` ⇒ HICK×6 |

**PLL 参数**：`fPLL = (f_in × ns) / (ms × fr)`；F435 跑 288M 用 `ns=144, ms=1, fr=4` 或 `ns=72, ms=1, fr=2`。

## 3. Flash 布局（照抄，容量算法不同）

| 容量 | 组织 |
|---|---|
| 4032K | bank1 2048K（32 block × 16 sector × 4K）+ bank2 1984K（31×16×4K）；**用户数据区 4K** |
| 1024K | 两片各 512K（8×32×2K）；**数据区 512B** |
| 448K | 仅 bank1：7×16×4K |
| 256K | 4×32×2K |
| ISP 通道 | **USART1 / USART2 / USB-DFU** |

## 4. ZW / NZW（零等待区）——AT32 最特殊、最容易配错的一块

| 项 | 内容 |
|---|---|
| 概念 | Flash 分**零等待区 ZW**（全速执行）与 **NZW**（**执行速率约为 ZW 的 0.4 倍**，240MHz→约 96MHz） |
| F403A 例子 | 默认 SRAM 96K → ZW 256K(`0x0800_0000~0x0803_FFFF`) + NZW 768K；SRAM 224K → ZW128K / NZW896K |
| F435/437 | SRAM 选 512K 模式 ⇒ ZW **只能 128K**；选 128K 模式 ⇒ ZW 可到 512K；通过 `EOPB0` 配置 |
| 系统数据字节 | **高字节必须是低字节的反码**，否则报 `USDERR`；更新后要**复位**才生效 |
| 性能问题定位顺序 | 跑不满主频/取指慢 ⇒ 先确认代码段在不在 ZW，再看是否在 NZW 上执行 |
| `⚠校核B` | 文档一处"不能动态修改 ZW/NZW 分界（除非支持 EOPB）"与同章"SRAM 动态配置改变 ZW 容量 / EOPB0 可设"矛盾 |
| `⚠校核C` | 文档贴的"AI 解释"称 CoreMark≈1080、288MHz≈280MIPS、CoreMark/MHz≈4.5 ⇒ **M4 的 CoreMark/MHz 实际约 1.2~1.5，4.5 明显越界**；NZW≈430 恰为 ZW 理论值。别拿这组数做选型依据 |

## 5. 外设映射与冲突（实操）

| 项 | 内容 |
|---|---|
| SPI 引脚 | SPI1 = PA5/6/7 **MUX5**；SPI2 = PB13/14/15 **MUX5**；**SPI3 = PB3/4/5 MUX6**（不是 5！） |
| SPI 分频 | 枚举值**非连续**（`⚠校核`：文档给的 `SPI_MCLK_DIV_3 = 0x0A` 属 AI 转录、无原文佐证，用前查 `at32f435_437_spi.h`） |
| DMA | 2 个控制器 × 7 通道 + DMAMUX；`buffer_size` 是 **16 位（≤65535）**；`wk_dma_channel_config()` 之后再设 `paddr/maddr/dtcnt` |
| ADC | **ADC1/2/3 共用一个中断向量 `ADC1_2_3_IRQHandler`** ⇒ 中断里必须自己判来源 |
| GPIO 时钟 | **必须先开 GPIO 时钟**（文档写成"通过 RCC"，AT32 应为 `crm_periph_clock_enable(CRM_GPIOx_PERIPH_CLOCK)` `⚠校核A`） |
| 工具 | `AT32_Work_Bench` 生成 `wk_*` 前缀的配置代码 |
| Keil DFP | `Keil.AT32F4xx_DFP.1.3.7.pack` + `ArteryTek.AT32F435_437_DFP.2.1.1.pack` |

## 6. 遗留/未验证（不要当结论）

- 作者自标：低速模式下 CKS 全 1 时串口不打印"不知道具体原因"；"后期再寻找 SPI 的 LCD 示例代码"；
  `kprintf` 不打印需注释掉低功耗相关代码（经验性，单点复现）。
- `Display_SPI_DMA_Send` 的 >65535 分支：先递归再更新 `Disp_DMA_CurrentPoint`，指针/长度逻辑不自洽，
  作者自己也注了"没有发送保护""会嵌套使用" ⇒ **该示例不可直接搬用**。

> 本节只记"看图才成立"的结论与对既有各节的修正。

| # | 结论 | 影响 |
|---|---|---|
| 1 | §3 的 Flash 布局**被图逐行证实**（4032K = bank1 2048K + bank2 1984K、每扇区 4K；1024K = 两片各 512K、每扇区 2K；信息块 16K 启动代码 + 4K/512B 用户区） | 从"照抄文字"升级为"有图证"，可放心用于 IAP 分区计算 |
| 2 | §4 的 F435/437 说法**被表 5-6 证实**：`000 → SRAM 512K + ZW 128K`、`110/111 → SRAM 128K + ZW 512K`、**`010 = 出厂默认 384K + 256K`**；且**改写前提是"安全库区未启动"** | 补上原文缺的**默认档**与**改写前提**：已启用安全库（ECP）的芯片改不动这个分配 |
| 3 | 256K / 448K / 1024K+ 三档的**位宽不同**（256K 用位 [1:0]，448K 与 1024K+ 用位 [2:0]），448K 档还有"101/110/111 都落到 192K+448K"的并档 | 写配置代码时**不能统一按 3 位处理**，要按容量档分支 |
| 4 | **跑 288 MHz 有供电前提**：WorkBench 红字 `Usage limited: Temperature range -40~85 degree, VDD must over 3.0V` | 电池/3.0V 临界供电的产品**不能按 288M 设计**；§2 的时钟表补上这条约束 |
| 5 | APB 外设 **144 MHz 上限**、定时器 `apb1/apb2 tmr = 288 MHz`（工具里显示为 `/2(*2)` 自动倍频） | 与 GD32 的"显式 x1/x2/x4"不同：**AT32 是自动 ×2**，算定时器分频要用 `tmr` 值不是 `peripheral` 值 |
| 6 | `SysTick = sclk/8 = 36 MHz`（图里 `systick(/8)=36.000`） | 用 SysTick 做微秒计时时**除数是 8**，与 §2 一致，图给出实际值 |
| 7 | **SPI 与 I2S 在 IOMUX 里共用同一格**（`SPI1_SCK/I2S1_CK` 等），且 `MUX15` 恒为 `EVENTOUT`；PA13/PA14 的 `MUX0` 就是 SWD | 配成非 0 MUX 即占用；**调试脚被 SPI 抢走**是 AT32/GD32 通用事故 |
| 8 | SPI 模式在工具里是 **11 个下拉项**（含"主机全双工仅接收/仅发送"这类半工变体），硬件 CS 分"输入信号/输出信号"两项 | 文字层只写"主/从、全/半双工"，**仅收/仅发这两档在移植时最容易漏**（LIN/单线应用会用到） |
| 9 | SPI1 驱动 LCD 的实测勾选：`主机全双工模式` + **硬件 CS 关闭 / CS 信号类型 = `软件CS`** + **`8位` 帧** + `MSB先传输` + `低电平/第一个边沿`（模式 0）+ **分频系数 8 → 18 MHz（只读自动算）**，调试接口 `SWD`、SWO 不勾 | 这是一份可照配的起点；**DC 脚要自己用 GPIO 控制**（软件 CS），别以为硬件 NSS 在管 |
| 10 | DMA 中断只有三组：**半传输 `HDTF`/`HDTFC`/`HDTIEN`、传输完成 `FDTF`/`FDTFC`/`FDTIEN`、传输错误 `DTERRF`/`DTERRFC`/`DTERRIEN`**；**没有"块传输完成"类事件** | ISR 里**写 `xxFC` 清标志**（不是清 `xxF`）；从 STM32 搬来的"TC/HT/TE 写 0 清"直觉会漏清 |
| 11 | WorkBench 选项卡是 `参数设置 \| GPIO设置 \| 中断设置 \| NVIC设置 \| **DMA设置** \| **EDMA设置**` | **DMA 与 EDMA 是两套资源、两个页**；§5 只讲了 DMAMUX ⇒ 大流量（XMC/DVP/QSPI）要另看 EDMA |
| 12 | 表 9-3 是 **`DMA1MUX` 一列 + `DMAMUX` 三列并排**：同一外设**有两个编号**（`SPI1_TX` = DMA1 侧 **11**、DMAMUX 侧 **107**；`SPI1_RX` = 10 / 106） | 填 `request_id` 前**必须先定用哪个控制器**；另有 `TIMR4_TRIG` 在 126/127 重复、`SPI3_TX` 出现在 15/77/109 ⇒ 见 ERRATA H2 |
| 13 | 表 9-4 的触发/同步输入**只有两类**：`exit_gpio[0..15]`（编号 0~15）与 `DMA_MUXext1~7`（16~22），**23~31 全 reserved** | "外部信号触发一次 DMA"用 `exit_gpio[n]`；`DMA_MUXext` 是软触发线；**没有 I2S 触发源** |
| 14 | 6.2.8 表里 `ODRV[1:0]` 列是**空的**，驱动强度实际由 **`HDRV`** 承担，且 `000/010/011` 三档说明文字相同（"适中"） | 中间档措辞几乎肯定 OCR 串行 ⇒ **驱动强度回手册**，别按本表选档 |
| 15 | Keil 两个 DFP 包（`Keil.AT32F4xx_DFP 1.3.7` 与 `ArteryTek.AT32F435_437_DFP 2.1.1`）**是否互斥，图里没有任何提示**；1.3.7 的日期在两图里还分别是 2015-02-19 / 2021-05-19 | 网传"必须先卸载旧包"属**推断未验证**；§5 只保留"两个包都要装"的事实 |
