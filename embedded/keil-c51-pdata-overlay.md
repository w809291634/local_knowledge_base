# Keil C51：pdata 跨页（L18）与 Overlay 重入（L15）的区别与排查

> 适用：Keil C51（8051 内核，如 STC8G/STC8H），COMPACT 内存模型
> 来源：WKW 手持低频工程实机排查（"加一行打印就开不了机"）
> 目标：把"编译能过但开机随机死机 / 偶发数据错乱"这两类链接期隐患区分清楚，并给出可落地的判断方法。

## 结论先行

- C51 的 **COMPACT 模型把所有局部变量和函数参数都放进 `pdata`**，而 `pdata` **一次只能覆盖一页（256 字节）**，所以 pdata 总量超 256 就会踩 L18。
- **`L18 SEGMENT DOES NOT FIT IN PDATA PAGE` 一旦出现，绝不可能是"无害警告"**：溢出的 `_PDATA_GROUP_` 会被链接器放到第 1 页，而编译器生成的 `MOVX @Ri` 页号恒为 0 → 这些变量**读写地址少 0x100**，踩到别人的变量上。
- 两个警告是**互相独立**的两类问题，修好一个不会顺带修好另一个：
  - `L15 MULTIPLE CALL TO SEGMENT` → **Overlay（时间）问题**：同一函数被中断和主循环共用局部变量空间。
  - `L18` → **地址问题**：变量放到了指令够不到的地方。
- 排查动作固定两条：**① 看编译警告有没有 L15/L18；② 打开 map 文件看 `_PDATA_GROUP_` 的"起始地址 + 长度"是否 ≤ 0x0100。**

---

## 1. pdata 跨页（L18）

### 1.1 原理：pdata 一次只能看一页

8051 访问 `pdata` 用这条指令：

```asm
MOVX A, @R0        ; 地址 = (P2 << 8) | R0
```

- 低 8 位（页内偏移）写在指令里；
- **高 8 位（页号）只能由 P2 寄存器在运行时提供**，指令里编码不了。

工程里若 P2 恒为 0（本工程 LED 由硬件 LED 驱动外设管，CPU 不写 P2），则：

```
能访问到的地址 = (0 << 8) | xx = 0x00xx     只有第 0 页
```

由此得到硬规则：**所有 pdata 变量加起来不能超过 256 字节**。
（把 P2 改成 1 能看第 1 页，但第 0 页的变量就又看不到了 —— **一次只能看一页**，所以总量超了无解。）

### 1.2 溢出后发生了什么

链接器发现第 0 页装满，就把装不下的放入 `_PDATA_GROUP_` 段并放到 `0x0100` 起（第 1 页），同时报 L18。
**但编译器不知道这件事**，它照样生成 `MOVX @Ri`（页号 0），于是：

```
变量真实地址              实际被访问的地址    后果
0x0100  i              →  0x0000             循环变量被别人踩
0x0113  result         →  0x0013             判断结果变成垃圾
0x010C  GPIO_InitStruct→  0x000C             GPIO 配置写错地方
0x011B  pData          →  0x001B             指针是垃圾 → 跑飞
```

最小例子：A 需 200 字节、B 需 100 字节，合计 300 > 256。

| 变量 | 链接器实际放置 | 说明 |
|---|---|---|
| A | 0x0000~0x00C7 | 第 0 页 ✅ |
| B | 0x0100~0x0163 | 第 1 页 ❌ |

读 B 的第 0 字节 → 生成 `R0=0x00; MOVX A,@R0` → 实际地址 `0x0000` → **读到的是 A 的第 0 字节**。写 B 就是改写 A。

### 1.3 现象特征

- **不是"内存不够"，而是"变量被静默写到错误地址"**。
- 对**掉进第 1 页的那部分变量**：该版本里**每次访问必错**（确定性，与中断/时序/调用关系无关）。
- 对**整个系统**：看起来偶发，因为
  1. 每次编译**掉进去的变量不一样**（链接器放置顺序随代码变化）；
  2. 被写坏的那段内存可能恰好没人用，或写坏的值恰好无害。
- 所以症状与"改动量"不成比例：**加一行打印也能弄死，删一堆反而能开机**。
- 极端案例：pdata 用量正好卡在 256（`_PDATA_GROUP_` 结束于 0xFF，零余量），此后任何改动只要让 pdata 多 1 字节，就立刻跨页 → 开机即死。

### 1.4 判断方法

1. 编译输出里搜 `L18` / `SEGMENT DOES NOT FIT IN PDATA PAGE`。
2. 打开 `list/*.m51`（map），看 pdata 分布：

```
XDATA 00B2H 0023H INPAGE _PDATA_GROUP_    # 0xB2+0x23 = 0xD5  ✅ 安全（有 42 字节余量）
XDATA 0100H 0027H INPAGE _PDATA_GROUP_    # 起始就是 0x100     ❌ 必然死机
```

判定式：**`_PDATA_GROUP_` 的起始地址 + 长度 ≤ 0x0100**。
另可看各模块 `?PD?<模块名>` 段（INPAGE），它们就是 pdata 的实际占用。

### 1.5 修复方法

| 方案 | 做法 | 代价 |
|---|---|---|
| 腾空间（推荐，改动小） | 给大块**文件内静态变量**显式加 `xdata`，把 pdata 占用压回 256 以下并留出余量 | 该变量访存变慢一点；必须是 `static` 或同步改所有 extern 声明，否则内存空间不匹配会踩得更狠 |
| 换模型（根治） | uvproj 里 `<MemoryModel>1</MemoryModel>`（COMPACT）改为 `2`（LARGE），变量/局部全部进 xdata，用 `MOVX @DPTR` 访问 | 全局访存变慢，需回归时序敏感功能（中断、激光、串口） |

本项目实际处置：把 `bsp_key.c` 的 `static KEY_T s_tBtn[]`（36B）与 `static KEY_FIFO_T s_tKey`（6B）加 `xdata`，pdata 占用从 256 降到 214，`_PDATA_GROUP_` 起始由 `0x00DC` 回落到 `0x00B2`，L18 消失，开机恢复。

## 2. Overlay 重入（L15）

### 2.1 原理

Keil 链接器做**覆盖分析**：若干函数的局部变量/参数**复用同一片地址**，前提是"这些函数不会同时活跃"。它靠调用图推断，以下情况会破坏该前提：

- **中断服务程序里调用了主循环也在调用的函数**；
- 通过函数指针调用、递归等。

一旦前提被破坏，局部变量会被对方冲掉。

```asm
*** WARNING L15: MULTIPLE CALL TO SEGMENT
    SEGMENT: ?PR?_BSP_UARTSEND?BSP_UART
    CALLER1: ?PR?TIMER3_INT?MAIN      ← 1ms 中断里
    CALLER2: ?C_C51STARTUP            ← 主循环里
```

含义：`bsp_UartSend` 的局部变量（`i`、`freeSpace`）在主循环和中断里共用同一片地址 —— 中断打断主循环的发送时把它们冲掉。

### 2.2 现象特征

- **时序相关、偶发**：要中断恰好插进那个窗口才踩。
- 表现为偶发的数据错乱、偶发的协议应答失败。

### 2.3 修复方法

**让"被多上下文调用的函数"只有一个调用上下文**：

- 中断里**只置标志 / 改状态、递减计数**，真正的发送、打印、耗时动作放到主循环执行；
- 或给该函数加 `reentrant`（栈上分配局部变量，代价是速度与栈空间）。

本项目实际处置：把 1ms 中断里 `bsp_BT_Tick1ms()` 的发送/改状态动作挪到主循环，中断只递减 u8 超时计数（u8 读取原子，避免 u16 撕裂），L15 消失。

## 3. 两者区别对照

| | Overlay（L15） | pdata 跨页（L18） |
|---|---|---|
| 本质 | 省内存的**分配优化** | **寻址范围**不匹配 |
| 影响对象 | 只影响局部变量/参数 | 局部变量 **+ 模块内静态变量** |
| 出错的提前量 | "这些函数不会同时活跃" | "所有 pdata 变量能装进一页" |
| 前提被谁打破 | 中断里调共享函数、函数指针、递归 | 总量超过 256 字节 |
| 出错性质 | **时序相关、偶发** | **确定性**：该版本里这些变量每次访问必错 |
| 波及面 | 那几个"多调用者"函数的局部变量 | 所有掉进 `_PDATA_GROUP_` 的变量，遍布各模块 |
| 典型表现 | 偶发数据错乱、偶发应答失败 | 开机即死、功能直接不正常 |
| 修法 | 别在中断里调共享函数 | 腾 pdata 空间（变量改 xdata）或换 LARGE 模型 |

一句话：Overlay 是"**几个人分时共用一个更衣柜，撞上了才乱**"；pdata 跨页是"**柜子明明在 102，钥匙上却刻着 002，每次开的都是别人的柜子**"。

## 4. 排查清单（8051 / Keil C51 项目通用）

1. 编译后**先看警告**：出现 `L15` 或 `L18`，都当作**必须处理**的错误，不要当噪音。
2. 打开 **map 文件**（Options→Listing 勾选 Linker Listing / 生成 .m51）：
   - 查 `_PDATA_GROUP_` 起始地址 + 长度 ≤ 0x0100；
   - 查各 `?PD?<模块>` 段看 pdata 占用排行，找最大的模块腾空间。
3. 中断服务程序里**只做标志/计数**，不做发送、打印、长循环、阻塞等待。
4. 大块数组/结构体（按键状态、缓冲区、点阵缓存等）**显式加 `xdata`**，既省 pdata 又避开跨页。
5. 变量改内存空间时，**定义和所有 `extern` 声明必须一起改**（C51 里内存空间不匹配会静默错地址）。
6. 每版改完都复查第 2 步 —— pdata 余量是"每次编译都可能变化"的资源。
