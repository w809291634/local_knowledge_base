# 概率性故障的自动压测与单变量矩阵：把"产线 7/400"变成可判定、可留现场的工程问题

> 适用：任何"偶发、需断电恢复、人工复现不稳定"的嵌入式问题（产线 x/N、客退"偶尔不响应"、
> 跑几小时才挂一次）。与芯片、协议、RTOS 无关。
> 来源：2026-11-02 一次产线概率性串口失效的复盘（案例细节见
> [`yjt/MultiParam/wifi-duocan-bh67f2265-uart-fifo-voice-emi-case.md`](../../yjt/MultiParam/wifi-duocan-bh67f2265-uart-fifo-voice-emi-case.md)）；
> 本文件只抽**换任何项目都能照用**的打法。
> 目标：解决三件平时最容易做错的事 —— **怎么让它必现、怎么算"通过"、怎么把现场留住**。

## 结论先行

概率性故障的排查成本几乎全部花在"复现"上。收口这套成本的四条：

1. **把人工动作搬进设备自动循环**（不是搬进脚本去点鼠标），让状态边界重叠起来制造压力；
2. **判定用专用测试帧 + 序号**，不用业务回复当判据；
3. **失败即冻结现场**：显示错误码、不休眠、不复位、不自动恢复，等人工看；
4. **"未复现"必须自带"几台 × 多久"**，且**一次只改一个变量**。

## 1. 复现：把人工手法翻译成自动压力

人工复现路径往往是"在某几个状态边界上快速反复操作"。自动化的要点：

| 要点 | 做法 | 为什么 |
|---|---|---|
| **去掉等待** | 直接调用状态迁移函数（如"关机流程"函数本体），跳过长按/动画/延时 | 人工手法里的等待是**给操作者看的**，不是给故障看的；去掉它等于把单位时间压力提高一个量级 |
| **压在边界上** | 在**显示 OFF 期间**、**熄屏与低功耗控制的边界**各来一组按键 | 概率性故障多发生在**状态迁移 + 多外设重叠**的窗口，不在稳态 |
| **不要求中间回复** | 每组按键产生的回复**不作为通过条件**，先攒着 | 边界期本来就不该期望即时应答；把它当判据会**误判失败**，也会漏掉真失败 |
| **交替动作** | 启动/停止交替，而不是一直启动 | 交替才覆盖两条代码路径与其交叉 |
| **先排空再判定** | 判定前先给一段"处理积压回复"的时间，再发查询 | 把"慢"和"死"区分开 —— 否则测出来的全是慢 |

## 2. 判据：专用测试帧 + 序号，三件齐才算一次成功

**不要用业务报文的成功与否当判据。** 加一条只在测试版存在的命令：
下位机**通过正常接收和校验后**，回一个专用应答，**带回请求里的相同序号**。

上位机判定一次成功要同时满足：

1. **帧完整**（头/长度/尾对得上）；
2. **校验正确**；
3. **序号与本次请求一致**。

**序号为什么不可省**：绝大多数自定义协议的业务帧没有序号。没有序号就排除不了
"上一轮的旧回复、调试回显、别的链路的数据"被当成本次成功 ——
而这正是概率性故障里最常见的**假通过**。
⚠ 测试命令与序号字段属**压测版扩展**，不要当协议变更引用；发布清单里要写明剥离还是保留。

**重试与阈值**：查询最多 N 次（案例用 5 次）、每次最多等 T（案例用 500ms）；
任一次有效应答即判本轮正常；**连续 N 次无有效应答才判失败**。

## 3. 留现场：失败时禁止系统"自愈"

判失败后要做的是**冻住**，不是恢复：

- 显示一个**专用错误码**（案例用 `E-H`），让产线/测试一眼知道是"压测判死"而不是业务错误；
- **不休眠、不自动复位、不重连**，停在失败点等人工分析；
- 串口/日志通道保持可用，把**原始字节**继续打出来。

**任何"失败自动复位/自动重连"的测试脚手架，都在销毁自己的证据。**
自动恢复逻辑可以另开开关，在需要跑"长期稳定性"时才打开，跑"定位"时必须关掉。

## 4. 定位：单变量矩阵 + 证据强度分级

**一次只改一个变量**，每项记录**条件 + 结果 + 台数×时长**。案例的九行矩阵是这个打法的样板：

| 变量类别 | 作用 | 例 |
|---|---|---|
| **放大诱因** | 把嫌疑窗口拉长一个数量级，看症状是否**同形**复现 | 关中断 3.2ms → 100ms，"极易复现且打印与原故障一致" |
| **消除诱因** | 反向确认 | 去掉该动作 → 不再复现 |
| **验证手段有效** | 压测本身要能复现原故障，否则后面全是空谈 | 原版本直接压测 → 极易复现 |
| **候选修复 A/B/组合** | 每个候选单独跑，再跑组合 | 复位外设 / 读尽缓冲 / 缩窗切片 / 组合 |
| **基线回归** | 最终方案在**产线版本**上再跑一遍 | 产线版 + 组合 → 未复现 |

**证据强度分级（写结论时按级用词，别越级）**：

- "**同形复现**" > "复现" > "暂未复现（缺台数时长）" > "未复现（n 台 × t 小时）"；
- **放大诱因成功只算"增强证据"**，不能写成"证明了根因"；
- **"未复现"没带台数与时长 = 无效行**，不许与其它行并列引用；
- 结论被新数据推翻时，**明确写出"由 A 更新为 B"以及依据哪一行数据**（案例：从"优先单项修复"改口为"组合整改"，依据是组合项 2 天未复现）。

## 5. 推理纪律：三条最容易犯的过度断言

1. **"窗口有多长" ≠ "丢了多少数据"**：积压到阈值才算丢失，中间状态是正常的缓冲行为。
   要写丢几个字节，必须有溢出标志或报文缺字的实测支撑。
2. **"复位能恢复" ≠ "复位是修复"**：复位只打断自我维持链，防不住首帧损坏。
3. **"样机没出问题" ≠ "满足规格"**：时序类改动的通过判据是**最重负载下的波形**，
   不是"功能还能用"。（案例原话：当前样机语音正常是有效观察，
   **但不足以证明最重中断负载下所有命令时序均满足要求**。）
