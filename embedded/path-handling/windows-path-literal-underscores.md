# Windows 路径中的下划线和反斜杠

## 结论

处理用户给出的 Windows 路径时，反斜杠 `\` 只能视为目录分隔符；下划线 `_` 是目录名的一部分。禁止根据视觉习惯把 `PTB-XL_500Hz_官方诊断分类` 拆成 `PTB-XL\_500Hz\_官方诊断分类`，也禁止把 `current_work` 拆成 `current\_work`。

## 执行规则

1. 将用户原始路径视为待验证的字符串，不自行改写目录层级。
2. 在写入、复制、移动、删除前，先使用 `Test-Path -LiteralPath` 检查该精确路径。
3. 路径存在时，使用 `Resolve-Path -LiteralPath` 回显最终绝对路径，再执行操作。
4. 路径不存在且下划线/反斜杠存在歧义时，只做只读列举以找出候选路径；向用户明确说明候选路径并请求确认，不能自行选择。
5. 使用 PowerShell 时必须加 `-LiteralPath`，避免通配符或特殊字符被解释。
6. 向用户回复最终位置时，复制工具实际验证过的路径，不根据输入文本重新拼写。

## 反例

错误：

```text
D:\current\_work\我的工作资料汇总\心电测试数据提交\PTB-XL\_500Hz\_官方诊断分类
```

该路径包含额外目录层级，可能与用户真正指定的路径不同。

正确做法是保留目录名中的下划线，并先验证：

```powershell
$path = 'D:\current_work\我的工作资料汇总\心电测试数据提交\PTB-XL_500Hz_官方诊断分类'
Test-Path -LiteralPath $path
Resolve-Path -LiteralPath $path
```

## 适用范围

适用于 Windows 上的文件复制、脚本部署、构建输出、工具包整理、文档交付和所有可能覆盖用户文件的操作。
