# EasyFlash 移植评估（CH571 实践）

> 适用：在 CH571/CH573 等 CH57x 的 DataFlash 上移植 EasyFlash ENV/KV；容量核算、端口层、实时性冲突的评估方法可跨芯片复用，其余芯片需替换页大小与 EEPROM API。
> 来源：ZY0_BLE_CH571 联网五折页项目（2026-10-27），EasyFlash V4.1，离线指令缓存 otq 队列；同芯片相关笔记见 `yjt/ch571/ble-device-id-rollcode-nv.md`。

## 0. 一句话结论

EasyFlash 适合"少量 KV + 掉电安全 + 需要 CRC"的场景；真正决定移植成败的不是库本身，而是**分区规划、容量核算、端口层对齐、与实时业务的冲突**这四件事。评估阶段把这四项量化，后续基本不会返工。

## 1. 评估前必须确认的 6 个事实

| # | 事实 | 为什么必须先确认 |
|---|---|---|
| 1 | DataFlash 总大小、页大小、擦除粒度、写粒度 | 决定 `EF_ERASE_MIN_SIZE` / `EF_WRITE_GRAN` / 扇区数 |
| 2 | 应用 NV、设备 ID、协议栈 SNV 的地址占用 | 决定 ENV 区能放哪、是否会误擦 |
| 3 | 需要缓存的条目数与单条长度 | 决定分区大小与容量上限 |
| 4 | 业务可接受的阻塞时间 | Flash 擦写会全局关中断，决定实时性风险 |
| 5 | release 是否需要封掉调试/写 Flash 命令 | 决定命令裁剪宏 |
| 6 | ENV 版本升级策略 | 决定 `EF_ENV_VER_NUM` 与默认值表维护方式 |

## 2. 分区规划（CH571 实例）

DataFlash 32 KB，绝对地址 `0x70000` 起：

| 区域 | 区内偏移 | 大小 | 用途 | 约束 |
|---|---|---|---|---|
| 应用 NV | `0x0000` | 256 B | magic/version/store_mode/sync_ts 等普通配置 | 按页擦写 |
| 设备标识 | `0x0100` | 6 B（独占 1 页） | 滚码，独立页擦写 | 不得与 NV 区重叠 |
| EasyFlash ENV | `0x0200` | 8 KB（`BOARD_CFG_EF_AREA_SIZE`） | 离线队列 `otq00~otq59` | 256 的整数倍 |
| BLE SNV | — | 预留至 `0x7E00` | 协议栈绑定信息 | 任何业务不得覆盖 |

关键点：

- EasyFlash 用**绝对地址**，CH57x `EEPROM_*` 用**区内偏移**；端口层必须统一换算：`offset = addr - FLASH_ROM_MAX_SIZE`。
- 必须做编译期断言（三重）：
  1. ENV 区不与应用 NV、设备 ID 重叠；
  2. ENV 区尾部不超过 `0x7E00`（给 SNV 留位）；
  3. ENV 区不超过 DataFlash 总容量。
- 任何分区调整必须同步四处：偏移宏、断言、容量核算、业务队列上限。

## 3. 配置项与取值

| 宏 | 取值 | 说明 |
|---|---|---|
| `EF_USING_ENV` | 定义 | 只用 ENV；IAP、LOG 不定义 |
| `EF_ERASE_MIN_SIZE` | 256 | CH57x EEPROM 页大小 |
| `EF_WRITE_GRAN` | 1 | 支持按字节写；库内单位是 bit |
| `ENV_AREA_SIZE` | 8 KB | 必须为 256 的整数倍 |
| 扇区数 | ≥ 2 | 必须留 1 个空扇区给 GC，否则库直接 `#error` |
| `EF_ENV_VER_NUM` | 0u | 必须显式定义为数值，不能留空 |
| `EF_CRC32_USE_TABLE` | 0 或 1 | 1=查表快、多约 1 KB Flash；0=位运算、慢约 8 倍，结果一致 |
| `BOARD_CFG_EF_CMD_ENABLE` | `1 - RELEASE` | 量产固件不暴露写 Flash 入口 |

## 4. 容量核算（最容易踩坑）

```
每扇区可用 = 扇区大小 − 扇区头(16B) − EF_SEC_REMAIN_THRESHOLD(56B)
单条成本   = ENV头(24B) + key 长度 + value 长度
每扇区条数 = floor(每扇区可用 / 单条成本)
总容量     = (扇区数 − 1) × 每扇区条数
```

本工程实例（key `otq00` 5 B、value 18 B）：

- 单条 = 24 + 5 + 18 = **47 B**
- 每扇区 = floor((256 − 16 − 56) / 47) = **3 条**
- 4 KB（16 扇区）= **45 条**；8 KB（32 扇区）= **93 条**
- 业务上限取 **60**，留 GC/其它 key 余量，并加编译期断言 `BOARD_CFG_OFFLINE_TX_NUM <= 理论上限`

余量不足会触发 GC，甚至 `EF_ENV_FULL`；`EF_ENV_FULL` 可能导致 ENV 区异常，评估时必须把"条目数 × 单条长度"算清。

## 5. 端口层实现要点（4 个必做）

1. **地址换算**：绝对地址 ↔ 区内偏移，集中在一个函数里。
2. **越界防护**：read/erase/write 都先校验"起始地址在区内 + size 不越尾"，防止 EasyFlash 异常时误擦 NV/设备 ID/SNV。
3. **4 字节对齐跳板缓冲**：CH57x `EEPROM_READ/WRITE` 要求 4 B 对齐，且写源必须在 RAM；非对齐读用小缓冲分块搬运，所有写都经对齐缓冲。
4. **非空默认值表**：`ef_env_set_default()` 会断言默认表非空；空表会在空 ENV（首次上电/全擦/efreset）时死循环卡在 `easyflash_init()`。至少放一条，如 `ef_init=1`。

另外：

- 无 OS 时 `ef_port_env_lock/unlock` 可空实现，但必须确认所有 ENV 调用都在同一线程上下文（本工程为 TMOS 单线程）。
- `ef_port_init` 返回默认表指针与条目数。
- 恢复 ENV 必须走官方 `ef_env_set_default()`，**不得直接 `EEPROM_ERASE`**。

## 6. 业务层封装（以离线队列为例）

| 设计点 | 做法 | 原因 |
|---|---|---|
| 存储粒度 | 一条记录一个 KV（`otq00`…） | 掉电最多丢正在写的一条；写放大小 |
| 记录结构 | 固定 18 B：seq(2)+cmd(1)+len(1)+data(14) | 长度固定，容量可精确核算 |
| key | 固定长度：前缀 + 两位十进制槽号 | key 长度不波动，容量稳定 |
| 顺序 | 独立单调 `seq`，补发取最小 seq | 与槽位复用无关 |
| 可靠性 | 发送成功才删，失败保留重试；上电扫描恢复 | 至少一次语义 |
| 满队列 | 宏切换：保新弃旧 / 保旧弃新 | 按业务语义选择 |
| 写放大 | 值不变不写（先比较） | 减少擦写次数 |
| 查询 | RAM 维护有效槽位索引，只查有效槽 | 避免逐槽 `ef_get_env_blob` 长时间阻塞 |

## 7. 与实时业务的冲突（评估重点）

| 影响对象 | 现象 | 对策 |
|---|---|---|
| BLE 协议栈 | Flash 擦写阻塞主循环，TMOS 调度延迟，严重时触发连接超时断开 | 降低写入频率、单条写、避免在连接关键期写 |
| 蜂鸣器（软件方波） | 方波被 Flash 操作打断，出现杂音、响时长被拉长 | 改硬件 PWM（TMR0）+ RTC 32k 补偿节拍 |
| TM1652 数码管 | 软件模拟时序被打断，偶发段码错误/全显缺位 | 写帧加临界区，或降低打断中断频率 |
| 显示/按键 | 主循环阻塞导致刷新与响应卡顿 | 避免高频写，写操作错峰 |

评估时必须做：**擦写/GC 期间的关中断时长测量**（GPIO 翻转 + 示波器或循环计数），并把"最大阻塞时间"写进结论。

## 8. 移植步骤（10 步清单）

1. 确认 DataFlash 大小、页大小、擦除粒度、写粒度。
2. 划区并写绝对/相对地址换算。
3. 端口适配 read/erase/write，加地址越界防护。
4. 加 4 B 对齐跳板缓冲（读、写都要）。
5. 只开 ENV，关闭 IAP/LOG。
6. 配置非空默认值表（至少一条）。
7. 初始化顺序：基础 NV/设备 ID → `easyflash_init()` → 业务模块。
8. 加编译期断言：区不重叠、容量上限、扇区数。
9. release 裁剪调试命令：`BOARD_CFG_EF_CMD_ENABLE = 1 - RELEASE`。
10. 提供恢复手段：`ef_env_set_default()`，不要直接擦除。

## 9. 验收用例（可直接当自测表）

| # | 项目 | 方法 | 判据 |
|---|---|---|---|
| E01 | 空片首次上电 | 擦除整片后启动 | 能完成 `easyflash_init`，业务正常 |
| E02 | 全擦/efreset 恢复 | 执行恢复命令后重启 | 默认值表生效，不卡启动 |
| E03 | 随机关机 | 写入过程中多次随机断电 | ENV 可读，损失不超过 1 条 |
| E04 | 容量边界 | 写到理论上限、再超限 | 达到上限前不报 `EF_ENV_FULL`，淘汰策略符合预期 |
| E05 | GC | 反复写删触发 GC | 数据不丢；记录最大阻塞时间 |
| E06 | 顺序与完整性 | 断链入库后重连补发 | 按 seq 升序；ID/时间戳保持事件原值 |
| E07 | 未订阅 | 已连接但未使能通知 | 进入队列，订阅后补发 |
| E08 | 失败重试 | 发送忙/未就绪 | 记录保留，下个周期重试 |
| E09 | 越界防护 | 人为构造越界地址 | 返回错误，不误擦 NV/设备 ID/SNV |
| E10 | release 裁剪 | release 构建 | 无调试/写 Flash 命令 |

## 10. 本次移植踩过的坑（症状 → 根因 → 修法）

| 症状 | 根因 | 修法 |
|---|---|---|
| 配置 60 条后偶发写入失败 | 4 KB 分区理论容量仅约 45 条，超出触发 `EF_ENV_FULL` | 扩到 8 KB（理论上限 93），业务取 60 |
| 空片/全擦后卡在启动，shell 不出现 | 默认值表为空，`ef_env_set_default()` 断言死循环 | 放置至少一条默认项 |
| 恢复 ENV 后数据异常 | 直接 `EEPROM_ERASE` 破坏 ENV 结构 | 改用 `ef_env_set_default()` |
| 查询队列时 BLE 断连 | 逐槽调用 `ef_get_env_blob()` 阻塞主循环，TMOS 得不到调度 | 只查有效槽位，RAM 维护索引 |
| 读回数据错乱 | 缓冲区未 4 B 对齐，或写源不在 RAM | 统一走对齐跳板缓冲 |
| 误擦应用配置/设备 ID | ENV 区与 NV/设备 ID 地址重叠 | 编译期断言 + 端口层越界防护 |
| 未初始化就调用 `ef_*` | 初始化顺序错误 | 先 `easyflash_init()`，再业务 |
