# ★ 语音关总中断 3.2ms × UART 中断"一次只取一字节"：尾字节跨帧残留 → 血压串口永久错帧（严重）

> 适用：WIFI 多参血压计项目（下位机 = BH67F2265 血压模组，一线语音 = WTN6 E 系列，9600bps 8N1 TTL）；

## 结论先行

**整改方案（报告 2026-11-02 定稿口径）= 每次 UART 接收中断读尽硬件 FIFO（`if (_rxif)` → `while (_rxif)`）
＋ 语音一线发送的关总中断窗口由 3.2ms 整体关闭改成 8 次 400µs 切片。**
组合版压测 **2 天未复现**；发布前仍需完成**正常测量、语音、低功耗**三项回归。

两件事各管一段，**不能互相替代**：读尽 FIFO 管"接收完整性"（消除积压后的残留），
400µs 切片管"中断服务时延"（降低积压与溢出的触发机会）。
报告明确写了这次是**从"优先单项读尽 FIFO"改口为"组合整改"**，依据是组合项的 2 天数据。

## 2. 复现路径（人工手法，报告原文口径）

1. 触发**关机**；
2. 在 **OFF 显示及熄屏边界**连续点击开始键；
3. **唤醒后再次快速点击**开始键；
4. **交替**启动、停止血压测量。

异常发生后的系统状态（关键观察，别漏）：
**上位机与下位机主循环仍在跑**，屏幕、按键、语音都没死；
只有**血压串口报文持续校验失败**。
⇒ 这类"整机活着、单条链路死了"的现象，排查面要直接收到**该链路的接收服务**上，不要去查复位/看门狗/电源。

## 3. 机制链

### 3.1 触发原因：语音一线协议要连续关总中断约 3.2ms

- WTN6 一线控制发 8 位数据，**每位 = 100µs + 300µs** 的高低电平对 ⇒ 一条指令 = 8 × 400µs = **3.2ms**。
- 原实现为保护语音时序，**这 3.2ms 全程关闭总中断 EMI**。
- 关中断期间 **CPU 不响应 UART 中断，但 UART 硬件照常接收**。
- 9600bps、8N1 ⇒ 一个字符 = 10 bit / 9600 ≈ **1.04ms**；3.2ms ≈ **3 个字符时间**
  ⇒ 足以把"两层 FIFO + 移位寄存器"填满并溢出。

### 3.2 持续失效原因：ISR 一次中断只取一个字节

原 `UART_ISR` 用 `if (_rxif)` —— 一次中断只取走一个字节。
FIFO 里已有两个有效字节时，取走一个**仍剩一个**，程序却已退出中断，**不保证 RXIF 清零**。
残留的字节随后被带进下一批软件接收数据，形成"**旧帧尾字节 + 新帧前部**"的错位
⇒ 之后每一帧的偏移都是 1 字节 ⇒ **校验和永远不对**，直到断电重启把 FIFO 和软件缓冲一起清掉。

完整链条（报告 §2.2 原话结构）：

> 语音长时间关闭中断 → FIFO 积压 → 中断单次取数未读空 → 尾字节跨帧残留 → 后续持续解析失败

`if` 改 `while` 后，按 RXIF 状态连续取数、直到 FIFO 无有效数据才退出，**切断了持续错位链**。

### 3.3 一条必须留住的推理纪律：「数据积压」≠「数据丢失」

报告专门写了一段反过度推断：

- FIFO 里**存有两个有效字节本身不是错误**；
- 只有"未及时取走而继续到数"才可能溢出；
- **不能仅凭"关了 3.2ms 中断"就认定每次固定丢 2~3 字节。**

⇒ 写分析结论时，"窗口有多长"和"丢了几个字节"是两件事，前者是**风险量**、后者要**实测或溢出标志位**才算证据。

### 4.1 BH67F2265 手册（报告引用件，Rev.1.50，2025-06-17）

| 报告说法 | 手册原文位置与内容 |
|---|---|
| "第 132 页说明 RXIF 代表接收寄存器中有有效数据" | **p132 Bit 2 RXIF**：`0：TXR_RXR 寄存器为空 / 1：TXR_RXR 寄存器含有有效数据`；并写明"**读取 USR 寄存器再读 TXR_RXR 寄存器，如果 TXR_RXR 中没有新的数据，那么将清除 RXIF 标志**" |
| "第 139~140 页说明接收寄存器是两层 FIFO，须在第三个字符接收完成前及时取数" | **p138~139**：`TXR_RXR 寄存器是一个两层的 FIFO 缓冲器，它能保存两帧数据的同时接收第三帧数据，应用程序必须保证在接收完第三帧前读取 TXR_RXR 寄存器，否则忽略第三帧数据并且发生溢出错误`；**p139**：`溢出错误发生之前至多还有一帧数据可读`；**p139 清 RXIF 步骤** = ①读 USR ②读 TXR_RXR |
| "规定先读 USR 再读 TXR_RXR 的状态清除方式" | **p131~132**：PERR / NF / FERR / OERR **四个标志全部**都是"先读 USR 再读 TXR_RXR"才清除 |
| "UARTEN 清零会清空缓冲并复位错误状态，解释了重新初始化 UART 能恢复" | **p132 / p136**：UART 被除能时"将清除缓冲器，所有缓冲器中的数据将被忽略，另外波特率计数器、错误和状态标志位被复位，`TXEN、RXEN、TXBRK、RXIF、OERR、FERR、PERR、NF` 清零，而 `TIDLE、TXIF、RIDLE` 置位，UCR1/UCR2/UCR3/BRG 其它位保持不变" |

补两条报告没写但同族通用的硬约束（同一份手册）：
- **OERR=1 会"禁止下一组数据的接收"**（p131 Bit 4）⇒ 溢出后不处理就**不再收数**，不是"丢一点继续跑"。
- **进 ISR 时 UnUSR 标志不会自动清**（p140）："USR 寄存器标志位为只读状态，软件不能对其进行设置，
  和其它一些中断一样，**在进入相应中断服务程序时也不能清除这些标志位**" ⇒ 必须靠"读 USR + 读数据寄存器"这个动作清。
- **OERR 本身也是接收中断源**（UCR2 的 `RIE=1` 时，OERR 或 RXIF 置位都会请求中断）⇒ 溢出会来中断，但**光进中断不读数据不会自愈**。

### 4.3 WTN6 E 系列语音芯片使用说明书 V1.13 §6.4（一线串口时序）

原文（打印页"第 6 页"）：

> 先把数据线拉低 4~20ms 后，推荐 5ms，发送 8 位数据，**先发送低位，再发送高位**，
> 使用高电平和低电平比例来表示每个数据位的值。
> 注意：**必须高电平在前，低电平在后**。
> 推荐使用 200us：600us。取值范围：**40us:120us ~ 400us:1200us**。注意使用 **3:1 和 1:3 电平比例**以保障通讯稳定。

⇒ 本项目的 100µs + 300µs = **1:3、每位 400µs**，落在允许范围的中段，**规格本身没问题**。
⇒ **关键一条：规格书并未要求"必须全程关闭 MCU 总中断"** —— 关 EMI 是**本项目的实现选择**，
不是协议要求。这句话是"取消 EMI 保护"和"切片"两个方案能立住的合法性来源。

同本说明书其它与本案相关的硬事实：
- §6.2 两条地址指令**时间间隔需大于 4ms**；
- 上电初始化约 **100ms**，期间**不响应指令**；
- PA1 = 一线 DATA，PA2 = BUSY（标准程序 BUSY 默认高、播放中为低；**串口控制模式下只有收到正确时序 BUSY 才变化**）；
- IO 默认内部 **1M 下拉**，低功耗休眠时语音播完要把 DATA **拉低**防倒灌电流。

### 5.1 协议帧格式（`2265血压模组方案通信协议V1.0.doc` §1、§4）

```
头部1 头部2 长度(1B)  CMD(1B)  数据(N B)  校验和(1B) 尾部1 尾部2
0xA5  0x5A  └─ 从头部到尾部所有字段长度和 ─┘        0x4F  0x4B
校验和 = 长度 + CMD + 数据 的逐字节累加（Data_Crc8：for(i=2;i<len-2;i++) temp+=pBuffer[i]）
```

**⇒ 帧尾是两字节 `4F 4B`，`0x4B` 是尾部 2、不是校验字节。** 报告特意纠正了这一点。

（发）：`81/82` 标定结果、`A0` 测量过程中状态、`A1` 测量结果、`A2` 错误状态、`A3` 电池状态。

## 6. 上下位机自动压测设计（报告 §3，手法本身可复用，见 `embedded/debug-methodology/probabilistic-fault-auto-stress-harness.md`）

分工：**上位机负责重复操作和发现异常；下位机负责真实业务和对应答复。**
压测目的：把人工快速按键交给设备自动完成，**在关机、唤醒、语音与串口收发重叠时持续制造压力**，并**自动判定通信是否失效**。

**第一步**：直接调用原关机流程（**省去长按记录键的等待**）；屏幕显示 OFF 期间调用开始键处理 **5 次**，
每次后等约 **50ms**；**保留原有启动/停止/语音相关业务**；**不等待这组操作的回复**。

**第二步**：继续原熄屏与下位机低功耗控制；关机函数完成外设恢复后**立即**再调开始键 **5 次**，
每次后等约 50ms；**同样不以这 5 次的回复作为通过条件**。
具体动作随设备状态变化：**首个睡眠态开始键用于开机**，之后才交替启动/停止测量。

**第三步**：先处理积压回复约 **500ms**，再发专用通信查询；**最多 5 次、每次最多等 500ms**；
收到任一次有效应答即判本轮通信正常，停止测量后进入下一轮关机。
**连续 5 次无有效应答 → 显示 `E-H` 并停留现场：不休眠、不自动复位，等人工分析。**

**判据帧**：下位机新增 **`0x39` 测试应答**处理——**通过正常接收和校验后回 `0xB0` 并带回相同序号**；
上位机核对**帧完整性 + 校验 + 序号**三样。
⇒ 为什么要序号：本协议的业务帧（§5.1）**没有序号字段**，不加序号就无法排除
"旧回复 / 调试回显 / 其它数据被当成本次成功"。
⚠ `0x39/0xB0` 与"带回相同序号"**只存在于压测版本**，两份正式协议文档里都查不到 ⇒ 属测试扩展，别当协议变更引用。

## 7. 九项验证矩阵（报告标题写"八项"，表里实列九行 —— 以表为准）

| 验证 | 修改或测试条件 | 结果 |
|---|---|---|
| 一 | 语音关 EMI 时间延长至 100ms | **极易复现**；串口打印和故障现象一致 |
| 二 | 去掉语音关闭 EMI 的动作 | **不再复现**；压测 1h |
| 三 | 压测版本：原产线版本直接自动压测 | **极易复现** ⇒ 说明压测手段有效 |
| 四 | 压测版本基础上：解析错误后关闭 UART 并重新初始化 | 暂未复现；**未提供设备数与时长** |
| 五 | 压测版本基础上：去掉语音 EMI 操作 | 2 台机器共 **4.5h** 未复现，语音正常 |
| 六 | 压测版本基础上：3.2ms 整体关闭改为 **8 次 400µs 切片** | 2 台机器压测 **2h** 未复现，语音播报正常 |
| 七 | 压测版本基础上：保留 3.2ms 语音保护，**每次中断读尽 FIFO** | 压测 **2h** 未复现 |
| 八 | 压测版本基础上：**每次读尽 FIFO ＋ 400µs 语音切片** | 压测 **2 天**未复现 |
| 九 | **产线版本**上：每次读尽 FIFO ＋ 400µs 语音切片 | 测试 **2h** 未复现，语音正常 |

报告给每项定的用途（读表时别混）：
一~三 = 确认**诱因**与**压测手段有效性**；四 = 证明**复位接收状态能打断持续错帧**；
五、六 = 从**源头减少中断阻塞**；七 = **直接修复 FIFO 接收服务**；八、九 = 给最终组合方案**2 天未复现的直接证据**。

⚠ 验证四"暂未复现"但**没给台数与时长** ⇒ 这一行的证据强度不能和五~九并列引用。
量产口径：**"未复现"必须自带"几台 × 多久"**，否则等于没说。

## 8. 四个候选方案：修改点、依据、优点、不足（报告 §6 全录）

| 方案 | 修改点 | 依据 | 优点 | 不足（报告原口径） |
|---|---|---|---|---|
| 6.1 错误后重新初始化 UART | 在 `deal_uart_data` 的**解析错误出口**关闭并重新初始化 UART | UARTEN 清零复位硬件 FIFO 及错误状态；初始化同步清空软件接收计数 | 恢复直接，可避免"持续异常必须断电" | **属事后恢复**；复位会丢弃正在收发的数据；**无法防止首帧损坏**。⇒ 只作"有明确触发条件的兜底"，**不得**用"所有解析失败都复位"替代根因修复 |
| 6.2 取消语音 EMI 保护 | 语音发送不再关/恢复 EMI | —— | 消除约 3.2ms 的接收阻塞窗口；两台合计 4.5h 未复现且语音正常 | 中断可发生在语音**数据位内部**，拉长高或低电平，**破坏规格书要求的 1:3 / 3:1 比例**。当前样机语音正常是有效观察，**但不足以证明最重中断负载下所有命令时序都满足要求** |
| 6.3 语音每 400µs 切片 | 保护**每位的高低电平对**，约 400µs 后恢复原 EMI 状态，再发下一位 | 单次阻塞较 3.2ms **下降约 87.5%**，且**小于 9600bps 下一个字符时间（1.04ms）**，同时保留位内脉宽保护 | 两台压测 2h 未复现，语音正常 | **位间 ISR 仍可延长低电平**（切片只保护位内，不保护位与位之间）⇒ 需实测波形；**不能替代"读尽 FIFO"这一基本接收要求** |
| 6.4 每次接收中断读尽 FIFO | `UART_ISR` 中 `if (_rxif)` → `while (_rxif)`，连续取数至 RXIF 为 0 | 直接对应"两层 FIFO + 有效数据标志"的硬件语义 | 改动小、**不改变语音波形**；单项压测 2h 未复现 | **无法恢复已溢出丢失的字节**；须保留错误处理；**并确保软件缓冲满时仍把硬件数据取走**，不因循环造成中断卡住 |

### 8.1 400µs 这个数字怎么来的（可复算）

- 一位 = 100µs + 300µs = **400µs**；8 位 = **3.2ms**；切片数 = 3200/400 = **8 次**。
- 阻塞时长下降 = (3200−400)/3200 = **87.5%**。
- 9600bps 8N1 一个字符 = 10 bit / 9600 s ≈ **1.0417ms** ⇒ **400µs < 1.04ms**，
  即"两次开中断之间最多只可能到 1 个字符"，两层 FIFO 永远来得及。
- 反过来看原实现：3.2ms ≈ **3 个字符时间** > FIFO 深度 2 ⇒ **必然有字符落在无人取走的时间之外**。

### 8.2 最终收口（报告 §7.1）

结合验证八"组合压测 2 天未复现"，本次建议由原先**优先单项读尽 FIFO**，
更新为**读尽 FIFO + 400µs 语音切片**的组合整改：
前者消除积压后的持续残留，后者减少积压与溢出的触发机会；
两项分别作用于**接收完整性**和**中断服务时延**，较单纯重置恢复更有针对性。
**发布前仍需完成正常测量、语音、低功耗三项回归。**
