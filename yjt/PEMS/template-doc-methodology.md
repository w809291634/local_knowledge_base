# 模板化文档生成方法论（医疗/注册类 Word 文档通用）

> 适用：**任何**需要按公司既定版式批量产出的 Word 文档族——医疗器械软件研究资料（PEMS）、
> 产品技术要求、说明书、验证/确认记录、设计文档等；也可用于非医疗的模板化文档。
> 目标：一套方法 + 一套配置，换项目只改数据，不重写流程。

## 一句话总纲

**先定基线 → 以模板「就地替换」生成 → 脚本对账 + 渲染对拍 → 人工核对图与签署 → 版本快照归档。**

## 十条通用原则

1. **格式靠继承，不靠复刻**：以一份已定稿文档为模板，保留其封面/目录/标题层级/图表/页眉页脚/
   分节，只替换文字与数据；**不要从零拼文档**（封面大标题字号、浮动封面表、目录域、样式
   直接格式都复刻不出来）。
2. **数据与文档分离**：把型号、功能、指标、编号、厂商等收进**唯一数据源**（`config.json`），
   文档由脚本生成。改数据只改一处，产物全量重生成。
3. **结构优先于内容**：先保证「目录树、标题层级、分节、编号」与模板一致，再谈内容丰度。
4. **封面独立成页，正文无空白页**：封面与正文之间必须有分节符或分页符；封面区不得残留空段。
5. **单一事实来源**：同一数据（型号、版本、编号）在多份文档中出现时，只能有一个定义处。
6. **一致性可自动化，正确性靠人工**：型号集合、关键字覆盖可脚本查；图、签署栏、交叉引用
   文件名必须人工核。
7. **相同代码封装为统一函数**：多个文档的相同处理（替换、填表、分页）只写一份，放公共模块，
   项目只提供配置（见 `tools/docx_ops.py`）。
8. **产物只增不覆盖**：输出到新版本目录（`*_V1/`、`*_V2/`），永不覆盖源文档与历史版本。
9. **每轮迭代留三样**：数据层快照、修订记录、差异清单。
10. **规则写成工具无关的纯文本**：知识片段用 Markdown，脚本用 Python + 命令行；入口文件
    `AGENTS.md` 一处定义，各 AI 工具引用（见 `multi-ai-tool-adaptation.md`）。

## 适用边界

| 适用 | 不适用 |
|---|---|
| 版式固定、内容按项目替换的文档族 | 版式每份都不同的创意排版 |
| 需要多份文档互相引用、必须一致 | 单份一次性文档（直接手写更快） |
| 会反复迭代（评审→修改→再审） | 无需回退与原样复现的场景 |
