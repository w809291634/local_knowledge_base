# 匿名案例：模板化 PEMS 文档族的生成与整改

> 本案例只说明方法和质量控制，不包含任何真实项目名称、编号、型号、参数、软件版本、人员、结论或测试数据。

## 起始条件

- 一套固定 Word 模板，包含封面、目录、页眉页脚、表格和若干图示；
- 一份事实基线，包含型号/配置、软件功能、版本、受控来源和证据状态；
- 一套当前源码、受控说明书、技术要求、风险文件和测试证据。

## 常见问题

| 类别 | 典型问题 | 通用处置 |
|---|---|---|
| 事实 | 型号、版本、功能或指标在不同资料中冲突 | 先冻结权威来源，冲突字段阻断生成 |
| 格式 | 封面与正文同页、封面后空白页、目录失效 | 用格式档案定位分页/分节/域，修复后全页渲染 |
| 图示 | 体系图、流程图或图内文字沿用旧项目 | 以当前事实和代码重绘，逐图核验 |
| 测试 | 模板带有通过结论、签署和样例数据 | 草稿清空结果与签署；仅用受控证据填写报告 |
| 追溯 | 需求、设计、代码和用例无法关联 | 建立追溯矩阵并将缺口列入待办 |

## 生成闭环

1. 预检事实基线与受控来源；
2. 建立模板格式档案和槽位清单；
3. 原位生成新版本文档；
4. 自动检查事实、槽位、残留词、编号、表格和追溯；
5. 生成当前项目必备架构图、流程图、拓扑图和任务图；
6. 全页渲染、逐图检查、核对证据和签署状态；
7. 归档事实快照、模板哈希、产物哈希、检查报告和变更清单。
