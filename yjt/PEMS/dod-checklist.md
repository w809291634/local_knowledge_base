# 交付质量清单（Definition of Done，通用）

> 每轮交付前自检。通用项与项目特有项分开：**A/B/D 通用，C 按行业/产品替换**。
> 本清单是**判据集合**；按什么顺序执行、每阶段跑完要回显什么，看 `authoring-workflow-and-experience-index.md` 的 S0~S10。

## 结论先行

高质量 = **数据一致** + **格式一致** + **安全项闭环** + **可追溯**。
格式需对象检查与逐页渲染共同验证，自动检查不能证明所有视觉维度正确。每轮逐项记录“通过／失败／未执行／不适用（理由与依据）”；适用项未完成不能勾为通过，工作稿归档不等于格式验收完成。阶段动作与证据统一见 `yjt/PEMS/authoring-workflow-and-experience-index.md` §1.3。

## A. 数据一致性（可自动化）

- [ ] 1. 主数据清单在各文档完全一致（数量、范围、每项取值）
- [ ] 2. 术语统一（部件/功能名称一套叫法，不出现同物异名）
- [ ] 3. 文件编号一致且无重复后缀（封面 = 页眉 = 正文引用）
- [ ] 4. 版本写法统一（区分「发布版本 / 完整版本」），符合命名规则
- [ ] 5. 性能/技术指标与权威出处逐条对应
- [ ] 6. 附录类清单（词条表/配置表）与正文一致
- [ ] 7. 交叉引用的文档名真实存在
- [ ] 8. 无他项目残留（别家代号、他项目产品名、外来内部文件名、模板批注）

## B. 格式与版式（部分可自动化）

- [ ] 9.  封面**恰好一页**，字号/表位与模板一致
- [ ] 10. 封面后无空白页；目录页独立
- [ ] 11. 标题层级和生效编号正确；沿段落／样式链检查 numPr 与 numbering.xml，核对显示结果。手写编号与自动编号不得重复（如“3.1 3.1”）；只读段落文字或判断是否使用单一编号机制不足以通过。
- [ ] 12. 页眉页码与模板一致，分节数一致。**同一文档内页眉/页脚出现的模板版号必须唯一且等于本项目 `template_version`**，
  首页眉（different-first-page）、偶数页眉、页脚都要各查一次；模板自带的旧版号属"生成时修"，不得原样继承（`pitfalls.md` §85）。
  调用 `tools/docx_ops.py:header_footer_text_audit(doc, allow=[...])` 取值比对。
- [ ] 13. 表格列头与数据列对应、行数正确；每张表按对应基线核对列宽、对齐、跨页与合并关系。
- [ ] 13b. 写入和复制行前后核对物理单元格、vMerge/gridSpan。独立记录的编号／名称／描述／结果必须逐行对应，标签不被覆盖、编号按该表定义唯一；允许合理分组列合并，但不能让编号与名称跨不同项目误合并。扩行不能盲目克隆带跨行合并的末行。
- [ ] 14. 「图」与正文描述一致（图内文字不得沿用旧项目）
- [ ] 14b. **图片白名单**（§69）：文档里每个图片部件的 SHA-256 必须 ∈ 本项目图示集合。
      模板继承的图片不会被任何"必需图在位"检查发现——只查"该有的有没有"，
      从不查"多出来的是什么"。实测漏过一张带数码管与蓝牙标志的旧产品渲染图，
      与正文"无剩余时间显示、不设无线通信接口"直接矛盾。
- [ ] 14c. **每张独立成段的配图都有图题**（§69）：图题形如 `图 N …` 且紧邻图形段落。
      判据只收"真的引用了图片部件"的段：文本框内图形、命名规则那种
      `v:line`/矩形图例（`mc:AlternateContent` 的 Fallback 里也带空 `v:imagedata`）
      都不是配图，按标签名判会整批误报。
- [ ] 15. **逐节符合对应基线**：核对节数、pgSz/pgMar、方向、首页不同及眉脚关系；基线本来含横竖页时分别保留，不强制全篇同向。结构变化必须有已确认依据和修前修后回归，不能为导出成功直接合并所有节。
- [ ] 16. **目录页无裸露域代码**：不得出现 `TOC \o` / `PAGEREF` 等字样（域壳破损，见 `docx-fields-and-toc-repair.md`）
- [ ] 17. **目录形式与已确认基线一致、页码与实际一致**：域目录刷新后核对 healthy、begin/separate、域配平及裸指令，并验证导航与页码；经本轮确认采用静态目录时，可保留确认形式并核对条目、实测页码及约定的导航能力。没有确认依据的不可点击目录仍列待处理，不能把所有无 TOC 域的目录一律推倒重建；按基线无目录者登记不适用。
- [ ] 18. **目录页尾部不混入正文**：正文首标题不得落在目录页；目录与正文之间须有符合基线的明确换页机制（换页分节符、段前分页或经确认的分页控制），不能靠空段顶页；不得将“显式换页”理解为必须插入 w:br

- [ ] 18b. 最终交付 DOCX 与最终渲染文件的哈希、引擎、页数及逐页复核结论已关联；无漏页、页顶／页中异常留白、裁切、错位、图题游离及表格断裂。未渲染、仅抽检或修改后未重渲染的文档不得标记全页验收通过。

## C. 安全与合规（人工；按行业替换具体项）

- [ ] 19. 安全相关项在**需求 / 设计 / 验证**三处闭环（阈值、保护动作、失效处理）
- [ ] 20. 互斥/联锁逻辑有设计说明与验证用例（如充电与工作互斥）
- [ ] 21. 网络安全/数据保护声明与资料对应（有联网功能时）
- [ ] 22. 级别/分类表述规范（如软件安全性级别，附分级依据）
- [ ] 23. 现成软件（OS/协议栈/第三方组件）有说明
- [ ] 24. 受控发布版的签署栏、测试人/时间、版本页和生效日期均有批准依据；草稿/待执行版相应栏位保持空白。

## D. 交付动作

1. 生成：使用当前项目的事实配置生成文档；调用本库脚本时，将事实配置适配为 `--config <project-config.json>`（产物进新版本目录）。
2. 校验：运行一致性检查；调用本库脚本时执行 `python tools/consistency_check.py --config <project-config.json>`，发现差异必须失败退出。
3. 渲染：`page_ink_coverage` 逐页量正文区墨占比并按 `grade_pages_by_ink` 分级，确认封面独立页 & 无空白页
   （**不要用 `pdftotext`/`get_text()` 的字数判空白页**，中文 PDF 缺 ToUnicode 时会双向误判，见 `pitfalls.md` §41）。
4. 记录：填文档内「修订记录」+ 仓库提交（`<工程名>：<类别>：<描述>`）。
5. 归档：保留本次数据层快照。
6. **三方收口（最后一步，必做）**：说明书 / 代码 / 注意事项 逐参数核对，
   冲突未清零**不发布**（方法见 `consistency-gate.md` 第 5 节）。

## E. 三方收口：说明书 / 代码 / 注意事项（必做）

> 文档族内部一致（A–C）只是一半；每轮输出文档后还要核这三者之间是否冲突。

- [ ] 25. 说明书中的每一项关键声明均有受控来源，并标明来源类型：代码、硬件/BOM、技术要求、风险文件、检验记录或临床/可用性证据。
- [ ] 26. 说明书与代码**口径一致**（如「治疗面温度」vs「加热体标定值」须分别注明）
- [ ] 27. 说明书操作路径 与 注意事项的禁止/限制项**不矛盾**（如加热中能否调时间）
- [ ] 28. 注意事项承诺的保护动作，代码里**真实存在且阈值一致**（超温/欠压/自动关机）
- [ ] 29. 型号差异（仅某型号具备的功能）在说明书与注意事项**都已标注**
- [ ] 30. 说明书版本 / 固件版本 / 提交版本 三者写法一致
- [ ] 31. 已产出「三方核对表」并留档（参数/条款 × 说明书 / 代码 / 注意事项 / 处置）

## F. 分页与标题树终检（每轮固定，逐份产物跑）

> 流程与判据见 `cover-pagination-and-sections.md` §8；坑详解见 `pitfalls.md` §38–§42。
> 同批文档的结构与数值检查用同一段脚本逐份执行并留档；这不能替代 S9 的每份文档逐页目检。

- [ ] 32. `pagination_audit` 按 S7 分三类处置，不写死返回键数：缺陷键 hard_page_breaks/stacked_breaks/keep_on_body/chapter_pad/outline_anomaly 清零；toc_field 仅记录；redundant_breaks/body_page_break/numbered_not_in_tree 结合基线和实际渲染逐项判定修复或有依据保留。保留项须记录具体位置、依据和复核；同类项可引用同一确认规则，但不能整键关闭或未经核验批量豁免。
- [ ] 33. **无空白页**：`grade_pages_by_ink(page_ink_coverage(pdf))` 无阻断项；页数 == 预期页数
      （仅删空白页且正文／其他版式未变时按“修复前 − 消除的空白页数”核账；其他受控修改逐项解释重排，不能以固定页数压缩正文）
- [ ] 34. **查叠加不查存在**：段前分页＋段内硬分页符**必须为 0**（`stacked_breaks`，实测必出整页空白）；
      分节符＋段前分页记为 `redundant_breaks`，由基线与实际渲染判断，不因键非空直接阻断；确认造成多余空白／错页时仅去掉多余控制，不删必要分节。无实际缺陷且符合基线时可登记依据后保留；清空段后再次核对，不为清零破坏模板骨架
- [ ] 35. **分页控制属性只在标题段**：正文级段落不得带 `keepNext`/`keepLines`；图片段、图题段、正文段一律不加（§38）
- [ ] 36. **布尔属性已按 `w:val` 判定**：闸门与被查脚本都不得用"元素存在即生效"；`val="0"` 是关闭（§40）
- [ ] 37. **标题树完整且无越级收录**：编号标题 100% 有大纲级别；封面文档名不带级别；无空标题段；
      目录域内段落不参与结构判定（§42）
- [ ] 38. **修复与判据同源**：只用 `pagination_repair`（与 `pagination_audit` 共用判据，顶页空段走
      `chapter_pad_map`），`apply` 收窄到本轮确认的动作；禁止另写一份修复脚本或手改产物 Word
- [ ] 39. **修完分页的三项回归**（§48）：`toc_diagnose` 的 `balance==0`（删空段可能吃掉域壳段）、
      页数核账按第 33 项区分纯删空页与其他受控重排、末页按 `c==0` 才阻断（1~2 行溢出只记提示）；
      逐份打印"封面后第一块落在第几页"确认封面仍独立成页（§46 前置件例外）

## G. 表格与封面版式终检（§51 §52，逐份产物跑）

- [ ] 40. `audit_table_geometry` 无真缺陷：**负 `tblInd`**、**正文表仍浮动且 `tblpX` < 左页边距**、
      **有框线表唯独左边缺线**、**单元格把左边设成 `nil`** 四类全部为零；
      "表级无 `tblBorders/left` 但首列单元格有单线"属正常，只记提示，不得据此补线（§51）
- [ ] 41. **列宽和 ≤ 版心宽**：`tblGrid` 各列之和不超过 `页宽−左右页边距` 的 1.05 倍；
      超过约 2 倍者判为列宽数据污染，**禁止等比缩放蒙混**，必须显式给 `grid_overrides` 指定列宽，
      并因页数会大幅变化而重渲染核账（§51.3）
- [ ] 42. **绝不给无框线表补线**：表级与样式都无框线的两栏列表属设计；
      补边框只补 `left`，**永不补 `insideH`/`insideV`**。改前改后各渲染一次比对，别只看 XML diff
- [ ] 42b. **项目要求"表格必须有边框"时**（配置 `tables.require_borders`）：每张表六向框线齐全
      （含 `insideH/insideV`），判定沿 `tblStyle → basedOn` 样式链取生效值（只看表级会把画在样式里的
      线误判成没有），补完必须摘掉单元格级 `tcBorders/left=nil`，闸门从"提示"升级为"阻断"（§60）
- [ ] 43. **封面留白已显式统一**：标题文字与封面信息表之间的空行数 == 配置值（如 3），
      同批文档族各份一致；加完必须复核封面仍恰好一页（§52）

## H. 标题字号族内统一终检（§font-and-style-normalization §10）

- [ ] 44. **基线来自参照文档而非手写表**：`heading_format_profile_from(参照文档)` 取逐级别多数派；
      `votes/total` 必须打印，一致率不到 100% 说明参照文档本身不干净，先确认再当基线
- [ ] 45. **每档每级只剩一种取值**：正文区各级标题按 (sz, 中文字体, 加粗) 分组，
      每个级别命中数 == 该级标题总数（跨文档同级别取值必须相同）
- [ ] 45b. **跨档检查**（`check_heading_tiers`）：各级标题字号互不相同且严格递减、章标题大于正文档——
      只查"每级唯一取值"会漏掉"三级挤在同一档"的退化（§10.5）；字号档位由配置显式给出，
      参照文档只用于继承字体与加粗，它自身可能正是退化的一方
- [ ] 45c. **标题编号机制成族一致**（§53）：`heading_numbering_mechanisms(doc)` 的 `mixed` 为空
      （同级别不混用），且**全批文档同级别的机制并排比对一致**（单份跑不出跨份不一致）；
      不一致时记为待决项交人选择「全自动」或「全手写」，**禁止脚本自动改标题文字**
- [ ] 45d. **没有"文字是正文、样式是标题"的段**（§67）：
      `body_paragraphs_with_heading_style(doc, cutoff, heading_shape=项目的标题形态判据)` 必须返回空。
      这类段两条链路都不管（正文基线按样式跳过、标题分档按文字排除），所以"正文版式==基线"
      和"各级标题字号唯一"两项全绿它也能活着交付。插入正文一律 `new_body_paragraph()` 新建，
      不克隆供体；降段必须改**样式**而不是只改直接格式。
      **新判据必须反向验证**：拿上一版已知有缺陷的产物跑，要命中；拿本版跑，要 0 命中
- [ ] 45e. **正文段生效字号==基线**（§68）：正文区每个有文字的 run 解析到生效 `sz` 后必须等于正文档；
      正文基线指纹只有"缩进/行距/对齐"时，挂 16pt 的正文段能带着"版式全对"交付
- [ ] 45f. **各级标题 spacing 族内一套口径**（§68）：`before/beforeLines/line/lineRule`
      每级取值唯一且==配置；模板继承常三种口径并存（显式 0／未写吃样式／段前 1.5 行），
      表现为"标题与上文忽紧忽松"。必须按段落显式写，只改样式会被直接格式盖住
- [ ] 45g. **编号字形与标题档位一致**（§65 §68）：`numbering_glyph_audit(doc)` 里非符号型
      `lvl` 的 `sz`/中文字体/西文字体必须==该级基线；`lvlText` 无 `%` 的符号型（Wingdings 圆点）
      只登记不动，换字体会把符号变成别的字符
- [ ] 45h. **表头底纹形态唯一**（§68）：每张表首行==配置的灰底、数据行无 `w:shd`；
      模板继承下来 无／FFFFFF／auto／灰 四种混用时肉眼看就是"有的表头有灰底"
- [ ] 45i. **页眉页脚无模板裸残留**（§68）：`header_footer_text_audit(doc, allow=…)` 为空。
      **含页码域的段落不算残留**（域的缓存结果会被读成 "1"/"11"，按文本判会一片误报）
- [ ] 45j. **正文区无字符缩放/加宽**（§69）：清缩放后正文 run 不再带 `w:w`／`w:spacing`。
      同页字宽不一致是"这段字体不对"的真因，而字体名与字号两项查的都是对的——只看属性名会漏
- [ ] 45k. **表后连续空段 ≤ 配置上限**（§69）：空段审计为空。模板习惯在表格与下一标题间留 2~12 个回车，
      清完后"表格下面一大片空白"才消失；压缩与清理要按元素身份删，不能按索引删
- [ ] 45l. **把"留空"改成"实值"之后的三项自查**（§70）：①新值有没有命中残留扫描词（尤其"无××/没有××"
      这类否定说明写进标签行时）；②同一短语是否在同一句里出现两次；③带括注的组合值是否正文与表格各说一遍。
      改申报口径时，**残留扫描词表与台账里的禁用值列表必须成对更新**，更新后复扫必须 0 命中，
      并把改动理由写进版本说明（否则下一轮会以为是漏删）
- [ ] 46. **封面大标题未被误改**：逐份回读封面标题字号 == 改前值（封面标题常也带 `outlineLvl=0`，
      不排除会被一起压成正文号，且 XML diff 看不出来）；目录域内段落与表内段落未被写入标题格式；
      标题缩号后页数与空白页复测，页数变了要重刷目录页码

## 反模式（一票否决）

- 直接在 Word 里改产物而不回数据层；
- 只改一份文档、其余不同步；
- 自相矛盾的表述（如「不超过 X±20%」）；
- 交付件里留着模板批注/占位文字；
- 图里是别的项目；
- 封面与正文同页，或出现空白页；
- 只删"看起来多余"的那一个分页符而不核页数账，或改完不重渲染就交付（页数账对不上必须停，见 `cover-pagination-and-sections.md` §8 第 5 步）；
- **说明书 / 代码 / 注意事项 三方存在未处置的冲突就发布**（最常见：说明书承诺的保护动作代码里没有）。
