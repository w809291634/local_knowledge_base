# PEMS 通用参考文档格式与图示要求

## 一、参考文档的使用边界

参考文档只用于提取版式、章节层级、表格结构、目录/页眉页脚机制、图示类型和内容深度。不得继承任何产品名称、型号、版本、技术指标、用途、风险结论、测试结果、人员、日期、签署或图内项目文字。

## 二、文字版格式要求

**严格执行要求（2026-11-10 用户明确）：**以下格式要求必须进入流程 S2～S10 的动作、完成判据与证据，不能只作阅读建议。执行表见 `yjt/PEMS/authoring-workflow-and-experience-index.md` §1.3。每份文档分别冻结基线，修改后重新检查；任何必要格式项失败或未执行时，不得标记为格式验收完成。

1. 每份文档使用同编号模板原位生成，保留封面、目录、分节、页眉页脚、页码、修订记录、表格和签署栏。
2. 封面独立成页，封面后无空白页；目录页与正文首节分开。
3. 封面表格的结构、合并关系、边框、对齐、字体和定位不变，只替换经登记的字段值。
4. 正文保持对应基线的标题层级、编号机制和段落风格；新增正文用 new_body_paragraph，并显式应用同类正文属性，禁止克隆标题段充当正文。编号须核对生效显示，避免手写＋自动重复。
5. 表格保留已确认的表头、列数、列宽、合理分组合并和跨页规则；填写／扩行前核对物理单元格，独立记录的编号、名称与结果不得被继承的纵向合并覆盖。必要的行数／合并调整登记具体依据并逐行回读；计划表可写预期和接受准则，报告的实际结果、异常和结论必须有证据。
6. 文档深度与职责匹配：描述类文件必须覆盖基本信息、风险、需求、架构、设计、验证、追溯、缺陷和版本；计划/报告类文件必须覆盖范围、方法、记录、证据、偏差和结论。
7. 页数仅用作异常压缩/空白页检测，不能以凑页数代替事实完整性。

## 三、通用 PEMS 文档深度

| 文档类型 | 最少应说明的内容 |
|---|---|
| 确认计划 | 范围、对象、策略、职责、确认活动、接受准则、偏差、记录输出 |
| 体系架构 | 实际模块、接口、数据/控制流、通信、存储、输出、异常与型号差异 |
| 需求说明 | 功能、输入输出、安全需求、接口、环境、验收需求、需求验证 |
| 详细设计 | 模块输入/输出、状态、关键逻辑、异常处理、算法、接口和流程 |
| 确认报告 | 实际确认对象、方法、记录、偏差、整改、证据和结论 |
| 软件描述 | 基本信息、风险、需求、架构、设计、生命周期、验证、追溯、缺陷、版本和算法 |
| 可用性报告 | 用户、环境、关键任务、使用错误、接口要求、验证计划、观察记录和结论 |
| 验证计划/报告 | 单元、集成、系统测试；用例、条件、方法、准则、实际结果、异常和复测 |

## 四、必备图示

应根据当前项目的系统和模板章节生成，而不是从其他项目复制：

- 体系架构章节：软件体系架构图；
- 多模块、通信、接口或执行输出：模块关系图或硬件/软件拓扑图；
- 状态切换、自动控制、异常恢复：流程图或状态机图；
- 生命周期、配置、验证或变更管理：过程图；
- 可用性关键任务：任务流程图或界面示意图。

每张图应有图号、图题、正文引用和事实来源。图内文字、模块名、接口名、箭头和型号差异必须与当前正文一致。无依据的图不得生成；应阻断相关章节发布并列入项目待办。

## 五、全页验收

生成后对每份最终状态文件的全部页面渲染并检查，记录最终 DOCX／渲染哈希、页数和逐页结论；抽检及旧版 PDF 不能代替修改后的全页验收。工具不可用时记录未执行并继续独立工作，不得为导出成功擅自删分节／改变首页眉脚，不能宣称格式已通过。检查范围：封面、目录、页眉页脚、页码、表格跨页、图示、签署栏、结果栏和空白页。发现旧项目残留、图内文字错误、图缺失、表格裁切、目录域异常或结论无证据时，不得发布。
