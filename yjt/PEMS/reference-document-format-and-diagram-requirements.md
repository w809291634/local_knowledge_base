# PEMS 参考文档格式与图示要求

## 目的

本文件把 `Docu_Pems/pems文档` 与血糖仪 058、062 参考文档中可复用的版式和文档深度要求转为文字规则。它不复制任何参考文档，也不继承其产品名称、型号、性能、风险结论、测试结果、人员或签署信息。

## 一、统一格式原则

1. 每份文档从同编号的参考模板复制，在原模板槽位内修改；不从空白 Word 重建封面、目录、页眉、页脚或表格。
2. 封面、目录、正文、表格、图示和签署栏构成一个整体。封面独立一页；目录、章节编号、页眉页脚和页码按模板原样保留。
3. 项目名称、项目编号、文件编号、软件名称、型号、版本和签署状态必须从当前项目事实基线读取，并在全套文档一致。
4. 模板正文可以提供章节结构和固定、已批准的通用表述；任何项目事实、测试数据、通过结论、人员姓名、日期和图中文字均不得从参考文档继承。
5. 页面数量不是机械指标。文档必须具有与其职责相称的内容深度；不得把原有 10 至 50 页的结构性文档压缩为只有封面和两页泛泛说明。

## 二、封面和版式硬约束

- 采用 A4 纵向。页边距、页眉距离、分节数以每份对应模板为准，不能强行统一。
- 封面保留大标题、`QR/RD/xxx` 文控页眉、横线、封面信息表和签署栏。更新值时保留单元格合并、边框、定位、字号、缩进和对齐。
- 封面后必须紧接目录或正文，不能出现只含页眉页脚的空白页。
- 目录为域代码或既定目录样式时，不能通过合并 run、重建段落或手工拼页码破坏；内容修改后在兼容文字处理程序中刷新/核对目录。
- 使用模板既有字体、标题层级、表头填充、边框和单元格对齐。新增内容应克隆同类段落或表格，不引入自建彩色样式、蓝色表格或不属于模板的页眉。
- 跨页表格保留表头、列宽和合并结构；结果列、签署栏、记录栏在无证据时留空。

## 三、文档深度和表格要求

### RD-026 软件确认计划

- 保留封面、目录、确认范围、确认策略、职责、计划、偏差处理和输出记录。
- 确认条款表至少能覆盖软件初始化、输入、核心功能、边界、异常/互锁、通信和恢复；每条含对象、条件、方法、接受准则和证据类型。

### RD-027 软件设计变更记录（有软件变更时）

- 采用项目基本信息、变更来源、影响分析、风险评估、实施验证、批准与归档的结构。
- 变更记录必须关联受影响的需求、设计、代码、测试、版本和风险控制；不能只写“已修改”。

### RD-028 软件体系架构

- 以封面加架构正文为主，必须有实际软件体系架构图。
- 图中展示真实的输入、主控/处理、存储、通信、显示/提示、执行输出和异常/保护链路；型号差异使用独立说明或表格，不把长文字塞进模块框。

### RD-029 软件需求说明书

- 保留引言、任务概述、开发环境、法规/安全、软件功能需求、输入输出、安全需求、需求验证和测试章节。
- 开发环境、功能配置、接口、需求条款和验收要求使用模板原有表格结构。每个安全需求必须可追溯到设计、代码和测试用例。

### RD-030 软件详细设计说明书

- 保留前言、目录、术语、产品背景、模块设计、接口、状态/流程、异常处理、关键算法和版本相关章节。
- 对每个主要模块写清输入/触发、处理逻辑、状态、输出、错误/边界处理和与其他模块的接口；不能仅罗列功能名称。

### RD-032 软件确认报告

- 保留确认过程、目的范围、方法、单元/集成/系统记录、测试结果和结论的结构。
- 测试记录表沿用模板列数和分组。计划可以写预期结果；报告中的实际结果、异常和结论只能引用受控原始记录。

### RD-052 软件描述文档

参考血糖仪文档的结构深度，至少包含：

1. 基本信息、产品标识、安全性级别、运行环境、适用范围和上市历史；
2. 文档与配置管理、生存周期、问题解决和缺陷管理；
3. 风险管理计划、危险识别、风险控制及其验证关系；
4. 需求规格、模块功能、输入输出、外部接口和型号/配置差异；
5. 体系架构、设计实现、验证确认、可追溯性、软件版本/修订历史和关键算法。

52 文档原有的大型风险表、追溯表、版本表和测试摘要表应按当前项目事实填充或保留空白受控栏位；不能因为资料暂少而删除整章、整表或改成无依据的通用说明。

### RD-057 可用性报告（适用时）

- 保留可用性输入、预期用户、使用环境、关键任务、易错情景、用户接口要求、验证计划、问卷/记录表、观察结果和结论。
- 参考文档中的参与人数、评分、通过率、统计结论和姓名均为样例；无实际研究证据时，记录表留空，不填 OK、通过人数或结论。

### RD-068 / RD-069 软件验证计划与报告

- 参考血糖仪文档按单元测试、集成测试、系统测试分组，使用独立计划/记录表。
- 每个用例包含编号、阶段、目的/描述、条件、方法、接受准则；报告另记录实际结果、异常、复测和结论。
- 验证计划不能预填实际结果；验证报告不能从计划或模板复制“符合/通过”。

## 四、必须具备的图示

下列图示不是装饰，存在对应系统/流程时必须具备，并且以当前源码、硬件图、接口定义和事实基线为依据：

| 文档 | 必要图示 | 最少表达内容 |
|---|---|---|
| RD-028 | 软件体系架构图 | 输入、处理、存储、通信、显示、输出、保护与型号差异 |
| RD-030 | 关键功能流程图/状态图 | 初始化、主流程、状态切换、异常或停止处理、关键算法分支 |
| RD-052 | 软件体系架构图、硬件关系/拓扑图、系统工作流程图 | 软件模块关系、硬件接口、数据/控制流、关键状态和输出路径 |
| RD-052 | 生存周期/配置管理流程图、验证流程图 | 需求、设计、编码、验证、发布、变更和缺陷关闭的受控关系 |
| RD-057 | 关键任务流程或用户界面示意图 | 用户启动、设置、运行、异常识别、暂停/停止的操作路径 |
| RD-026/032/068/069 | 测试分层流程图或追溯图（模板/项目需要时） | 需求、设计、代码、单元/集成/系统测试、结果证据的关系 |

每张图均须满足：

- 有图号、图题、来源/依据和正文引用；
- 图内文字使用深色、可读字号，不能贴边、重叠、截断或沿用旧项目模块名；
- 节点、箭头和接口方向清晰；同一模块名称、通信名称、型号差异与正文一致；
- 图插入 Word 并缩放后，必须对最终渲染页复核；
- 没有当前项目依据的图不能用其他项目图替代。必要图缺少时，生成任务应阻断并列入待办，而不是删掉该图对应章节。

## 五、发布前格式验收

1. 以模板文件和最后受控输出分别渲染为 PDF/PNG，检查全部页面。
2. 对比封面位置、标题层级、目录页、分节、页眉页脚、表格列宽、跨页表头、图题、签署栏和空白页。
3. 建立“图示清单”：文档 ID、图号、图题、事实来源、插入位置、是否全页核验。
4. 发现旧项目文字、未更新图、缺图、页码异常、表格裁切或封面偏移时，禁止交付。
