# PEMS 通用参考文档格式与图示要求

## 一、参考文档的使用边界
参考文档只用于提取版式、章节层级、表格结构、目录/页眉页脚机制、图示类型和内容深度。不得继承任何产品名称、型号、版本、技术指标、用途、风险结论、测试结果、人员、日期、签署或图内项目文字。

## 分类规则 -- 封面

### 封面格式要求（14 条）

一、封面必须恰好占一页，封面之后不得出现空白页；不启用「首页不同」，封面沿用本份文档的页眉页脚。

二、封面由「大标题文字」和「封面信息表」两部分组成，这两部分必须视为**一个整体**排版，不得分别定位。

三、这个整体必须在该页**垂直居中**。判据：剔除页眉页脚后，取大标题与封面表全部文字的合并包围盒，上留白与下留白之差不超过 3pt（等价于整体中心与页面中线偏差不超过 1.5pt）。

四、居中只能通过**增减大标题前面的空行（空段）**实现。空行数量不固定，以渲染后的居中结果为准，不得预先写死行数。

五、**空行本身必须统一格式：字号 12pt（与正文一致），中文宋体、西文及数字 Times New Roman，单倍行距，段前段后均为 0，无首行缩进、无加粗、无底纹；空行内不得含文字、域、图形、书签或分页符。** 每个空行占高必须一致，不得通过改变某一段的字号、行距或段前段后来微调位置。

六、每次增减空行后必须重新渲染并重新测量；经 Word 保存后也须重渲染重测，不得沿用修改前的渲染结果判定通过。

七、大标题为 36pt 宋体、水平居中；该字号保持模板原值，不参与正文与标题的字号分档，不得被改为正文号或标题号。

八、大标题与封面信息表之间保持 3 个空行，不得增减；封面表之后承载分节符的空段不得删除。

九、封面信息表保持模板原有结构：四列、列宽、行列数、合并关系、六向边框、表格定位、底纹和签署栏一律原样，只允许替换已登记的字段值，禁止等比缩放列宽。

十、表内所有单元格文字**水平居中**；垂直对齐按对应模板版号的基线处理。

十一、表内文字为 14pt，中文宋体，西文与数字 Times New Roman，字色黑色；封面表字号不随正文表字号改动。

十二、只填写登记字段：文件编号、项目名称、项目编号、软件名称、型号、版本。编制、审核、批准、日期、测试人、测试时间、结果一律留空，标签文字必须完整保留。

十三、禁止用单元格垂直对齐或单独分节来实现居中，禁止改页边距压页，禁止调整表格定位或缩进来顶页，禁止用固定空行数推定已经居中。

十四、交付前须对最终渲染稿逐页检查封面页：整体居中、无空白页、文字与表格无裁切、无重叠。未渲染或渲染失败时该项记「未执行」，不得判为通过。

### 封面结构保留

一、封面必须独立成页：依靠**封面信息表之后的分节符（下一页）**或**正文首标题段的段前分页**。二者都没有时封面与正文挤在一页；封面表之后到首个正文块之间残留纯空段，会渲染出空白页。

二、排查顺序：① 封面表后有没有 `sectPr` 或段前分页？没有就补；② 封面表**之后**、首个正文块**之前**有没有纯空段？有就删。**删除范围仅限此区间**：大标题前面的居中空行、大标题与封面表之间的 3 个空行、以及封面表之后承载分节符的空段，均不得删除（本节「封面格式要求（14 条）」第四、五、八条）。

三、三种坏形态与处置：

| 现象 | 成因 | 处置 |
|---|---|---|
| 封面与正文同页 | 封面表后无分节符/段前分页 | 按第一条补分节符或段前分页 |
| 封面后多一页空白 | 封面表之后溢出纯空段 | 删该区间纯空段（受保护段不删） |
| 正文页眉丢失 | 删正文时把含 `sectPr` 的段一起删了 | 含 `sectPr` 的段**只清 run、保留该段** |

四、封面信息表常带 `tblpPr`（绝对定位、锚定文本），**不占正常流高度**：「封面占多少版面」不能只数段落数，居中判据按本节「封面格式要求（14 条）」第三条用渲染包围盒。克隆表格另作内容表时，可保留 `tblPr` 整体（边框、单元格边距）而去掉 `tblpPr`；**封面表本身的定位保持模板原样，禁止调整定位或缩进顶页**（本节「封面格式要求（14 条）」第九、十三条）。

五、清理纯空段的三个实现细节（原语见 `tools/docx_ops.py`）：

1. 遇到非段落元素（`bookmarkEnd` 等）必须 `continue` 而不是 `break`，否则循环提前结束、空段清不干净；
2. 判「空段」不能只看文本为空：只含域标记（`w:fldChar`／`w:instrText`）的段落同样无文字，删掉会破坏域闭合、使目录指令裸露，必须排除（域禁忌见「分类规则 -- 目录」的「目录域形态与修复判据」第四条）；
3. 含 `sectPr`、含分页符 `w:br`、含图形 `drawing`/`pict` 的段落一律不删。

六、若必须脚本重建正文（不推荐，仅模板结构不可用时）：保留第一个含 `sectPr` 的段落（清空文字、保留分节符），其余分节符段落删除；文档末尾的 `body/sectPr` 不动。禁止为导出成功合并所有节或改变首页设置（第五节）。

判据：渲染第 1 页只有封面、第 2 页有内容；`count(w:sectPr)` 与模板基线一致；封面居中按本节「封面格式要求（14 条）」第三条复测。

### 封面居中的实现禁令

一、**封面「整体垂直居中」用段前空段实现，不要用 `w:vAlign` ＋ 单独分节**：新建节的眉脚引用与正文节重复（哪怕换 `r:id` 指向同一部件）会让 Word 判「文件可能已经损坏」；且节边界不等于封面页，同节里的目录／前言页会被一起竖排居中。

二、段前空段做法必须**幂等**（先清成基准再补到 n），且补空段排在删空段／刷新目录之后，补完复核封面仍恰好一页。完整 14 条见本节「封面格式要求」。

## 分类规则 -- 目录

### 目录与正文分页

一、目录页必须独占一页，正文首标题不得落在目录页；目录与正文之间必须有明确换页机制（换页分节符、段前分页或经确认的分页控制），**禁止靠空段顶页**。

二、坏形态：模板在「目录末条目 → 正文首标题」之间塞入数十个纯空段当垫片，靠空段把正文顶到下一页；字体或行高稍变就顶不准，标题掉回目录页、目录页码全错。

三、**现行处置（唯一口径）**：删除全部垫片空段，把分页写在**正文首标题段的 `pageBreakBefore`** 上；**不得插入 `w:br type=page`**。旧做法「删垫片后插一个硬分页符」与 `pitfalls.md` §23／§39 冲突，已废弃，沿用会重新造出「段前分页＋段内硬分页符叠加 → 多一张整页空白」的缺陷。

四、判据：目录末条目与正文首标题之间的纯空段 **≥5 个**即视为「靠空段顶页」（1～2 个属正常留白）；删垫片不得改变节数，节数以模板为准；删除时按「分类规则 -- 封面」的「封面结构保留」第五条排除含域标记的段落。

五、硬分页符与段前分页**不得并存于同一段**（`pitfalls.md` §39；另见「分类规则 -- 分页」的「分页与空段处置要求」第二条）；每个叠加点会多一张空白页并造成页码跳号。

六、目录页码必须等于最终渲染实测页（S7／`pitfalls.md` §54）：自动目录域刷新后核对域健康与条目；静态点线目录逐条核对，改页码只改 `w:hyperlink` 内最后一个 `w:t`。判据与形态按 `dod-checklist.md` 16/17/18。

### 目录域形态与修复判据

一、目录页不得出现裸露域代码（`TOC \o`、`PAGEREF` 等字样）；出现即判域壳破损。**判定只看 XML，不用渲染**：把全文 `w:fldChar`／`w:instrText` 按文档顺序拉成序列，核 ① `begin/end` 是否配平、② TOC 指令有没有被 `begin … separate` 包裹、③ 目录条目里有没有域。

二、四种形态与处置（先判形态再动手，否则会修错）：

| 形态 | 结构特征 | 判据 | 处置 |
|---|---|---|---|
| A 未闭合 | 有 `begin`+`instrText`+`separate`，缺 `end` | `begin − end > 0` | 在目录末条目段落末尾补 `end`（个数＝差值） |
| B 域壳被拍平 | 指令在 `instrText` 但前面没有 `begin`；或指令直接落在 `w:t` | `toc_has_begin == False` 或 `text_has_toc == True` | 补 `begin`；`w:t` 改名为 `w:instrText`；再补 `separate` 与 `end` |
| C 目录无域 | 条目是纯文本＋硬编码页码，全文无 TOC 指令 | `toc_instr == False` 且 `entry_has_field == False` | **按已确认基线决定**：经确认保留静态点线目录的，不重建，逐条核对条目与实测页码（见本节「目录与正文分页」第六条）；确需改用域目录的，才在 Word/WPS 里用「引用→目录→自动目录」或 COM 的 `TablesOfContents.Add` 重建，且须注册人确认。**脚本禁止硬造 `PAGEREF`** |
| D 无目录 | 全文既无 TOC 指令也无目录条目 | 目录样式段落数为 0 | 按模板口径**不补纸面目录页**；先查版式基线档案确认是模板有意删除，再决定是否新建。**纸面目录页与导航窗格标题树是两件事**：不补目录页不意味着不建标题树，标题树按「分类规则 -- 标题树」处理 |

三、两个判定陷阱：① 一份文档可能有多个 TOC 域，全局 `begin/separate/end` 计数会把「一条链断了、另一条链多一个 `end`」抵成 `balance == 0` 的假健康，多目录文档必须**按域链分组**分别核配平；② `begin == end` 不代表正常——形态 B 可能是平衡的（每个 `PAGEREF`／`HYPERLINK` 自带 `begin/end`，而外层 TOC 连 `begin` 都没有），必须再查 `toc_has_begin`／`text_has_toc`。

四、域相关禁忌：**不得对含 `fldChar`／`instrText` 的段落做 run 合并或整段重写文本**（会把域拍平成普通文字）；删「空段」时必须排除含 `fldChar` 的段落；**不得试图用脚本重算 `PAGEREF` 的结果值**；补 `end` 只补外层，不动成对闭合的内层 `PAGEREF`／`HYPERLINK`。

五、形态 C 只想改页码时的最小动作：条目文字与页码常包在 `w:hyperlink` 内，段落直接子级没有 `w:r`，`python-docx` 的 `p.runs` 为空；此时用 `add_run` 会把新文字**追加**在旧文字后面，条目变成「5. 结论55. 结论4」。正确做法是只改 `w:hyperlink` 内**最后一个 `w:t`**（页码），其余不动；含 `w:hyperlink` 的段落与含域段落一并列入整段替换的排除名单。页码值按最终渲染实测页回填。

诊断与补壳原语见 `tools/docx_ops.py:toc_diagnose`；判据按 `dod-checklist.md` 16/17/18。

### 目录刷新与复诊

一、正确顺序：**先修复域壳 → 用 Word 刷新（F9／更新目录）→ 回读复诊 → 复诊不通过就再补壳**，**绝不能「刷新完就直接交付」**。刷新（等价于 Word 里按 F9）可能把本来健康的域壳拍平、把 TOC 指令变成可见文字，后果无法预知，因此「刷新后必须复诊」是硬性要求。

二、排查收口：改完域 → `toc_diagnose()` 通过 → 渲染 PDF 看目录首行没有 `TOC \o` → 才算完成。

三、形态 C 确需重建时，标题须可被自动目录识别（有大纲级别 0～8），但**不得为迁就目录而套 Heading 样式**——标题树只写 `w:outlineLvl`、不改 `pStyle`、不动字号（见「分类规则 -- 标题树」第一条）；书签字形与条目顺序不保证对应，禁止脚本硬塞 `PAGEREF`。

四、目录页码同步与静态目录改页码的写法**沿用本节「目录与正文分页」第六条**，本条不重复登记。

## 分类规则 -- 标题树

### 补齐标题树后的目录刷新护栏

一、**条目数不能只按「±2」判**。给文档补了标题树（`outlineLvl`）之后，Word 刷新会把以前收不到的真标题收进来，条目数增加是**正确结果**；继续用「±2」会把好结果还原掉、退回旧页码。改成按内容判：

```
可收录标题数 = 文档里「有文字 + 大纲级别 0~8 + 不在表格单元格内」的段落数
通过条件     = 域健康 且 旧条目数-1 ≤ 新条目数 ≤ max(旧条目数+2, 可收录标题数+1)
```

二、**表格单元格段落必须先降为正文级**（`w:outlineLvl val="9"`）。模板表格常整片继承带 `outlineLvl` 的段落样式，Word 更新目录时会把单元格当标题收进去，造成条目数暴涨、只能整份还原放弃刷新；生成阶段统一降级后，刷新可正常成功。

三、**刷新之后还要再清一次空标题段**。Word 重写目录区时会新造「带大纲级别的空段」（发生在刷新之后，生成阶段清不掉），导航窗格会出现空白条目。刷新脚本的收尾顺序：更新目录 → 复诊／补壳 → 重新统一字体 → **降级空标题段** → 保存。

判据按 `dod-checklist.md` F37；标题树要求与刷新护栏已详细化见本分类节。

### 标题树与大纲级别要求

一、**每份文档都要有标题树**：按编号形态写 `w:outlineLvl`（0/1/2 级），**不改 `pStyle`、不动字号**（套 Heading 样式自带字号会改掉标题字号，导航窗格与目录域认的只是 `outlineLvl`）。无编号模板的"××："小节名按整行短标题＋全段加粗识别。层级识别见 `pitfalls.md` §25。

二、编号段要区分「短标题」与「编号＋正文同段」：后者正文误挂了大纲级，须按统一判据全族扫描后拆成「标题段 ＋ 紧邻正文段」，不能只改被点名处。

三、**空标题段要么删、要么降级为 `outlineLvl=9`**；带分节符／域代码／图形／表格隔离的段落只能降级，删除会破坏结构。表格单元格段落统一降 9 级、刷新收尾再清一次空标题段，见本节「补齐标题树后的目录刷新护栏」。

四、**`keepNext`／`keepLines` 只写在标题段上**：图片段、图题段、正文段一律不加——加了会在段前显示与标题相同的大纲／分页标记，还会把「图＋后文」粘成整块推走，制造上一页底部大片空白。

五、判布尔型属性**必须读 `w:val`**：`<w:keepNext w:val="0"/>` 是关闭（压样式继承），只判「元素存在」会一次误报几十段、把真缺陷淹掉。同理适用于 `pageBreakBefore`／`keepLines`／`widowControl`／`pBdr val="none"`。

### 编号显示与双写禁令

一、编号须核对**实际显示**与连续性，不得出现「3.1 3.1」等**手写编号与自动编号（`numPr`）并存**造成的重复显示；手写与自动编号两套机制不得并用。

二、模板标题口径须统一：要么 Heading 样式＋一套自动编号，要么保持手写 `Normal` 编号，两套不并存（见 `template-baseline-rd052-2.1.md` §2）。不得为迁就目录域而套 Heading 样式（见「分类规则 -- 目录」的「目录刷新与复诊」）。

三、编号字形（`numbering.xml` 的 `lvl/rPr`）纳入三层审计（run 显式属性 → 样式链生效值 → 渲染 bbox），见「分类规则 -- 字体颜色」的「生效值与分层审计」，不得只看 run 显式属性。

## 分类规则 -- 正文

### 正文段落与样式链基线

一、**正文段落统一「全量套用基线」**，不是只补齐本轮新写段：模板自带段的行距／缩进／对齐本身就不一致。基线写进配置（首行缩进字符数、左右缩进、行距、对齐、正文样式），生成末尾**先删后写**全量套用；排除项与版式比对共用同一判据函数（见「分类规则 -- 字体与版式」§8／§9）。

二、**判结构段与套正文基线都要沿样式链**：样式自带 `numPr`、`ind:leftChars` 时段落自己没有，判据与基线会双双漏判；写缩进基线要显式压零 `left/right/leftChars/rightChars`（不能只删 `w:ind`，删了等于放回继承值）。

三、**新增正文段不得克隆供体**（标题锚点或"随便找一个正文样式段"会命中封面大标题）：用 `new_body_paragraph()` 新建、`demote_paragraph_to_body()` 降段（**必须改样式**，只改直接格式没用）、`body_paragraphs_with_heading_style()` 给闸门做检查。克隆会产出"挂标题样式的正文段"，正文基线与标题分档两条链路一起放过。

四、标题判据必须含**纯文本编号形态**（`1.1 名称`／`第X章`）：只按整段加粗会漏半粗体标题，漏了就被加上正文缩进。

五、断句合并用配置显式声明（`merge_paras`），启发式只做扫描报告；补标点的整句替换必须排在合并之后。

### 首行缩进适用范围与保护区

一、首行缩进、行距、段前段后距及对齐按对应基线；**缩进只加正文自然段**：标题、图题／表题、目录条目、封面区、表内单元格、文本框、真列表、居中／右对齐段一律不加。新增正文段与同类段落一致，写法见「正文段落与样式链基线」第三条。

二、判「哪些段是正文自然段」必须先按角色分类（见 `pitfalls.md` §95），适用范围与保护区边界共用同一套判据，不得在检查脚本里另写一套；写法与常见误用见 `pitfalls.md` §90。

三、改完必须过 Word 保存再回读生效值（docDefaults → 样式链 → 直接 `pPr`），不能以直接格式为准。判据见 `dod-checklist.md` 45d/45e/45j。

## 分类规则 -- 分页

### 空白页与分页缺陷：定位—修复—复验

**第 1 步 先跑判据，不要先改。** `pagination_audit(doc, cover_texts=[封面文档名])` 的返回键以同源原语为准，按 S7 与 `dod-checklist.md` 第 32 项分为缺陷键、形态位及待分诊项；不写死「七项／九项」，不要求所有键为空。**判据自身要先自证清白**：历史上出过三类误报（`w:val="0"` 被当开启、目录域条目被当正文标题、封面留白被当顶页空段），任何一类报出后先回原始 XML 复核其中一处，确认判据可信再看全表。

**第 2 步 用渲染定位，不要用文字。** `page_ink_coverage(pdf)` → `grade_pages_by_ink(cov)`（`pitfalls.md` §41）。中文 PDF 缺 ToUnicode 时整页取不到字，`pdftotext`／`get_text()` 不可信；`get_text()` 只用于确认「某页是否出现了不该出现的字符串」，且须先确认该 PDF 有 ToUnicode。

**第 3 步 查「叠加」，不要查「存在」。** 空白页根因几乎总是同一效果被写两遍：段前分页＋段内硬分页符、分节符(NEW_PAGE)＋段前分页、样式分页＋段落分页（`stacked_breaks`）。段前冒点同理是属性写到不该写的段上：正文级段落带 `keepNext`／`keepLines`，或封面文档名带 `outlineLvl`（`pitfalls.md` §38）。

**第 4 步 修复与判据共用同一套函数。** `pagination_repair(doc, cover_texts=[...], apply=[...])` 直接复用 `pagination_audit` 的判据，避免「查的是一套、改的是另一套」。原则是**只删多余那一份，保留规范那一份**（一律留 `pageBreakBefore`，删 `w:br type=page`）；`apply` 收窄到本轮已确认的动作，不默认全开。改完立即复跑 `pagination_audit`：缺陷键清零，形态位记录，待分诊项逐项修复或有具体依据的豁免；同时比对修前修后结构。禁止为清零而删除必要分节；同类项可引用同一条已确认规则，但每个位置仍须复核，不得未经核验批量豁免。

**第 5 步 重渲染并核账页数。** 重导 PDF 并记录对应 DOCX／PDF 哈希：纯删除空白页、正文及其他版式均未变化时，`len(cov)` 应等于「修复前页数 − 消除的空白页数」；有受控内容／版式调整时逐项说明重排依据。`grade_pages_by_ink` 必须无阻断项，且还需目检页顶／页中留白、图表截断和目录页码。再人工看修复点前后各一页——标题是否仍在页首、居中是否被多余制表符顶偏。仅在本轮明确预期删除空白页、正文和其他版式均未改变时，页数未按预期减少或少得超过核账值，须检查修复是否生效、是否误删结构或被保存回滚，不能当「顺手又排了一版」；其他受控重排中页数可不变也可增减，按已登记的变化与逐页结果判断。

**收尾**：第 1 步的分类判据与第 5 步的墨占比分级已并入 `dod-checklist.md` F 组，是每轮交付的固定终检项；同批文档的结构与数值检查用同一段脚本逐份执行并留档，不能替代 S9 的每份文档逐页目检。

### 分页与空段处置要求

一、**章节之间用 `w:pageBreakBefore`**：不插 `w:br type=page`、不靠回车顶页，并删除章标题前的顶页空段；前一段是分节符时不写，避免多一页空白（与「分类规则 -- 目录」的「目录与正文分页」第三条同源）。

二、**硬分页符与段前分页不得并存于同一段**：两者叠加每个叠加点多一张整页空白、页码跳号，而正文逐段看都「合理」；交付前查 `hard_page_breaks==0` 且 `stacked_breaks==[]`。

三、**章级排版按模板多数派在同一文档内统一**（补齐／保持连续／取消少数派），不要机械「每章一页」；表单式报告全拆页会造出半空页。封面后第一块（目录／前言）是**前置件例外**，必须保留分页，且要找封面表之后的第一个有字段落，不能用序号差。

四、**「无文字的空段」有三种命运**：单独承载域 `end` 的删了 TOC 域不闭合；只含硬分页符且是封面与正文之间唯一换页的删了正文会挤回封面页，应就地转成 `pageBreakBefore`；只有纯回车占位才删。守卫写进「数空段」的循环里，别写在删除动作的 `if` 上。

五、**修复动作不得污染自己的判据**：`drop_hard_break` 会把硬分页符换成 `pageBreakBefore`，所以判「是否已按章分页」要同时数**段前分页／段内硬分页符／前一段换页分节符**三种等价形态，且复核必须排在清空段之后。

六、**中文 PDF 的空白页判据改用渲染墨占比**（`page_ink_coverage` + `grade_pages_by_ink`），不要用 `pdftotext` 字数：子集字体无 ToUnicode 时汉字全丢，正常中文页会被判成空白页。裁掉页眉页脚带后量像素灰度分级；末页 1～2 行溢出记提示并写进版本说明，**不得用偏离基线的行距压页**。

七、修完分页的三项回归：目录域 `balance==0`、页数核账（仅删空白页且正文与其他版式未变时按旧页数减空白页数；有内容或受控版式变化时逐项记录重排依据）、图示核对**图张数**而非「有图的页」。

## 分类规则 -- 页面设置

### 各节页面尺寸与横竖混排

一、不能要求所有分节与第一页完全相同：横向宽表、附录、图页或封面可能是模板有意设置。逐节读取 `pgSz`／`pgMar`（宽、高、`orient`、四边边距、眉脚距离），与当前项目格式档案中登记的预期值比对。

二、处置：档案规定该节纵向而输出被改成横向或边距变化 → 按档案恢复；档案规定横向（宽表／宽图）→ 保留横向并检查表格、图示未裁切；**未建立格式档案时不得擅自以第一页覆盖其余分节**，应先确定每节预期格式。

三、横版节三条硬约束：

1. **版心宽度按所在节算**：可用宽 = 该节页宽 − 该节左右边距。同一份文档里竖版节与横版节差异很大，配图与宽表的宽度判据必须取所在节的值（含绘图工具的单位换算），否则图会超出横版节版心或被竖版节裁切；
2. **正文不得落进横版节**：横版节只承载它自己的宽表／宽图；补分页、承接段落或清理空段时，不要把正文推进横版节，也不要把横版节的图挤回竖版节；
3. **分节符所在段不能删**：横版节常由一个空段携带 `sectPr` 开启，删掉它横竖排并回一节、整页版式全废；「数空段」的守卫必须把携带 `sectPr` 的段落列为不可删。

四、分节类型与页码：`w:type` 未写即 `nextPage`，禁止 `continuous`；页码仅第 1 节可写 `pgNumType start=1`，后续节不写、连续不重启；节缺 `footerReference` 时按前节链接解析，不得据此断言该节无页码。

五、首页不启用「首页不同」（`titlePg=false`）；`evenAndOddHeaders=false` 时 first/even 眉脚引用可存在但不生效，不得据此判定有多套眉脚。横竖混排不强制全篇同向。

判据：逐节比对 `pgSz`／`pgMar` 全部字段（不能只比宽高集合）；渲染逐页方向必须与节划分一致；**跨渲染程序的页数差异不作判据**，以最终渲染产物与页脚 `NUMPAGES` 为准。

## 分类规则 -- 图示图题

### 必备图示类型与要素

应根据当前项目的系统和模板章节生成，而不是从其他项目复制：

- 体系架构章节：软件体系架构图；
- 存在多模块、通信、外部接口或执行输出：模块关系图或硬件/软件拓扑图；
- 存在状态切换、关键控制、自动处理或异常恢复：流程图或状态机图；
- 有生命周期、配置、验证或变更过程要求：相应过程图；
- 有关键用户任务或高使用风险：任务流程图或界面示意图。

每张图应有图号、图题、正文引用和事实来源。图内文字、模块名、接口名、箭头和型号差异必须与当前正文一致。无依据的图不得生成，也不能用其他项目的图替代；应阻断相关章节发布并列入项目待办。每张图还须有**最终页面渲染核验记录**（图题位置、图示是否被裁切、与所属章节是否对应）。图示是否需要由当前项目的软件系统、模板章节和追溯关系决定，不由通用规则替项目指定。图题排版、绘图与插图验收见本节「图题与图内文字格式」与「绘图与插图替换要求」。

### 图题与图内文字格式

一、每条图题**居中 + 加粗**，字号取图题档（分区基线见「分类规则 -- 字体与版式」§2／§7，逐份以项目格式档案为准）；图题必须位于**正文区**（第一个章级标题之后），不得落在目录区。

二、**图内不写图名**：图名由 Word 图题承担，图里再画一遍标题会造成「图 1」重复出现。

三、图内文字、模块名、接口名、箭头指向和型号差异必须与当前正文一致；图内中文字体随正文（正文统一宋体时配图脚本须同步改字体并重绘，PNG 不受 Word 字体设置影响）。无依据的图不得生成；应阻断相关章节发布并列入项目待办。

### 绘图与插图替换要求

一、三条绘图硬规则（消掉文字压框与箭头错位）：① **1 数据单位 = 1 英寸**（`axes` 占满 `figure`、`set_aspect('equal')`，字号 pt 才能直接换算）；② **方框一律用 Rectangle**，边界必须精确等于 `(x, y, w, h)`（`FancyBboxPatch` 的 pad/rounding 会让实际边界偏移，只用于不接箭头的圆角容器）；③ **箭头端点由框边界计算**（`edge()` 从 `(x,y,w,h)` 取边，多箭头用不同 `t` 错开），禁止文字坐标与箭头端点硬编码。

二、图内文字不得压框线、不得与图形重叠、注释不得越界；生成时做文本宽度预警（中文按 `1.0em`、西文按 `0.55em` 估宽，超框必须报出而非静默）。**脚本读不到图内文字**，生成 PNG 后必须逐张人工看图核对，一次只复核一张，有问题改坐标重生成再看。

三、插图锚点定位必须**跳过目录样式段**（TOC 条目与正文标题同文本时会先被命中，把图插进目录区）；插图只给宽度、不给高度，否则同时指定宽高会造成拉伸，高度按 PNG 原始比例算。

四、图片有 **DrawingML（`a:blip@r:embed`）与 VML（`v:imagedata@r:id`）两种形态**，旧版模板、文本框与艺术字常混用 VML；所有「找图片／列图片段／取 rId／删孤立关系／校验」都必须同时识别两种，VML 需用 Clark 记法（python-docx 的 nsmap 无 `v` 前缀）。只认 `a:blip` 会数错图并误删仍被引用的媒体关系，造成图在保存后消失。加函数前先搜同义实现，不另写一套。

五、删除未引用的媒体部件前**必须对账**：图片段落总数应等于文中 `a:blip` + `v:imagedata` 的引用数之和；不等就停下别删。保存后重开确认 media 部件数等于实际被引用数、无悬空 rId。

六、保存前先探独占写权限（文档被 Word/WPS 打开时 `doc.save` 抛 `PermissionError`，且此前改动全部作废），保存后重开一次确认结构与图片数。

七、**整包无图形部件的模板不得自动插图**：`[Content_Types].xml` 只有 `xml`/`rels`、包内无 `w:drawing`／`word/media` 的模板，脚本加图会让 Word 判「文件已损坏」，而 LibreOffice 静默不产出、python-docx 结构检查正常、XML 层查不出毛病。处置优先级：① 该模板不自动插图，图留在 `figs/`，`todo.md` 记「需人工插入」；② 换一份本就含图形部件的同版式模板作供体；③ 先用 Word 打开模板另存一次 `.docx` 再插图。定位用最小复现操作二分，别猜。

八、两项机器校验（截图看不出但必须做）：① 嵌入图片 blob 的 SHA-256 与源 PNG 逐张相等且顺序正确；② `wp:extent` 的 `cx/cy` 与 PNG 像素宽高比差 < 1%。VML 图无 `wp:extent`，只核哈希（核宽高比前须判空，否则 `IndexError`）。

九、交付前最后一道闸门必须**用 Word 逐个只读打开并记录页数**，再人工在 Word/WPS 里翻页确认渲染效果；LibreOffice 渲染 + `python-docx` 结构校验不能替代，抓不到「Word 拒开」这类损坏。

绘图与插图原语见 `tools/fig_tools.py` 与 `tools/docx_ops.py`（`canvas/box/txt/edge/arr/flow/save/warn_report`、`iter_image_paragraphs`、`image_rids`、`replace_figures`、`drop_orphan_image_rels`、`verify_figures`、`assert_writable`）；项目只提供图清单（png／图题／锚点／宽度）与事实来源，绘图与插图逻辑不重复实现。判据见 `dod-checklist.md` 14/14b/14c。

### 结论先行

1. 字号统一不是"全选改一遍"：要**分区**（正文 / 各级标题 / 表格 / 图题 / 封面区 / 目录 / 页眉页脚），

2. 只改 run 的直接格式**不够**：必须同时改 `styles.xml` 里 `Normal`、`Heading 1~4` 的默认值，
   否则用户在 Word 里新打一个字又回到旧字体。
3. **空 run 也要设字号**——它们不显示文字，但决定行高与后续输入。
4. 中文与西文分槽：`w:rFonts@eastAsia` 管中文，`@ascii`/`@hAnsi` 管西文与数字。
   注册资料里大量标准号、型号串与带单位的数值（如 `GB 9706.1`、`XX-1000`、`10mW±20%`）属西文，惯例配 Times New Roman；
   强行让西文也用宋体会让长串换行变多。
5. **表格字号一般要比正文小一档**（正文小四 → 表格五号）。宽表（5~7 列窄列）全上小四会撞破列宽、
   行高膨胀、页数增加；这是取舍，不是偷懒，需在版本说明里写明。
6. 配图是 PNG，**不受 Word 字体设置影响**：正文换宋体后，图内若还是黑体就仍然"不统一"，
   必须回到绘图脚本换字体重绘（matplotlib：`rcParams['font.family']='SimSun'`，在 import 绘图库之后覆盖）。

```python
import os, collections
from docx import Document
from docx.oxml.ns import qn

def eastasia(r):
    rPr = r._r.find(qn('w:rPr'))
    if rPr is None: return None
    rf = rPr.find(qn('w:rFonts'))
    return rf.get(qn('w:eastAsia')) if rf is not None else None

agg = collections.Counter()
for f in os.listdir(OUT):
    if not f.endswith('.docx'): continue
    d = Document(os.path.join(OUT, f))
    for p in d.paragraphs:
        for r in p.runs:
            if r.text.strip():
                agg[(f[:6], 'body', eastasia(r),
                     r.font.size.pt if r.font.size else None)] += 1
    for t in d.tables:
        for row in t.rows:
            for c in row.cells:
                for p in c.paragraphs:
                    for r in p.runs:
                        if r.text.strip():
                            agg[(f[:6], 'table', eastasia(r),
                                 r.font.size.pt if r.font.size else None)] += 1
for k, v in sorted(agg.items(), key=lambda x: -x[1]):
    print(k, v)
```

看三件事：① 有多少 run 的字体槽是 `None`（继承样式，改样式即可批量生效）；
② 有多少被**直接格式**钉死（必须逐 run 覆写）；③ 表格与正文各占多少（决定要不要分档）。

### 2. 版式规则写进事实文件（唯一来源）

```yaml
formatting:
  east_asia: 宋体
  ascii_font: Times New Roman
  body_pt: 12          # 正文 小四
  table_pt: 10.5       # 表格 五号（宽表用小四会撞破列宽）
  caption_pt: 10.5     # 图题/表题 五号
  h1_pt: 16            # 三号；h2 15（小三）、h3 14（四号）、h4 12（小四），均加粗
  keep_untouched: [封面区, 目录条目, 页眉页脚, 文本框图形]
  figure_font: SimSun  # 配图内文字随正文
```

### 3. 执行要点

> **模板自带的字体混排按"模板错误"处理**：注册人已定交付稿字体按本库基线统一，不因"模板就是这样"而保留（模板里的微软雅黑章标题、楷体正文、黑体目录条目、同级一半 Times 一半宋体都要统一）。
> 唯一例外是 Symbol/Wingdings 私用区字符 run（见 §9 排除项）。只改字体不改字号，封面大标题字号仍走 §10 护栏。

> **先查共享原语**：`docx_ops.unify_document_fonts()` 已实现本节全部要点
> （`iter_zone_paragraphs` 分区、删 `*Theme` 属性、遍历表格、跳过文本框、改样式默认值）。
> 项目脚本只应做**薄封装**补自己的差异（如标题分级字号），不要再抄一份分区逻辑，
> 否则库修了"主题属性优先级"这类 bug，项目那份仍带旧行为（`pitfalls.md` §30）。

字号单位是**半磅**：小四=24、五号=21、三号=32、小三=30、四号=28。

```python
def _apply_font(run, ea, ascii_font, size_pt, bold=None):
    run.font.name = ascii_font                    # python-docx 会同时写 ascii 与 hAnsi
    rPr = run._element.get_or_add_rPr()
    rf = rPr.find(qn('w:rFonts'))
    if rf is None:
        rf = OxmlElement('w:rFonts'); rPr.insert(0, rf)
    rf.set(qn('w:eastAsia'), ea)
    rf.set(qn('w:cs'), ascii_font)
    run.font.size = Pt(size_pt)                   # 用 python-docx 写 sz/szCs，避免元素顺序违规
    if bold is not None:
        run.font.bold = bold
```

分区判定顺序（先特殊后一般）：

| 判定 | 依据 | 处置 |
|---|---|---|
| 封面区 | 正文块序列里**封面表之前**的所有段落 + 封面表本身 | 跳过不动 |
| 目录 | `p.style.name` 以 `toc` 开头、`Table of contents` | 跳过不动 |
| 页眉页脚 | `section.header/footer` | 不遍历即不动 |
| 文本框图形 | `p.runs` 天然取不到 `w:txbxContent` 内的 run | 自动跳过（要改见 `pitfalls.md` 节点级替换） |
| 标题 | 样式名 `Heading N` / `标题 N` | 该级字号 + `bold=True` |
| 表格 | 遍历 `doc.tables` 全部单元格（去重合并格） | 表格字号，`bold` 不覆盖（保留表头加粗） |
| 图题/表题 | 样式 `Figure`/`Caption`，或文本以「图」「表」开头且 ≤40 字 | 图题字号 |
| 其余 | — | 正文字号 |

**同时改样式默认值**：`Normal` → 正文档，`Heading 1~4` → 各级字号，并写 `rFonts@eastAsia`。

### 4. 验证（不能只看"改成功了"）

1. 复跑第 1 节的测量脚本：目标档位之外**只允许**出现"故意保留"的封面/目录条目；把例外逐项指认到位置（封面大标题、封面表）。
2. 页数会因字号变大而增加：逐页渲染检查**无空白页、无列宽撞破、无表格被挤到跨页断行**。
3. 用 Word（不只 WPS、不只 LibreOffice）逐个打开确认无损坏，并记录页数。
4. 版本升级：输出到新版本目录（`*_V2/`），旧版保留；在版本说明里写清"本版仅版式，内容未变"，
   避免评审把版式改动误读为内容变更。

### 5. 反模式

- 在 Word 里全选改字体 → 封面大标题、目录、页眉一起变，且下次重生成又被模板打回原形。
- 只改 `Normal` 样式 → 被直接格式钉死的 run 一个都没变，看起来"改了没用"。
- 正文/表格同字号 → 宽表溢出，回头又手工缩小表格，重新变成不统一。
- 忘记重绘配图 → 文档正文宋体、图里黑体，肉眼一眼看出不统一。


### 6. 执行顺序（实测，错了会白改一遍）

```
生成/就地替换 → 表格与图示 → 封面与分页
   → 目录刷新（Word 更新域）→ ★ 字体统一（第二遍）→ 闸门 → 渲染
```

字体统一必须**在目录刷新之后再跑一遍**，两个原因：

1. Word 保存时会重写封面标题与目录条目的 run，把显式 `rFonts` 丢掉（实测三份文档各
   141/39/50 处变成 `None/None`）——刷新前统一得再干净也会被抹回去；
2. Word 还会顺手规掉与 `docDefaults` 等价的**样式默认字号**，需从刷新前的备份把各级样式
   `w:sz` 写回，否则产物 XML 不再等于模板版式。

### 7. 覆盖清单与闸门项

统一动作必须覆盖四处，缺一处就是"看起来改了其实没改"：

| 位置 | 手段 | 漏掉的后果 |
|---|---|---|
| 正文段落 run | `unify_document_fonts` | 主体 OK |
| **表格单元格** | 同上（内部遍历 `doc.tables`） | `doc.paragraphs` 不含表内段落，旧字体整片残留 |
| **空 run** | 同上（不按有无文字过滤） | 行高与用户新输入仍走旧字号 |
| **样式默认值** | `style_font(Normal/Heading 1~4/Caption)` | Word 里新打一个字就回到旧字体 |

配套硬约束：改 `w:rFonts` 时必须删掉 `asciiTheme/eastAsiaTheme/hAnsiTheme/cstheme`，
否则主题优先级更高，显式字体名不生效。

闸门最少四条（非零退出码阻断发布）：

1. 分区字体基线：所有非文本框 run 的 `eastAsia`/`ascii` == 基线值；
2. 分区字号：正文=正文档、表格与图题=表格档；**正文区各级标题按族基线校 `sz`/`eastAsia`/`bold`
   且每级取值唯一（见 §10，本条修订原"标题只校字体不校字号"的规定）**；封面区、页眉页脚仍只校字体不校字号；
3. 样式默认值：`Heading N` 的 `sz` 等于**族基线**（不是模板原值，见 §10.3），`eastAsia` 已统一；`Normal` 随正文档变；
4. 配图字体：绘图脚本的 `font.family` 与正文一致，重绘后跑宽度预警 + 逐张看图
   （PNG 不受 Word 字体设置影响，正文换宋体而图里还是黑体，一眼就能看出来）。

### 8. 段落级版式一致性（字体统一之后仍会剩下的那类问题）

字体与字号统一解决"字长什么样"，解决不了"段落怎么排"。同一份文档里最常见的段落级缺陷是
**本轮新写的正文段没带段落属性**，与上下文缩进／行距／对齐不一致；以及**同一句话被写两遍、
两遍格式还不同**（承接与槽位双轨撞车）。两者都要按"生效版式"判，不能只看段落自己写了什么。

#### 8.1 判据

```
生效版式 = docDefaults → 样式链（basedOn 逐级）→ 段落直接 pPr     # 逐层合并，后层覆盖前层
指纹 = (首行缩进, 左缩进, 行距, 行距规则, 对齐)
归一 = 0/c0/t0 视为无缩进；line=240+auto 视为单倍（不写）；未写 jc 与 both 视为相同
```

不参与比对的段落：标题、目录条目、图题／表题、含域代码、含图形、文本框内、带自动编号的段，
以及短行居中／整段加粗的小标题。

#### 8.2 处置

| 动作 | 规则 |
|---|---|
| 配锚点 | 本轮新写段 ← 左边最近的"模板原样段或自己写了 pPr 的段"；左边没有就取右边最近的 |
| 对齐 | 先双向对齐 `pStyle`（参照没写而本段写了要摘掉），再抄参照**直接写了**的 ind/spacing/jc |
| 边界 | 带 pPr 的段不动（那是模板给该位置的版式）；空 `<w:pPr/>` 不算带 pPr |
| 重复段 | 去重时若胜者无版式而败者有，先把败者版式接过来 —— 留文字与留版式分别取最合适来源 |

#### 8.3 闸门补两条（非零退出码阻断）

1. **无重复正文段**：`para_ops.find_duplicate_paragraphs`，模板自带的同族并列条目用 `dup_allow` 声明；
   两段都是模板原样时只报不删。
2. **本轮正文段版式与锚点一致**：`para_ops.para_format_issues` 必须为空。
   判定必须依赖生成器记录的"每段来历"（slot/extra/carry/base）—— 没有来历就分不清
   "本轮写坏了"与"模板本来就这样"，只能整片重排，既越界又危险。

### 9. 正文段落基线（全量套用，与字体基线并列）

字体/字号统一之后，剩下的"段落格式不同"全部属于**段落属性**层面。基线要显式写进配置，
并在生成末尾对所有正文段全量套用；只补齐"本轮新写段"不够（模板自带段本身就不统一）。

```
body_format = { first_line_chars, first_line_twips, left, right, jc, line, style }
# 典型取值：首行缩进 2 字符（firstLineChars=200 + firstLine 兜底）、左右无缩进、
#          单倍行距（不写 w:spacing）、左对齐、正文样式 Normal
body_format_sig = 生效版式指纹（用于闸门逐段核对）
```

落地要点（都是实测踩出来的）：
1. **先删后写**：`pStyle / ind / spacing / jc / autoSpaceDE / autoSpaceDN / adjustRightInd /
   snapToGrid / textAlignment / contextualSpacing / widowControl` 全删，再按基线写，
   元素顺序须符合 `CT_PPr` 的 schema（pStyle → 开关 → ind → spacing → jc）。
2. **排除项与版式比对共用同一函数**（标题/目录/图题/编号段/含域/含图形/文本框/封面区/
   Symbol 与 Wingdings 私用区字符 run），否则会出现"闸门说统一、其实漏了三类段"。
   行首是 `\uf07a` 一类私用区字符的项目符号段被改成宋体后会直接显示成方块，这类 run 必须排除。
3. **标题判据要含纯文本形态**：只按"整段加粗"会漏掉"编号 run 加粗、文字 run 不加粗"的小标题，
   它们会被加上正文缩进（见 `pitfalls.md` §21）。
4. **封面区＝分节符之前且非成段正文**：前言可能在封面节里。
5. **例外用配置声明**（`body_format_keep`），例如带左侧标签栏的挂缩进块。
6. **两处"段落自己没有、样式链里有"的值必须一起处理**：样式自带 `numPr`（如 `Figure` 样式的
   "测试方法"条目）→ 段落级判据会把它当正文并加上首行缩进，判"编号列表项"要沿 `base_style` 链查；
   样式自带 `ind:leftChars=150` → 只写 `firstLineChars` 不写 `leftChars=0`，生效值仍是 150，
   套完基线指纹照样偏离。写基线时把 `left/right/leftChars/rightChars` 一并显式压零。
7. **字体统一排在 Word 刷新目录之后**（见 §6），且刷新后必须复测样式默认值：Word 会顺手规掉与
   `docDefaults` 等价的 `Heading N` 字号，复测不通过就从刷新前的备份写回。

闸门硬检查（非零退出阻断）：① 每份文档所有正文段的生效版式 == 基线指纹；
② 正文段末尾都有句末标点（`no_punct_allow` 例外）；③ 标题无"同名不同号"；
④ 分区字号（正文/表格/图题三档）与样式默认值分别复核，**以生效值为准，不以"我写了什么"为准**；
⑤ 套用后仍偏离基线的段落必须逐段打印（实测漏网 6 段全部来自第 6 条的两类继承值）。


### 10. 文档族内标题字号统一：以参照文档取基线，逐级别多数派投票

**这条修订 §7 闸门第 2 条。** 原先规定"标题/封面/页眉只校字体不校字号"，那只解决"一份文档内
字体乱"的问题；同一批文档族各自套了不同模板后，会出现**同级别标题跨文档字号不一致**
（实测同一文档族里章标题同时存在 12/14/16/22 磅，节标题存在 10.5/12/14/16 磅，
还有一处子节标题是五号 10.5 磅而其余都是小四）。跨文档并排看就是"格式不统一"。

#### 10.1 基线怎么定

不要手写一套"标准字号表"——**指定一份文档当参照，从它身上量出来**：

```python
prof = heading_format_profile_from(参照文档)     # {级别: {sz, ea, latin, bold, votes, total}}
normalize_heading_format(每份文档, prof)
```

取**逐级别多数派投票**，不取第一段、也不取平均值：参照文档自身常有一两段偏离
（实测某参照文档 23 段二级标题里有 1 段漏加粗），投票多数派才能把那几段也一并纠正过来。
`votes/total` 要打印出来——**一致率不是 100% 就说明参照文档本身不干净**，先确认再当基线。

#### 10.2 四条硬护栏（缺一条就会毁掉封面或目录）

1. **只动封面表之后的段落。** 封面大标题通常也带 `outlineLvl=0`（实测 sz=72 即 36 磅），
   不排除的话七份封面大标题会被一起压成正文号，且 XML diff 看着完全"正常"。
   以封面信息表位置为界，改完必须逐份回读封面标题字号确认没动。
2. **跳过目录域内段落**（含 `fldChar`/`instrText`，或样式名以 `TOC`/`目录` 开头）。
   目录条目改了字号会与正文标题不一致，且 Word 刷新目录时会被覆盖回去，白改。
3. **跳过表格内段落。** 只遍历 body 直接子级天然满足；但注意 COM 的 `Paragraphs`
   集合含表内段落（§45.3），用对象模型复核时不能按序号对齐。
4. **引导句降级，不要套标题格式。** "××如下图所示："这类被误标成标题级的句子
   （§42 的漏判形态），正确处置是把 `outlineLvl` 降为 9，而不是给它加粗放大。

#### 10.3 执行顺序与回归

`normalize_heading_format` 会同时改 `Heading N` 样式的默认字号（`also_style=True`）——
只写 run 级显式值的话，Word 保存时可能按样式回涨（§13）。改完按 §6 的顺序收尾：
刷新目录域 → 重跑字体统一 → 重渲染。

回归三项：① 逐档逐级别统计"字号/中文字体/加粗"组合数，**每级必须只剩 1 种**；
② 封面大标题字号逐份回读，必须等于改前值；③ 页数与空白页复测——标题缩号会让章节变矮，
可能把原本压着页尾的表挤到上一页，页数变了就要重刷目录页码。

#### 10.4 闸门改写

§7 第 2 条改为：正文区标题按级别校 `sz`/`eastAsia`/`bold` 等于族基线，**每级取值唯一**；
封面区、页眉页脚仍只校字体不校字号。第 3 条补充：`Heading N` 样式的 `sz` 必须等于族基线，
不得停留在模板原值。


#### 10.5 分档，不是"取值统一"——全级别同字号是另一种不统一

§10 的第一版做法是"把各级标题统一到参照文档的取值"，实测把 L1/L2/L3 全压成了正文档的 12 磅。
字号确实"每级唯一"了，闸门全绿，但结果是**章标题与正文同号**，只靠加粗和"第X章"编号区分，
层级感消失，用户立刻反馈"这个章节字号可以大一点"。

**族内统一的正确目标是"分级成档"，不是"取值归一"。** 闸门第 45 条只查"每级只剩一种取值"，
查不出"三级挤在同一档"这种退化，必须补一条**跨档检查**：

```
各级取值必须互不相同，且严格递减：sz(L1) > sz(L2) > sz(L3) > 0
且 sz(L1) 必须大于正文档（否则章标题与正文同号，层级不可辨）
```

典型三档（正文小四 12pt 时）：**章标题 三号 16pt（`sz=32`）／节标题 四号 14pt（`sz=28`）／
子节标题 小四 12pt（`sz=24`）**，全部加粗。档位写进项目配置，不要散在各脚本里；
参照文档只提供"字体与加粗"，**字号档位由配置显式给出**——参照文档自身可能正是退化的一方，
拿它当字号基线会把它的毛病固化成族标准。

推论：`heading_format_profile_from()` 的返回值要当**候选**看，不当**指令**看。
用它之前先看一眼各级取值是否成档；不成档就改用显式 profile 字典，只从参照文档继承字体与加粗。


### 常用配置默认值（开工速查权威登记处）
