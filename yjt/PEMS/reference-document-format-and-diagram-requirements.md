# PEMS 通用参考文档格式与图示要求

## 一、参考文档的使用边界

参考文档只用于提取版式、章节层级、表格结构、目录/页眉页脚机制、图示类型和内容深度。不得继承任何产品名称、型号、版本、技术指标、用途、风险结论、测试结果、人员、日期、签署或图内项目文字。

## 二、文字版格式要求

**严格执行要求（2026-11-10 用户明确）：**以下格式要求必须进入流程 S2～S10 的动作、完成判据与证据，不能只作阅读建议。执行表见 `yjt/PEMS/authoring-workflow-and-experience-index.md` §1.3。每份文档分别冻结基线，修改后重新检查；任何必要格式项失败或未执行时，不得标记为格式验收完成。

**本文件是格式要求的主文件（2026-11-12 登记，2026-11-13 起统一迁入专题条文）**：第六节按分类指向库内既有条款，**引用处即真值来源**，不重新定规则、不重复登记数值；第七节「封面格式要求」为已详细化的硬要求；第八节起为全文迁入的专题格式条文（已迁入：字体与版式），原专题文件已删除。本库其他文件中的「按本轮基线／按已确认基线／按项目情况调整」等表述，在其已确认类别范围内仍按对应专题条款执行。

1. 每份文档使用同编号模板原位生成，保留封面、目录、分节、页眉页脚、页码、修订记录、表格和签署栏。
2. 封面独立成页，封面后无空白页；目录页与正文首节分开。
3. 封面表格的结构、合并关系、边框、对齐、字体和定位不变，只替换经登记的字段值。
4. 正文保持对应基线的标题层级、编号机制和段落风格；新增正文用 new_body_paragraph，并显式应用同类正文属性，禁止克隆标题段充当正文。编号须核对生效显示，避免手写＋自动重复。
5. 表格保留已确认的表头、列数、列宽、合理分组合并和跨页规则；填写／扩行前核对物理单元格，独立记录的编号、名称与结果不得被继承的纵向合并覆盖。必要的行数／合并调整登记具体依据并逐行回读；计划表可写预期和接受准则，报告的实际结果、异常和结论必须有证据。
6. 文档深度与职责匹配：描述类文件必须覆盖基本信息、风险、需求、架构、设计、验证、追溯、缺陷和版本；计划/报告类文件必须覆盖范围、方法、记录、证据、偏差和结论。
7. 页数仅用作异常压缩/空白页检测，不能以凑页数代替事实完整性。

## 四、必备图示

应根据当前项目的系统和模板章节生成，而不是从其他项目复制：

- 体系架构章节：软件体系架构图；
- 多模块、通信、接口或执行输出：模块关系图或硬件/软件拓扑图；
- 状态切换、自动控制、异常恢复：流程图或状态机图；
- 生命周期、配置、验证或变更管理：过程图；
- 可用性关键任务：任务流程图或界面示意图。

每张图应有图号、图题、正文引用和事实来源。图内文字、模块名、接口名、箭头和型号差异必须与当前正文一致。无依据的图不得生成；应阻断相关章节发布并列入项目待办。

## 五、全页验收

生成后对每份最终状态文件的全部页面渲染并检查，记录最终 DOCX／渲染哈希、页数和逐页结论；抽检及旧版 PDF 不能代替修改后的全页验收。工具不可用时记录未执行并继续独立工作，不得为导出成功擅自删分节／改变首页眉脚，不能宣称格式已通过。检查范围：封面、目录、页眉页脚、页码、表格跨页、图示、签署栏、结果栏和空白页。发现旧项目残留、图内文字错误、图缺失、表格裁切、目录域异常或结论无证据时，不得发布。

## 七、封面格式要求（已详细化）

> 本节为封面的可直接执行要求（第六节封面行为指向本节的引用）。单位同上，版号差异按对应基线件处理。

一、封面必须恰好占一页，封面之后不得出现空白页；不启用「首页不同」，封面沿用本份文档的页眉页脚。

二、封面由「大标题文字」和「封面信息表」两部分组成，这两部分必须视为**一个整体**排版，不得分别定位。

三、这个整体必须在该页**垂直居中**。判据：剔除页眉页脚后，取大标题与封面表全部文字的合并包围盒，上留白与下留白之差不超过 3pt（等价于整体中心与页面中线偏差不超过 1.5pt）。

四、居中只能通过**增减大标题前面的空行（空段）**实现。空行数量不固定，以渲染后的居中结果为准，不得预先写死行数。

五、**空行本身必须统一格式：字号 12pt（与正文一致），中文宋体、西文及数字 Times New Roman，单倍行距，段前段后均为 0，无首行缩进、无加粗、无底纹；空行内不得含文字、域、图形、书签或分页符。** 每个空行占高必须一致，不得通过改变某一段的字号、行距或段前段后来微调位置。

六、每次增减空行后必须重新渲染并重新测量；经 Word 保存后也须重渲染重测，不得沿用修改前的渲染结果判定通过。

七、大标题为 36pt 宋体、水平居中；该字号保持模板原值，不参与正文与标题的字号分档，不得被改为正文号或标题号。

八、大标题与封面信息表之间保持 3 个空行，不得增减；封面表之后承载分节符的空段不得删除。

九、封面信息表保持模板原有结构：四列、列宽、行列数、合并关系、六向边框、表格定位、底纹和签署栏一律原样，只允许替换已登记的字段值，禁止等比缩放列宽。

十、表内所有单元格文字**水平居中**；垂直对齐按对应模板版号的基线处理。

十一、表内文字为 14pt，中文宋体，西文与数字 Times New Roman，字色黑色；封面表字号不随正文表字号改动。

十二、只填写登记字段：文件编号、项目名称、项目编号、软件名称、型号、版本。编制、审核、批准、日期、测试人、测试时间、结果一律留空，标签文字必须完整保留。

十三、禁止用单元格垂直对齐或单独分节来实现居中，禁止改页边距压页，禁止调整表格定位或缩进来顶页，禁止用固定空行数推定已经居中。

十四、交付前须对最终渲染稿逐页检查封面页：整体居中、无空白页、文字与表格无裁切、无重叠。未渲染或渲染失败时该项记「未执行」，不得判为通过。

### 结论先行

1. 字号统一不是"全选改一遍"：要**分区**（正文 / 各级标题 / 表格 / 图题 / 封面区 / 目录 / 页眉页脚），
   并明确哪些**故意不动**（封面版式、目录层级、页眉页脚）。
2. 只改 run 的直接格式**不够**：必须同时改 `styles.xml` 里 `Normal`、`Heading 1~4` 的默认值，
   否则用户在 Word 里新打一个字又回到旧字体。
3. **空 run 也要设字号**——它们不显示文字，但决定行高与后续输入。
4. 中文与西文分槽：`w:rFonts@eastAsia` 管中文，`@ascii`/`@hAnsi` 管西文与数字。
   注册资料里大量标准号、型号串与带单位的数值（如 `GB 9706.1`、`XX-1000`、`10mW±20%`）属西文，惯例配 Times New Roman；
   强行让西文也用宋体会让长串换行变多。
5. **表格字号一般要比正文小一档**（正文小四 → 表格五号）。宽表（5~7 列窄列）全上小四会撞破列宽、
   行高膨胀、页数增加；这是取舍，不是偷懒，需在版本说明里写明。
6. 配图是 PNG，**不受 Word 字体设置影响**：正文换宋体后，图内若还是黑体就仍然"不统一"，
   必须回到绘图脚本换字体重绘（matplotlib：`rcParams['font.family']='SimSun'`，在 import 绘图库之后覆盖）。

### 1. 先测量，再动手

```python
import os, collections
from docx import Document
from docx.oxml.ns import qn

def eastasia(r):
    rPr = r._r.find(qn('w:rPr'))
    if rPr is None: return None
    rf = rPr.find(qn('w:rFonts'))
    return rf.get(qn('w:eastAsia')) if rf is not None else None

agg = collections.Counter()
for f in os.listdir(OUT):
    if not f.endswith('.docx'): continue
    d = Document(os.path.join(OUT, f))
    for p in d.paragraphs:
        for r in p.runs:
            if r.text.strip():
                agg[(f[:6], 'body', eastasia(r),
                     r.font.size.pt if r.font.size else None)] += 1
    for t in d.tables:
        for row in t.rows:
            for c in row.cells:
                for p in c.paragraphs:
                    for r in p.runs:
                        if r.text.strip():
                            agg[(f[:6], 'table', eastasia(r),
                                 r.font.size.pt if r.font.size else None)] += 1
for k, v in sorted(agg.items(), key=lambda x: -x[1]):
    print(k, v)
```

看三件事：① 有多少 run 的字体槽是 `None`（继承样式，改样式即可批量生效）；
② 有多少被**直接格式**钉死（必须逐 run 覆写）；③ 表格与正文各占多少（决定要不要分档）。

### 3. 执行要点

> **模板自带的字体混排按"模板错误"处理**：注册人已定交付稿字体按本库基线统一，不因"模板就是这样"而保留（模板里的微软雅黑章标题、楷体正文、黑体目录条目、同级一半 Times 一半宋体都要统一）。
> 唯一例外是 Symbol/Wingdings 私用区字符 run（见 §9 排除项）。只改字体不改字号，封面大标题字号仍走 §10 护栏。

> **先查共享原语**：`docx_ops.unify_document_fonts()` 已实现本节全部要点
> （`iter_zone_paragraphs` 分区、删 `*Theme` 属性、遍历表格、跳过文本框、改样式默认值）。
> 项目脚本只应做**薄封装**补自己的差异（如标题分级字号），不要再抄一份分区逻辑，
> 否则库修了"主题属性优先级"这类 bug，项目那份仍带旧行为（`pitfalls.md` §30）。

字号单位是**半磅**：小四=24、五号=21、三号=32、小三=30、四号=28。

```python
def _apply_font(run, ea, ascii_font, size_pt, bold=None):
    run.font.name = ascii_font                    # python-docx 会同时写 ascii 与 hAnsi
    rPr = run._element.get_or_add_rPr()
    rf = rPr.find(qn('w:rFonts'))
    if rf is None:
        rf = OxmlElement('w:rFonts'); rPr.insert(0, rf)
    rf.set(qn('w:eastAsia'), ea)
    rf.set(qn('w:cs'), ascii_font)
    run.font.size = Pt(size_pt)                   # 用 python-docx 写 sz/szCs，避免元素顺序违规
    if bold is not None:
        run.font.bold = bold
```

分区判定顺序（先特殊后一般）：

| 判定 | 依据 | 处置 |
|---|---|---|
| 封面区 | 正文块序列里**封面表之前**的所有段落 + 封面表本身 | 跳过不动 |
| 目录 | `p.style.name` 以 `toc` 开头、`Table of contents` | 跳过不动 |
| 页眉页脚 | `section.header/footer` | 不遍历即不动 |
| 文本框图形 | `p.runs` 天然取不到 `w:txbxContent` 内的 run | 自动跳过（要改见 `pitfalls.md` 节点级替换） |
| 标题 | 样式名 `Heading N` / `标题 N` | 该级字号 + `bold=True` |
| 表格 | 遍历 `doc.tables` 全部单元格（去重合并格） | 表格字号，`bold` 不覆盖（保留表头加粗） |
| 图题/表题 | 样式 `Figure`/`Caption`，或文本以「图」「表」开头且 ≤40 字 | 图题字号 |
| 其余 | — | 正文字号 |

**同时改样式默认值**：`Normal` → 正文档，`Heading 1~4` → 各级字号，并写 `rFonts@eastAsia`。

### 4. 验证（不能只看"改成功了"）

1. 复跑第 1 节的测量脚本：目标档位之外**只允许**出现"故意保留"的封面/目录条目；把例外逐项指认到位置（封面大标题、封面表）。
2. 页数会因字号变大而增加：逐页渲染检查**无空白页、无列宽撞破、无表格被挤到跨页断行**。
3. 用 Word（不只 WPS、不只 LibreOffice）逐个打开确认无损坏，并记录页数。
4. 版本升级：输出到新版本目录（`*_V2/`），旧版保留；在版本说明里写清"本版仅版式，内容未变"，
   避免评审把版式改动误读为内容变更。

### 5. 反模式

- 在 Word 里全选改字体 → 封面大标题、目录、页眉一起变，且下次重生成又被模板打回原形。
- 只改 `Normal` 样式 → 被直接格式钉死的 run 一个都没变，看起来"改了没用"。
- 正文/表格同字号 → 宽表溢出，回头又手工缩小表格，重新变成不统一。
- 忘记重绘配图 → 文档正文宋体、图里黑体，肉眼一眼看出不统一。


### 6. 执行顺序（实测，错了会白改一遍）

```
生成/就地替换 → 表格与图示 → 封面与分页
   → 目录刷新（Word 更新域）→ ★ 字体统一（第二遍）→ 闸门 → 渲染
```

字体统一必须**在目录刷新之后再跑一遍**，两个原因：

1. Word 保存时会重写封面标题与目录条目的 run，把显式 `rFonts` 丢掉（实测三份文档各
   141/39/50 处变成 `None/None`）——刷新前统一得再干净也会被抹回去；
2. Word 还会顺手规掉与 `docDefaults` 等价的**样式默认字号**，需从刷新前的备份把各级样式
   `w:sz` 写回，否则产物 XML 不再等于模板版式。

### 7. 覆盖清单与闸门项

统一动作必须覆盖四处，缺一处就是"看起来改了其实没改"：

| 位置 | 手段 | 漏掉的后果 |
|---|---|---|
| 正文段落 run | `unify_document_fonts` | 主体 OK |
| **表格单元格** | 同上（内部遍历 `doc.tables`） | `doc.paragraphs` 不含表内段落，旧字体整片残留 |
| **空 run** | 同上（不按有无文字过滤） | 行高与用户新输入仍走旧字号 |
| **样式默认值** | `style_font(Normal/Heading 1~4/Caption)` | Word 里新打一个字就回到旧字体 |

配套硬约束：改 `w:rFonts` 时必须删掉 `asciiTheme/eastAsiaTheme/hAnsiTheme/cstheme`，
否则主题优先级更高，显式字体名不生效。

闸门最少四条（非零退出码阻断发布）：

1. 分区字体基线：所有非文本框 run 的 `eastAsia`/`ascii` == 基线值；
2. 分区字号：正文=正文档、表格与图题=表格档；**正文区各级标题按族基线校 `sz`/`eastAsia`/`bold`
   且每级取值唯一（见 §10，本条修订原"标题只校字体不校字号"的规定）**；封面区、页眉页脚仍只校字体不校字号；
3. 样式默认值：`Heading N` 的 `sz` 等于**族基线**（不是模板原值，见 §10.3），`eastAsia` 已统一；`Normal` 随正文档变；
4. 配图字体：绘图脚本的 `font.family` 与正文一致，重绘后跑宽度预警 + 逐张看图
   （PNG 不受 Word 字体设置影响，正文换宋体而图里还是黑体，一眼就能看出来）。

### 8. 段落级版式一致性（字体统一之后仍会剩下的那类问题）

字体与字号统一解决"字长什么样"，解决不了"段落怎么排"。同一份文档里最常见的段落级缺陷是
**本轮新写的正文段没带段落属性**，与上下文缩进／行距／对齐不一致；以及**同一句话被写两遍、
两遍格式还不同**（承接与槽位双轨撞车）。两者都要按"生效版式"判，不能只看段落自己写了什么。

#### 8.1 判据

```
生效版式 = docDefaults → 样式链（basedOn 逐级）→ 段落直接 pPr     # 逐层合并，后层覆盖前层
指纹 = (首行缩进, 左缩进, 行距, 行距规则, 对齐)
归一 = 0/c0/t0 视为无缩进；line=240+auto 视为单倍（不写）；未写 jc 与 both 视为相同
```

不参与比对的段落：标题、目录条目、图题／表题、含域代码、含图形、文本框内、带自动编号的段，
以及短行居中／整段加粗的小标题。

#### 8.2 处置

| 动作 | 规则 |
|---|---|
| 配锚点 | 本轮新写段 ← 左边最近的"模板原样段或自己写了 pPr 的段"；左边没有就取右边最近的 |
| 对齐 | 先双向对齐 `pStyle`（参照没写而本段写了要摘掉），再抄参照**直接写了**的 ind/spacing/jc |
| 边界 | 带 pPr 的段不动（那是模板给该位置的版式）；空 `<w:pPr/>` 不算带 pPr |
| 重复段 | 去重时若胜者无版式而败者有，先把败者版式接过来 —— 留文字与留版式分别取最合适来源 |

#### 8.3 闸门补两条（非零退出码阻断）

1. **无重复正文段**：`para_ops.find_duplicate_paragraphs`，模板自带的同族并列条目用 `dup_allow` 声明；
   两段都是模板原样时只报不删。
2. **本轮正文段版式与锚点一致**：`para_ops.para_format_issues` 必须为空。
   判定必须依赖生成器记录的"每段来历"（slot/extra/carry/base）—— 没有来历就分不清
   "本轮写坏了"与"模板本来就这样"，只能整片重排，既越界又危险。

### 9. 正文段落基线（全量套用，与字体基线并列）

字体/字号统一之后，剩下的"段落格式不同"全部属于**段落属性**层面。基线要显式写进配置，
并在生成末尾对所有正文段全量套用；只补齐"本轮新写段"不够（模板自带段本身就不统一）。

```
body_format = { first_line_chars, first_line_twips, left, right, jc, line, style }
# 典型取值：首行缩进 2 字符（firstLineChars=200 + firstLine 兜底）、左右无缩进、
#          单倍行距（不写 w:spacing）、左对齐、正文样式 Normal
body_format_sig = 生效版式指纹（用于闸门逐段核对）
```

落地要点（都是实测踩出来的）：
1. **先删后写**：`pStyle / ind / spacing / jc / autoSpaceDE / autoSpaceDN / adjustRightInd /
   snapToGrid / textAlignment / contextualSpacing / widowControl` 全删，再按基线写，
   元素顺序须符合 `CT_PPr` 的 schema（pStyle → 开关 → ind → spacing → jc）。
2. **排除项与版式比对共用同一函数**（标题/目录/图题/编号段/含域/含图形/文本框/封面区/
   Symbol 与 Wingdings 私用区字符 run），否则会出现"闸门说统一、其实漏了三类段"。
   行首是 `\uf07a` 一类私用区字符的项目符号段被改成宋体后会直接显示成方块，这类 run 必须排除。
3. **标题判据要含纯文本形态**：只按"整段加粗"会漏掉"编号 run 加粗、文字 run 不加粗"的小标题，
   它们会被加上正文缩进（见 `pitfalls.md` §21）。
4. **封面区＝分节符之前且非成段正文**：前言可能在封面节里。
5. **例外用配置声明**（`body_format_keep`），例如带左侧标签栏的挂缩进块。
6. **两处"段落自己没有、样式链里有"的值必须一起处理**：样式自带 `numPr`（如 `Figure` 样式的
   "测试方法"条目）→ 段落级判据会把它当正文并加上首行缩进，判"编号列表项"要沿 `base_style` 链查；
   样式自带 `ind:leftChars=150` → 只写 `firstLineChars` 不写 `leftChars=0`，生效值仍是 150，
   套完基线指纹照样偏离。写基线时把 `left/right/leftChars/rightChars` 一并显式压零。
7. **字体统一排在 Word 刷新目录之后**（见 §6），且刷新后必须复测样式默认值：Word 会顺手规掉与
   `docDefaults` 等价的 `Heading N` 字号，复测不通过就从刷新前的备份写回。

闸门硬检查（非零退出阻断）：① 每份文档所有正文段的生效版式 == 基线指纹；
② 正文段末尾都有句末标点（`no_punct_allow` 例外）；③ 标题无"同名不同号"；
④ 分区字号（正文/表格/图题三档）与样式默认值分别复核，**以生效值为准，不以"我写了什么"为准**；
⑤ 套用后仍偏离基线的段落必须逐段打印（实测漏网 6 段全部来自第 6 条的两类继承值）。


### 10. 文档族内标题字号统一：以参照文档取基线，逐级别多数派投票

**这条修订 §7 闸门第 2 条。** 原先规定"标题/封面/页眉只校字体不校字号"，那只解决"一份文档内
字体乱"的问题；同一批文档族各自套了不同模板后，会出现**同级别标题跨文档字号不一致**
（实测同一文档族里章标题同时存在 12/14/16/22 磅，节标题存在 10.5/12/14/16 磅，
还有一处子节标题是五号 10.5 磅而其余都是小四）。跨文档并排看就是"格式不统一"。

#### 10.1 基线怎么定

不要手写一套"标准字号表"——**指定一份文档当参照，从它身上量出来**：

```python
prof = heading_format_profile_from(参照文档)     # {级别: {sz, ea, latin, bold, votes, total}}
normalize_heading_format(每份文档, prof)
```

取**逐级别多数派投票**，不取第一段、也不取平均值：参照文档自身常有一两段偏离
（实测某参照文档 23 段二级标题里有 1 段漏加粗），投票多数派才能把那几段也一并纠正过来。
`votes/total` 要打印出来——**一致率不是 100% 就说明参照文档本身不干净**，先确认再当基线。

#### 10.2 四条硬护栏（缺一条就会毁掉封面或目录）

1. **只动封面表之后的段落。** 封面大标题通常也带 `outlineLvl=0`（实测 sz=72 即 36 磅），
   不排除的话七份封面大标题会被一起压成正文号，且 XML diff 看着完全"正常"。
   以封面信息表位置为界，改完必须逐份回读封面标题字号确认没动。
2. **跳过目录域内段落**（含 `fldChar`/`instrText`，或样式名以 `TOC`/`目录` 开头）。
   目录条目改了字号会与正文标题不一致，且 Word 刷新目录时会被覆盖回去，白改。
3. **跳过表格内段落。** 只遍历 body 直接子级天然满足；但注意 COM 的 `Paragraphs`
   集合含表内段落（§45.3），用对象模型复核时不能按序号对齐。
4. **引导句降级，不要套标题格式。** "××如下图所示："这类被误标成标题级的句子
   （§42 的漏判形态），正确处置是把 `outlineLvl` 降为 9，而不是给它加粗放大。

#### 10.3 执行顺序与回归

`normalize_heading_format` 会同时改 `Heading N` 样式的默认字号（`also_style=True`）——
只写 run 级显式值的话，Word 保存时可能按样式回涨（§13）。改完按 §6 的顺序收尾：
刷新目录域 → 重跑字体统一 → 重渲染。

回归三项：① 逐档逐级别统计"字号/中文字体/加粗"组合数，**每级必须只剩 1 种**；
② 封面大标题字号逐份回读，必须等于改前值；③ 页数与空白页复测——标题缩号会让章节变矮，
可能把原本压着页尾的表挤到上一页，页数变了就要重刷目录页码。

#### 10.4 闸门改写

§7 第 2 条改为：正文区标题按级别校 `sz`/`eastAsia`/`bold` 等于族基线，**每级取值唯一**；
封面区、页眉页脚仍只校字体不校字号。第 3 条补充：`Heading N` 样式的 `sz` 必须等于族基线，
不得停留在模板原值。


#### 10.5 分档，不是"取值统一"——全级别同字号是另一种不统一

§10 的第一版做法是"把各级标题统一到参照文档的取值"，实测把 L1/L2/L3 全压成了正文档的 12 磅。
字号确实"每级唯一"了，闸门全绿，但结果是**章标题与正文同号**，只靠加粗和"第X章"编号区分，
层级感消失，用户立刻反馈"这个章节字号可以大一点"。

**族内统一的正确目标是"分级成档"，不是"取值归一"。** 闸门第 45 条只查"每级只剩一种取值"，
查不出"三级挤在同一档"这种退化，必须补一条**跨档检查**：

```
各级取值必须互不相同，且严格递减：sz(L1) > sz(L2) > sz(L3) > 0
且 sz(L1) 必须大于正文档（否则章标题与正文同号，层级不可辨）
```

典型三档（正文小四 12pt 时）：**章标题 三号 16pt（`sz=32`）／节标题 四号 14pt（`sz=28`）／
子节标题 小四 12pt（`sz=24`）**，全部加粗。档位写进项目配置，不要散在各脚本里；
参照文档只提供"字体与加粗"，**字号档位由配置显式给出**——参照文档自身可能正是退化的一方，
拿它当字号基线会把它的毛病固化成族标准。

推论：`heading_format_profile_from()` 的返回值要当**候选**看，不当**指令**看。
用它之前先看一眼各级取值是否成档；不成档就改用显式 profile 字典，只从参照文档继承字体与加粗。
