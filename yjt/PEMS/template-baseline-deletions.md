## 2. 文件级改动只有两类

- **改颜色**：RD-026（12 处红字 run + 4 处段落标记红字 → 黑），文字一字未动。
- **通道转换**：RD-028/029/030/032/052 由 `.doc` 经 WPS 转出 docx，零内容改动；RD-057/068/069 原生 docx 与原件同哈希。

除这两类之外，基线件与模板原件内容一致。**任何删除都发生在生成交付稿阶段**，逐份清单见同目录 md。

## 3. 通用计数口径（跨份共用，各清单不再重复）

- 残留计数一律用**全包 XML 计数**（`word/*.xml` 含页眉页脚与文本框），不要用 python-docx 展开后的单元格数：
  合并单元格会按网格位置重复返回（RD-069 三处签署行会被读成 12 格）。
- 形状里的文字有两种存放方式，两种都要扫：`w:txbxContent`（RD-029 的故障评估表头）与**普通正文段 + 缩进硬排版**
  （RD-028 的架构图，`v:shape` 只画框）。只扫 `word/media/` 会把 RD-028 判成零残留。
- 页数判据要写明测量程序：WPS／Word／LibreOffice 对同一份可差 1 页。
- 结构数字（段落数、`numPr`、字体 run 数、目录条目数）以**主通道 WPS 转出稿**为准，LibreOffice 稿系统性偏差见 `pitfalls.md` §1。

## 4. 复核方式

每份同目录 md 的「复核判据」小节都要能脚本反查：残留词计数、段落数、表格行列、`FF0000` 计数、
带 `sectPr` 的段数、页眉文本、页脚域集合、基线件与原件哈希。交付时把脚本输出贴进版本说明，不能只打勾。
