# AGENTS.md — 模板化文档生成规则（本目录适用）

> **工具无关**的规则入口：Trae / Claude Code / Cursor / Codex 等均可读取。
> Claude Code 可在 `CLAUDE.md` 写 `@AGENTS.md`；Cursor 在 `.cursor/rules/*.mdc` 引用本文件。
> 本目录方法**不针对某一项目**，适用于任何版式固定、内容按项目替换的文档族。

## 适用场景

按公司既定版式批量生成 / 迭代 Word 文档族，例如：医疗器械软件研究资料（PEMS：软件确认计划、
软件体系构架、软件需求说明书、软件详细设计说明、软件确认报告、软件描述文档、软件验证计划、
软件验证报告）、产品技术要求、说明书、验证/确认记录、设计文档等。

## 硬约束（违反即返工）

1. **数据唯一**：项目事实仅写入当前项目指定的主事实文件（`facts.yaml`、`facts.json` 或受控 `config.json` 三选一）；禁止在脚本、经验库或文档中另写一套。
2. **格式靠继承**：以参考文档 `.docx` 为模板「就地替换」，**禁止从零拼 Word**
   （会丢封面大标题、浮动封面表、目录域、页眉页脚、分节）。
3. **封面独立成页**；封面后不得出现空白页。
4. **输出到新版本目录**（`*_V{n}/`），永不覆盖源文档与历史版本。
5. **相同代码只写一份**：公共处理封装在 `tools/docx_ops.py`，项目只提供配置。
6. **三方收口**：每轮输出文档后，必须核对 **说明书 / 代码 / 注意事项** 三者一致性，
   冲突未清零不得发布（规则见 `consistency-gate.md` 第 5 节）。
7. **模板版号是独立的一条轴**：模板改版时旧版基线件与判据原样保留，新版单独建档；生成前先定 `template_version`，
   只取该版判据，两版判据与产物目录都不得互用。见 `iteration-and-versioning.md` §7。

## 每次交付前必做（6 步）

```
1) 使用当前项目主事实文件生成；调用本库脚本时执行 `python tools/build_docs.py --config <project-config.json>`，确认输出目录中的 `manifest.json` 已记录配置、事实文件、模板和产物的哈希。
2) 运行一致性检查；调用本库脚本时执行 `python tools/consistency_check.py --config <project-config.json>`。跨文档对比必须按 `scope` 分组，禁止把本来不应包含同一型号或术语的文档强行判为不一致。
3) soffice --headless --convert-to pdf --outdir out "某份.docx"   # 一次只转一份
   → 逐页 page_ink_coverage + grade_pages_by_ink：封面独立页 + 无空白页 + 页眉编号正确
     （不要用抽文字字数判空白页：中文 PDF 缺 ToUnicode 会双向误判，见 pitfalls.md §41）
3b) pagination_audit(doc, cover_texts=[封面文档名]) 七项必须全清；需修复时只用同源的
     pagination_repair(..., apply=[本轮已确认的动作])，改完复跑 audit 并重渲染核账页数
     （流程见 cover-pagination-and-sections.md §8，终检项见 dod-checklist.md F 组）
4) 人工核对：图（图文一致）、签署栏、交叉引用文件名、他项目残留
5) **用 Word 只读打开每一份产物并记录页数**（LibreOffice 与 python-docx 都不报的损坏，Word 会报；
   典型诱因见 `pitfalls.md` 第 6/7 节）
6) 三方收口：说明书 / 代码 / 注意事项 逐参数核对 → 冲突清零（consistency-gate.md 第 5 节）
```

## 环境

- Python 3 + `python-docx`；`.doc` 转换需 `pywin32`（Word 或 WPS）。
- 配图需 `matplotlib`（中文字体用 SimHei/Microsoft YaHei；**文档正文统一宋体时，图内也要改用 SimSun 重绘**，否则一眼看出不统一，见 `font-and-style-normalization.md`）。
- 渲染校验用 LibreOffice（`soffice --headless`）。

## 质量闸门补充（2026-10-14）

- 编写前冻结项目事实基线；用户新增确认先回写 YAML 或受控变更记录，再生成文档。
- 未命中的替换槽位、事实冲突、旧项目残留、缺少必要图示或未提供实测证据时，必须阻断发布。
- `build_docs.py` 默认拒绝覆盖已有输出；仅在确认同一版本目录需要重建时才显式使用 `--force`。每次交付保留生成的 `manifest.json` 与一致性检查报告。
- 草稿、待执行、待审核和受控发布分开管理；无证据不填通过结论、签署人或测试日期。
- 适用文档必须有当前项目的架构图、关键流程/状态图、硬件关系/拓扑图或可用性任务流程图；图示逐页渲染核对。
- 配图先过机器自检（文本宽度预警 + 内嵌图片哈希/宽高比校验），再人工逐张看 PNG（脚本读不到图内文字）。
- **字体基线要"分区 + 二遍"**：正文/表格/图题各有字号档，标题与封面只统一字体不改字号；
  字体统一必须在**目录刷新之后**再跑一遍（Word 保存会抹掉显式 `rFonts` 与等价样式字号）。
  覆盖正文、表格单元格、空 run、样式默认值四处，配图回绘图脚本换字体重绘。
  见 `font-and-style-normalization.md` §6/§7 与 `tools/docx_ops.py:unify_document_fonts`。
- 承接旧稿做块对齐时：空段先剔除、封面区与目录域禁止插入、刷新后比对目录条目数，
  超阈值还原备份（`pitfalls.md` §11/§12）。
- **承接与槽位是两条写入轨道，必须互相查重**：写前用"本轮正文池"拦承接／插入，写后全量扫
  `dup_kind` 四形态（exact／near／same-lead／contained），优先级 本轮正文 > 模板原样 > 承接；
  两段都是模板原样时只报不删，去重前确认独有事实已并入保留段（`pitfalls.md` §16）。
- **段落版式按"生效版式"对齐**：本轮新写段以就近模板段为锚点，先双向对齐 `pStyle` 再抄其直接
  pPr；只读段落 pPr、用多数派或互相参照都会误伤模板（`pitfalls.md` §18、
  `font-and-style-normalization.md` §8）。闸门两条：无重复正文段、本轮正文段版式与锚点一致。
- 同锚点多段插入必须按顺序 `append`；闸门校验承接段先后与来源版一致（`pitfalls.md` §17）。
- 渲染复用只在"PDF 不比 docx 旧"时成立；页码补丁必须在渲染之后跑（`pitfalls.md` §19）。
- 详细规则见 `one-pass-quality-gate.md`、`reference-format-profile-template.md`、`reference-document-format-and-diagram-requirements.md` 和 `diagram-generation-and-figure-insertion.md`。

## 通用性边界

- 通用经验库不得写入具体项目名称、项目号、型号、芯片、版本、阈值、人员、测试结果或结论。
- 案例、历史文档和格式档案仅用于方法与版式参考，不能作为新项目事实来源。
- 事实来源、证据边界、必备图示和发布条件遵循 generality-boundaries-and-precedence.md。

## 段落基线补充（2026-10-15）

- **正文段落统一要"全量套用基线"**，不是只补齐本轮新写段：模板自带段的行距/缩进/对齐本身就不一致。
  基线写进配置（首行缩进字符数、左右缩进、行距、对齐、正文样式），生成末尾先删后写全量套用；
  排除项与版式比对共用同一判据函数。见 `font-and-style-normalization.md` §9、`pitfalls.md` §20。
- 标题判据必须含**纯文本编号形态**（`1.1 名称`／`第X章`），只按整段加粗会漏半粗体标题，
  漏了就被加上正文缩进（`pitfalls.md` §21）。
- 断句合并用配置显式声明（`merge_paras`），启发式只做扫描报告；补标点的整句替换必须排在合并之后
  （`pitfalls.md` §22）。
- 闸门新增三条：正文段生效版式 == 基线指纹、正文段末有句末标点、标题无"同名不同号"。

## 分页与导航补充（2026-10-15）

- 章节之间用 `w:pageBreakBefore`（不插 `w:br type=page`、不靠回车顶页），并删除章标题前的顶页空段；
  前一段是分节符时不写，避免多一页空白。见 `pitfalls.md` §23。
- **每份文档都要有标题树**：按编号形态写 `w:outlineLvl`（0/1/2 级），不改 `pStyle`、不动字号；
  无编号模板的"××："小节名按整行短标题+全段加粗识别。见 `pitfalls.md` §25。
- 空标题段要么删、要么降级为 `outlineLvl=9`；带分节符/域代码/图形/表格隔离的段落只能降级，
  删除会破坏结构。见 `pitfalls.md` §24。
- 闸门新增五条：章标题前分页、章前无回车占位、有标题树、无空标题段、编号标题全部入树。

- 补齐标题树之后，目录刷新的护栏要**从"条目数 ±2"改成"按可收录标题数判"**，并在生成阶段
  把表格单元格段落统一降为 `outlineLvl=9`；刷新收尾还要再清一次 Word 新造的空标题段。
  见 `docx-fields-and-toc-repair.md` §9。
- 看到"行首是半个英文词"先分清断段还是断词：同一个 `w:p` 内的两行是断词，
  改措辞或去掉英文两侧空格，**不要合并段落**。见 `pitfalls.md` §27。

## 分页与标题树的四条追加纪律（2026-10-15 第二轮）

- **`keepNext`/`keepLines` 只写在标题段上**。图片段、图题段、正文段一律不加——加了会在段前
  显示与标题相同的大纲/分页标记（用户视角＝"图片前面冒出点点，变成标题了"），还会把
  "图＋后文"粘成整块推走，制造上一页底部的大片空白。见 `pitfalls.md` §38。
- **硬分页符与段前分页不得并存于同一段**。两者叠加＝每个叠加点多一张整页空白，页码跳号而
  正文逐段看都"合理"。交付前查 `hard_page_breaks==0` 且 `stacked_breaks==[]`。§39。
- **判布尔型属性必须读 `w:val`**。`<w:keepNext w:val="0"/>` 是**关闭**（压样式继承），不是开启；
  只判"元素存在"会一次误报几十段、把真缺陷淹掉。同理适用于 `pageBreakBefore`/`keepLines`/
  `widowControl`/`pBdr val="none"`。§40。
- **中文 PDF 的空白页判据改用渲染墨占比**，不要用 `pdftotext` 字数——子集字体无 ToUnicode 时
  汉字全丢，正常中文页会被判成空白页。裁掉页眉页脚带后量像素灰度：正文区 <0.15% 阻断、
  中间页 <0.8% 阻断、末页 <0.8% 记提示（分级沿用 §37）。§41。
- 标题／图题判据四条收紧（图题用位置判据、图号 `2.7-1` 不算小节号、目录域内段落先剔除、
  封面区空段不算顶页回车）见 `pitfalls.md` §42。
- **表格"左边框丢失/像被隐藏"有四类根因，症状同名成因不同**（负 `tblInd`、正文表继承封面浮动、
  单元格把左边设 `nil`、本就无框线的两栏列表）。只补"其他边有框线唯独左边没有"的真缺失，
  **只补 `left`、绝不补 `insideH`/`insideV`**；列宽和超版心 2 倍判为数据污染，禁止等比缩放蒙混，
  须显式 `grid_overrides` 指定列宽并重渲染核账。见 `pitfalls.md` §51。
- 封面「标题文字→封面信息表」之间的空行数**必须显式配置并统一**（如 3 行），用 `set_cover_spacers`；
  加完复核封面仍恰好一页。见 `pitfalls.md` §52。
- **标题字号族内统一：以参照文档为基线，不要手写字号表。** 用 `heading_format_profile_from(参照文档)` 取逐级别多数派，再 `normalize_heading_format(每份, prof)` 套用。
  四条硬护栏：只动封面表之后的段落（**封面大标题也带 outlineLvl=0，不排除会被一起压成正文号**）、
  跳过目录域内段落、跳过表内段落、引导句降级而不是套标题格式；同时改 `Heading N` 样式默认值，
  否则 Word 保存会按样式回涨。终检：每档每级只剩一种取值 + 封面字号回读等于改前值 + 页数与空白页复测。
  见 `font-and-style-normalization.md` §10、`dod-checklist.md` H 组。
- 上述全部判据已封装为一条原语，交付时直接调用，不要另写：
  `tools/docx_ops.py:pagination_audit(doc, cover_texts=[...])` 返回 `hard_page_breaks` /
  `stacked_breaks` / `body_page_break` / `keep_on_body` / `chapter_pad` / `outline_anomaly` /
  `numbered_not_in_tree` / `toc_field`；渲染侧配 `page_ink_coverage(pdf)` + `grade_pages_by_ink(cov)`。

## 分页收口第三轮：判据形态与残留状态（2026-10-15 追加，§45–§50）

- **修复动作不得污染自己的判据**：`drop_hard_break` 会把硬分页符换成 `pageBreakBefore`，所以判
  "本文档是否已按章分页"要同时数**段前分页 / 段内硬分页符 / 前一段换页分节符**三种等价形态，
  并且复核必须排在清空段之后。§46、§45.1。
- **章级排版按模板多数派在同一文档内统一**（补齐 / 保持连续 / 取消少数派），不要机械"每章一页"：
  6 页的表单式报告全拆页会造出 §41 的半空页。封面后第一块（目录／前言）是**前置件例外**，
  必须保留分页，且要找封面表之后的第一个有字段落，不能用序号差。§46。
- **"无文字的空段"有三种命运**：单独承载域 `end` 的删了 TOC 域不闭合（刷新后指令裸露在页面上）；
  只含硬分页符且是封面与正文之间唯一换页的删了正文会挤回封面页，应就地转成 `pageBreakBefore`；
  只有纯回车占位才删。守卫写进"数空段"的循环里，别写在删除动作的 if 上。§47。
- **修完分页的三项回归**：`toc_diagnose` 的 `balance==0`、页数核账（新页数＝旧页数−消除的空白页数）、
  末页只在 `c==0` 时阻断（1~2 行溢出记提示，压页不得动正文基线）；图示核对数**图张数**不是"有图的页"。§48。
- **判据对、对象也会选错**：紧跟分节符的第一章不算"自己分了页"；目录条目文本是"标题＋制表线＋页码"；
  表头列名不是"标签：值"点位。生成器与闸门必须共用同一个豁免函数，否则一边豁免一边不豁免。§49。
- **无头 Office/LibreOffice 失败多为状态残留**：`GetActiveObject` 取的是 ROT 里任意一个实例
  （同一句代码可能取到用户的可见实例）；"服务器运行失败 / Operation unavailable" 先回收孤儿实例再退避重试；
  LibreOffice 每次转换用**全新** `UserInstallation` 目录并重试 3 次；判占用先试 `os.rename()`。§50、§44。
- **封面"居中偏上"用段前空段，不要用 `w:vAlign`+单独分节**（§63）：新建节的眉脚引用与正文节
  重复（哪怕换 `r:id` 指向同一部件）会让 Word 判"文件可能已经损坏"；且节边界不等于封面页，
  同节里的目录/前言页会被一起竖排居中。段前空段是纯流式做法，且必须幂等（先清成基准再补到 n）。
- **两个静默失效写法**（§64）：①lxml 元素的真值判断——空元素 `<w:vAlign/>` 在布尔上下文里是 False，
  `a and b` 会返回 a，一律写 `is not None`；②自写配置解析器的键模式太窄（`[\w_]+` 接不住
  `RD-057: 6` 这类带连字符的键），override 类配置必须有"生效证据"回读进闸门。
- **新判据入库后先回扫自己上一轮的脚本**（§57）：库里刚禁止的写法，往往正躺在更早写的收口脚本里。
  实测抓到两处活例——用 `id(p._p)` 记段落身份（§43）导致可收录标题少算、一次正确的目录刷新被误判越界还原；
  共享原语路径只在"转换失败才走"的分支里插入，导致成功那轮 import 不到、墨占比判据静默退化。
- **判据跑不起来必须失败退出**（§58）：导入失败、缺依赖、拿不到中间产物时不许退回弱判据还报"全部通过"；
  报告里要把"判据是否生效"本身当一项打印（墨占比区间、参照文档 `votes/total`、识别出的章标题个数）。
- **补空段排在删空段之后，压继承要写零**（§59）：按配置补的封面空段会被后续清理/刷新目录吃掉，
  必须"清完再补、补完复核封面仍恰好一页"；样式链带来的缩进不能靠删 `w:ind`（删了就是放回继承），
  要显式写 `0` 并按**生效值**复算验收。
- **闸门全绿不等于文档没错**（§68）：正文段**字号**、标题段**spacing**、**表头底纹**、
  **页眉页脚裸残留**、**编号字形**（`numbering.xml` 的 `lvl/rPr`）这五类维度不写判据就没人管。
  审计要分三层：run 显式属性 → 样式链生效值 → 渲染产物逐字 bbox；
  第一层扫出的"零偏离"是假结论，非基线字体往往来自样式默认或编号定义。
  渲染层负责发现问题、docx 层负责定性，两层不一致时以 docx 为准并回查判据。
  另外两条铁律：**上一轮自己报告过的缺陷也要重新核对**（别拿模板原文或截断片段当正文下结论）；
  **新判据必须反向验证**（旧版命中、本版 0 命中）。
- **改完别急着信自己**（§69）：批量删元素一律**按元素身份**，不能按索引（删完第一处后面全错位，
  实测一次删掉整章内容与三张表，靠"逐节页宽/页边距==模板"才抓到）；
  点名替换要排在所有会改写/拼接文本的步骤之后，验收看"坏写法是否还在"而不是"这轮命中几次"；
  模板图片清理**不能挂在"本文档要插图"这个条件上**，且闸门要有图片白名单＋图题检查
  （图题判据只收真的引用了图片部件的段，形状图例不算配图）。
  凡是"和上一版比"的护栏（如目录条目数下界），都要问一句：这一版是不是**故意**不同。
- **把"留空"改成"实值"是有一整类新风险的动作**（§70）：值会同时进正文句、表格行与族内多份文档，
  三类缺陷一起冒出来——①补进标签行的否定说明会命中自家残留扫描词（表格值只写值本身，
  "没有某某"由正文专门一句说一次）；②台账值里混了解释，与模板槽位那句拼出重复短语
  （台账存**原子值**，括注另起一键，句内 4 字以上短语出现两次就复核）；
  ③带括注的组合值被正文与表格各引用一次（正文用不带括注的原子值）。
  改申报口径时，**残留扫描词表与台账禁用值列表要成对更新**并复扫为 0，理由写进版本说明；
  口头指定的元器件参数注明是"公开资料标称值"并留"与实物物料核对"的待办——
  **申报口径已定 ≠ 与实物一致**，待办里不要把两件事写成一件。补长句后必须重跑目录刷新与逐页渲染。
- **对账表的每个 ✅ 都要能被脚本反查命中**（§72）：正向"来源关键值→产物"归一化字面反查＋反向
  "产物里所有数字＋单位→来源"两条都要跑（反向才是"有没有编数据"的真防线）；表里每行存
  `值→应命中文档→实测次数`，次数不足自动降级 ⚠️。"有意不写"也要占一行并写理由（否则下轮被当漏项补进来）；
  模板方法学指标、注册人口头指定的元器件值、按指示预填的结论列，这三类必须写明真实出处与状态。
- **注册人要求"结果列填结论"时，判据改白名单、不许整条关**（§71）：只放行声明过的"文档＋列名"
  （列名从表头解析，表头可能不在第 0 行，别写死列号），同表签名/日期与未声明文档继续阻断；
  另加一条反向判据"**豁免列必须填齐**"；并用受控实验证明它还在咬（清空白名单→必须全部命中）。
  台账记 `src=注册人指示＋日期`，正文"以受控原始记录为准"的句子与"草稿/待执行"状态一律不动；
  同族其他报告**不自动跟着填**（填一半留一半比全留白更像数据完整性问题）。
- **插入正文段不要克隆供体**（§67）：克隆标题锚点、或"随便找一个正文样式段"（会命中封面大标题），
  都会产出**挂标题样式的正文段**——正文基线按样式当它是标题、标题分档按文字形态当它不是标题，
  **两条链路一起放过**，几百项闸门可以全绿。原语：`new_body_paragraph()` 新建、
  `demote_paragraph_to_body()` 降段（**必须改样式**，只改直接格式没用）、
  `body_paragraphs_with_heading_style()` 给闸门做 dod 45d 检查。
  新判据必须反向验证：上一版已知有缺陷的产物要能命中，本版必须 0 命中。
- 以上修复动作一律走同源原语 `tools/docx_ops.py:pagination_repair(doc, cover_texts=[...], apply=[...])`
  （动作：`drop_hard_break` / `drop_pbb_after_sect` / `drop_pad_tabs` / `drop_chapter_pad` /
  `demote_cover` / `demote_empty` / `drop_body_keep` / `drop_keep_before_table` /
  `drop_page_lead_pad`（换页边界后夹着的纯空段，任意级别标题都管，§68）），
  顶页空段判据与 audit 共用 `chapter_pad_map(doc)`；项目里不再自写第二套分页修复。

## 第二轮改同一批文档时的七条硬约束（2026-10-15 追加）

- **槽位"已消费"按段落元素身份记录**，不按序号：多行插入、去重删段、显式合并都会让序号错位并
  静默改错段。见 `pitfalls.md` §31。
- **同一标签在多处出现（标识章 + 版本章）必须全部改**：槽位支持 `all` 或登记第二条同锚点槽位，
  闸门加"同标签多点位取值一致"，并把 `dup_allow` 放行该对（否则去重会删掉合法的第二处）。§32。
- **改静态目录页码只动 `w:hyperlink` 内最后一个 `w:t`**；含 hyperlink 的段落一律不做整段替换。§33 /
  `docx-fields-and-toc-repair.md` §5。
- **判结构段与套正文基线都要沿样式链**：样式自带 `numPr`、`ind:leftChars` 时，段落自己没有，
  判据与基线双双漏判；写缩进基线要显式压零 `left/right/leftChars/rightChars`。§34。
- **页眉页脚是独立残留槽位**：生成器显式遍历各节 header/footer 做词替换（用跳过含域段落的原语），
  残留扫描覆盖全包 `word/*.xml`。§35。
- **版式收口排在 Word 刷新目录之后**，收口之后**重算交付清单哈希**（清单—产物—检查三者同代）。§36 /
  `font-and-style-normalization.md` §6。
- **渲染判据分级**：无文字页与中间页文字极少＝阻断；末页仅 1～2 行溢出＝记提示并写进版本说明，
  不要用偏离基线的行距去压页。§37。
