# 一致性闸门：多文档同数据对账（通用）

> 适用：文档族内部必须互相一致（型号、编号、版本、指标、术语）的任何场景；
> 医疗器械注册资料尤其严格——**同一数据不一致是发补首因**。

## 结论先行

一致性检查分三层：

1. **集合层**（可自动化）：同一清单在各文档中的集合是否相等（型号集合、附件集合、用例集合）。
2. **字段层**（半自动）：同一主键（如型号）在各文档中的字段取值是否一致（可勾选/可选/数量）。
3. **关键字层**（可自动化）：关键项是否**覆盖**于各文档（安全阈值、时间范围、标准号、编号前缀）。

**正确性与完整性必须人工**：图内容、签署栏、交叉引用文件名、图文是否吻合。

**外加一层（每轮交付的最后一步，必做）**：**三方收口** —— 说明书 / 代码 / 注意事项 逐参数核对（第 5 节）。
文档族内部一致 ≠ 与真机一致；说明书写的数字必须能在代码里找到出处。

## 1. 建立「对照表」

把每类数据指定「权威出处」，其余文档必须跟随：

| 数据项 | 权威出处（示例） | 需同步的文档 |
|---|---|---|
| 型号清单与每型号配置 | 产品技术要求 / 型号规格表 | 说明书、需求、设计、描述、验证、确认 |
| 文件编号规则 | 体系文件规定 | 所有文档封面/页眉/正文引用 |
| 版本号与命名规则 | 命名规则文件 | 软件类全部文档 |
| 性能指标 | 产品技术要求 | 说明书、需求、验证/确认用例 |
| 术语（部件名称） | 说明书 | 其余全部 |

## 2. 自动化检查要点

```bash
python tools/consistency_check.py --config config.json
```

- **主键正则**（如型号 `[A-Z]{2,3}-\d{5}`）配在 config 里，跨项目可换。
- 集合差集：报告「A 有 B 无」。**A 有而 B 无 = 覆盖范围不一致**（最严重）。
- 同键取值比对：把各文档中同一型号所在行的字段抽出来对比，报「取值相反」。
- 关键字覆盖：安全项（阈值、保护动作）在需求/设计/验证三处都要出现。

## 3. 典型冲突模式（换项目同样会遇到）

| 模式 | 表现 | 根因 |
|---|---|---|
| 覆盖范围不一致 | 文档甲 30 条、文档乙 40 条 | 各自抄了不同来源 |
| 同键取值相反 | 同一型号「可选」在甲为 √、乙为 / | 排序规则不同（奇偶/分组） |
| 术语漂移 | 甲「照射器」乙「探头」 | 未统一术语表 |
| 版本写法不一 | `V1` vs `V1.0` vs `V1.0.0.0` | 未区分「发布版本/完整版本」 |
| 指标自相矛盾 | 「不超过 X ±20%」 | 表述本身逻辑冲突 |
| 章节号/错别字 | `1,3,2`、`4..1.3`、形近错字 | 模板复用未校对 |
| 追溯断链 | 引用文档名实际不存在 | 引用未随改名更新 |

## 4. 人工必查四项

1. **图**：体系结构图/框图/流程图/界面图——脚本读不到图内文字；沿用他项目模板时图上
   文字很可能还是旧的。
2. **签署栏**：编制/审核/批准、测试人/测试时间是否填写。
3. **交叉引用**：文中引用的文档名是否真实存在且一致。
4. **他项目残留**：别家公司代号、他项目产品名、外来内部文件名、模板批注。

## 5. 交付后三方收口：说明书 / 代码 / 注意事项（每轮交付最后一步，必做）

> 第 1–4 节只保证**文档族内部**一致；真正会出事的是**文档与真机行为对不上**。
> 三方 = **说明书（IFU）** + **代码（固件/上位机源码 + 板级配置宏）** + **注意事项**
> （说明书里的注意事项章节，或独立的注意事项文件）。**每次输出文档后都要跑这一节。**

### 5.1 三条边都要核

| 对照边 | 核什么 | 本项目真实例子 |
|---|---|---|
| 说明书 ↔ 代码 | 说明书写的每个参数/动作 == 代码常量/分支 | 三档温度说明书 35/40/45℃，代码宏是 39.5/48.0/56.0℃（**加热体侧标定值**，口径不同，须在文档里说清） |
| 说明书 ↔ 注意事项 | 操作路径 与 禁止/限制项不矛盾 | 「加热中不可调时间」若注意事项写「可随时调节」即冲突 |
| 代码 ↔ 注意事项 | 代码真实行为是否兑现注意事项的承诺 | 注意事项承诺「超温自动断电」→ 代码必须有该保护且阈值一致（63.0℃） |

### 5.2 必核参数清单（按「说明书里出现的每一个数字」逐个查）

- 时间：默认值 / 上下限 / 步进
- 档位：档数 / 每档目标值 / 允差
- 温度：目标温度 / 测温补偿 / 超温阈值 / 保护动作与次数
- 电压：欠压阈值 / 采样周期
- 提示：提示音次数与时长 / 指示闪烁次数 / LED 极性
- 交互：短按/长按阈值 / 连发间隔 / 自动关机时间
- 型号差异：哪些功能仅某型号有（如蓝牙仅 YL-5801）
- 版本：说明书版本 / 固件版本 / 提交版本 三者写法

### 5.3 输出「三方核对表」（留档）

| 参数/条款 | 说明书值 | 代码值（出处） | 注意事项值 | 是否一致 | 处置 |
|---|---|---|---|---|---|
| 超温阈值 | 65℃±5℃ | 63.0℃（`board_config.h` 的 `..._SW_OVER_TEMP_X10`） | 未提 | 需补 | 注意事项补写阈值口径 |
| 三档温度 | 治疗面 35/40/45℃ | 加热体侧 395/480/560（×0.1℃） | 未分类说明 | 口径冲突 | 统一为治疗面口径 + 加注标定值 |

- **一致** → 勾掉；**不一致** → 定基线（哪份为准）后同步其余两份；**缺失** → 补写。
- **冲突未清零不得发布**；冲突项按「影响范围」排序处置。

### 5.4 三方特有冲突模式

| 模式 | 表现 | 根因 |
|---|---|---|
| 口径不同却说成同一件事 | 说明书「治疗面温度」vs 代码「加热体温度」 | 测温点/标定基准不同，未在文档区分 |
| 说明书承诺 > 代码实现 | 宣称三段功率，实际只有两段 | 需求变更后代码与文档未同步 |
| 注意事项禁止 > 说明书允许 | 注意事项「禁止连续使用超 30 分钟」，说明书允许 60 分钟 | 两份分别维护，无人对照 |
| 型号差异漏标 | 说明书未注明「蓝牙仅某型号」 | 型号差异没进注意事项 |
| 保护阈值与宣称不符 | 宣称 65℃ 保护，软件实际 63℃ 触发 | 阈值与允差口径未换算 |

## 6. 处置原则

- 先**定基线**（哪份为准），再全文统一——不要在未定基线时逐份小修。
- 冲突清单按「影响范围」排序：影响多份文档的先解决。
- 每次修改后**重跑对账**，直到三份完全一致。
