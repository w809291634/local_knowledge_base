# 环境与格式坑（通用）

> 处理 Word 文档族时反复会遇到的工具/格式问题，与具体项目无关。

## 结论先行

四个高频坑：**① 老旧 `.doc` 会被 Word 以「检测到问题」拒开**（换 WPS 转出）；
**② LibreOffice 并发/复用实例会失败或卡死**（一次一份 + 独立用户配置目录）；
**③ 清理空段时残留的 `bookmarkEnd` 会让循环提前 `break`**（非段落元素要 `continue`）；
**④ 图片内容脚本读不到**（只能人工核对，图上可能还带着旧项目文字）。

新增三个"看起来是文档坏了"的坑，共同点是**python-docx 与 LibreOffice 都不报错，只有 Word 拒开**：
**⑥ 往整包无图形部件的模板脚本加图**；**⑦ 孤立媒体清理只扫正文段落**（删掉页眉/文本框在用的图）；
**⑧ 克隆带 `numPr` 的段落**（双编号 + 顶偏后续章节号）。另有 **⑨ 文本框内文字**词替换覆盖不到。
→ 结论：**交付前的最后一道必须是"Word 逐个只读打开"**，不能只靠 LibreOffice 渲染。

## 1. 打不开的 `.doc`

WPS 写的 `.doc` 常被 Word 判「检测到问题」拒开，`OpenAndRepair` 同样失败。先 Word、失败退 WPS：

```python
import win32com.client as w
for prog in ('Word.Application', 'KWPS.Application'):   # 先 Word，失败退 WPS
    try:
        app = w.DispatchEx(prog)                        # 独立实例，见 §44
        app.Visible = False; app.DisplayAlerts = 0
        d = app.Documents.Open(src, False, True)        # 只读打开原件
        d.SaveAs2(dst, FileFormat=16)                   # 16 = .docx
        d.Close(False); app.Quit(); break
    except Exception:
        continue
```

- 通道要选一个当主、另一个只做交叉核对，别混用：LibreOffice 与 WPS 转出的渲染逐页一致，但 XML 不等价
  —— LibreOffice 会给封面大标题多挂 `numPr`、把 `w:jc` 写成 `start`、丢掉 `.doc` 的左缩进。
- 判"能不能用"以 Word 只读打开为准：转出稿必须能开、页数对得上，否则这份模板不能进生成链。
- 模板件本身要登记哈希与版式判据，见 `template-baseline-rd026-2.1.md`。

## 2. LibreOffice 转 PDF

```powershell
# 不要终止用户正在使用的 soffice 进程；为本次自动化任务创建独立用户配置目录。
$profile = Join-Path $env:TEMP ("pems_lo_" + [guid]::NewGuid())
New-Item -ItemType Directory -Path $profile | Out-Null
soffice --headless "-env:UserInstallation=file:///$($profile -replace '\\','/')" --convert-to pdf --outdir OUT "file.docx"   # 一次一份
```

- 现象：一批命令里连续转多份 → 只成功第一份；卡死后只留 `lu*.tmp` 锁文件。
- 别死循环重试：改用 PDF 文本抽取做结构核对，或直接看 XML。

### 兜底：改用 Word COM 只读导出（LibreOffice 持续卡死时）

本轮实测 LibreOffice 连续卡死（隔离 profile、清锁文件都无效），**改用 Word COM 导出 PDF 成功且稳定**：

```python
import win32com.client as w
app = w.Dispatch('Word.Application'); app.Visible = False; app.DisplayAlerts = 0
try:
    d = app.Documents.Open(src, ReadOnly=True)
    print('页数 =', d.ComputeStatistics(2))       # 2 = wdStatisticPages
    d.ExportAsFixedFormat(pdf_out, 17)            # 17 = PDF
    d.Close(False)
finally:
    app.Quit()
```

- 优点：拿到的是**Word 自己的分页**（比 LibreOffice 更接近用户所见）。
- 想取页宽/页高：用 PyMuPDF 读 `page.rect`（`595×842pt = 21×29.7cm`）。
- 只用 `ReadOnly=True` 打开；**不要在用户正开着文件时写回**。

## 3. 遍历 `w:body` 清理时的 `break` 陷阱

```python
for el in list(body):
    if el.tag == qn('w:p'):   ...
    elif el.tag == qn('w:tbl'): break
    else: continue            # ★ bookmarkStart/End 等：跳过而非 break
```

- 反例：非段落元素直接 `break` → 后面的空段漏清 → 封面后多一页空白。

## 4. 图片两种形式都要认

| 形式 | XML | 备注 |
|---|---|---|
| DrawingML | `a:blip` / `w:drawing` | 新式 |
| VML | `w:pict` / `v:shape` / `v:imagedata@r:id` | 老式（模板图常见，必须逐图识别） |

`Paragraph.text` 里**没有图内文字**；沿用旧模板时图上的标注（模式名、部件名、颜色）很可能
还是旧项目的 → 交付前逐图人工看。

> ⚠️ **只认 `a:blip` 会删掉 VML 图**：判定"图片是否被引用"若漏了 `v:imagedata@r:id`，
> 瘦身函数会把仍被 VML 引用的图当孤立件删除（实测 RD-030：media 7→3、4 处引用悬空、丢 4 张图）。
> 另：python-docx 的 nsmap 无 `v` 前缀，写 `qn('v:imagedata')` 会 `KeyError`，须用 Clark 记法。
> 详见 `diagram-generation-and-figure-insertion.md` 第 3.4 节。

## 5. 其他零碎

| 坑 | 说明 |
|---|---|
| `.doc` 与 `.docx` 混放 | 按后缀分流，`.doc` 先转 `.docx` |
| 合并单元格计数 | `row.cells` 对合并区域会重复返回同一 cell，拼文本会重复，写值无碍 |
| 目录（TOC） | 多为「超链接 + `PAGEREF` 域」，替换要**避开含域代码的段落**；域壳破损有三种形态，见 `docx-fields-and-toc-repair.md` |
| 目录后垫片空段 | 「目录 → 正文」之间几十个纯空段是**靠空段顶页**，脆且常顶不准（正文标题掉到目录页），要改成显式分页符 |
| 各节页宽不一致 | 模板可能把某节设成**横向**（`pgSz@orient="landscape"`）→ 后面页宽和前面不同，检测/修法见 `cover-pagination-and-sections.md` 第 6 节 |
| 页眉编号 | 页眉常含 `<编号> <版本>`，换项目时它也要改 |
| 输出目录 | 产物目录独立，避免覆盖源文档与历史版本 |
| 字体/编码 | 中文文档注意 `eastAsia` 字体槽；GBK 文件读写别用 UTF-8 假设（详见 `font-and-style-normalization.md`） |
| 无 PyYAML 环境 | 事实文件仍用 YAML 时，自带一个只支持"两层 key: value + 标量列表 + 内联字典 + 嵌套列表"的极简解析器；解析器要能容忍 `key:` 行后跟行内注释 |
| 上游生成器留下的同义重复段 | 用"承接旧稿 + 插入新段"方式产出的文档，常有两段几乎同义的句子（如两版"目的：…"、两版"设计准则：…"）。下游继承时**必须逐份去重**：删除项按"只有重复段才命中的尾串"精确匹配，同键多次出现用 keep-first-only |
| 控制台中文乱码 | Windows GBK 终端里 `print` 中文是乱码，但**文件本身没坏**；核对内容请写 UTF-8 文件后用编辑器/读文件工具看，别据乱码判断文档出错 |

## 6. 向「整包无图形部件」的模板脚本加图 → Word 判"文件可能已损坏"（最阴的一个）

现象：某模板本身能正常打开（Word/WPS/python-docx 都正常），但用 `doc.add_picture()` 或
`docx_ops.insert_figure_before()` 给它加一张图后，**Word 报"文件可能已经损坏"、LibreOffice 不出 PDF**；
而同一套代码往别的模板加图完全正常。

定位方法（二分，别猜）：

```python
# 1) 只做最小操作：open + add_picture + save，成功即排除"内容改写"因素
# 2) 逐步叠加：段落替换 → 表格 → 封面 → 分页/缩进 → 插图 → 孤立媒体清理
#    每步存一个文件，用 Word COM 只读打开判成败
d = Document('模板.docx'); d.add_picture(png, width=Inches(5.9)); d.save('t_min.docx')
```

判据：包结构看起来**完全正常**（`[Content_Types].xml` 已加 `Default Extension="png"`、
`word/media/image1.png` 在位、rId 不冲突、`w:drawing` 片段与能正常打开的文档逐字节同构）——
即"查不出 XML 毛病但 Word 就是拒开"。

处置（按优先级）：

1. **该模板不自动插图**：把图留在 `figs/`，在 `todo.md` 记"需在 Word/WPS 中人工插入"，其余文档照常批量。
2. 换一份**本来就含图形部件**的同版式模板作供体。
3. 先用 Word 打开模板 → 另存为 `.docx`（补齐 Word 自己的 drawing 上下文）→ 再用脚本插图。

> 教训：闸门必须包含"**Word 逐个打开**"这一条。LibreOffice 与 python-docx 都通过 ≠ Word 能开；
> 评审用的正是 Word。

## 7. 清理孤立媒体部件：判定范围必须是「整包 XML」而不是「正文段落」

`drop_orphan_image_rels` 若只用 `doc.paragraphs` 收集已引用 rId，会把**页眉/页脚/脚注/文本框**
正在用的图判成孤立件删掉 → 保存后 Word 报文档损坏（与第 6 节症状相同，极易误判）。

```python
used = set(正文引用)                                  # 不够！
blob = '\n'.join(part.blob.decode('utf-8','ignore')   # ★ 遍历包内所有 xml/rels 部件
                 for part in doc.part.package.iter_parts()
                 if 'xml' in (part.content_type or ''))
for rid, rel in list(doc.part.rels.items()):
    if 是图片部件 and basename not in used and re.search(r'["/>]%s["]' % rid, blob) is None:
        doc.part.drop_rel(rid)
```

安全网：只有"本轮确实删过旧图"的文档才执行瘦身；日志打印每个被删部件名，删 0 个也要打出来，
便于事后回溯是哪一步引入的损坏。

## 8. 克隆模板段落时，`w:numPr` 会造出双编号并顶偏后续章节号

从模板克隆段落（插新章节、补小节、加图题）时，供体段若带 `numPr`：

- 手写序号 + 自动编号 → 渲染成 `1.6. 1.6 适用范围`；
- 克隆段还会**占用编号序列**，把后续章节的自动编号整体顶偏（原 `1.8` 渲染成 `1.11`）。

分两种处置：

| 克隆用途 | 处置 |
|---|---|
| 正文段 | 去掉 `numPr`（`insert_paragraphs_after` 已内置此逻辑） |
| 标题段 | **保留** `numPr`，并把文本里的手写序号删掉，交给自动编号排号（`1.6 适用范围` 写成 `适用范围`） |

配套检查：渲染后扫描"独占一行的 `\d+(\.\d+)*\.`"，逐个确认是模板正常自动编号还是叠加缺陷；
模板本身在标题里手写了序号（如 `1.4 硬件关系`）而样式又带 `numPr` 时，用槽位把文本改成不含序号，
让自动编号接管，一次修全章。

## 9. 文本框（`w:txbxContent`）里的文字：`p.runs` 取不到，要按 `w:t` 节点改写

`python-docx` 的 `Paragraph.runs` 只含 `w:p` 的直接子 `w:r`；文本框里的 run 深藏在
`w:r → w:pict|mc:AlternateContent → v:textbox → w:txbxContent → w:p` 里，**词替换与整段替换都覆盖不到**，
残留旧项目文字就藏在这些地方（命名规则示意图、示意图标注）。

```python
for t in p._p.iter(qn('w:t')):            # 读：整段（含文本框）全文
    ...
nodes = list(p._p.iter(qn('w:t')))        # 写：按节点位置整段改写
assert len(nodes) == len(new_texts), (len(nodes), len(new_texts))
for t, v in zip(nodes, new_texts):
    t.text = v; t.set(qn('xml:space'), 'preserve')
```

三条注意：① `mc:AlternateContent` 会把同一图形的文字**存两份**（DrawingML + VML 回退），
节点数与替换列表必须按"两份"给，否则只改一半；② 一句话常被拆成 `(`、`M代表…`、`，`、`)` 多个节点，
按整句匹配会落空 → 用"节点位置 + 等长替换表"并校验节点数；③ 残留检查（禁用词扫描）必须用
`iter(qn('w:t'))` 与页眉页脚一起扫，只用 `paragraph.text` 会漏报。


## 10. `run.text = ...` 会连带抹掉同一个 run 里的图形

`python-docx` 给 run 赋文本时是"清空该 run 的其它子节点再写一个 `w:t`"。因此对
含 `w:pict` / `w:drawing`（尤其 VML group 里带 `w:txbxContent` 的表单、示意图）的段落做
整段替换或"合并 run"式词替换，会**把图形一起删掉，且不报任何错**——只在渲染时表现为
"表单没了 / 示意图只剩一行散字"。

```python
if p._p.findall('.//' + qn('w:pict')) or p._p.findall('.//' + qn('w:drawing')):
    substitute_wt_nodes(p, subs)      # 逐 w:t 节点替换，不合并 run
else:
    apply_substitutions(p, subs)
```

槽位确实要改写这种段落时：**先摘图形再换文字**（`_strip_images(p)` → `set_paragraph`），
否则改完的文字带着旧图形，或图形带着旧文字。

## 11. 「承接旧稿 + 插入新段」做块对齐时，空段必须先剔除

模板封面区常有十几个空段。两侧都 `norm()` 成 `''` 后，`difflib` 会把它们当成**大段相同内容**
配对，于是真正的正文被整体判成"新增"并插到封面区——实测症状是**封面整页消失**、目录条目
落到封面表前后。

```python
bi = [(i, norm(t)) for i, t in enumerate(base_texts) if t.strip()]   # ★ 先过滤
vj = [(j, norm(t)) for j, t in enumerate(v6_texts) if t.strip()]
```

配套两条护栏：① **第一个分节符之前不接受任何插入**（封面区）；② 目录域区内（含 `fldChar`
或 `toc` 样式）不接受插入纯文本条目，否则会和自动目录叠成两套。

## 12. Word「更新目录」对模板手工条目结构会**过收**

模板目录若是 `TOC \o "1-2"` + 手工条目（`HYPERLINK` 而非 `PAGEREF`），而正文表格单元格段落
又带着 outline 级别，Word 重新生成会把"测试人：""验证条款"这类表格文字全收进目录
（实测 6 条 → 47 条），目录反而更长更错。

处置：刷新后**比较条目数**，超出阈值就还原刷新前的备份，改为只校正缓存页码：

```python
ok = td1['healthy'] and (ntok0 - 1) <= ntok1 <= ntok0 + 2
if not ok: shutil.copy2(bak, path)      # 宁可用旧页码，也不交一份 47 条的错目录
```

> 与 `docx-fields-and-toc-repair.md` 第 4 节合起来看：**刷新可能拍平域壳，也可能过收**，
> 两种都得复诊；"刷完就交付"从来不成立。

## 13. Word 保存会顺手重写 `styles.xml`，把等价的样式字号规掉

实测：Word 更新目录并保存后，某级标题样式的 `w:sz` 被删（值与 `docDefaults` 等价时 Word 认为冗余）。
视觉可能无差，但产物 XML 不再等于模板版式，且**下一次字体统一会以为样式没设**。

→ 顺序要求：**字体统一 / 样式默认值必须在"目录刷新"之后再跑一遍**，并从刷新前的备份把
各级样式的 `sz` 原值写回。

## 14. 表格重建：列数看 `tblGrid`，克隆行前先去 `vMerge`

- 判现有列数用 `table_grid_cols(tbl)`，**不要用末行 tc 数**——合并单元格会让 tc 数少于列数，
  据此判断会漏调列，产出"表头 5 列、数据行 4 格"的错位表。
- 用末行作样式供体克隆新数据行前必须 `flatten_table_rows()`：带 `vMerge` 的首个新行没有可继承的
  上方 tc，`row.cells` 直接抛 `ValueError: no `tc` element at grid_offset=…`。

## 15. 字体统一的两个"改了不生效"

1. `w:rFonts` 上的 `asciiTheme` / `eastAsiaTheme` / `hAnsiTheme` / `cstheme` **优先级高于显式字体名**，
   不删掉这些属性，写了 `宋体` 也仍按主题渲染。
2. `doc.paragraphs` **不含表格内段落**：只遍历它就以为整份文档统一完了，实测表格里的旧字体
   （上千字）一个都没动。字体与残留扫描都要单独遍历 `doc.tables` 的单元格（合并格去重）。

## 16. 承接与槽位是两条写入轨道，会把同一句话各写一遍

双轨写入（模板原样 + 上一版承接 + 本轮按权威源重写的槽位）必然出现的碰撞：槽位把某段
重写成新表述，承接又把上一版的旧表述落到相邻段落 → 文档里同一内容两遍，而且**两段格式
不同**（一段带模板缩进，一段是本轮新写的空 pPr），读者一眼就看到"这段话重复了、格式还不一样"。

判据必须四条一起用（`tools/para_ops.py:dup_kind`），只用整体相似度必漏：

| 形态 | 例子 | 只按 ratio 的后果 |
|---|---|---|
| `exact` | 上一版一段被承接到两个位置 | 能抓到 |
| `near` | 只差标点／一个连接词 | 能抓到 |
| `same-lead` | 开头"××遵循以下设计准则："相同，后面条目列表不同 | **漏**（列表差异把 ratio 稀释到 0.6 以下） |
| `contained` | 上一版两句合成一句，本轮又拆开写 | **漏**（长度差太大） |

处置：
1. **写前拦**：承接／插入前先与"本轮正文池"（所有槽位新文本 + 槽位自带补充段）比一遍，
   命中就不写；被让路的那个模板段属于被替换内容，要删掉而不是留旧文。
2. **写后扫**：文档末尾再跑一次全量去重，优先级 `本轮正文 > 模板原样 > 上一版承接`，同级留靠前。
3. **两段都是模板原样时禁止自动删**：那是模板自带的并列写法（实测两条"××验证"条目开头相同），
   自动删等于吃正文；只报闸门由人判断，并在配置里用 `dup_allow` 显式声明同族条目。
4. 去重前先确认"本轮正文"是否已覆盖被删段的**独有事实**（工具名、参数、功能项）。实测被删段
   常带"测试工具包括…"这类细节，直接删就是丢信息 —— 正确做法是把细节并进保留段。

## 17. 同一锚点连续插多段，插入函数写错就成了整章倒序

`insert_after_para(anchor, [A, B, C])` 内部用 `el.addnext(new)` 逐段追加时顺序正确；
但如果**每次调用只传一段**（或外层把多段 `list.insert(0, x)` 累积），后插的总排在前面，
整段正文倒序：「概述 → 总体构架 → 模块 → 接口 → 约束」变成「约束 → 接口 → 模块 → …」。
文字都对、内容都不缺，只有顺序反了 —— 逐字校对很容易漏，必须专门设一条顺序检查。

- 累积同锚点的多段一律 `append`，不要 `insert(0, …)`。
- 闸门加一条：承接段（来自上一版的文字）在产物里的先后，必须与它在上一版里的先后一致
  （把上一版段落编号映射到产物段落序号，检查非递减）。
- 顺序错了不能靠"再倒着插一遍"修，要回到累积处修，否则下一次改锚点又会翻。

## 18. 新写段落没带 pPr，就是"内容对了、格式不同"

Word 正文观感来自**段落属性**（首行缩进／行距／对齐）或正文样式，不来自字符格式。本轮新写的
段落有两个来源都不带正文版式：① 槽位命中了模板里的"注：…"批注段（本来就无缩进）；
② 插入函数复制的锚点段自己就没有 pPr。结果是新写的正文贴着页边、上下文却缩进两字符。

三条实测结论：

1. **必须按"生效版式"比对**：`docDefaults → 样式链（basedOn 逐级）→ 段落直接 pPr`。
   只读段落 pPr 会把"样式里已设好缩进、段落不写 pPr"误判成缺格式，于是冤枉模板、乱改一通。
2. **锚点要单向就近**：给每个本轮新写段配"左边最近的模板段（或自己写了 pPr 的段）"作锚点。
   实测两种直觉做法都错 —— "就近互指"在整片都是新写段时 A 抄 B、B 抄 A，几轮都定不下来；
   "±N 多数派"会把模板刻意写了缩进的段拉平成样式默认值，等于新造不一致。
3. **对齐方式：pStyle 双向对齐 + 只抄参照段直接写了的属性**。
   只抄直接 pPr 不够（两段都无 pPr 时差异全在样式：Normal / Default / 自定义正文样式）；
   反过来把参照段的"生效值"全量写成直接属性也不行 —— 正文会冒出一堆模板没有的硬格式，
   用户之后在 Word 里改样式跟不动。

另外：空 `<w:pPr/>` 不算"刻意写了版式"。把它当锚点会让整片缺缩进的段落互相充当参照，
漂移反而检不出来（实测修复前判 0 处、修复后才判出真实数量）。

## 19. 渲染脚本"PDF 已存在就跳过"，逐页核对全部作废

`to_pdf()` 写成 `if os.path.exists(dst): return dst` 后，改完文档再跑渲染，读到的还是上一轮
的 PDF：页数、分页、逐页文字全是旧的，而脚本会正常打印"渲染通过 0 项"。更糟的是**页码补丁
基于旧分页**，目录页码会跟着改错。

- 复用条件必须是 `PDF 不比 docx 旧`（比较 mtime），否则删除重转；交付前再核对一遍
  `pdf/` 与产物 docx 的时间戳关系。
- 管线顺序：生成 → 目录刷新 → **渲染** → 按渲染结果改目录页码 → 再渲染确认页数不变 → 闸门。
  先改页码后渲染，等于拿旧分页改新文档。
- 凡是"能跳过"的缓存，都要问一句：它读的是不是本轮的输入？打印"通过"不等于真的检查过。

## 20. 「只补齐本轮新写段」不等于正文统一

把本轮新写的段落对齐到上下文之后，文档仍然不统一：**模板自带的正文段本身就五花八门**——
1.5 倍行距、WPS 手调的 `leftChars/hanging/right=-20`、`jc` 有的 left 有的 both、
同一套文档族里三份用样式 Normal、两份用 Default、还有用 Figure 当正文样式的。
用户看到的是"正文段落长得不一样"，不会区分这段是本轮写的还是模板带的。

正确做法：把"正文段落基线"写成配置里的一条显式规则（首行缩进字符数、左右缩进、对齐、行距、
正文样式），生成末尾**对所有正文段全量套用**，先删后写（删 `pStyle/ind/spacing/jc/autoSpace*/
adjustRightInd/snapToGrid/textAlignment` 再按基线写）。排除项必须与版式比对一致：
标题、目录、图题表题、编号段、含域、含图形、文本框、封面区。

两个坑：
1. **封面区的判定不能只看第一个分节符**——有的文档「前言」正文就在封面节里，
   按 `i < sect_i` 排除会把它漏掉，全套只有它两段不统一。改成"分节符之前 **且** 不是成段正文
   （长度阈值）"。
2. **删 `pStyle` 要成对处理**：段落行距来自样式时，只删 `w:spacing` 会露出样式的默认行距；
   反过来只抄参照段的直接属性也修不动"两段都无 pPr、样式不同"的差异。

## 21. 编号标题按「整段加粗」识别会漏，漏了就给标题加上正文缩进

模板里 `1.1 编写目的` 这类小标题常常只有**编号那个 run 加粗**、文字 run 不加粗（粗体由样式或直接
格式混出来），按"整段 run 都 bold"判标题就漏；漏掉的标题被当成正文加上首行缩进，
同章另一类真加粗标题却没缩进 —— 一眼就是"段落格式不统一"。
补一条纯文本判据：`^(第X[章节篇]|附录|\d+(\.\d+)*[.、\s]?\s*汉字/字母{1,20})$` 且整行短 → 标题。
判据要放在版式统一**之前**，否则每次统一都会误伤一批标题。

## 22. 一句话被切成两段：合并要显式配置，收尾标点要在合并之后再补

模板/WPS 转换常把长句切成两段（前段以"…就必须对软件"收尾、后段以"进行维护。"开头），
读起来是断句。用启发式（"前段不以句末标点收尾 + 后段紧邻"）能找出来但**误报很多**：
"标签：值"式规格行、`1.1 编写目的` 这类标题后接正文、以 `]` 收尾的命名公式都会被牵连。
做法：① 启发式只用于**扫描报告**；② 合并用配置显式声明 `merge_paras: [[前段尾, 后段头]]`，
两段必须相邻，合并时把后段的 run 接到前段（保留前段版式）；③ 合并发生在整句替换之后，
所以"补句末标点"的整句替换必须排在合并**之后**，否则匹配不到合并后的完整句子；
④ 闸门留两条：正文段末尾必须有句末标点（例外用 `no_punct_allow` 声明）、
标题不得"同名不同号"（两节标题文字相同只编号不同，是章节改题后的典型残留）。

## 23. 章节之间用"敲回车顶页"，改一次内容就全乱

模板常见：章标题前留若干空段落把标题顶到下一页。正文一增删，分页点就漂，
表现为"上一章还剩两行、下一章从半页开始"。正确做法是给章级标题写
`w:pageBreakBefore`（**不要**插 `w:br type=page`：那会新增段落、又变成可被误删的空段，
且正文增删后分页点仍跟着内容走）。写完分页符后，章标题前那些顶页空段必须一并删除，
否则每章前面多出一页空白。

三条边界：
1. 标题前一段就是**分节符**时不要再写 `pageBreakBefore`——分节符已换页，叠加会多一页空白。
2. 章标题判定不能只看 `^\d+[.、]`：`1. 软件简单易用，操作简单方便。` 这种编号正文句会被当成
   章节标题，于是每条列表项都另起一页。要加"短行 + 不以句末标点收尾 + 是结构段"三重限制。
3. 删空段要按**最新段落表反复重扫**：删掉一段后序号全变，一次性遍历会漏（实测连续空段只删掉一半）。

## 24. 空标题段＝导航窗格的空白条目，也会被目录域收成空条目

模板里常见"带 Heading 样式或 `outlineLvl`、但整段没有文字"的段落（多在小节末尾或表格后），
Word 导航窗格就会列出一堆空白条目；目录域刷新时它们同样被收进去（与 §12 的"刷新过收"同源）。
处置分两种：
- 能删的直接删（普通空标题段）。
- **不能删的降级**：段落带着 `sectPr`（分节符载体）、含域代码（目录/页码域）、是图形载体、
  或正好夹在两个表格之间作隔离段——删了会破坏结构。给它们写 `w:outlineLvl val="9"`
  （9＝正文级，覆盖样式给的大纲级别），导航窗格与目录域就不再收它，版式与结构都不动。

## 25. 「每份文档都要有标题树」：只写 outlineLvl，不要套 Heading 样式

无编号模板（正文只有"××："式小节名）或从 .doc 转换丢样式的项目，导航窗格是空的。
补法：按编号形态识别层级（`第X章`/`N.`=0、`x.y`=1、`x.y.z`=2），写 `w:outlineLvl`。
**不要**改 `w:pStyle` 去套 Heading 1~3：样式自带字号，会把标题字号改掉，
违反"标题只统一字体、不改字号"的基线；而导航窗格与目录域认的只是 `outlineLvl`。

配套判据要一起补两处，否则误伤：
- 图号+图名（`2.7-1 ××流程图`）不是标题：编号后跟连字符或整行以"图"结尾 → 排除。
- 引导句（"××如下图所示："）不是小节名：含"如下/所示/见图/见表" → 排除。
- 封面区只认真标题（第X章/前言/目录/编号标题），文档名等短行不写级别。
- 已自带大纲级别的段落以模板为准，不覆盖。

## 26. 中途终止"Word 导 PDF"的脚本，会留下无头实例锁住产物

`export_pdf_via_word` 的 `finally: app.Quit()` 只在脚本正常退出时执行；脚本被终止后
WINWORD 仍在后台开着产物文档，下一轮生成器写同名文件就是 `PermissionError`，
目录里还会留下 `~$xxx.docx` 锁文件。

恢复办法（保守，不会误伤用户自己开的 Word）：用 COM 连上实例 → **先判 `Visible`**，
可见就是用户在使用，直接放弃 → 不可见才逐个 `Document.Close(SaveChanges=0)`
（导出期 Word 会往文档打临时改动，写回去等于污染产物）→ 文档清空后 `Quit()` → 删 `~$` 锁文件。
见 `tools/docx_ops.py:release_orphan_word_locks`。

预防：交付类流水线不要用"杀进程"的方式中止正在导 PDF 的步骤；要停就等这一份导完。

## 27. 行末"i / OS 12.0"不是断段，别当重复段合并

中文正文里夹英文词（iOS、APP、BLE、GB 9706.1-2020）时，Word 允许在**中文字与英文字母之间**断行，
于是 `iOS` 被拆成上一行末的 `i` 和下一行首的 `OS`，从 PDF 或页面上读就像"一句话被切成两段"。

鉴别只看一件事：**是两段还是一个段落的两行**。取该文字的 XML，看是否同一个 `w:p` 里的两个
`w:r`/两行渲染 —— 同一个 `w:p` 就是断词，不是断段。断段的判据必须是"两个相邻 `w:p`，
前段不以句末标点收尾"（见 §22），光看排版观感会误合并。

处置分两类：
- 断段（两个 `w:p`）：按配置显式合并，保留前段版式。
- 断词（同一个 `w:p`）：**不要动段落结构**。要消掉拆行，改措辞把英文词挪到行中
  （如"iOS 12.0 及以上"→"系统版本 iOS 12.0 及以上"），或删掉该英文词前后的半角空格，
  让它与中文之间不产生可断点。改完必须重新逐页看图确认这一行不再拆。

## 28. 章级标题判定：§23 防的是"误判"，还会"漏判"

§23 教怎么不把 `1. 软件简单易用。` 这类编号正文句当成章节。反方向同样致命：**章级判不出 → 该章不另起一页**，
上一章尾巴挂在下一章前面；而闸门"章标题前分页"会因为"根本没识别出章标题"判 0 违规、**静默通过**。

三类模板必然漏判：

| 模板形态 | 为什么漏 | 补法 |
|---|---|---|
| 无编号小节名（"××："式），章级用的是 **Heading 2** 而非 Heading 1 | 判据写死"Heading 1 或 `^\d+[.、]`" | 章级 = **本文档实际存在的最浅大纲层级**：先扫全文取 `min(outline_level)` 再按它判 |
| 深层编号（`1.4.1.3`）被当成小节 | 只匹配 `^\d+\.\d` | 层级按点分段数算，别硬编码"两级" |
| 标题文字靠自动编号（文本里没有序号） | 纯文本判据落空 | 结构判据（样式/`outlineLvl`）与文本判据**取并集**，不要只取交集 |

> 判据要双向验证：既数"误判了几个"，也数"**该分页的章标题有几个没分页**"。日志必须打印
> "识别出章标题 N 个"，N 与目录条目数明显不符时报警——只报"0 违规"不等于识别正确。

## 29. 三条配套约束：判据共用、白名单双传、显式合并要校验命中数

1. **"是不是标题"只能有一套判据，被所有检查共用**。正文基线套用、句末标点检查、重复段检测、
   标题树写入各判各的，就会出现"标题被当正文加缩进""编号小标题被要求句末标点"
   （实测 `1.4.1.3正常使用场景` 被判缺标点）。做法：抽 `outline_kind(text)`，
   所有"只作用于正文"的地方先 `if outline_kind(...) is not None: continue`。
2. **`dup_allow` 要同时传给生成器和闸门**。只给生成器 → 它不删（正确）但闸门一直红；
   只给闸门 → 生成器可能把模板自带的并列条目删掉。两处读同一事实文件的同一个键。
3. **显式配置的断句合并必须校验命中数**。`merge_paras: [[前段尾, 后段头]]` 的键会随上游改写失效
   （槽位改措辞后"前段尾"不再是段尾），不校验就是**静默不合并**。命中数 < 配置数 → 报错，
   不能只打日志。补句末标点必须排在合并之后（否则匹配不到完整句子）。

## 30. 共享原语的两条纪律

1. **入参要兼容 `Paragraph` 与 `CT_P`**。`_ppr_direct(p)` 写成 `p._p.find(...)` 后，任何传
   `p._p` 进来的调用方（`is_struct_carrier` 就是这样）都会 `AttributeError: 'CT_P' object has
   no attribute '_p'`；而这条路径只在真删空段时才走到，模板没空段就一辈子不报错。
   写法：`el = getattr(p, '_p', p)`。**被其他原语调用的函数必须跑通整条调用链**，不能只测函数本身。
2. **经验库升级后，把项目脚本里的同名实现回收到共享原语**。项目曾在 `build_*.py` 自写
   `normalize_fonts`（分区+表格+样式默认值）；库升级出 `docx_ops.unify_document_fonts`
   （另含主题属性清理、文本框跳过、封面分区）后，项目函数应改成**薄封装**：调共享函数，
   只保留项目差异（本项目是"标题分级字号"，共享函数对标题只改字体不改字号）。
   留两套的代价：库修了 bug（如 `asciiTheme` 优先级高于显式字体名），项目那份仍带旧行为。
   例外要写清：全量套基线后**故意保留**的次级缩进（如"测试方法"条目多 0.26cm 左缩进）
   必须在版本说明点名，否则下一轮会被别人当漂移一刀切平掉。

## 31. 槽位"已消费"要按**段落元素身份**记，按序号记会被插入/删除冲掉

一轮生成里同时存在三种改变段落数的动作：多行槽位 `insert_paragraphs_after`、去重删段、
显式合并。只要它们在**任何一条尚未执行的槽位之前**发生过，`enumerate(doc.paragraphs)` 的序号
就与记录 `used` 时的序号错位，后果不是报错而是**静默改错段**：

| 症状 | 机理 |
|---|---|
| 某槽位报"未命中"，但正文里那段旧文字还在 | 它的索引被算进了 `used`，`find_para` 跳过时跳过了别的段 |
| 同一段被改两次 / 该改的那段没改 | 插入使后段前移，旧索引指到了前一段 |
| 闸门全绿，产物却带着上一项目的字段值 | 改错段 = 正确段没被替换，而该值恰好不在残留词黑名单里（见 §32） |

写法：`used = set()` 存 `id(p._p)`（或元素本身），`find_para` 里 `if id(p._p) in used: continue`。
**并且槽位表要按"文档顺序"排列**——身份判定消除了错位，但先命中的仍是文档中靠前的段。

## 32. 同一标签在文档里出现多处：只命中第一处就是**静默漏改**

固定标签句（"软件名称：""生产企业：""软件版本："）常在**产品标识章**和**版本规定章**各出现一次，
文字完全相同。一条锚点 + "取首个未命中段"的机制只会改第一处，第二处原样留着上一项目的值。

三重防线，缺一不可：

1. **槽位支持 `all` 模式**（替换全部命中段），或为第二处再登记一条同锚点槽位（身份判定后天然可行）；
   两处内容应当不同时用后者，并在 `NOTES` 里报"标了 all 但只命中 1 处"，防止锚点失效后静默少改。
2. **闸门加"同标签多点位取值一致"**：对每个标签取全部出现点的值做集合比对，>1 个取值即失败。
   残留词黑名单只能抓住"已知是旧项目"的词；"控制软件"这类**通用词形式的旧值**抓不住。
3. **重复段检测的 `allow` 要放行它**：两段同前缀、后半不同，会被 `same-lead` 判成重复段；
   若生成器据此去重，就会把合法的第二点删掉，正文直接缺项（见 §29.2 白名单双传）。

## 33. 无域静态目录的页码在 `w:hyperlink` 里：整段替换会把文字写两遍

形态 C（纯文本目录，见 `docx-fields-and-toc-repair.md` §5）常仍带着**超链接**：条目文字与页码
分处 hyperlink 内的多个 `w:r`，段落直接子级没有 `w:r`。此时 `p.runs` 为空（python-docx 不取
hyperlink 内的 run），`set_paragraph` 走 `p.add_run(text)` 分支 → **新文字追加在旧文字后面**，
目录条目变成"5. 结论55. 结论4"。而 `toc_diagnose` 的 `entry_has_field=False` 让人以为这是纯文本段，
更容易下手错。

正确做法：只改 hyperlink 内**最后一个 `w:t`**（页码），其余一概不动。

```python
links = para._p.findall(qn('w:hyperlink'))
ts = links[-1].findall('.//' + qn('w:t'))     # 条目文字与页码同属一个 hyperlink
if ts and ts[-1].text != str(page):
    ts[-1].text = str(page)
```

顺带一条硬约束：**整段替换前必须排除含 `w:hyperlink` 的段落**（与"含域段落不合并 run"同一条纪律的
扩展形态）。目录条目、交叉引用、带书签的标题都属此类。

## 34. 两处"段落自己没有、样式链里有"的值：`numPr` 与 `ind:leftChars`

判"结构段/编号列表项"和套"正文段落基线"都容易只看段落 `pPr`，于是漏掉两类继承值：

| 继承值 | 现象 | 修法 |
|---|---|---|
| 样式（如 `Figure`）自带 `numPr` | 段落没有 `w:numPr`，`is_structural_paragraph` 判为正文 → 给列表项加了正文首行缩进 | 判定要沿 `base_style` 链找 `pPr/numPr`；样式带编号的一律视同编号段 |
| 样式自带 `ind:leftChars=150` | 直接写了 `ind:firstLineChars=200` 却没写 `leftChars`，生效值仍是 150 → 套完基线指纹仍不等于基线 | 写基线时**同时显式压零** `leftChars/rightChars`（以及 `left/right`），别只写要改的那一项 |

自检方式：套用后立刻用 `effective_para_format` 复算生效值并与基线指纹比对，不匹配就打印该段前若干字
（本项目实测到 6 段偏离，全部来自这两条）。**"闸门说统一"必须以生效值为准，不能以"我写了什么"为准。**

> **第三例（2026-10-15 补）**：`w:sz` 同样会「段落自己没有、样式链里有」。
> Word 刷新目录时会把与样式等价的 run 级字号归并进样式并删掉显式值（§13），
> 于是只读 run 的标题字号闸门会把已经改好的文档判成「读不到字号」而**假 PASS**
> （实测某份章/节标题已正确落在 32/28，闸门却只报出 `[32]`，看起来通过、实际没看到第二级）。
> 判据必须走 `run 显式值 → pStyle 链 → Normal` 三级解算（`docx_ops._effective_sz`）。
> 推论：**闸门报 PASS 且某一级"消失"时，先怀疑闸门读不到，而不是文档没问题**——
> 用 `styles.xml` 里各级样式的 `sz` 反向核对一次再下结论。

## 35. 页眉页脚是**独立残留槽位**，替换要绕开页码域

正文级替换（`doc.paragraphs`）不含页眉页脚，模板里印的上一项目公司名/项目号会整片留在
`word/header*.xml`、`word/footer*.xml` 里，肉眼在正文找不到。两条纪律：

1. 生成器显式遍历 `section.header/footer`（含 first/even 三种页脚）套用词替换；用
   `docx_ops.apply_substitutions` 而非裸字符串替换——它**遇到含域段落不做 run 合并**，
   页码域（`PAGE`）不会被拍平。
2. 残留扫描必须覆盖**全包** `word/*.xml`（document + header + footer + 脚注 + 文本框），
   只扫 `document.xml` 的闸门等于没扫。
3. **"链接前节"的部件在 XML 里是空的**：`header2/3`、`footer2/3` 常常没有 `<w:t>`，文字来自继承。
   按部件文本判"这节没页眉"是错的，替换时也不能只改 `header1` 就以为全节改到位。
   判据取**解析后的生效值**（`section.header` 会回溯继承），或渲染逐页核对；两种都要写明用的是哪一种。

## 36. 二次改写之后必须**重算交付清单哈希**

`manifest.json` 若在生成阶段写死产物哈希，而版式收口（字体统一、标题树、分页）发生在
Word 刷新目录之后并再次保存了同一批文件，清单里的哈希就指向一个**已经不存在的产物状态**，
可追溯性归零。做法：把"重算 outputs/figures 哈希"作为流水线**最后一步**，并在清单里记
`post_format_at` 与两份闸门报告的哈希，使"清单—产物—检查"三者同代。

## 37. "末页只有一行"不是空白页，判据要分级

逐页渲染检查里"正文 < N 字即失败"太粗：文档最后一页常常只有正文末段溢出的一行
（实测末页仅 4 字），压回上一页需要动该段行距——而**动行距就偏离正文段落基线**（§34、正文基线一节）。
分级处理：

- 无任何文字 → 空白页，**阻断**；
- 中间页文字极少 → 疑似顶页/分页错位，**阻断**；
- 最后一页仅 1～2 行 → 记"提示"写进版本说明，交人决定是否接受，不阻断。

同类判据还有"表格跨页断行"（给数据行写 `w:cantSplit` 消掉）与"单元格文字甩到下一页"，
都属于**版式取舍**而不是数据错误，报告里要分开列，避免下一轮被人当 bug 一刀切。

## 38. `keepNext` / `keepLines` 加到正文段或图片段，段前会冒出"标题样标记"

为了让"标题＋图＋图题"落在同一页，顺手给图片段、图题段甚至正文段加 `keepNext`/`keepLines`
是**错的**：WPS 页面视图会在这些段前显示与标题相同的大纲/分页标记，用户看到的就是一句
"图片前面出现一个点点，感觉变成了标题，它应该属于正文"。Word 里同样会把该段并进标题的分页组。

正确做法只有一条：**`keepNext` 写在标题段自己身上就够了**——它绑定的是"本段与下一段同页"，
下一段正是图片段，图题紧随其后；图片段与图题段保持纯正文（最多留 `jc=center`）。
单行标题上的 `keepLines` 没有意义，一并去掉。

副作用还不小：给较高的图所在段加 `keepNext`，会把"图＋后文"粘成一整块，块高超过剩余页高时
整块被推到下一页，反而在上一页底部留出一大片空白。

闸门：统计"生效大纲级别为正文级、却带 `keepNext`/`keepLines`"的段落数，必须为 0。
（`tools/docx_ops.py:pagination_audit` → `keep_on_body`）

## 39. 硬分页符与段前分页**叠加**，每个叠加点多一张空白页

§23 说"用 `w:pageBreakBefore`，别插 `w:br type=page`"。更隐蔽的是**两者同时存在**：
承接 .doc 转换稿、或"补分页时没删旧分页符"，标题段上既有 `w:br type="page"` 又有
`pageBreakBefore`，两个都生效 → 中间凭空多一张整页空白。表现是页码跳号、目录页码对不上，
但逐段看 XML 每处都"合理"，肉眼看正文最难发现。

处置：二选一，按 §23 一律保留 `pageBreakBefore`、删掉 `w:br type=page`。
另外**正文段上出现 `pageBreakBefore`**（把某段正文强行推到新页）同属误用，要清掉；
但"前言／目录／章标题"这类前置件段带它是正常的，报告里逐条打印文本交人确认，不要一刀切。

闸门两条：全包 `w:br[type=page]` 计数为 0；同时带硬分页符与段前分页的段落列表为空。
（`pagination_audit` → `hard_page_breaks` / `stacked_breaks` / `body_page_break`）

## 40. `keepNext`、`pageBreakBefore` 这类布尔属性**必须判 `w:val`**

Word 用同一个元素表达"开"和"关"：`<w:keepNext/>` 是开，`<w:keepNext w:val="0"/>` 是**关**。
写成 `val="0"` 通常是为了**压掉从样式继承来的设置**，是承接稿里的常态。

判据若只写 `pPr.find('w:keepNext') is not None`，会把"显式关闭"当成"开启"，一次误报几十段。
实测一份长文因此报了数十个"正文段被强制分页"、数个"图片段带 keepNext"，真问题全被淹没；
改成判 `w:val not in ('0','false','off','none')` 后误报归零，真实缺陷只剩一处。

同类属性：`keepNext` / `keepLines` / `pageBreakBefore` / `widowControl` / `suppressAutoHyphens`
／ `w:bdr val="none"` ／ `w:spacing` 的 `beforeAutoSpacing`。凡是"元素存在即生效"的假设都要先查 `w:val`。
同理适用于 §34 的样式链：值可能在样式里，段落自己没有；也可能段落实心写了一个 `val="0"` 压住样式。

## 41. 中文 PDF 的"字数"不能判空白页，改用渲染墨占比

§37 的"正文 < N 字即失败"在中文文档上**不成立**：Word/WPS 导出的 PDF 常是子集字体且不带
ToUnicode，`pdftotext` 只吐得出数字、拉丁字母和目录点线，整页汉字全部丢失。后果是双向误判——
内容正常的纯中文页被判成"空白页"，而真正只有一串数字的页反而"有字"。

判据换成**像素墨占比**：`pdftoppm` 出图 → 裁掉页眉页脚带（上下各约 8%）→ 统计灰度低于阈值的像素占比。
经验档位：封面页约 2~3%，正文页 3~13%，**真空白页 0.0%**。分级沿用 §37：
正文区 <0.15% 判空白页（阻断）、中间页 <0.8% 判疑似顶页（阻断）、末页 <0.8% 记提示。

配套纪律：`pdfinfo` 的 Pages 可信，`pdftotext` 的文字量不可信；要用文字核对内容时先确认该 PDF
有 ToUnicode，否则一律回到 `pdftoppm` 出图人工看图。
（`tools/docx_ops.py:page_ink_coverage` + `grade_pages_by_ink`）

## 42. 标题／图题判据要收紧四处，否则既漏判又误伤

§25 的配套判据"整行以'图'结尾 → 排除"过宽，实测会连坐三类真标题：
`××原理框图`、`××结构图`、`××参数列表` 这类本身就"以图/表结尾"的合法标题，被判成图题后**漏掉大纲级别**，
导航窗格与目录域就不收它——这是漏判，比误判更难发现。

四条收紧：

1. **图／表题用位置判据**：`^(图|表)\s*[\d\-.]` 才算题注；"以图/表结尾"只能作辅助信号，
   且必须叠加"该段不是编号标题形态（`第X章`/`x.y`）"才排除。
2. **图号不是小节号**：`2.7-1 ××流程图` 会被 `^\d+(\.\d+)+` 命中，识别编号标题时要排除
   "编号后紧跟连字符"的形态（`^\d+(\.\d+)*-\d+`）。
3. **目录域内的段落先剔除**：TOC 条目文本是"标题＋制表线＋页码"（如 `第一章 概述4`），
   既会被编号判据误收，也会让"空标题段"判据误报。含 `fldChar`/`instrText` 或样式名以
   `TOC`/`目录` 开头的段落一律不参与结构判定。
4. **封面区不算顶页空段**：封面文档名之前的空段是封面留白（归 `trim_cover_spacers` 管），
   不是 §23 说的"章前回车顶页"。以封面信息表为界，只统计表之后的连续空段；
   计数途中遇到分节符载体段要归零停止。

另有一条与 §25 并列的正向闸门：**封面文档名（正文样式＋直接 `outlineLvl=0`）不得带大纲级别**，
否则它会作为第一条混进目录域，表现为"目录第一行是文件名"。闸门即
`pagination_audit` 的 `outline_anomaly`（`numbered_not_in_tree` 覆盖漏判，`chapter_pad` 覆盖误判）。

## 43. 判断"这段我改过了"要用**元素对象**做键，不能用 `id(p._p)`

§31 把槽位消费记录从序号改成"元素身份"之后，还有一个更隐蔽的坑：lxml 的 element proxy 是**临时对象**，
没有 Python 引用时会被回收，地址随后会被别的元素复用。

```python
used.add(id(p._p))          # ✗ 只存了整数，proxy 被回收 → 地址复用 → 后来的段被误判"已用过"
used.add(p._p)              # ✓ 集合持有引用，proxy 常驻 → 身份判定稳定
AUTH[p._p] = "slot"         # 同理，来历表也用元素做键
```

症状极难归因：**同一份脚本、同一份输入，换一轮运行就有 N 条槽位报"未命中"**，而且未命中的是
哪几条不确定（实测某份文档 7 条槽位集体漏命中，正文整片留着上一项目的旧值，
而残留词黑名单因为旧值是通用词形式也没抓到）。规则：**凡是"按元素身份"记账的集合/字典，
键必须是元素本身**（或同时持有元素引用），`id()` 只能用于同一表达式内的临时比较。

## 44. Word/WPS COM 要用 `DispatchEx` 起独立实例；僵尸实例按"可见窗口 + 文档名"双重判据处置

`win32com.client.Dispatch('Word.Application')` 会**复用注册表里已有的实例**——如果用户当时开着 Word，
脚本就等于在他的会话里打开、保存、导出文档；脚本被中断后，文档留在用户实例中锁住产物，
下一轮写入直接 `PermissionError`。

1. 交付类流水线一律用 `DispatchEx('Word.Application')`（强制新实例），退出时 `Quit()` 只影响自己。
2. 清理遗留时先分身份：`GetActiveObject` 取实例 → 读 `Visible`；再按窗口枚举交叉验证
   （`IsWindowVisible` + 进程 PID）。**两条判据不一致时按"可见"处理**，即不动实例，
   改为请用户关闭对应文档——僵尸实例的 `Documents.Item(i)` 往往抛 `AttributeError`，
   COM 路径已经不可用，此时只有用户（或明确授权）能安全收尾。
3. 只关闭文件名命中本项目产物前缀的文档，且 `Close(SaveChanges=0)`：Word 在导出期会给文档打临时改动，
   写回去等于污染产物。随后删除 `~$` 锁文件。
4. 判"文件是否被占用"不要只看 `open(f,'rb+')` 抛错——只读属性、ACL 与句柄占用都报 errno 13；
   先查 `GetFileAttributesW` 再下结论。

## 45. 分页收口的三条时序与判据细节（§38 §39 的补充，实测各踩一次）

1. **"前一段是不是分节符"必须在删完顶页空段之后再判一次。** 加分页时章标题与分节符之间常隔着
   若干空段，判"前一段是分节符"落空 → 照写 `pageBreakBefore`；随后清理空段，分节符紧贴标题，
   两个都生效就多一张整页空白（§39 的叠加形态，但只在清理后才显形）。
   正确顺序：`加分页 → tidy_navigation 删空段 → unstack_page_breaks 复核并摘掉叠加`。
2. **`keepNext` 不要加在"后面紧跟整张表"的标题上。** §38 只说了高图的情形，表同理且更常见：
   标题 + 整张表被粘成一整块，块高超过剩余页高时整块跳到下一页，上一页底部留大片空白，
   甚至把表后的说明行挤成 0.26% 墨的孤立薄页。做法：写 `keepNext` 前看 `p._p.getnext()`，
   是 `w:tbl` 就跳过；闸门的"标题段全部分页受控"检查要用同一豁免条件，否则永远红。
3. **Word 的 `Paragraphs` 集合含表格单元格段落，python-docx 的 `doc.paragraphs` 不含。**
   做 COM 对象模型复核时按序号 `doc.paragraphs[i-1]` 对齐会整片错位（两张表就错了 8 段，
   把正文段报成"非标题却成标题级"）。做法：按**归一化文本**配对（一处消费一个候选），
   并且逐段取值要 try/except——Word 重排会让段落对象失效（"对象已被删除"）。


## 46. 判"这一章已经分页"要数**三种形态**；章级排版按模板多数派统一（§39 §23 的落地细节）

`pagination_repair` 把 `w:br type=page` 换成 `pageBreakBefore` 之后，任何"只看 `pageBreakBefore`"
的多数派判定都会得出"本文档不分页"，于是把长文的章分页全压成连续——**修复动作自己污染了判据**。
承接稿里"让这一章另起一页"有三种等价写法，必须一起算：

| 形态 | 位置 | 判据 |
|---|---|---|
| 段前分页 | 标题段 `pPr/pageBreakBefore`（判 `w:val`，§40） | `flag_on(pPr, 'w:pageBreakBefore')` |
| 段内硬分页符 | 标题段第一个文字之前的 `w:br w:type="page"` | `any(b.get(w:type) == 'page' for b in el.iter(w:br))` |
| 前一段换页分节符 | 前一段 `pPr/sectPr` 且 `type != continuous` | `sect_breaks_page_el(prev)` |

统一规则（同一文档内必须一致，混用才是缺陷）：
**已分页占多数 → 补齐缺的；一个都没有 → 保持连续；少数派分页 → 统一到连续并删掉其硬分页符**
（只删属性不删硬分页符的话，`drop_hard_break` 会按 §39 把它又换成 `pageBreakBefore`，等于刚删的又加回来）。

理由：§23 的"章前分页"针对长文档章节。6 页的表单式报告（大项只有 5~6 条）全部拆页，
只会多出几张半空页——实测某份短报告的末条大项带段前分页，把上一章表格最后一行
挤成 0.73% 墨的孤立薄页，正撞 §41 的阻断线。

**前置件例外**：封面信息表之后的第一块（目录／前言）必须保留分页，否则正文第一块会被排到封面页，
"封面独立成页"直接失守。找这块**不能用序号差**：`cover_cutoff_index` 在"封面节里就写着正文"的模板上
返回 0，序号差会指到封面文档名本身；要从 `find_cover_table()` 之后顺序取第一个有字段落，
生成器与闸门共用同一个函数。

## 47. "没有文字的空段"有三种命运，删空段不能一刀切

`tidy_navigation` / `drop_chapter_pad` 都要删顶页回车空段，但**无文字 ≠ 无内容**：

| 这种"空段" | 删了的后果 | 正确处置 |
|---|---|---|
| 单独承载目录域 `end`/`separate`（`w:fldChar`） | 某份文档 begin/separate 各 6、end 只剩 5 → **TOC 域不闭合**，Word 刷新时把 `TOC \o "1-2" \h \u` 指令裸露在页面上 | 整条顶页空段链作废，一段都不删（守卫要写进"数空段"的循环里，不是写在删除动作的 if 上） |
| 只含硬分页符，且是封面与正文之间**唯一**的换页手段 | 删完封面与正文挤到同一页 | 就地转成 `pageBreakBefore`；下一段自己会换页时才删（否则"空段分页＋下段分页"又是一张空白页） |
| 纯回车占位（无域、无图形、无分节符、无分页符） | 无 | 删（§23；连续 ≥2 段才算缺陷，见 §42.4） |

同理，`chapter_pad_map` 往回数空段时遇到**分节符载体段要整条作废**：它前面的空段属于上一节，
不是本章的顶页回车。守卫方向写反（"有文字/是载体 → 删"）会直接删掉正文和分节符，
这类函数最好把判据抽成 audit 与 repair 共用的一份（§8 第 4 步），别让两处各写一遍。

## 48. 修完分页必须做的三项回归：域平衡、页数核账、末页降级

1. **域平衡**：修复动作可能吃掉域的壳段（§47），所以修完除了复跑 `pagination_audit` 七项，
   还要复跑 `toc_diagnose`，看 `balance == 0` 且 `text_has_toc == False`。
2. **页数核账**（§8 第 5 步）：`len(page_ink_coverage(pdf))` 必须等于"修复前页数 − 消除的空白页数"。
   实测一份 17 页收口后 13 页（消除 4 张叠加空白页）、另一份 11 页变 8 页（1 张）；页数没变＝修复没生效或被
   Word 保存回滚，少得比预期多＝误删了结构段，两种都要停下查。
3. **末页降级**：只剩 1~2 行的末页墨占比会低到 0.10%，若按"<0.15% 即空白页"会阻断，
   而唯一"压页"手段是改行距/字号——那会破坏正文基线，§37/§41 明令禁止。
   `grade_pages_by_ink` 里末页只在 **c == 0（一点墨都没有）** 时阻断，其余 <0.8% 记提示。
   另外：图示核对要数**图的张数**而不是"有图的页"，两张框图同页是正常排版，按页数判会误报缺图。

## 49. 判据对了、对象选错的三类闸门误报

分页判据换成 `pagination_audit` 之后仍然红了 11 项，全部是"取值方式对、取的对象错"：

| 误报 | 根因 | 修法 |
|---|---|---|
| 章级分页"混用 1/N"，每份都报 | 把"紧跟分节符的第一章"当成它自己分了页——那是封面/目录独立成节的结果 | 一致性判定里排除前置件与新节第一章；`on` 只数 `pageBreakBefore` |
| 编号标题未入树：`第一章 概述\t4`、`前 言\t2` | 目录条目文本就是"标题＋制表线＋页码"，自己写的文本判据把它当正文标题（§42.3） | 用 audit 的 `numbered_not_in_tree`（已排除域段与 TOC 样式） |
| 标签「软件版本」多点位取值不一致 | 修订记录表 r0 的**表头列名**恰好叫"软件版本"，被当成一处取值 | 表格侧只认"标签：值"同处一格的点位，单元格文本等于标签的是列名 |

> 闸门复用共享判据不等于"自动正确"。凡是要把某个结构对象排除在判定之外的，
> 生成器与闸门必须调**同一个**豁免函数（这里是一个"封面后第一块"取块函数），否则一边豁免一边不豁免。

## 50. 无头 Office / LibreOffice 的失败大多是瞬时的：先回收、换全新 profile、退避重试（§26 §44 的延伸）

一轮 9 份文档的交付流水线里同时出现：Word 目录刷新报 `(-2146959355, '服务器运行失败')`、
`GetActiveObject` 报 `Operation unavailable`、5 份 LibreOffice 不出 PDF 后 Word 兜底也失败。
共同点是**状态残留**，不是文档坏了：

1. `GetActiveObject('Word.Application')` 取到的是 ROT 里**任意一个**实例。机器上同时有用户的可见实例
   和脚本留下的无头实例时，同一句代码这轮取到可见的（判"用户在用，不动"），下轮取到无头的（正常释放）。
   所以 `release_orphan_word_locks` 返回 `(0, False)` 有两种完全不同的含义。**动之前重新连一次并读 `Visible`**，
   拿不到或异常就按"可见"处理（不动实例）。
2. COM 报"服务器运行失败 / Operation unavailable"常常是**上一个实例正在退出、ROT 还没清完**：
   先 `release_orphan_word_locks()`，退避几秒再试，2~3 次即可通过；不要据此判"文档损坏"。
3. LibreOffice 的 `-env:UserInstallation` 目录**每次转换都要全新**：上一轮被强杀的实例会在该目录留锁，
   复用同一目录的实例会"静默不产出 PDF"（返回码 0，什么文件都没有）。每份文档每次尝试用不同目录名，
   并最多重试 3 次，再走 Word 兜底。
4. 判"文件被占用"要两步：`open(path, 'rb+')` 抛 `PermissionError` 后**先试 `os.rename()`**——
   能改名说明只是属性/ACL 或已消失的句柄；孤儿 Word 死透后 `~$xxx.docx` 属主文件会留在目录里，
   但真文件是可写的，别因为看到 `~$` 就以为锁着（§44.4 同一族问题）。

## 51. 表格"左边框丢了/像被隐藏"有四类根因，症状同名、成因不同

用户报"部分文档的表格左侧边框丢失，像是被隐藏了"。**不要一上来就补 `tblBorders/left`**——
实测四类根因里，只有两类是真缺线，另两类补线反而做错事：

| 根因 | 判据 | 处置 | 为什么容易误判 |
|---|---|---|---|
| A 负 `w:tblInd` | `tblInd/w:w < 0` | 归 0，左边框回到版心左沿 | 线在，只是整表左移压进页边距，看着像"被裁掉" |
| B 正文表继承了封面模板的 `w:tblpPr` | 有 `tblpPr` 且 `horzAnchor=page`、`tblpX < 左页边距` | 去浮动改回行内（封面表按 §2 保留浮动） | 同上；浮动表还会让后续段落绕排 |
| C 单元格级 `w:tcBorders/w:left val="nil"` | 表级有框线、部分单元格左边被显式删除 | 只摘这些 `nil` 节点 | 真缺线，但**只缺局部几行** |
| D 表级与样式都无框线 | 表级无 `tblBorders`、`tblStyle` 无框线 | **什么都不加** | 这是设计上无框线的两栏列表，不是缺陷 |

三条必须守住的判据纪律：

1. **表级 `tblBorders/left` 缺失 ≠ 看不见**。首列单元格自带 `single` 时渲染完全正常，
   按"表级没有就补六向"会顺手补出 `insideH/insideV`，给设计上无内线的表凭空加满网格。
   只补"其他边有框线、唯独左边没有"的真缺失，且**只补 `left`，绝不碰 `inside*`**。
2. **摘 `nil` 之前先确认该表本应有框线**。四边皆 `nil` 且表级/样式无框线者是无框线表，
   摘掉 `nil` 是空操作（无东西可继承）；但若样式链里有框线，摘 `nil` 就会把线加出来。
   改前改后各渲染一次对比，别只信 XML diff。
3. **列宽溢出要分档，不能一律等比缩放**。`tblGrid` 列宽和 > 版心 1.05 倍时等比缩放可救；
   超过约 **2 倍**（典型形态：从两列表拷来，后几列全等于同一个大数值）属于**列宽数据污染**，
   等比缩放后首列仍是一字宽、型号被竖排成一列字，必须人工指定列宽。
   原语对这类只报 `grid-corrupt` 不改，另给 `grid_overrides={表号:[各列twips]}` 入口。
   改列宽会显著改变页数（实测一张 31 行表从每行 8 行高压回 1 行，全文 17 页 → 13 页），
   所以必须重渲染核账，不能只看 XML。

4. **体检函数必须实现同样的规则 D**，不能只在修复函数里判。实测 `normalize_table_geometry`
   已按"表级与样式都无框线则不动"实现，而 `audit_table_geometry` 只看首列单元格有没有单线，
   于是把设计上无网格的两栏列表报成"左边框真缺失"——**修复与体检判据不同源，等于闸门自己造误报**
   （与 DoD 第 38 条"修复与判据同源"是同一条纪律的另一半：不仅修复要用判据，体检也要）。

配套原语：`normalize_table_geometry(...)`（四类处置）、`audit_table_geometry(...)`（只读体检，
把"表级缺失但首列有单线"降级为仅提示，避免误报淹没真问题）。

> 规则 D 是**通用默认**，不是不可违。项目/注册方明确要求"每张表都要有完整网格"时，
> 按 `generality-boundaries-and-precedence.md` 第一节的优先级照做，但要用**另一个原语**
> （`set_table_borders_six_way`）显式表达这个决定，别改 §51 的默认实现——
> 否则下一个"两栏列表本就没框线"的项目会被这条改动误伤。三条配套纪律：
> ①生效框线要沿 `tblStyle → basedOn` 样式链取（路径是 `w:style/w:tblPr/w:tblBorders`，找错一层会把正常表判成缺线）；
> ②只补外框等于没补，两栏列表仍需要 `insideH`；③补完必须摘掉单元格级 `tcBorders val="nil|none"`，
> 否则刚补的左边框又被单元格级写法抹掉。补完改前改后各渲染一次比对。

## 52. 封面「标题文字 → 封面信息表」之间的空行数必须显式统一

同一批文档族里，封面标题与封面表之间的空段实测出现过 **0 个**（文字紧贴表格）与
**13 个**（表格被顶到很下面）两种极端，观感就是"封面格式不统一"。这类留白**没有任何结构含义**，
纯靠手敲回车，每份模板继承时各抄一遍就跑偏。

做法：把它变成显式配置项（如 `cover_spacers: 3`），生成/收口阶段调
`set_cover_spacers(doc, n=3)` 统一；空段一律用正文样式，样式取已存在空段的样式，没有则不写
`pStyle`（即 Normal）。

两条护栏：

- 标题与封面表之间**混入非空段或图形时直接跳过不动**，交人处理——那里可能有版本号、编号或图片；
- 加完空段必须重新确认**封面仍恰好一页**（`page_ink_coverage` 第 1 页有墨、第 2 页不是被顶出来的
  空白页）。3 行正文空行在常见版式下安全，但这个数与字号、行距、封面表行数耦合，换模板要重测。

## 53. 标题编号机制三态混用：渲染全对、无双编号，闸门却一条都不报

字号分档（`font-and-style-normalization.md` §10.5）做完之后，标题看起来已经统一了，
但**编号机制**可能还是三种混在一起：

| 机制 | 形态 | 判据位置 |
|---|---|---|
| 手写 | 序号写在文字里：`1.1 编写目的`、`第X章 概述` | `w:t` 文本 |
| 自动-样式 | 文字里没有序号，编号来自 `pStyle` 沿 `basedOn` 链上的 `w:numPr` | 样式链（§34） |
| 自动-段落 | 文字里没有序号，编号来自段落自己的 `w:pPr/w:numPr`（`numId` 非 0） | 段落 |
| 无编号 | 三者皆无，靠样式名或纯文字充当章名 | — |

**为什么必须管**：这三种在**当前页面上可以完全正确**——没有 §8 的双编号，没有跳号，
肉眼和现有闸门（字号档、分页、目录域）全部放行。但它们的**可维护性不同**：
插入或删除一章/一节后，只有"自动"那部分会重排，"手写"那部分原地不动，编号当场断裂，
而断裂发生在下一轮内容改动时，不在本轮交付的视野里。同一级别混用等于给未来埋雷。

**两类混用要分开查**（原语 `heading_numbering_mechanisms(doc)` 只覆盖第一类）：

1. **文档内同级别混用**——同一份里 L2 既有 `1.1`（手写）又有 `2.1`（自动-段落）。
   返回值 `mixed` 直接给出混用的级别与占比。
2. **跨文档同级别机制不同**——同一批文档族里，A 份章标题全手写、B 份走样式自动、
   C 份走段落自动。单份跑 `mixed` 可能全空，**必须把各份的 `{级别: {机制: 段数}}` 并排比对**
   才能发现。做法：同一段脚本对全批跑一遍，把结果打成一表交人判读。

**处置方向（选一种，全族一致，不要按份就地取材）**：

| 方向 | 做法 | 代价 |
|---|---|---|
| 全交给自动编号 | 把文字里的手写序号删掉，只留标题名，由 `numPr` 排号（§8 表里"标题段"那一行） | 会改标题文字本身；目录条目文本随之变化；需要给每级挂正确的 `numId`/`ilvl` |
| 全改成手写 | 摘掉 `pPr/numPr` 与样式链上的 `numPr`，把序号写进文字 | 插删章节不再自动重排，靠人工维护；但 XML 简单、跨工具（WPS/Word/LibreOffice）表现最稳 |

两条都不要的中间态：**同一份里一半一半**。收口时宁可暂时全手写，也不要混着。

配套闸门：`heading_numbering_mechanisms(doc)` → `(per_level, mixed)`；
交付时把全批的 `per_level` 并排打印，`mixed` 非空或跨份同级别机制不一致，都记为待决项交人确认，
**不要由脚本自动改**——它动的是标题文字，属于内容级变更。

## 54. 分页粒度：只有"第X章"级大标题分页——判大标题要解析**生效编号格式**，且必须"先清后加"

用户口径："小标题不需要分页，明显可以放在一页里面，只有第一章、第二章这样的大标题才分页。"
§46 已给出理由（表单式报告全拆页只会多出几张半空页）。落地时有四条不是显然的：

1. **文本判据不够**。章标题的"第X章"可能根本不在文字里：Heading 1 的文本是"产品背景"，
   "第%1章"写在 `numbering.xml` 的 `lvlText` 里。判据必须解析**生效编号格式**
   （段内 `numPr` → 沿 `base_style` 链 → `numId/ilvl` 查 `abstractNum/lvl/lvlText`），
   含"第…章/部分/篇"才算大标题；`lvlText="%1."` 的自动编号节标题（"1./2./3."）一律不分页。
2. **只加不清等于没执行**。承接稿里小标题、甚至目录条目段自带 `pageBreakBefore`
   （实测"2.2 开发环境"和目录条目"第一部分 基本信息"各占一张多余页）。
   做法是**先清后加**，两边共用同一个放行集合函数（§49 查改同源）。
3. **放行集合 = 大标题 ∪ 封面区之后第一个内容块 ∪ 正文第一块**。
   只豁免"大标题"会退化出另一种错：目录与封面信息表同页排布，"封面独立成页"失守
   （单节文档、目录没有自己的分节符时最容易踩）。
4. **改分页必须回头同步目录页码**。Word 刷新目录发生在版式收口之前，收口一改页号就全错
   （实测目录四条全写"3"）。收口链走"刷新 → 收口 → 再刷新 → 再收口"，
   最后按**导出 PDF 的实测页号**回写条目里最后一个纯数字 `w:t`
   （域目录的 PAGEREF 缓存结果与静态目录同一处置），再导出复核。
   配套：同一编号序列的章级标题被拆在两个 `numId` 上会**从 1 重起**（渲染成 1./1./2./3.，
   与目录和手工编号的末章都对不上号），`lvlText` 相同就并到一个 `numId`。

## 55. 标题版式三坑：分档字号要连样式一起改、正文缩进会渗进标题段、字体统一顺手压掉封面大标题

1. **§10.5 的"分档"落地后，分区字号闸门必须先把标题段排除**，否则章标题的 32（16pt）
   会被正文档判成偏离。排除判据用**生效大纲级别**（样式链合并后），不是段落自己写了什么。
   跨档递减只在"该文档实际存在的级别"之间判：只有 L1 的表单式报告不能因为没有 L2/L3 就报退化。
2. **标题段前面的"一长条空白"是正文缩进渗进来的**：模板把 `w:ind left="658"`（约 1.1cm）
   直接写在编号小标题上，Heading 1 样式又自带 `firstLine="289"`。处置是把标题段的
   `left/leftChars/right/rightChars/firstLine/firstLineChars/hanging/hangingChars` 全部显式压零，
   并把"标题段生效指纹的首行/左缩进必须为空"写进闸门。
   两个写法细节：`w:ind` 的值是**属性**不是子元素（写 `<w:left w:val="0"/>` Word 不认，
   改后 XML 看着写了、实际一段没变）；新增 `w:ind` 必须用 `pPr.get_or_add_ind()`，
   手工 `insert` 会把它放到 `w:spacing` 之前或 `w:rPr` 之后，违反 CT_PPr 元素顺序而被忽略。
3. **`unify_document_fonts` 会压掉封面大标题**。它的封面区边界按"封面信息表的位置"划，
   而"标题在上、信息表在下、中间隔着空段"的封面里标题落在边界之外 → 被判 zone=body，
   36 磅当场变 12 磅；XML diff 完全看不出来，只有并排看或逐份回读才发现（§10.2 护栏一）。
   项目侧处置：收口**前**读出封面大标题字号，字体统一**后**写回（含空 run 与段落标记 rPr），
   闸门再逐份比对版式基线文档的同一值。凡是"跳过封面区"的共享判据，都要拿一份
   "标题在表上方"的样张验一遍。
4. **标题里的空格要连 run 属性一起管，否则"同页两种观感"**。三个连在一起的坑：
   ① 编号与标题常被拆成 `'3.1' + ' ' + '系统应用范围'` 三个 run，共享的标题格式函数按
   "有无文字"过滤 run，那个纯空格 run 会保留正文的 12 磅 → 空格比同页 `'3.2 '`（空格在编号 run 里）窄一半；
   ② 直接给 `w:t.text` 赋值补空格时，python-docx **不会**自动补 `xml:space="preserve"`
   （只有 `run.text` 赋值才会），缺它的空格被渲染器吞成零宽；
   ③ 判"编号后有没有空格"必须按**整段拼接文本**判——只看第一个 run 会把 `'1.1'` 误判成
   "编号是 `1`"，补出 `'1 .1'`；正则前瞻里要排除 `.` 才不会被回溯；
   ④ 标了 `xml:space="preserve"` 也不一定有效果：那个空格 run 上还挂着模板遗留的**负字距**
   `w:spacing w:val="-96"`（配合 `w:w="99"` 用来收紧编号的字距），空格被压成零宽。
   处置：标题段的空白 run 一并摘掉 `w:spacing`/`w:w`，让它回到自然宽度。
   定位手法：`page.get_text('dict')` 看 span 的 bbox——若空格 span 与后一个 span 起点相同
   （x 重叠），就是"空格存在但零宽"，与"空格丢失"是两种成因。
   闸门配套：正文区标题段的空白 run 字号必须等于该级档位；全包"首尾带空白但未标
   `xml:space=preserve`"的 `w:t` 计数必须为 0。

## 56. 空白页还有三种形态，`pagination_audit` 的常规项查不到（§47 §39 的补充）

| 形态 | 为什么留下来了 | 处置 |
|---|---|---|
| **空段自己带 `pageBreakBefore`** | 模板里的硬分页符被转成段前分页后，属性留在了没有文字的段上（§47 只讲了硬分页符那种） | 把分页意图**迁给下一个有文字的段**；下一段本就换页（段前分页／段内分页符／自己带分节符）时直接摘掉 |
| **紧邻分页段的一个回车空段** | `chapter_pad_map` 按"连续 ≥2 段"才算缺陷（§42.4），正好漏掉单个空段；上一页写满时它被顶到新页，后面段前分页又把内容再推一页 → 中间整页只有它，墨占比 0.0% | 删掉紧邻分页段（段前分页或换页分节符）之前的空段；封面区与结构载体段不动 |
| **分节符与章标题之间隔着一个空段** | `drop_pbb_after_sect` 只看紧邻前一段，隔着空段就判不出来，"分节符 + 段前分页"照样叠出一张空白页 | 回溯时**跨过空段**找分节符载体段；且必须在顶页空段清理**之后**再判一次（§45.1） |

闸门配套三条：空段不得带段前分页、只有大标题分页（放行集合与生成器同源）、
目录条目页码 == 导出 PDF 的正文实测页。


## 57. 新判据入库后的第一件事是回扫自己上一轮的脚本，不是急着产新版

规则是别人（或上一轮的自己）写的，代码却是更早写的 —— 于是出现"库里明明禁止，项目脚本里还在犯"。
本轮入库 §43（元素做键）之后，同一条坑在自己写的收口脚本里被抓到两处：

| 犯规处 | 症状 | 修法 |
|---|---|---|
| 用 `id(p._p)` 记"表格内段落"集合，再判正文段落是否在其中 | 代理对象随循环回收、地址复用，**不属于表内的标题被误判成表内**，可收录标题数凭空少 2；连带把目录条目数上限算低，一次**正确的目录刷新被判越界并自动还原** | 集合里放**元素对象**（集合本身持引用，代理不回收） |
| 只在"转换失败才走兜底"的分支里 `sys.path.insert(工具目录)` | 转换全部成功的那一轮反而 import 不到共享原语，**墨占比判据静默退化成"无文字且无图"**，渲染报告"0 项不通过"其实是根本没查 | 共享原语路径放**模块导入期**，且判据不可用即失败（§58） |

做法：每轮开工先把本轮新增/修订的判据当"grep 关键词"扫一遍项目脚本
（`id(`、`exists(`、"元素存在即生效"、"只写不压零"、硬编码 0 级标题…），
再动手产新版；否则新版是"带着旧违规"产出来的，闸门还全绿。
同一条纪律的另一半是 §29.2：库里已有实现时，项目里那份要收成薄封装，别两套并存。

## 58. 校验判据"跑不起来"必须失败退出，不能退回弱判据还报通过

自动核对最常见的失效方式不是报红，而是**静默降级**：导入不到共享原语、缺依赖、
拿不到中间产物时，脚本 fallback 到一个更弱的判据继续跑，最后打印"全部通过"。
读的人把"通过"理解成"强判据查过了"，实际什么都没查（§57 第二行就是这条的活例）。

三条规矩：

1. 降级分支一律 `FAILS.append(...)` / 非零退出，**提示级不算通过**；
   文案里写清"已退化成什么判据"，别让"0 项不通过"含糊过去。
2. 报告里把**判据是否生效**本身当一项打印出来（如逐份打印墨占比区间、参照文档的 `votes/total`、
   识别出的章标题个数），空值/n-a 就是没跑。
3. 依赖路径、可执行文件位置在模块导入期就配好，不放在只在异常时才走到的分支里。

## 59. "补空段/补属性"要排在所有"删空段"动作之后；压样式继承要写零而不是删属性

两条时序/写法纪律，都是"改完看起来生效，下一动作又抹掉"：

1. **补出来的东西要被后面的清理动作放过**。封面标题与信息表之间的空段按配置补成 n 行（§52），
   但清理顶页空段、Word 刷新目录、`drop_chapter_pad`、`demote_empty` 都在"删空段"，
   先补后删等于没补（实测补完 3 行，收口后变 0 行）。正确顺序：
   `删空段/降级 → 再补空段 → 复核封面仍恰好一页`；刷新目录之后还要再补一次并复核。
2. **压掉样式链带来的值必须显式写零，删属性是反向操作**。段落自己不写 `w:ind` 时吃的是样式链的值
   （实测标题段生效首行缩进来自样式，段内根本没有 `w:ind`）；
   看到"段里有 ind 就删掉 ind"就以为清干净了，实际是把继承又放回来了
   （实测删完 `left` 之后生效值仍是 289 twip）。
   写法：`firstLine/firstLineChars/hanging/hangingChars/left/leftChars/right/rightChars`
   全部显式 `=0`（`right` 类不需要压时可留空，但**凡是被判"偏离"的那一项必须写**），
   并且**按生效值复算一遍**作为验收，不按"我删了没有"验收。

## 60. 用户要求"表格必须有边框"时，§51 规则 D 让位；但判定必须沿样式链，否则一半是误报

用户口径："表格需要有边框，我看有的表格没有边框。"这与 §51 规则 D（表级与样式都无框线＝
设计上无网格，**什么都不加**）直接冲突。**冲突时以用户要求为准**：把"是否必须带框线"变成
配置项（如 `tables.require_borders: true`），闸门从"只记提示"升级为"缺即阻断"。

三条实测纪律：

1. **生效框线 = 表级 `tblPr/tblBorders` ∪ 样式链（`tblStyle` → `basedOn` 逐级）的
   `w:style/w:tblPr/w:tblBorders`**。两个坑叠在一起最容易全判错：
   ① 只看表级 → `Table Grid` 这类把线画在样式里的表会被误判成"无框线"；
   ② 样式里的框线路径是 `w:style/w:tblPr/w:tblBorders`，**不是** `w:style/w:tblBorders`——
   找错一层，8 张正常表会被报成缺陷，实测据此白补了一轮线。
2. **补线要六向一起补齐**（`top/left/bottom/right/insideH/insideV`）。只补外框，
   两栏列表仍然没有行分隔线，用户看到的还是"没边框"。线型取族内既有表的取值
   （`single`、`sz=4`、`space=0`、`color=auto`），不要自己发明粗细。
3. **补完必须摘掉单元格级 `w:tcBorders/w:left val="nil"`**（§51 根因 C）。
   单元格上的 `nil` 优先级高于表级，留着它等于刚补的左边框又被抹掉；
   摘完若 `tcBorders` 变空元素要一并删掉，别留空壳。

配套：`normalize_table_geometry` 的 `borders` 动作按规则 D 只补"其他边有、唯独左边没有"，
在"必须全有边框"的项目里**不要**把它和自研的补线动作叠着跑（会互相抵消）——
本项目改为 `apply=('indent','float','grid')`，框线统一交给 `ensure_table_borders`。
`facts` 里写布尔项要显式判值（最小解析器把 `true` 读成字符串，`if cfg.get('x')` 对 `'false'` 同样为真）。

## 61. 模板用"连续回车"把图表顶到下一页：一片空白不在属性里，清完还要重分类薄页

症状：小节标题下面一大片空白，图被顶到下一页。根因不是任何分页属性，而是模板/承接稿里
**10~19 个纯回车空段**在占位（实测某份详细设计说明三处 10~13 段、某份需求说明书一处 19 段）。

四条纪律：

1. `chapter_pad_map` 只清"章级标题（lvl==0）前"的顶页空段，**图前、小节前的空块它管不到**；
   要另有一条通用判据：正文区（封面区之后）连续 ≥2 个"无文字、非结构载体、无图形"的空段。
   单个空段是正常段间距，保留（§42.4）。
2. **每删一处就重算一次**。删完第一块后所有段落序号整体前移，拿旧序号继续删会正好删到
   图片段或两表之间的隔离段——实测一次删掉 2 张配图，闸门"图数"当场归零才发现。
   同理适用于任何"按序号批量删段"的循环（§45.1 同一族问题）。
3. 清完空块后内容上移，原先的薄页可能变成**章尾页**：用户要求"只有大标题分页"，
   上一章的尾部页必然短，这是设计而不是 §41 要抓的"顶页/分页错位"。
   分类规则：中间页墨占比 <0.8% 且**下一页开头就是"第X章"级大标题** → 记提示；
   墨占比 0.0%（真空白页）仍阻断。判断窗口要按模板页眉实际行数放宽
   （页眉占 3~4 行时只看前 3 行会漏判，实测某份文档页眉把公司名断成两行）。
4. 这类改动会改页数，**必须重新同步目录页码**（§54 第 4 条），并重跑"图数/表格数不变"的
   内容闸门——结构段被误删时，版式闸门可能全绿而内容闸门才发现。

## 62. "编号后补空格"的正则要按**最长合法前缀**匹配，否则把"第三部分"切成"第三部 分"

症状：正文与目录出现"第三部 分 算法描述"这种断字——用户一眼指出"这个部分明显错误"。
根因：判章前缀的正则写成 `第[一二三四五六七八九十0-9]+[章部分篇]`。`[章部分篇]` 是**单字集合**，
"第三部分"里的"部"就满足了字符类，前缀被吃成"第三部"，前瞻发现后一个字符"分"不是空白，
于是在词中间插入空格。做"分类判定"时这种写法无害（匹配到"第三部"仍算大标题），
一旦用它**改写文本**就把词切开了。

三条纪律：

1. 中文章前缀里"部分"是**双字词**，必须整体进交替式：`第[…]+(?:部分|章|节|篇)`；
   单字集合只适用于"章/节/篇"这类单字单位。写完用一组用例自检：
   `第三部分算法描述` 应匹配到"第三部分"，`第三部分 算法描述` 应**不匹配**（已有空格不再动）。
2. 任何"补空格／补分隔符／大小写规整"这类**文本改写**动作，都要配一条反向检查进闸门。
   这类缺陷只在渲染后可见，结构类闸门（分页、字号、缩进、域）会全绿——
   本轮 301 项版式检查当时全部通过，错误是靠人眼发现的。这里补的检查是"正文中不得出现
   `第X部\s+分`"。
3. 改写要**幂等**：先跑"合回"的修复（`第X部 分` → `第X部分`），再跑补空格逻辑；
   否则稿子一旦被上一版污染，重跑也回不来。


## 63. 封面"居中偏上"别用 `w:vAlign`＋单独分节，两条硬伤实测踩过

`vAlign` 是**节**属性，要让封面单独居中就得让封面单独成节。两条路都不通：

1. **眉脚引用不能跨节重复**。克隆 body 级 `sectPr` 造新节时，只要新节带着与正文节相同的
   `headerReference`/`footerReference`，Word 直接判"**文件可能已经损坏**"（LibreOffice 也不出图）；
   换成新的 `r:id` 指向**同一个部件**照样判损坏。把引用**搬**到新节则改变正文节首页眉脚状态，
   还会让节数与模板不一致（dod 第 12/17 项一类问题）。
2. **节边界 ≠ 封面页**。实测同一批文档里 3 份的第一节本来就含前言或目录，
   给这一节设 `vAlign=center` 会把被拖进来的那一页一起竖排居中。

正确做法：封面标题之前放 n 个正文空段（纯流式，不动节、不动眉脚、不影响其它页），
并且**幂等**——先把已有前导空段清成基准再补到 n，否则每轮生成累加。
"偏上"的量按渲染墨区标定（本批落在版心 19%~20% 起），换模板或改字号必须重标：
空段行高与字号、行距、版心高度耦合。

配套纪律：位置是否达标由**渲染层按墨区量**（裁掉页眉页脚带后取封面块上下边界），
闸门只复核行数与"封面恰好一页"，不要用结构断言代替观感核对。
原语：`tools/docx_ops.py:set_cover_top_spacers(doc, n)`；`set_cover_block_valign()` 保留但
只适用于"封面本来就自成一节、且该节不含别的页"的模板，且 `raise_pt` 这类"当前值 + N"的写法**只能应用一次**。

## 64. 两个"静默失效"的写法坑：lxml 元素真值、配置解析器的键模式

1. **lxml 元素不能直接放进布尔上下文**。`<w:vAlign/>` 这种没有子元素的元素，
   `if el:` 判为 **False**（新版 lxml 会告警），于是 `a and b` 返回的是 `a` 而不是 `b`：
   实测闸门写 `sec0.find(qn('w:vAlign')) and sec0.find(qn('w:pgMar'))`，取到的是 vAlign 元素，
   再 `.get('w:bottom')` 得到 None，九份全报"封面 None"，看着像功能没做。
   一律写 `is not None`；同理 `el.get(qn('w:val'))` 判开关要按 §40 读 `w:val`。
2. **自写配置解析器的键模式太窄，会让配置静默不生效**。本项目 `facts.yaml` 的极简解析器
   行内字典键只允许 `[\w_]+`，于是 `{RD-057: 6, RD-068: 8}` 被切成垃圾键 →
   per-doc 覆盖一直没生效，而生成日志、闸门、渲染全是绿的（默认值恰好也在容差内）。
   两条纪律：①解析器要覆盖真实用到的字符集（文档代号带连字符是常态）；
   ②**per-doc/override 类配置必须有"生效证据"**——把它回读进闸门（本项目改成逐份复核实际行数），
   而不是只打印配置本身。与 §58"判据降级必须失败退出"是同一条纪律的两种表现。

## 65. 自动编号的"编号文字"字号藏在 `numbering.xml` 的 `lvl/rPr`，标题分档必须一起改

症状：标题按 §10.5 分档之后，同一行里"第三章"是 22 磅、"用户界面和体验"是 16 磅——
用户原话"前面的字号和后面的字号不统一"。

根因：Word 渲染 `lvlText="第%1章"` 这类**自动编号**时，字形属性取
`numbering.xml` 里 `abstractNum/lvl/rPr`（模板常留着 `sz=44`），段落 run 的 `rPr`、
`pPr/rPr`（段落标记）、`Heading N` 样式的 `rPr` 全都管不到它。
所以"改标题字号"的常规三处改完，编号仍是模板原字号；
`heading_format_profile_from()` 也量不到——它只看 run 的字号，于是闸门全绿、人眼一看就露。

处置与纪律：

1. 新增一步 `sync_heading_numbering_rpr`：先求出**各级标题实际用到的 `(numId, ilvl)`**
   （段内 `numPr` 优先，再沿 `base_style` 链），只改这些 `lvl` 的 `rPr`
   （`sz/szCs` 取该级档位、`rFonts` 随字体基线、`b` 与标题一致）；
   正文编号列表用到的 `numId` 一律不动。
2. **单独一条闸门复测**（`numbering_rpr_audit`：编号 lvl 的 `sz` 必须等于该级档位）。
   原则同 §58：结构类判据查不到的维度，就要为它专门加一条判据，不能指望"标题字号唯一"
   那条检查顺带覆盖。
3. 写 `rPr` 子元素必须按 `CT_ParaRPr` 的顺序插入（`rFonts → b → … → kern → position → sz → szCs → …`），
   直接 `append` 会把 `w:sz` 放到 `w:lang` 之后，Word 忽略（与 §55 的 `w:ind` 顺序坑同一类）。
4. 相关的两个编号属性顺手核对：`w:suff`（`tab`/`space`/`nothing`）决定编号与文字之间的间隔，
   模板混用时同一文档里会出现"1.标题"与"2. 标题"两种观感；
   `lvl/pPr/w:ind` 是编号段缩进，段落级 `w:ind` 会覆盖它（压零缩进时一并生效，§55）。

## 66. 标题"统一"要量到渲染层：编号的字形、间隔、字体三处，判据用逐字 bbox

§65 把编号字号对齐之后，用户仍会说"不统一"——因为一行标题里有**三个隐藏来源**在起作用：

1. **镜像 `lvl/rPr` 时把 `w:hint="eastAsia"` 一起抄了过来**。带 hint 的空格按东亚字体渲染，
   宋体的空格本来就是 0.5em（16pt 字号下 8pt），而西文编号后那个空格是 0.25em（4pt）。
   镜像时只保留 `rFonts(去 *Theme、去 hint) / sz / szCs / b`。
2. **`lvl` 带 `w:pStyle`，会再继承该样式的 `rPr`**。模板常把 `w:spacing`（字符加宽）、`w:kern`
   留在 `Heading 1` 样式里——只改 lvl 不改样式，编号仍会跟着整段被"拉宽"。
3. **中文编号后的 0.5em 空格不是缺陷**。`第%1章` 这类编号后 `suff=space` 的空格由东亚字体渲染，
   天然比 `1.` 后面的宽；按西文 0.25em 一刀切判，会把整批文档全报成缺陷（实测第一轮误报 6 条）。

所以"改属性→看 XML"到这一步已经不够，判据必须落在**渲染产物**上：
用 `page.get_text('rawdict')` 取逐字 bbox，对每个标题行查三件事——

- 行内汉字**字号唯一**（这一条才真正抓得住"第三章 22 磅 + 概述 16 磅"）；
- 行内汉字**宽度离散 ≤2%**（字符加宽 `w:spacing` 会破坏它）；
- 编号后**不得出现连续两个空格**，且空隙 ≤0.62×汉字宽（允许东亚字体的 0.5em 正常空格）。

推论：凡是"跨字体/跨语言"的度量阈值，都要按**该字符实际使用的字体**给档位，
不能拿一个 em 比例套所有情形；能一刀切的是"是否出现两个空格"这类离散判据。

## 67. 插入正文段不要克隆供体：这类段"正文链和标题链都不管"，几百项闸门可以全绿

批量插内容时最常见的写法是"找个样子像的段落深拷贝，再把文字换掉"。标题项这样做是对的
（要继承自动编号），**正文项这样做一定会出事**，而且分三种：

1. **供体按"模板里的某句原话"查找**。那句话随模板版本一变就失配，失配后如果代码有
   `donor = donor or anchor` 这类回退，锚点通常是**标题段** → 整块正文继承 `Heading N` 样式。
2. **供体改成"第一个正文样式的段"**。命中的往往是**封面大标题**（也叫 Normal，
   居中、36pt、行距 221）→ 版式照样错，只是错得不同。
3. **共享库里的 `insert_paragraphs_after`** 就是"克隆锚点 + 只摘 `numPr`"，
   锚点是标题时与第 1 种同病。它只适合"锚点本身就是正文段"的场合。

真正难发现的是**后果**：挂标题样式的正文段，两条处理链路都会放过它——

- 正文基线（字号／缩进／行距）按**样式**判"这是标题段"而跳过；
- 标题分档按**文字形态**判（长句、以句号结尾、无编号形态）而排除；
- 于是它带着 14pt 加粗、标题缩进、1.5 倍行距留在页面上，而"正文段版式==基线""各级标题字号唯一"
  这些闸门**一条都不会报**。

所以三件事要一起做：

- **新建而不是克隆**：`new_body_paragraph(text, style)` 只放正文样式 + 一个 run，
  版式交给正文基线统一写；`demote_paragraph_to_body()` 用于必须降段的场合。
  **降段必须改样式**，只改直接格式（字号、缩进）没用——上一轮就是被样式挡在链路外面的。
- **闸门加一条"文字正文·样式标题"检查**（dod 第 45d 项）：
  `body_paragraphs_with_heading_style(doc, cutoff, heading_shape=…)`，命中数必须为 0。
  "文字形态是不是标题"要由项目把自己的判据传进来（编号式、冒号式小节名等）；
  **不要拿 `para_ops.is_structural_paragraph` 的否定面当它**——那条还包含"居中短段、加粗短段、
  表 N 引导句"，反过来用会把一批正常正文段误报成缺陷。
- **新判据要做反向验证**：拿上一版（已知有缺陷的产物）跑一遍，必须命中；拿本版跑，必须 0 命中。
  只在本版上跑出 0 不能证明它会抓——它可能只是永远返回 0。

配套：正文段里重复上一级标题的文字（标题"适用范围"＋正文"适用范围：……"）是同一处代码
留下的第二种症状，读起来像模板没填。规则：**有标题的段落，正文不再重复标题字**；
但"禁忌证：……"这类**标签即内容**的开头要保留，它不是重复。

## 68. 闸门全绿不等于文档没错：四类"没人管"的维度与"生效值审计"的三个层次

一轮交付后用户回来说"我发现了很多问题"，而闸门 379 项全通过。复盘发现缺陷集中在四类**从来没有判据覆盖**的维度：

1. **正文段的字号**。正文基线指纹只比"首行缩进／行距／对齐／样式"，不含字号——
   于是挂着 16pt 的正文段可以带着"版式全对"的指纹交付。字号必须进指纹，或单列一条
   "正文段生效字号==基线"。
2. **标题段的 spacing（段前距/行距）**。模板继承下来常三种口径并存：显式写了 0、
   吃样式默认、段前 1.5 行。同族文档标题与上文之间就"忽紧忽松"，同一份内部也不一致。
   必须"每级标题 spacing 族内唯一且==配置"，且**按段落显式写**（只改样式会被直接格式盖住）。
3. **表头底纹**。单元格级 `w:shd` 有 无／`FFFFFF`／`auto`／灰 四种形态混用时，
   肉眼看就是"有的表头有灰底、有的没有"。统一时**必须连非表头行一起清**，否则旧灰底留在数据行。
4. **页眉页脚的裸文字**。模板残留的 `111` 这类字面量；注意**含页码域的段落不算残留**
   （python-docx 会把域的缓存结果读成 "1"/"11"，按文本判会一片误报）。

第 6 类是**正文页顶部空白**：换页边界之后残留的空段会垫在新页顶上，页面看就是"半页空白"，
但下半页是满的、墨占比不低，§41 的墨判据查不到。要单独量"页眉带以下、第一处正文内容以上"的距离
（封面页不参与，它本来就有定位留白）。清它要用**任意级别**的"标题自己换页 → 删它前面紧挨的纯空段"，
只按章级清（`drop_chapter_pad`）会漏掉节级/子节级换页的情形。

还有一类要单独记：**编号文字**（`第一章`、`1.1.`、`a)`）不是 run，字号字体藏在
`numbering.xml` 的 `abstractNum/lvl/rPr`。只改 run 与样式，标题行就会"编号 22pt＋文字 16pt"
两档并存（§65）。改它要连**列表编号**（`a)`、`(1)`）一起改，但 `lvlText` 里没有 `%` 占位的
是符号型（Wingdings 圆点），换字体会把符号变成别的字符，必须跳过。

**教训一：审计要落到"生效值"，而且要分三层查。**
run 显式属性 → 样式链（`pStyle → basedOn → docDefaults`）→ 渲染产物（PDF 逐字 span 的字体/字号/bbox）。
只在第一层扫会得到"零偏离"的假结论：非基线字体往往来自样式默认或 `lvl/rPr`，
而"编号比文字大 6pt"这种只有渲染层看得见。反过来也别把渲染层当唯一真相：
PDF 的字体名有编码差异、10.5pt 会报成 10.6、标题里的刻意空格会被"中文之间有空格"的规则误伤，
所以渲染层负责**发现问题**，docx 层负责**定性**，两层结论不一致时以 docx 为准并回查判据。

**教训二：上一轮"我报告过的问题"必须重新核对，不能当既有事实往下带。**
本轮自查中，上一轮口头报的两条其实是误报：一条"两份文档用词不一致"——实际两份都已被同一个
槽位改成同一句话；一条"列举最后一条没改句号"——实际最后一条就是句号，中间几条以分号收尾是正确的列举标点。
根因是拿**模板原文**或**截断后的片段**当正文下了结论。规则：写进交付记录的每条缺陷，
都要给出"文档内实际文本 + 段号"，而不是模板原文或记忆。

**教训三：新判据一律做反向验证。**
把上一版（已知有缺陷的产物）喂进去必须命中，本版必须 0 命中；只在本版上跑出 0 不证明它会抓——
它可能只是恒返回 0。§57 的"入库后回扫旧脚本"在这里同样成立：库里已有"编号字形要一起改"这条规则，
但项目脚本从未实现它，规则躺了三个版本，缺陷就交付了三个版本。

## 69. 三个"改完反而更糟"的坑：按索引批量删元素、点名替换的时序与幂等、图片清理的条件门

这一轮修的是"用户逐页看出的问题"，但改的过程中自己踩了三个新坑，都值得单独记：

**① 按索引批量删元素＝自我移位 bug。**
"把正文区超过 N 个的连续空段删掉"这类操作，如果写成
"审计返回若干 `(起始索引, 条数)`，再 `kids[start:start+count]` 切一刀"，
那么**删完第一处之后，后面每一处的索引都前移了**，第二刀会切到中间的正常段落上。
实测一次就删掉了某文档的整章内容与三张表（段落 215→116、表 6→3、节 3→2）。
规则：批量删除一律**先收集元素对象、再按身份删**（`el.getparent().remove(el)`），
绝不跨删除动作复用索引。这类事故能被抓到，靠的是"逐节页宽/页边距==模板"
"表数/节数==模板"这种**结构不变量**判据——它们看着与"删空段"毫不相干，却是唯一的兜底。

**② 点名替换有两类时序与幂等错误，都会静默。**
- **时序**：删"中文词内断字空格"的替换排在"合并被模板切断的长句"**之前**，
  而那个空格正是合并时从两段之间带进来的——第一遍整段文本还不是最终样子，替换不命中，
  也不报错。规则：任何"对最终文本做清洗"的步骤，必须排在所有会**改写/拼接文本**的步骤之后。
- **幂等**：清洗步骤在流水线里跑两遍（构建一遍、刷新目录后再一遍）时，
  验收判据不能是"这一轮我命中了几次"——第二遍必然 0 命中，会把正常状态报成故障。
  判据要写成"**坏写法是否还存在**"。同理，"未命中即报错"这类护栏只在**首次**执行时有意义。

**③ 图片清理不能挂在"本文档要插图"这个条件上。**
`if 本文档有 figures 要插: 清理旧图 → 插入新图` 这种写法，让"没有要插图的文档"
**从来不清理**——于是模板继承来的产品渲染图（图上画着数码管与蓝牙标志）
一路活到交付，而正文写的是"无剩余时间显示、不设无线通信接口"。
规则：**清理无条件跑，插入按配置跑**；并且闸门要有"图片白名单"——
文档里每个图片部件的哈希必须 ∈ 本项目图示集合，多出来的就是外来图。
配套还有一条"每张独立成段的图都要有图题"，但**文本框/图例里的图片不是配图**，
判据要先排除 `w:txbxContent` 里的图形，否则整批误报。

**④ 目录刷新护栏的"下界"要能解释减少。**
护栏原来写死 `条目数 ≥ 刷新前 - 1`，用来防 Word 吞条目。
但当这一轮把两处"加粗引导句"从标题里摘出来之后，条目**合理地减少了**，护栏把正确结果当成故障还原了。
规则：下界不该是"上一次的数"，而应是"**刷新后文档自己的可收录标题数**"；
旧的 ±界只当第二道保险。凡是"和上一版比"的护栏，都要问一句：这一版是不是**故意**和上一版不同。

**⑤ 副作用预告：收紧"加粗短段＝结构段"这条判据会连带影响目录与去重。**
引导句一旦不再算结构段，就会开始吃正文基线（缩进/行距/字号统一）、
也不再被目录收录，还会进入重复段判据的范围。改这种"多处共用的分类判据"之前，
先把下游用到它的环节列一遍（基线、标题树、目录、去重、闸门），改完逐项复验。

**⑥ 眉脚字体统一有两个必须踩到的死角。**
一是页码常装在页脚的**文本框**里（`mc:AlternateContent` → `w:txbxContent`），
只遍历 `section.footer.paragraphs` 走不进去；二是**域 run 没有 `w:t`**，
只有 `w:instrText`/`w:fldChar`，按"这个 run 有没有文字"过滤会把它跳过——
而 Word 刷新域时恰恰是照**这个 run 的 `rPr`** 重新生成结果文字，于是字号字体一起回潮。
判据：眉脚处理要遍历 `part._element.iter(w:txbxContent)`，且对"有文字 **或** 是域载体"的 run 都写格式。
另有一条通用的：字体残留要按**是否承载可见文字**分类统计——只含空白的 run 报出来全是噪声，
会把真正该修的那几处（本次是页脚页码）淹掉。

## 70. 把"留空"改成"实值"会引出三类新缺陷：命中自家禁用词、短语重复、括注被说两遍

申报文档里长期留空的格（因为当时没有受控依据）一旦拿到值，值会**同时进入多个落点**：
一句正文、一个表格行、族内多份文档。此时三类缺陷会一起出现，而且都不是版式类判据能发现的。

**① 填进去的文字命中自家的残留扫描词。**
禁用词表是为"上一项目残留清扫"建的，里面有些词与本项目正当表述同形：
某个工具链名、"移动端/APP"这类**在本项目里只允许以否定形式出现**的词。
最容易踩的是**标签行/表格值**——补值时顺手加一句否定说明（"……，无某某"），
就撞在禁用词上，构建期残留扫描直接报 ERR，且报在最不像会有问题的地方。
规则：
- 表格值**只写值本身**；"没有某某"这件事由正文里专门的一句表达一次即可，不在标签行重复；
- 申报口径改变时（换平台/换工具链），原先的"他项目残留值"可能变成本项目正当值，反之亦然。
  **必须成对更新**两处：残留扫描词表 + 台账里的禁用值列表；更新后复扫要求 0 命中，
  并把"为什么解禁/为什么新增禁用"写进版本说明，否则下一轮会以为是漏删。

**② 值里混了解释，组合成句时重复。**
台账把键值写成"某某（用途说明）"，模板槽位那句又写了用途（"程序下载烧录用 …"），
拼出"程序下载烧录用 某某 下载烧录工具"这种句子。
规则：**台账存原子值，括注/用途另起一键**（`x` 与 `x_note`），组合方式留给表述层（生成配置）决定；
新增或改写句子后，对**句内短语重复**做一次自查（同一 4 字以上短语在同一句出现两次即复核）。

**③ 同一个"带括注的组合值"被正文与表格各引用一次。**
表格里需要"值（说明）"，正文句里也直接引用了这个组合值，于是正文读起来像
"说明，说明"。规则：**正文句引用不带括注的原子值，括注只留在表格那一格**；
需要更完整表述时，正文另写一句，不要复用表格那个组合形态。

**三条通用的收尾动作**（补值轮必做）：
1. 值落点后按"出现位置清单"逐处核对写法是否一致（同一型号/容量在正文、表格、族内多份必须一字不差），
   并统计出现次数——**漏掉一处**通常表现为"某份文档还在说泛指"；
2. 补值会让句子变长，**页数与目录页码可能变**：必须重跑目录刷新与逐页渲染，不能只看闸门；
3. 交付前把这一轮"仍未填的格"与"填了但未核对的值"分开记：
   口头指定的元器件参数要注明是**公开资料标称值**并保留"与实物物料核对"的待办，
   不要在待办里把它写成"已闭环"——申报口径已定 ≠ 与实物一致，这是两件事（与 §68 同一纪律）。

## 71. 注册人要求"结果列填结论"时：把纪律判据改成白名单，而不是关掉判据

场景：报告类文档（验证报告／确认报告／可用性记录表）的"结果""是否通过"列原本按证据纪律留白，
注册人书面指示"结果要写符合要求"。这是**申报口径的决定**，不该由工具自行推断，也不该拒绝执行；
但**不能因此把"不得预填结论"这条判据整条删掉**——删掉之后，任何位置出现"通过／合格／是／符合要求"
都没人管了，下一轮真正的预填缺陷会一起漏过去。

四条做法：

1. **判据不关，改成"文档＋列名"白名单**：只放行声明过的那几列；同一张表里的签名、日期、结论格，
   以及未声明的其他文档，继续按原规则阻断。列号要从**表头文字**解析（表头行未必是第 0 行，
   允许在前两行里找），不要写死列索引——列序一变就会悄悄放行错误的列。
2. **补一条反向判据：豁免列必须真的填齐**。只放宽"允许填"而不检查"填没填"，会产出新缺陷：
   授权填 25 格、实际填了 21 格，漏的多半是跨页的续表和最后的汇总表。
   判据写法：`该文档声明的列里，数据行非空的格数 > 0 且未授权位置 0 命中`。
3. **用受控实验证明判据还在咬**：把白名单临时清空重跑闸门，必须立刻命中全部已填格；
   恢复名单后 0 命中。**没有这一步，"豁免生效"和"判据失效"两种状态长得一模一样**（与 §68 的
   新判据反向验证是同一条纪律，只是方向相反：这次要验证的是"放宽的那条仍能收紧"）。
4. **留痕与前置条件一律不动**：台账记 `src=注册人指示＋日期`；正文里"结果以受控原始记录为准、
   原始记录齐备并经审核后本文件方可转受控发布"这类句子必须保留；**文档状态不得因为填了结果就升级**。
   同族其他报告不自动跟着填——要么一起拿到授权，要么保持留白；最忌"一份填了、另一份全空"，
   那比全部留白更像数据完整性问题，评审会直接问"为什么两份报告的证据状态不一致"。

## 72. 多源对账表里的每个 ✅ 都必须能被脚本反查到命中，否则那是断言不是证据

**踩过的现场**：对账表把"应用部分／防电击类型"标成"✅ 两方一致"，位置写的是"文档 A 2.3、文档 B 6.1"。
实际去查才发现：那两处只写了应用部分（BF 型），**防电击类型整族一次都没出现**——
✅ 标的是"这个位置本该覆盖它"，不是"这里真的写了它"。

**根因**：对账表是人工填的，填表人按"章节职责"推断覆盖关系；而"值有没有真的落到文档里"这一步没做。
同类误标在长文档族里几乎必然发生：共用句改了、某份文档没同步；参数换了单位写法（`2mm，误差 ±20%` vs `2mm±20%`）
导致字面不匹配，人被"意思一样"说服。

**做法（双向都要跑，缺一不可）**：

1. **正向：源→文档**。把权威来源（说明书／技术要求／图纸）的关键值列成清单，逐条在全部产物的
   正文＋表格＋页眉页脚里做**归一化字面反查**（去空格、统一 `～/~`、`±`、全半角），报告三态：
   `两边都有` / `源有文档无`（漏项或有意不写，必须逐条判定并记理由）/ `文档有源无`（要么补出处，要么删）。
2. **反向：文档→源**。用正则抓产物里所有"数字＋单位"的形态（nm/mW/VA/kPa/Hz/℃/%/mm/分钟/小时/KB…），
   逐个回来源找出处。**这一步才是"有没有编数据"的真正防线**——正向清单永远只覆盖你想到的项。
3. **对账表的 ✅ 由脚本生成**：每行存 `值 → 应命中的文档列表 → 实测命中次数`，
   命中数 < 应命中数就自动降级成 ⚠️ 并进待办。人工只负责判"源有文档无"是漏项还是有意不写。
4. **有意不写也要占一行**（如可靠性指标 MTBF 属硬件属性不写进软件文档、保养周期属说明书事项），
   标成"✅ 未误用"并写理由；否则下一轮对账会把它当漏项补进去，反而引入新错误。
5. **来源不是权威文件也要显式登记**：模板自带的方法学指标（如可用性问卷"合格标准 100%"）、
   注册人口头/书面指定的值（元器件型号与容量）、按指示预填的结论列——
   这三类在反向扫描里都会报"来源无出处"，必须在表里写明真实出处与状态（"待与实物核对"），
   不能留成"无出处"，也不能因为"注册人说了"就升级成"已闭环"。

**一句话判据**：对账表若不能整表重跑，它就只是一份好看的声明；能重跑的 ✅ 才算证据。

## 73. 模板里的"架构图"可能不是图：VML 形状 + 正文段用缩进硬排版

公司模板的体系架构图常见这种实现：`w:pict` + 若干 `v:shape` 只画框和箭头，**框内文字是普通正文段落**，
靠 `leftChars`/`firstLine`/制表符/成串全角空格对位，行距压成 `lineRule=exact` 的小值才排得进框高。

三条后果：

1. **残留扫描要扫正文段**，只扫 `word/media/` 与 `w:txbxContent` 会一条不漏地判成"零残留"（实测 RD-028：形状内文字 0 处，
   旧项目模块名 13 段全在正文里）。判"模板能不能入库"时同理。
2. **动不得**：改字号、改行距、改缩进、按"顶页空段"判据清图区空段，都会把文字挪出框。图区段落要显式排除在版式统一与
   空段清理之外，排除判据与生成器共用同一个。
3. **换项目不能"替换图片"**：没有图片部件可换。要么整块删掉图元与文字段后重绘，要么插入一张 media 图并删掉原 VML，
   两条路都要重渲染逐页核对文字是否仍在框内。

## 74. 数图片不能只数 `inline_shapes`：VML 图不计入，WPS 稿会判成"零图"

同一份带 7 张配图的 `.doc`，两条转换通道存图的方式不同：

| 通道 | 图形标记 | 媒体件 | `python-docx` 的 `len(doc.inline_shapes)` |
|---|---|---|---|
| LibreOffice | `w:drawing` 7 | `image1–5.png` | **7** |
| WPS | `w:pict` + `v:imagedata` 7 | `image1–7.png` | **0** |

`inline_shapes` 只认 DrawingML 的 `<w:drawing>`，**VML 老式图形一律不数**。于是按它写闸门会出现两类事故：

- 图片白名单判成"本文档无图"，瘦身/清理逻辑把 VML 图当孤立件删掉（与 §69 的"只扫正文段落"叠加必炸）；
- 反过来，"图张数 = 期望值"的交付判据在 WPS 稿上恒为 0，看着通过其实没测。

**判据写法**：图数 = `word/media/` 部件数 **与** `w:drawing` + `v:imagedata` 引用数**双口径取大**，两者不等就报出来说明有悬空引用或漏登记；
需要区分形态时分别记 `drawing` 与 `pict` 两个计数，别合并成一个"图片数"。

## 75. 校验器必须读交付物本身，不能读过程副本

闸门脚本里写 `tmp/…_wps.docx` 这类**过程件路径**，跑起来全绿，但绿的是副本：库里那份基线件（或交付稿）
哪怕已经换版、被改坏，判据也不会报。实测一次：把校验器的输入从暂存副本改成库内基线件，
立刻暴露"段落数 280 ≠ 279"的真实不一致——此前几轮的"全绿"是假绿。

三条纪律：

1. 判据脚本的文件参数**只允许指向交付物路径**（模板基线件、版本目录里的产物），过程件（探针、转换稿、crop）不进判据。
2. 交付物换版后，**先重跑全部判据再改档案数字**；顺序反了就会把新事实写成旧数字。
3. 每份交付物都要有"哈希核对"这一条：脚本内计算的哈希 == 档案登记的哈希，不一致直接失败；
   只登记不核对的哈希等于没有。

## 76. 公司模板自带的表格普遍略超版心，判据要按"所在节 + tblInd"算并先存底

九份模板实测：026/028/029 的表不越界，其余六份都有表格宽度合计超过所在节版心：
RD-030 最多 +1.9cm、RD-052 +2.4cm、RD-032 +0.9cm、RD-057 有 11 张 +0.1~0.4cm、RD-068/069 三张各 +0.4cm。
三条纪律：

1. **越界量 = `tblInd` + 列宽合计 −（该节页宽 − 左右边距）**。`tblInd` 可为负（模板用它把表往左拉回版心），
   只加列宽会把"已经补偿过的表"误判成越界；表归属哪一节要按文档顺序数 `sectPr` 定，横版节版心另算。
2. **先给基线件存底**：把模板自身的越界清单当作已知状态。交付稿只对"新增越界"报错，
   否则闸门会把模板原样判成缺陷，或反过来"顺手缩表"改坏了版式（缩表要注册人点头，且改后重渲染核账）。
3. `tblLayout=fixed` 的越界是真越界；`autofit` 的表 Word 会按内容/边界自动收，
   列宽合计超版心只是**风险信号**，报告里要分开列，不要混成一个"越界 N 张"。

## 77. 墨占比判据要按页型分级；LibreOffice 还会静默转不出某些 docx

渲染审计九份模板时的两条实测：

1. **低墨页不等于空白页**：封面页、目录页、章节起始页天然低墨（RD-068 的目录页 0.59%、RD-030 的图前页 0.30%）。
   用统一的"中间页 <0.8% 阻断"会把模板自己拦下。判据要先分页型：
   `p1=封面`、`含 toc 样式段的页=目录页`、`含图形/表格部件的页=图页` 这三类只报提示，不阻断；
   正文页才用阈值阻断。豁免判据与生成器共用同一个函数。
2. **LibreOffice 对某些 Word 生成的 docx 会静默失败**（RD-068/RD-069 重试三次仍不产出 PDF，返回码却不报错）。
   渲染核对不能只挂一条通道：拿不到 PDF 就**失败退出并换通道**（WPS `ExportAsFixedFormat`），
   不许"跳过渲染继续报通过"（§58 同源纪律）。

## 78. 模板里的"表单"可能是浮动文本框；表格单元格还有四个隐形约束

RD-029 2.1 的第九章实测（2026-10-24，交付稿被注册人当场指出"这个表有问题"）：

1. **"软件异常报告表"不是表格，是 1 个 `w:txbxContent` + 3 个 `v:shape`**：绝对定位，随上下文字数/行高变化不会重排，
   收口后会压在正文上、字段互相叠印。交付前必须改成正文流表格（字段名照抄，只改产品无关的字段），
   改完把文本框从段落里摘掉（只删 `w:pict`/`w:drawing`，别用会清 run 文字的清理函数）。
2. **单元格缩进要把值写成 0，不是"删掉 `w:ind`"**：模板单元格常带 `w:ind left="2946" right="2926"`，
   删掉后缩进回落到 `pStyle` 的首行 480，照样把「01」挤成竖条；必须显式写
   `left/right/firstLine/hanging=0`，并去掉 `pStyle`（样式 5/6 还带字间距，会把「单元测试」拆两行）。
3. **`tblW` 与 `tblGrid` 合计必须一致**：052 表 9 的 `tblW=11482`（20cm）而网格只有 14cm，设完列宽表仍冲出右边界；
   固定列宽时要同步改 `tblW` 并置 `tblLayout=fixed`。
4. **合并格要用 `w:tc` 位置写**：首列常是 vMerge，`row.cells` 会把合并格展开重复，整行错位
   （030 功能表写成过「04｜输出方式｜长按主机开关键」）；写入前摘掉目标行 vMerge。
5. **别用 keepNext 让表格"不跨页"**：给单元格段落加 keepNext，COM 复核会判成
   「非标题段带KeepWithNext」（052 实测 2 处）；把行高压紧（去 `trHeight`）比 keepNext 更稳。
