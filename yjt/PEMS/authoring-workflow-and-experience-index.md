# 模板化文档族编写流程与经验索引（AI 工具无关的开工手册）

> 适用：任何由 AI 或人执行的「按公司既定模板批量产出/迭代 Word 文档族」任务（注册资料、技术要求、说明书、验证/确认记录等）。
> 来源：2026-11-09 由多项目交付复盘整理；本文件只做**流程编排与经验索引**，判据细则在各专题文件与 `pitfalls.md` 里
> （为什么要单独有一份编排文件，见 `pitfalls.md` §84）。

## 0. 为什么别的 AI 会写坏

同一套模板，出错几乎都落在这十类，本文件的每个阶段都对着它们设了卡点：

1. 把上一个项目/上一版产品的口径当事实照抄（型号、主体、参数、结论、人员名单）。
2. 拿推断值或常识补空白（元器件型号、阈值、日期、测试结果），事后无人能追溯。
3. 只跑闸门不看渲染；闸门全绿≠文档没错（`pitfalls.md` §68）。
4. 新写或移植的判据没做反向测试，判据其实一直在静默放行。
5. 按段落索引批量删元素、按格序往表格里写值，静默吃别的内容与标签（§69、§82）。
6. 按文字找锚点先命中目录条目；改静态目录页码改了整段（§79、§33）。
7. 版式收口排在 Word 刷新目录之前，或收口后不重算交付清单哈希（§36）。
8. 把过程话术（待确认/自动生成/占位/内部注释）写进正文（`one-pass-quality-gate.md` §5）。
9. 上下文被压缩或续接后，直接引用记忆里的旧数字、旧文件状态汇报。
10. 改完就报"已完成"，没有可复现命令与实测输出。

2. 换一个 AI 或新会话接手，先读本文件与项目侧的阶段状态文件，再干活；不靠会话记忆里的结论。

## 2. 十条铁律（违反即返工，不分项目）

1. **事实只进主事实文件**（`facts.yaml` / `facts.json` / 受控 `config.json` 三选一），脚本、正文、经验库不得另写一套。
2. **格式靠继承**：以基线 `.docx` 就地替换，禁止从零拼文档。
3. **模板只读，输出去新版本目录**，永不覆盖模板、源文档与历史版本。
4. **模板版号是独立一条轴**：新旧版建档与判据互不通用（`iteration-and-versioning.md` §7）。
5. **无证据不填实值**：签署人、测试人员、测试结果、日期、结论，未经注册人/受控记录不得代填。
6. **不编数据**：来源缺失就留白并进待办，不从相近项目、案例或常识推断。
7. **判据必须能失败**：跑不起来、缺依赖、拿不到中间产物一律非零退出，不许降级为弱判据后报通过（§58）。
8. **新判据必做反向测试**：投一个已知坏样本必须命中，旧样本本版必须 0 命中。
9. **修改走同源原语**（`tools/docx_ops.py`、`tools/para_ops.py`），项目里不写第二套分页/字体/表格修复。
10. **汇报只讲可复现证据**：命令 + 实测数字 + 产物路径，没跑过的数字不写。

## 3. 阶段流水线

### S0 立项与资料冻结
- 动作：收齐受控说明书、技术要求、代码/BOM/图纸、历史版本、模板与版号；列明缺什么。
- 完成判据：资料清单与来源标注齐全；缺项已写进项目待办而不是"等下补"。
- 该读：`one-pass-quality-gate.md` §0~§1、`generality-boundaries-and-precedence.md` §一~§三。
- 停手条件：只有口头描述、没有受控来源的关键字段 → 先问，不生成正式结论。

### S1 事实基线台账
- 动作：逐字段写「值 / 来源 / 状态 / 确认日期 / 责任人」；冲突不合并，只登记。
- 完成判据：主事实文件通过 Schema 校验；每个正文出现的数字都能反查到一个来源键。
- 该读：`consistency-gate.md`、`pitfalls.md` §72（对账表每个 ✅ 可脚本反查）、§70（留空改实值引出的三类缺陷）。
- 停手条件：同一字段出现两个来源且都不是"受控变更" → 报冲突等裁决，不自选其一。

### S2 模板基线与版号
- 动作：确认每份文档用哪个版号；核对基线件哈希与档案；登记"模板自带的已知缺陷清单"。
- 完成判据：版号总表逐份有值；模板缺陷分成「生成时修 / 原样保留 / 需注册人裁决」三类。
- 该读：`template-baselines.md`、`template-format-audit-2026-10.md`、`templates/<版号>/<件名>_基线.md`、`iteration-and-versioning.md` §7。
- 停手条件：新版模板相对旧版增删章节，而要求是"照旧骨架补回来" → 停，先说明差异。

### S3 结构核查（先结构后内容）
- 动作：比对标题序列、目录形态、分节、表格骨架、图示位置与基线件是否一致。
- 完成判据：标题文字序列与基线一致；各节页宽/方向 ⊆ 基线；目录域 begin/separate/end 配平。
- 该读：`cover-pagination-and-sections.md`、`docx-fields-and-toc-repair.md` §5/§9、`pitfalls.md` §79、§53、§65。
- 停手条件：结构差异需要删章节或补章节 → 属于版号问题，回 S2 裁决。

### S4 槽位清单与生成器
- 动作：给每个可替换点登记锚点原句、来源键、允许长度、适用文档；写"命中即校验"的替换函数。
- 完成判据：未命中槽位数为 0 且槽位命中数等于配置项数；同标签多点位取值一致；槽位消费按段落元素身份记录。
- 该读：`template-inheritance-in-place-replace.md`、`one-pass-quality-gate.md` §4、`pitfalls.md` §31、§32、§82。
- 停手条件：锚点原句在模板里找不到（版号对不上或模板被改） → 停，不猜序号。

### S5 配图
- 动作：按章节需要画图（架构/流程/拓扑/硬件关系），图内文字字体与正文一致，走机器自检。
- 完成判据：文本宽度预警为空；图有哈希与宽高比校验；文档内嵌图哈希与本项目图一致；必备图示不缺项。
- 该读：`diagram-generation-and-figure-insertion.md`、`reference-document-format-and-diagram-requirements.md`、`pitfalls.md` §73、§74、§69（图片清理条件别挂在"要插图"上）。
- 停手条件：图内文字机器读不到，需目检 → 交人工，不自行宣布"图正确"。

### S6 生成
- 动作：只跑生成器，产物落新版本目录；`.doc` 转换/PDF/PNG/临时件一律进工作临时目录。
- 完成判据：生成日志打印每条槽位命中段号；ERRORS 为空；残留词全包扫描（document + 眉脚 + 文本框）0 命中；
  输出目录按 `<族名>_V<版本号>` 命名且与 `manifest.json` 里的版本号一致。
- 该读：`one-pass-quality-gate.md` §4、`tools/build_docs.py`、`pitfalls.md` §35、§50、§64、§78。
- 停手条件：目标目录已存在且非本轮重建 → 生成器必须拒写；需要覆盖时先取得明确授权。

### S7 收口（版式 / 分页 / 目录）
- 动作：Word 刷新目录 → 版式收口 → 二次刷新 → 二次收口 → 导出 PDF → 按实测页同步目录页码 → 再导出。
  这条顺序要先按本项目实测确认（哪几份有目录域、哪几份是静态目录），不照抄别项目脚本（`pitfalls.md` §83）。
- 完成判据：分页七项全清；字体分区且正文小标题不挂标题样式；编号字形统一；封面独立成页且无空白页；
  目录页码与渲染实测一致，且页码同步只跑一遍。
- 该读：`font-and-style-normalization.md` §6~§10、`cover-pagination-and-sections.md` §8、`pitfalls.md` §36、§38~§42、§45~§49、§54~§59、§66、§83。
- 停手条件：压页需要偏离正文基线的行距/缩进 → 不压，记为提示项交人工（§37）。

### S8 自动闸门与对账
- 动作：内容闸门、版式闸门、对象模型审计、渲染墨占比分级、跨文档一致性对账，逐份产物跑。
- 完成判据：三类报告齐且退出码为 0；对账表每行存「值 → 应命中文档 → 实测次数」，并跑反向"产物数字 → 来源"。
- 该读：`dod-checklist.md` A~H 组、`consistency-gate.md` §5、`one-pass-quality-gate.md` §6、`pitfalls.md` §68、§71、§72、§75、§83。
- 停手条件：任一判据被降级、跳过或改成"只打印提醒" → 本次不得报通过。

### S9 反向测试与人工复核
- 动作：复制产物做注入实验（旧项目词、代填结果列、自加措辞、密码/敏感串），确认逐项命中；再逐页目检渲染。
- 完成判据：注入样本全部命中且退出码非 0，测试副本已删除；人工复核清单逐条有结论。
- 该读：`dod-checklist.md`、`one-pass-quality-gate.md` §7、`pitfalls.md` §83。
- 停手条件：图内文字、观感、签署状态只能人判 → 明确写"待人核"，并给出可自跑的验证入口。

### S10 三方收口与归档
- 动作：说明书 / 代码 / 注意事项逐参数对账，冲突分级为「一致 / 不一致 / 单方独有 / 已定口径」；重算交付清单哈希；写版本说明与待办。
- 完成判据：产物—清单—检查报告三者同代；每条"有意不写"有行有理由；不一致项都有裁决人记录。
- 该读：`consistency-gate.md` §5、`iteration-and-versioning.md`、`pitfalls.md` §72。
- 停手条件：存在未清零的实质冲突（同一参数两个真值） → 不得标记为可提交版本。

## 4. 交付物最小集

新版本目录里必须有：全部产物文档、`manifest.json`（配置/事实/模板/产物/图/报告哈希）、生成记录（本轮改了什么、为什么、检查结果）、
闸门报告（内容 + 版式 + 对象模型 + 渲染）、三方对账表、待办与裁决清单。缺任一项不算交付完成。

### 4.1 生成记录骨架

```
# 生成记录 <版本号>（<本轮主题>）
生成日期 / 输出目录 / 本轮退出码
依据：<受控说明书与日期>、<代码或受控记录>、<模板版号>
本轮触发：<用户新指示或发现的缺陷>
一、口径变更：字段 | 旧值 | 新值 | 来源 | 状态（受控/推断/待裁决）
二、残留与模板处理：改了哪几处模板原文，为什么
三、检查结果：build / 收口 / 三类闸门 / 渲染 / 反向测试，逐行给命令与实测数字
四、留白与待办：无证据未填的字段清单
五、需注册人裁决：逐条列冲突与两个候选值
```

### 4.2 三方对账表骨架（说明书 / 代码 / 历史受控文档）

```
字段 | 说明书值 | 代码值 | 老文档值 | 采用值 | 依据来源 | 分级 | 落点文档与段号
分级 = 一致 / 不一致 / 单方独有 / 已定口径
```

1. 三个来源都有值且不同 → 必须写清采用哪一个、谁在何日裁定，正文不得同时出现两个值。
2. 只有代码有（保护、互锁、超时、存储位置一类） → 归"单方独有"，评估是否补进受控文档，不直接抄进正文。
3. 三处都无值 → 留白并进待办；禁止用常识补数。
4. 上一项目/上一版文档有值，本轮两个受控来源都没有 → 按"沿用受控历史值"处理，并在记录里标出这是沿用而非新证据。
5. 表里每个"采用值"都要能被脚本反查到落点文档；反查不过的行降级为 ⚠️，不得留 ✅。

## 5. 续接与会话纪律（防"记忆当事实"）

1. 续接会话动手前先取现场真值：`date`、工作目录文件清单与修改时间、事实文件内容、上一轮报告结论。
2. 汇报里引用的数字必须是本轮实测；压缩前的结论要重新跑一遍才能复述。
3. 同一句要求被用户重复第二次 → 当"理解错了"处理，停下来问清期望行为，不再改代码试探。
4. 用户可能手工改过送审稿；覆盖前先看归属与差异，必要时先备份再重放。
5. **阶段状态落盘**：在项目工作目录记一行「当前阶段 S 几 + 各阶段判据实测值 + 未决项」；换人或换工具接手时按这行接手。

## 6. 给任意 AI 的开工提示词五元组

缺项先补问，不要边做边猜。模板可直接复制：

```
目标：产出 <文档族> 的第 <N> 版，目录 <输出目录>，不覆盖历史。
口径：事实只取 <主事实文件>；模板版号 <各份文档版号>；未确认的字段留白并进待办。
验收：S3 结构判据、S4 槽位命中数、S6 残留 0、S7 分页七项、S8 三报告退出码 0、S9 反向测试命中、S10 三方冲突清零。
约束：模板与源文档只读；无证据不填实值；不编数据；公共处理只调用 <工具库原语>；不许降级判据。
验证归档：每条判据附可复现命令与实测输出；写生成记录 + manifest；未决项列成裁决清单交回。
```

## 8. 机器环境占位符（B 类路径必须先问用户）

以下每台电脑不同，库里只写做法不写真值，禁止照抄或扫盘猜：

- 模板与基线件根目录、经验库根目录；
- PC 仿真/渲染通道（LibreOffice 可执行文件与独立用户配置目录、Word 版本与通道）；
- Python 环境与依赖来源；
- 配图字体在系统里的实际文件名。

命中占位符时先向用户取真值，写入项目侧配置，不回填经验正文。

## 9. 一票否决清单
