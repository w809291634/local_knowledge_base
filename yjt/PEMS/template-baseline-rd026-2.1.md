# 公司模板 2.1 版式基线：RD-026 软件确认计划

> 本档案只描述 **2.1**。2.0 的版式与判据在 `template-baseline-rd026-2.0.md`。
> 两套判据不得互用：生成前先定 `template_version`，只读本版基线件与本版判据。

## 0. 用途与边界

本文件登记 2.1 版模板的版式身份与生成口径。2.0 基线保持不动，两版并存，按项目指定版本选用。

基线件：`templates/2.1/RD-026_软件确认计划_2.1_基线.docx`。它只用于版式参考，不是任何项目的事实来源。
项目化档案仍按 `reference-format-profile-template.md` 填写，并保存在项目工作目录，不写入本经验库。

## 2. 版式基线（逐项可反查）

- 页眉：`QR/RD/026   2.1`，"2.1" 前 3 个空格；两节同文；页眉内无域。
- 页脚：`footer1` 含 `PAGE` 与 `NUMPAGES`（渲染为"1 / 2"）；`footer2` 只含 `PAGE`。
- 封面：p0–p8 空段顶页 → p9 大标题「软件确认计划」宋体 36pt 加粗居中，`outlineLvl=0`，**无 `numPr`** → p10–p22 空段 → 封面表。
- 封面表 T0：5 行 4 列，列宽 2096/2003/2003/2005 twips。第 0 行「文件编号」值跨后三列合并；第 1 行「项目名称｜值｜项目编号｜值」；第 2–4 行「编制/审核/批准｜值｜日期｜值」。全部值单元格基线为空。
- 正文：p24「标准要求：」用样式 `一级条标题`，宋体 14pt 加粗；p25–p27 是计划四要素；p28–p34 是正文范例段。
- 正文基线：宋体 12pt；首行缩进显式写 `firstLineChars=200`（3 段）或 `firstLine=420`（1 段）。
- **模板自身行距不统一**：非空正文段的 `w:line` 有 360/362/390/402 四种取值（均 `lineRule=auto`，约 1.5 倍）。
  这与"正文全量套用统一基线"的通则冲突。口径：**注册人要求"完全按模板"时，保留模板原取值，不做统一改写**；
  要统一必须先经注册人确认，并在版本说明里写明改了几段。
- 确认小组表 T1：6 行 3 列，列宽 2141/2141/3926，表头行灰底。角色 5 行固定为确认组组长、临床专家、临床医生、软件测试、市场专员，「确认人员」列基线为空。

## 4. 红色编写指引的处理口径

2.1 原件用红字标注注册人的编写要求：`标准要求：`、四要素（1、2、3、4）、"另，所有验证活动的结果应被文档化"、
以及括号内"PEMS 确认的责任小组应是独立于设计小组，不应包含设计小组成员"。

交付稿一律把红字转成黑色正文。文字不改、不删、不另起样式，只改 `w:color`。

反查判据：全包 `w:color w:val="FF0000"` 计数为 0，段落标记的 `w:pPr/w:rPr/w:color` 也在扫描范围内。

## 5. 模板获取通道（`.doc` 原件 Word 打不开）

- Word 15 对 2.1 的 `.doc` 直接拒开，`OpenAndRepair` 同样失败。WPS 12（`KWPS.Application`）能正常打开并另存 docx。
- 主通道固定为 WPS 转出 docx，LibreOffice 只作交叉核对。两者渲染逐页一致，但 XML 不等价：
  LibreOffice 会给封面大标题多挂一个 `numPr`、把 `w:jc` 写成 `start`、丢掉 `.doc` 的左缩进（540/120 twips）。
- 转出稿必须再用 Word 只读打开确认页数与无损坏提示，才算模板可用。

## 6. 生成与验收

- 只填三处：封面表的「文件编号」「项目名称」「项目编号」。编制、审核、批准、日期与「确认人员」列没有受控原始记录就留空。
- 文件编号按 `{document_id}-{project.number}-001` 生成；页眉版号取模板原值 `2.1`，不跟项目走。
- 闸门判据（全部可脚本反查）：段落 36、表格 `[[5,4],[6,3]]`、分节 2、页眉文本等于基线值、`footer1` 域含 `PAGE` 与 `NUMPAGES`、
  `FF0000` 计数 0、渲染 2 页、封面页墨占比约 1.5%、正文页墨占比 6%–8%（红转黑后正文页墨占比上升属预期）。
- 输出写新版本目录，基线件只读；每次交付保留模板哈希与渲染证据。
