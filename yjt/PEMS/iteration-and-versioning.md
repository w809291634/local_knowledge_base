# 迭代与版本管理：让「反复改」不失控（通用）

> 适用：会经过「评审 → 修改 → 再审 → 再改」多轮的文档族。

## 结论先行

把工作分成两层：**数据层（唯一可改）** 与 **产物层（可丢弃重生成）**。

```
project/
  config.json            # ★ 唯一数据源：型号、功能、指标、编号、厂商、文件清单
  tools/docx_ops.py      # 通用原语库（跨文档、跨项目复用；不含项目数据）
  tools/build_docs.py    # 通用生成入口：读 config + 模板 → 出产物
  tools/consistency_check.py
  templates/             # 参考文档（只读）
  out_V1/  out_V2/       # 产物（可删可重生成）
```

**迭代流程**：改 `config.json` → 重跑 `build_docs.py` → 跑一致性校验 → 渲染对拍。
**绝不逐份手改 Word**——手改无法回退、无法保证多份同步、下轮生成即被覆盖。

## 1. 为什么必须这样

| 手改 Word 的后果 | 数据层生成的好处 |
|---|---|
| 改了 1 份，其余 N-1 份不同步 | 一次改，全量重生成 |
| 无法回退到上一版 | 数据层留快照即可复现 |
| 每轮迭代重新手工劳动 | 下一轮只改数据 |
| 格式被误改、封面错乱 | 版式由模板锁定 |
| 冲突无人发现 | 对账脚本自动查 |

## 2. 版本节奏

| 版本 | 触发 | 备注 |
|---|---|---|
| V1 | 首次成稿 | — |
| V2 | 版式/格式调整 | 换模板或改分页 |
| V3 | 结构/内容调整 | 章节增删、数据变更 |

- 文件名带版次：`<文档名>_V{n}.docx`。
- **旧版本保留**，新版本写**新目录**；永不覆盖源文档与历史版本。

## 3. 每轮迭代留三样

1. **数据层快照**：`config.json` 入库（或另存 `config_V{n}.json`）→ 任意版本可复现。
2. **变更记录**：文档内「修订记录」表 + 仓库提交信息。
3. **差异清单**：本轮改了哪些**跨文档数据点**（型号体系、主控、指标阈值），因为这类改动
   会影响所有引用它的文档。

## 4. 提交信息格式（本知识库统一）

```
<工程名>：<更新类别>：<更新描述>
```

- 中文；更新类别：`doc / code / fix / other`。
- 示例：`PEMS：doc：V3 封面独立成页并补充过简章节，型号表统一为30型号`

## 5. 最容易失控的三处

| 失控点 | 现象 | 防法 |
|---|---|---|
| 基线漂移 | 同一集合在不同文档来回横跳 | 基线写死在 config，只改一处 |
| 手改产物 | 有人直接改 docx，下轮被覆盖 | 产物目录视为只读；改动一律回数据层 |
| 引擎与内容耦合 | 改版式要动内容映射 | 编排只描述「内容」，版式由模板决定 |

## 6. 回退

- **产物层**：删目录重生成。
- **数据层**：`git checkout config.json` 或恢复快照。
- **模板层**：参考文档只读，不被修改，可随时重跑。

## 7. 模板版号是独立的一条轴

模板自身有版号（写在页眉，如 `QR/RD/026   2.1`），与产物目录的 `*_V{n}/` 是两条轴，不得混用同一个"版本"字样。

- 模板改版时：旧版基线件与判据档案原样保留，新版单独建档；配置里显式写 `template_version`，生成器与闸门只取该版判据。
- 两版产物不混在同一版本目录，也不得用新版"无目录/无章节"判据去检旧版稿，反之亦然。
- 版式冲突的优先级：注册人点名的模板版号基线 > 经验库通则（如"正文统一行距"）。模板自身不一致就按模板原样，要统一先经确认并写进版本说明。
- 落位约定：`template-baseline-<文档编号>-<版号>.md` + `templates/<版号>/<基线件>`；差异表只写在**新版**档案里，旧版档案不重复。


## 8. 版本目录、文件名与交付包的构成（唯一写法）

| 对象 | 写法 | 说明 |
|---|---|---|
| 输出目录 | `<族名>_V{n}`（如 `PEMS-嵌入式_V7`） | 只有族名与轮次。模板版号、交付主体、型号、工具名一律不进目录名 |
| 产物文件名 | `<文档编号> <文档名>_V{n}.docx` | 后缀 `_V{n}.docx` 由同一个 `VER` 派生，与目录名严格同号 |
| 交付包 | `<项目号>_<产品名>_<族名>_V{n}.zip` | 需要标主体/型号时写在这里，不写进目录名与文件名 |
| 草稿与外部工具产物 | `<族名>_V{n}_{来源标记}`（`_codex`、`_manual` 等） | 独立目录；不进受控交付目录，不作为基线继承，不作为闸门对象 |

三套版本号各归各处，不得互相顶名：

| 轴 | 取值处 | 落点 |
|---|---|---|
| 模板版号 | 页眉原值、配置 `template_version`（逐文档一张表） | 决定用哪套结构判据 |
| 文档族轮次 | 目录名与文件后缀 `V{n}`、`manifest.doc_round` | 决定交付与回退 |
| 软件发布/完整版本 | 正文与封面里的 `E V…`、`manifest.software_version` | 申报口径，与上两轴无关 |

**反例（都是历史上真出现过的形态）：** 把模板版号或主体拼进轮次串 —— `<族名>_模板<版号>_V{n}_<主体>`、
`<族名>_<主体>_V{n}`、`<族名>文档V{n}`。后果是换模板版号时轮次断裂、文件名后缀与目录不同号、
每轮都要重写哈希基线与页码同步判据。已存在旧形态时不强行改名，
在项目侧写一张「旧形态 → 新形态」对照表，新轮次起按本节执行。

## 9. 默认版本号怎么算（禁止硬编码字符串）

1. **单点定义**：项目侧只允许一处定义 `VER / OUT / SUFFIX`（`work/version.py` 或等价配置）。
   同一项目出现第二处默认值（哪怕只是另一份生成器脚本自带一份），即为缺陷，先合流再生成。
2. **默认值 = 现场推导**：扫描项目根既有 `<族名>_V*` 目录，取最大 n，默认 `V(n+1)`；
   显式环境变量（如 `PEMS_VER`）才允许覆盖。写死字符串会让默认值落后若干轮，一跑就重刷旧目录。
3. **推导过程要打印**：生成前打印「已存在轮次 / 本轮默认轮次 / 是否被环境变量覆盖」，让人能当场拦住。
4. **已存在即拒写**：目标目录存在时拒绝写入；确需重建同一轮次要显式 `--force`，且先把旧目录改名备份。
5. **同号自检**：闸门比对目录名轮次、文件名后缀、`manifest.doc_round` 三处，必须完全一致。
6. **manifest 必登记**：`doc_round`、`template_version`（逐文档）、`software_version`、每份页数、
   脚本版本、事实/模板/产物/配图/检查报告哈希。

判据口径见 `pitfalls.md` §83（换项目要重设的项目级口径）与 §88（版本命名与默认轮次）。
