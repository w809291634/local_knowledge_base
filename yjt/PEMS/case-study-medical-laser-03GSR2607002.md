# 实例：半导体激光治疗仪软件研究资料（PEMS）

> 这是**通用方法论的一次落地**，只作参考实例——换项目时只需替换本文件里的「项目数据」，
> 其余方法论文件与脚本不动。

## 1. 项目要素

| 项 | 值 |
|---|---|
| 产品 | 半导体激光治疗仪（II 类，09-03-01 激光治疗设备） |
| 项目号 | `03GSR2607002` |
| 结构 | 主机 + 鼻腔/耳塞/体表激光照射器（选配）+ APP |
| 文档族 | 嵌入式 8 份：RD-026/028/029/030/032/052/068/069；APP 侧另有 RD-027/057 |
| 参考模板 | 06 项目的 `PEMS文档V4`（9~10 份 docx） |
| 产物版本 | V1 →（改版式）V2 →（改结构/内容）V3 |

## 2. 该项目的基线数据（写进 `config.json`）

| 项 | 取值 |
|---|---|
| 型号体系 | `YL-10101～YL-10130`（30 个，附件配置式 + 联网开关） |
| 附件 | E01 耳塞(2)、B01 鼻腔(2)、T01/T02/T03 体表(8/12/16) |
| 联网 | 型号表「联网」列 √ 者具备 APP |
| 主控/环境 | CKS32M0+ 单片机 + 易加蓝牙模组 ECB01（BLE）、freeRTOS、Keil MDK、C |
| 治疗时间 | 10~60 min，步进 10 min，默认 30 min |
| 输出方式 | 连续输出；脉冲输出 脉宽 1s / 频率 0.5Hz |
| 光学指标 | 650nm±10nm；单支激光器 5mW±20%；发散角 42°±20% |
| 安全项 | 电压 < 3.6V 提示并**停止激光输出**；充电与治疗互斥 |
| 软件版本 | 发布 `E V1`/`M V1`；完整 `E V1.0.0.0`/`M V1.0.0.0`；规则 `M/E VX.Y.Z.B` |
| 编号 | `0XX-03GSR2607002-001`（无重复后缀） |
| 术语 | 统一用「激光照射器」，不用「探头」 |

## 3. 本轮（V3）落地时发现并处理的问题

| 类别 | 问题 | 处理 |
|---|---|---|
| 数据 | 型号体系 30 vs 40 冲突、同型号「联网」取值相反 | 以说明书为基线统一为 30 |
| 数据 | 术语「探头 / 激光照射器」混用 | 全局替换统一 |
| 数据 | 版本 `V1` vs `V1.0` 写法不一 | 区分发布/完整版本 |
| 格式 | 封面与正文同页（RD-052）、封面后空白页（RD-026/068/069） | 补分页符 + 清封面区空段 |
| 格式 | 小标题被套错样式、标题下内容过简 | 就地替换 + 按节补充内容 |
| 合规 | 模板批注未删、他项目残留、编号重复后缀 | 清理 |
| 待人工 | 图（沿用旧模板，图上仍有旧标注）、签署栏 | 需人工替换/签署 |

## 4. 复用要点（换项目的三步）

1. 复制方法论文件与 `tools/`（无需改动脚本）。
2. 新建 `config.json`：填项目号、产品名、型号/附件、主控、指标、版本、编号、术语替换表。
3. 指定参考模板（只读），跑 `build_docs.py` → `consistency_check.py` → 渲染对拍 → 人工核图与签署。

> 关键：**只有本文件与 `config.json` 含项目专有信息**；方法论与脚本保持通用。
