# NTC 测温与控温：比率式不受 VCC 影响，但采样窗口与热耦合会骗你

> 适用：STC8H/STC8G 用片上 ADC + 上拉电阻 + NTC 分压测温的工程；其中"采样窗口""热梯度"两节对任何 MCU 的 ADC 都成立
> 来源工程：STC8H1K08 家用红蓝光治疗仪固件（2026-10-12 ~ 2026-10-16；用 1% 精密电阻替代 NTC 核对链路）
> 目标：把"测温代码正常，但测到的不是面温"这件事的判据与自检方法讲清。

## 结论先行

1. **分压高侧与 ADC 基准同源时，参考电压（5V / 3.3V）不影响读数**——10 位 ADC 读的是比值，VCC 在公式里被约掉；**唯一副作用是 VCC 越高 NTC 自热越大**（5V 约为 3.3V 的 2.3 倍），方向**偏高**、量级 **+0.3~0.6℃**，属固定偏差，可被标定偏移吸收。
2. **"多次采样去极值平均"能否抑制 LED PWM 纹波，取决于采样总时长是否覆盖 PWM 周期**：背靠背 8 次转换只有几十 µs，而 500 Hz PWM 周期是 2 ms ⇒ **8 点落在同一相位，这条注释实际不成立**。
3. **单点 NTC 只能代表它自己那一点**：NTC 与 LED 板热耦合过紧时，读数**随 LED 通断大幅摆动**（停光后仍继续上升 = 热惯性），此时"按通道标一个固定偏移"永远贴不准。

## 1. 比率式：VCC 不影响读数，但影响自热

分压高侧与 ADC 基准为同一路 VCC 时：

```
ADC码 = 1023 × V(NTC) / V_ref
      = 1023 × R_ntc / (R_ntc + R_pull)        ← VCC 被约掉
```

⇒ **同一温度下 5V 与 3.3V 得到相同的 ADC 码**，所以"按 ADC 码写的查表"**不需要因为改电压而重算**。

**必须排查的例外**：分压高侧与基准**不同源**（例如 NTC 上拉到 3.3V，而 MCU VCC = 5V）⇒ 读数整体被缩放，**这是硬件问题，不要用偏移去补**。

**自热**（P = V(NTC)² / R_ntc）：25℃ / 10 kΩ 时，5V 下 V(NTC) = 2.5V ⇒ **0.63 mW**；3.3V 下为 **0.27 mW**。方向偏高且固定，标定偏移可吸收。
参考：芯片侧的地线/大电流纪律见 `embedded/mcu-chip-families/stc-c51-and-ch32-wch.md`（ADC 采样期间 I/O 不驱动大电流）。

## 2. 采样窗口：8 点去极值 ≠ 抑制 PWM 纹波

- **判据**：**采样总时长 ÷ PWM 周期 ≈ 0**（几十 µs vs 2 ms）⇒ 8 个采样点落在**同一个 PWM 相位**，"去极值平均"退化成"同相位多点平均"，纹波照样进来、且**随占空比变化**。
- **现场验证（几分钟）**：设备**冷却后**，分别在"完全不出光 / 25% 占空比 / 100% 占空比"三种状态各读一次 `ntc_adc`：
  - 三态读数**几乎一致** ⇒ 属于热的问题（见第 3 节）；
  - 读数**随占空比明显变化** ⇒ 属于采样/滤波问题 ⇒ 在 NTC 节点加 RC（如 10 kΩ + 100 nF），或把 8 次采样**分散到一个 PWM 周期内**。
- 注意：单次说明不了问题，**必须取稳定后的值**（本工程实测温度打印周期 ≥ 1 s，不要按瞬时抖动下结论）。

## 3. 热耦合：单点 NTC 测的不是"面温"

- **症状**：同一个 NTC、同一个补偿值，红光"准"、蓝光差约 5℃；蓝光运行中读数高到 **80℃+**（治疗面不可能是这个温度）；**停光之后读数还在继续上升**。
- **根因**：NTC 的热耦合对象是 **LED 板**（热阻小），与**治疗面**之间热阻大。LED 一起一停，NTC 立刻跟着大幅摆动，而面温几乎不动 ⇒ **两者的差值不固定，固定偏移不可能贴准**。
- **判据 / 修法**：
  - **治本**：把 NTC 移到治疗面，或与 LED 板做热隔离（这是唯一能让读数代表面温的办法）。
  - **治标**：按通道各标一个偏移（本工程为 `BOARD_CFG_APP_NTC_OFFSET_RED_X10` / `..._BLUE_X10`），且整机标定时用**实测面温**定值，**不要用电阻反推**（电阻只能验证链路，验证不了热梯度）。
  - **安全方向**：若某通道 NTC 读数**低于**面温 ⇒ 会突破 43℃ 上限，必须先把该通道偏移调上去；若 NTC 被 LED 板主导而读到 80℃，说明 **LED 板本身已 80℃**，是 LED 寿命与结构隐患，需硬件一并确认。

## 4. 链路自检：用 1% 精密电阻替代 NTC

10 kΩ 上拉、NTC 下拉到 GND 时，`ADC ≈ 1023 × R / (R + 10000)`，允许约 ±2% 偏差：

| 电阻 | ADC | 对应温度 |
|---|---|---|
| 33 kΩ | ~788 | 0 ℃ |
| 10 kΩ | ~512 | 25.0 ℃ |
| 5.1 kΩ | 345 | 41.0 ℃ |
| 4.7 kΩ | ~327 | ~43 ℃ |
| 3.6 kΩ | 270 | 50.0 ℃ |
| 2.0 kΩ | ~170 | 66.5 ℃ |
| 1.5 kΩ | 133 | 75.0 ℃ |

**实测案例**（2 kΩ、蓝光通道、偏移 +60）：理论应打印 **725**，实测 **716** ⇒ 差 **0.9℃（−2%）**，落在公差内 ⇒ **测温链路（采样 / 查表 / 插值 / 通道偏移）全部正常**；剩余偏差归属模拟链路（测试电阻实际值、上拉阻值、ADC 增益误差），且是**比例误差**，在 41~44℃ 工作窗口折算约 0.8℃。

⇒ 结论模板：**"代码正常" ≠ "测到的是面温"**，这两件事必须分开下结论。

## 5. 附带的设计经验（方法本身换 MCU 也成立）

- **执行器只有几档时，控温用"三带 + 迟滞的 bang-bang"，不要上 PID**：PI 的输出必须量化成档位，量化之后就退化成开关，徒增积分饱和/溢出/参数整定风险。
- **"亮度不跳变"要靠独立的限速层结构性保证**（每个刷新节拍最多挪 N 个占空比单位），而不是靠调控制参数；上层阈值怎么跳都行，亮度永远匀速过渡。
- **单点测温的闭环只能控那一个点**：多点均匀性、面温上限属热设计与测温点布局问题，算法解决不了。
