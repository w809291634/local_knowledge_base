# Keil C51 语言层坑合集：变参 3 字节通用指针 / data 关键字 / 指针存储区限定 / CONST 段 / tick 撕裂

> 适用：一切 Keil C51 工程（不限 STC），这些全是"编译能过或报错诡异、凭直觉必错"的语言层知识
> 来源工程：STC8G_8H_SDK（apl_kprintf / apl_pubsub / drv_tm1650 / apl_soft_timer 实踩）
> 目标：一次记牢 C51 与标准 C 的关键差异，避免在新工程重复交学费。

## 结论先行

四条铁律：① 给 `...` 传指针**一律按 3 字节通用指针编码**，拿不准就反汇编实测，别凭直觉；② `data` 是存储类型关键字**不能当标识符**，一律叫 `dat`；③ 指向确定存储区的指针**必须写明限定符**（`xdata`/`code`/`idata`），否则退化成 3 字节通用指针、每次访问走运行时分派白占几百字节 ROM；④ CONST 段整体合并，**没人调的字符串常量不会自动裁**，想省 flash 必须删源码或 `#ifdef` 包住。

## 1. 【最严重】变参 `...` 传指针一律 3 字节通用指针

**事故**：自研 `kprintf` 最初假设"裸字符串常量传给 `...` 时 C51 按 2 字节 code 地址压栈"，自实现的 `kva_arg(ap, char code *)` 只读 2 字节。2026-08-06 实机测试发现 **`%s` 一律打印空字符串**。

**排查方法**（唯一可靠）：`C51.EXE ... SRC(xxx.lst)` 生成**带指令码的完整反汇编**（不是默认 `PRINT()` 的纯源码清单），逐字节数调用点实际压栈内容——发现对 `%s` 实参写的是 `MOV ?xxx?BYTE+02H,#0FFH / +03H,#HIGH(...) / +04H,#LOW(...)`，共 **3 字节**（1 字节空间标签 + 2 字节地址），`kva_arg` 只读 2 字节，少读的 1 字节标签导致后面所有参数错位。

**修复**：`%s` 分支改用不限定存储区的通用指针取参（`kva_arg(ap, char *)`，3 字节），解引用走一次 `?C?ILDPTR` 运行时分派——正确性必须付的开销，省不掉。

**教训**：C51 变参调用约定跟普通具名形参不是一回事；具名形参哪怕限定了存储区，也不代表 `...` 里传指针同样处理；文档/直觉判断压栈字节数不可靠，拿不准就反汇编实测。

## 2. `data` 不能当标识符用

`data` 是 C51 存储类型关键字（与 `code`/`idata`/`pdata`/`xdata`/`bit` 同伙），当变量名/形参名/结构体成员名都报语法错误。已踩过 `apl_pubsub.c` 事件结构体成员、`drv_tm1650.c` 形参两处。

**约定：凡是"一段数据/一个字节"含义的形参或变量，一律叫 `dat`，不要叫 `data`。**

## 3. 指针必须写存储区限定符，否则拉入通用指针运行时分派

- 反例（`drv_input_lite.c` 注释原文）：`input_lite_obj_t *` 不写 `xdata`，编译器不知道指向哪个存储区，每次 `in->xxx` 都要调 `?C?PSTOPTR`/`?C?ISTOPTR`，**白占几百字节 ROM**。正解：`input_lite_obj_t xdata *in;`
- 同理：指向 xdata 对象的局部指针（`input_lite_obj_t xdata *obj;`）也要写全，循环体内反复解引用时收益更大。
- 监控手段：看 `.map` 里 `?C?...PTR...` 符号总字节数（check_overlay_safety.py 的 Check 3 顺手报），明显变大就回头查新写的指针。

## 4. CONST 段整体合并——字符串常量不会自动裁

链接器把所有 `code` 常量合并进 CONST 段，函数没人调了，它引用过的字符串常量**仍然占 flash**。想真省：删源码，或用 `#ifdef` 把字符串/调用点整段包住。

## 5. ISR 逐字节写 32-bit 变量的读取撕裂

**场景**：1ms 定时器 ISR 里 `tickCnt++`（uint32_t 在 xdata，逐字节写），主循环单条读可能撞上写一半——读到撕裂值。

**修法**（`apl_soft_timer.c` 的 `tickCnt_Get()`）：两次读一致法，读到相等才返回：

```c
uint32_t t1, t2;
do {
    t1 = tickCnt;   /* volatile xdata */
    t2 = tickCnt;
} while (t1 != t2);
return t1;
```

无锁、不动 EA，对单调递增计数器正确（两次一致必是完整值）。配套：阻塞延时用无符号差值比较 `(now - start) < ms`，天然兼容 tick 回绕。凡"ISR 写多字节变量、主循环读"的地方都适用此模式。

## 6. SMALL 模型 DATA 纪律

- 内部 DATA 总共 128 字节，`Program Size` 的 data 超 90% 就要警惕。
- 调度函数/高频函数里的重量级局部数组直接挪 `xdata`（如 kprintf 的 11 字节转换 buf），别留在 DATA 里参与 overlay 争用（实测会挤爆）。
- 回绕类型按场景选：输入时间戳 `uint16_t`（65 秒回绕对消抖/长按够用），系统 tick 必须 `uint32_t`；Keil C51 不支持 64 位。
