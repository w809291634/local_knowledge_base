# 软件交付数据统计（月度） → 软件N月份工时统计表：按人补录

> 适用：把《2026年软件交付数据统计（月度统计）》里某人某月的日报节点，转成《软件N月份工时统计表》里
> "一人一块、块末小计"的工时报账行。上一步《项目计划表 → 交付统计》见 `yjt/delivery_stats/plan-to-stats-monthly-transfer.md`。
> 来源：2026-11-02 实做（10 月统计表 → 10 月工时表，75 行 7 人）；两份 xlsx 位置属 **B 类机器路径**，本文与脚本只留占位符。
> 目标：换月份只改月份数字和文件路径；行数、合计、样式、门禁都可复现。

## 1. 三张表的分工与命名

| 表 | 一行代表 | 命名 |
|---|---|---|
| 项目计划表 | 一个项目 | `研发中心N月项目计划定版<日期>.xlsx` |
| 交付数据统计 | 一个工程师的一个节点 | `2026年软件交付数据统计（月度统计）.xlsx` |
| 工时表 | 一个工程师的一个节点（报账口径） | `软件N月份工时统计表（YYYYMMDD汇总）.xlsx`，每月一册、历史月页保留 |

工时表是**按月一册**：新月份以上一册为模板复制，命名带月末日期；8/9 月页作为历史保留，逐格不得改。

## 2. 工时表结构（模板事实）

- 第 1–7 行是表头：A1:J1 合并大标题，C4:G4 合并填写规则，第 7 行是列名，数据从第 8 行开始。
- 20 列：A 序号、B 月份、C 项目经理、D 职能部门、E 提交人、F 所属业务部门、G 项目类型、
  H 项目编号、I 项目名称、J 任务内容、K 主要完成事项、L 完成阶段、M 计划工时（天）、N 实际工时（天）、
  O 单位1标准数量、P 有无延期、Q 延期原因、R 备注、T 计划日期。
- **一人一块**，块末一行只填 N 列 `=SUM(N首行:N末行)` 作小计；块与块之间不插空行。
- B 列月份跟最近月份的写法：08 月写 `202608`，09 月写 `9月`，10 月照最近写 `10月`。
- 模板里预先编号的空白行就是给人填的；**序号不要重编**，跨月重复是常态。
- 样式：微软雅黑 10、居中、细框、行高 21.95；小计行沿用既有小计行的样式（全框、自动换行）。
- 冻结 B16、A1:J1 与 C4:G4 合并、列宽都保持模板原样。

## 3. 取数边界：统计表里哪些行算本月

1. 先按统计表 A 列的 `N月份` 分组行框出本月区块（到下一个 `X月份` 行之前）。
2. 区块内：需求时间在本月 → 收；无日期 → 收（放在本月块里即本月的事）。
3. 区块内但需求时间是上月、结果时间在本月 → 收（跨月完成）。
4. 区块内但需求时间是上月、且没有本月结果 → 不收（上月结转，上月已报）。
5. 区块内但需求时间是下月 → 不收（下月计划）。
6. 本月块**之后**、日期却属于本月的行 → 收（实测有记录被错放到后面的月份段下，如 12 月段里躺着一行 10 月 27 日的记录）。
7. 本月块**之前**的同日期行 → 不收（属于上月段的记录，上月已按同事项报过，例如统计表里同一件事常有两行重复记录）。

## 4. 列映射与取值优先级

| 工时表列 | 来源 | 优先级 |
|---|---|---|
| A 序号 | 模板原有编号 | 不动 |
| B 月份 | 月数字 | `N月` |
| C 项目经理 | 统计表 AA → 上月同项目 → 本月计划表 → 下月计划表 | 空且类型=注册时兜底 黄雅萍 |
| D 职能部门 | 固定 | `软件` |
| E 提交人 | 统计表 D（软件工程师） | — |
| F 所属业务部门 | 名称尾注主体 → 本月计划表 → 下月计划表 → 上月同项目 → 统计表 AB | 只接受部门词表或注册主体；名称里出现的客户名不算 |
| G 项目类型 | 上月/8 月同项目 → 本月/下月计划表"类别" → 注册主体或 PM=黄雅萍 → 内部事务词 → 统计表阶段 | 见 §5 |
| H 项目编号 | 统计表 A，去掉"（订单）"后缀 | 双编码整串保留 |
| I 项目名称 | 统计表 B | — |
| J 任务内容 | 统计表 H（节点事件） | — |
| K 主要完成事项 | 统计表 Q | — |
| L 完成阶段 | 统计表 P 的百分比 ÷100 | 100%→1、80%→0.8 |
| M 计划工时 | 统计表 N 估计工时；空则 M 外部工时 | 两列一般只填一个 |
| N 实际工时 | 统计表 L 实计工时 | 文本要先归一，见 §6 |
| O 单位1标准数量 | `=M{行}/7`，数字格式 0.0 | 计划工时为 0 或空则不填（8 月口径） |
| P 有无延期 | 结果时间晚于需求时间，或完成进度<100% → 有 | 否则无 |
| Q 延期原因 | 统计表 R 备注事项 | 仅延期时填；源表没写就留空 |
| R 备注、T 计划日期 | 留空 | 08/09 月也一直空 |

**F/G 没有直接来源列**：计划表的"类别"是订单/模具样机/注册样机这类交付阶段，不是项目类型；
统计表的"阶段"（开发阶段/小批量/注册…）也不等价。所以只能按上表优先级推，推断出来的行要列给人复核。

## 5. 项目类型的推导口径（按证据强弱）

1. 上月/8 月工时表同编号或同名 → 直接用原值（最可靠，先查这个）。
2. 计划表"类别"：订单→订单；注册送检/注册体考/注册样机/新产品送检/体考（未出报告）→注册。
3. 所属部门是注册主体（益健堂/元良/康特瑞/普莱/泽生康）或项目经理是黄雅萍 → 注册。
4. 内部事务词：软著/技术探索/测试用例/模板 → 研发验证；协调管理 → 协调管理重难点跟进（9 月原词）。
5. 统计表阶段兜底：注册→注册；小批量/试产验证→订单；中试跟进/送样→样机；开发阶段/测试BUG修复→全新。
6. 都没有 → 留空，不硬猜。

## 6. 数字与文本归一

- 工时文本：`0,5`→0.5、`4+0.5`→4.5、`0.75 +0.2`→0.95、`2.5 + 0.2`→2.7、`1.1⏎`→1.1；`实时`等非数字→空。
- 完成阶段：`100%`→1、`85%`→0.85。
- 同一事项在统计表可能出现两行（重复记录），按 §3 第 7 条只收本月那行，避免重复计工时。

## 7. 不代填的项

统计表没有、工时表却需要的：J/K 的细化描述、M 的估算、N 的实计、R 的加班补记。
源表空着就留空，等本人补；不要拿估计工时去顶实计工时。

## 8. 写入五步与门禁

1. 以上一册为模板，目标页 = `N月` 页；先备份成 `tmp/…备份前_日期.xlsx`。
2. 从第 8 行起按 §3 重排；每人一块，块末写 `=SUM(N首:N末)`。
3. 保存：**先写临时文件再 `os.replace`**。目标被 WPS/Excel 打开时（目录有 `~$` 锁文件）另存 `_待替换.xlsx` 并提示关闭，**不要杀进程**。
4. 打开重算：`wb.calculation.fullCalcOnLoad = True`，否则小计列看不到数。
5. 对账（四条，缺一不可）：
   - 历史页（08/09 月）与模板逐格零差异；
   - 行数 = 本月取数行数；计划/实际工时合计 = 统计表对应列按同口径合计；
   - 小计公式条数 = 人员块数，且每条 SUM 范围正好覆盖本块；
   - ZIP 结构可读（`zipfile.testzip()` 为空），sheets/合并/冻结未变。

## 9. 已知坑

- 统计表的月份分组行可能缺字（例如 10 月块只有 `10月份` 行可定位），先打印 A 列月份行确认。
- 计划表工作簿里还有 `8-10月延误记录`，标题里含"10月"，按标题筛表会误读；只认标题含"项目计划分解/项目交付目标/项目目标"的页。
- 计划表各分段列序不同（有的段 M 是"类别"，有的段 M 是"备注"），**每段表头都要重新取列位**，不能只认第一段。
- 同编码不同注册主体（如 04KF006R2507 同时挂益健堂与普莱）两条都要留，靠名称前缀/主体列区分。
- 编码有缺前导 0 的写法（`3GSR2607002` vs `03GSR2607002`），照抄不改，存疑登记。
- 统计表 AB 列可能是客户人名（如"宋强"），不是部门；只接受部门词表里的值。
- 部门值有历史错字（如"国内"），不在词表里就跳过，继续往下一个来源找。

## 10. 脚本

`yjt/delivery_stats/tools/stats_to_timesheet.py`，`sys.path.insert` 直接 import。

| 参数 | 作用 |
|---|---|
| `--stats` | 交付数据统计 xlsx（B 类真值） |
| `--template` | 上一册工时表（提供 `N月` 页与 8/9 月历史） |
| `--plan` | 项目计划表（补项目经理/部门/类型，可省） |
| `--month` | 月份数字 |
| `--out` | 输出文件 |
| `--apply` | 不加只干跑打印；加了才写盘（临时文件 + 原子替换） |

2026-11-02 用 10 月真实数据重跑验证：75 行、7 个人员块、计划 147.3 / 实际 87.0，与交付件一致；
A/B/D/E/H/I/J/K/L/M/N/O/P/Q 逐格一致；F/C 两列有 10 格不同，全部是"计划表本月口径 vs 上月习惯写法"的差异
（脚本以本月计划表优先），这类差异要人工拍板后回填。
